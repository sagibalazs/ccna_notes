> 🧭 **The mental shift:** in IPv4 an interface had *one* address. In IPv6 an interface normally has **several at once** — a link-local **plus** a global and/or unique-local — each with a different **scope** (how far it's allowed to travel). This doc is about those three **unicast** scopes. Multicast/anycast are 3.9.

---

## 2. 🗺️ Visualization — The Whole Picture at a Glance

**Three unicast types = three reachability scopes (a ladder):**

```
 SCOPE          TYPE                RANGE          Routed where?              Always on?
 ────────────   ─────────────────   ────────────   ────────────────────────  ──────────
 🔗 link        Link-Local (LLA)    fe80::/10      THIS segment only          ✅ always
 🏠 site/org    Unique Local (ULA)  fd00::/8       inside your org (no NAT)   ⬜ optional
 🌍 global      Global Unicast(GUA) 2000::/3       the whole Internet         ⬜ if online
```

**One interface, many addresses (the normal state):**

```
   Router G0/0:
     fe80::1                         ← link-local  (auto, for NDP/next-hop)
     fd00:abcd:1234:1::1/64          ← ULA         (stable internal identity)
     2001:db8:acad:1::1/64           ← GUA         (internet-facing)
   ...all three live on the SAME interface simultaneously.
```

**ULA bit-structure (fd00::/8 — the half actually used):**

```
   | 7 bits |L|   40 bits    | 16 bits |        64 bits          |
   | 1111110|1|  Global ID   | Subnet  |      Interface ID       |
     └fc00::/7┘  (random!)     (0-FFFF)
     └────── fd ──────┘
   e.g.  fd 12:3456:789a : 0001 :: /64      L=1 ⇒ "fd", locally assigned
```

**GUA bit-structure (2000::/3):**

```
   |     48 bits (from ISP)      | 16 bits |        64 bits          |
   |    global routing prefix    | Subnet  |      Interface ID       |
   e.g.  2001:db8:acad          : 0001    :: /64
```

> 🧭 **One idea:** **scope** is the organising principle. Pick the address whose reach matches the job — never route a link-local, never expose a ULA, never rely on a GUA being present offline.

## 3. ⚡ TL;DR

- 🟢 **Link-Local (LLA) `fe80::/10`** — **auto-generated on every IPv6 interface**, valid only on the **local link**, never routed. It's *load-bearing*: NDP, the default gateway, and routing-protocol adjacencies all run over it.
- 🟢 **Unique Local (ULA) `fc00::/7`** — the internal/private type. In practice only **`fd00::/8`** (L-bit = 1) is used; the `fc00::/8` half is undefined. Routable **inside your org**, never on the internet — and **no NAT** in the intended model. Defined in **RFC 4193**.
- 🟢 **Global Unicast (GUA) `2000::/3`** — the **internet-routable**, globally-unique type; the IPv6 equivalent of a public IPv4 address.
- 🟢 **An interface holds several at once** — always a link-local, usually a GUA and/or ULA — so IPv6 troubleshooting means knowing *which* address is in play.
- 🟢 **ULA's 40-bit Global ID is random** so two orgs that merge almost never collide — a direct fix for IPv4's `192.168.1.0/24`-everywhere problem (3.5).
- 🔵 🕵️ **Your IPv6 default gateway is a link-local (`fe80::`) address** — routing next-hops and OSPFv3/EIGRP adjacencies use link-local, not global. Link-local is infrastructure, not disposable auto-junk (§6.6).

> ⚠️ **Deprecated:** **site-local `fec0::/10`** was the original "private" type — **killed by RFC 3879**, replaced by ULA. Never use it.

---

## 4. 🎯 Importance — The Problem First

**The problem:** "reachability" is not one thing. Different jobs need traffic to travel **different distances**:

- 🔗 Two devices need to talk **on the same wire** *before* any global config exists — e.g. a host asking "who is my router?" (NDP), or a routing protocol forming an adjacency. This must work **with zero configuration and zero routing**.
- 🏠 An organisation needs **stable internal addresses** for its servers, printers, and management — addresses that **don't change** when the ISP changes, and that **never leak** to the internet.
- 🌍 A device needs to reach and be reached **across the internet** — a globally-unique, routable identity.

In IPv4 these were bodged together: link-local was the rarely-used APIPA fallback (3.6), "internal" meant RFC 1918 **+ NAT** (3.5, with all its end-to-end damage), and "public" meant a scarce, ISP-tied address. One address per interface had to try to cover everything.

**The solution — explicit, simultaneous scopes.** IPv6 gives every interface **a purpose-built address for each distance**, all at once:
- **Link-local (`fe80::`)** — automatic, guaranteed, link-only → the bootstrap layer everything else stands on.
- **Unique-local (`fd00::`)** — provider-independent, stable, internal-only, **globally unique by random Global ID** → private addressing **without NAT** and **without merge collisions**.
- **Global unicast (`2000::/3`)** — the routable internet identity → end-to-end restored.

> **Why this matters at engineer depth:** almost every IPv6 "it doesn't work" ticket comes down to **using the wrong scope** — routing a link-local, exposing a ULA, or expecting a GUA that isn't there. Once you internalise the scope ladder, IPv6 behaviour becomes predictable. And knowing that the **gateway/next-hop is link-local** (§6.6) is the single fact that unlocks IPv6 routing tables.

## 5. 📖 Description

- 🟢 **Scope.** How far an address is valid/routable: **link** < **site/org** < **global**. Every IPv6 address has one.
- 🟢 **Link-Local (LLA) `fe80::/10`.** Auto-configured on *every* interface at start-up; unique only **per link**; **never forwarded** by routers. Effectively `fe80::/64` (bits 11–64 are zero), so you only ever see `fe80::…`.
- 🟢 **Unique Local (ULA) `fc00::/7` → `fd00::/8`.** Internal, provider-independent, non-internet-routable. **L-bit = 1** ⇒ locally assigned (`fd`); the `fc00::/8` half (L=0) is **undefined/unused**. 40-bit **random Global ID** for uniqueness.
- 🟢 **Global Unicast (GUA) `2000::/3`.** Globally unique and internet-routable; typically **48-bit routing prefix (ISP) + 16-bit subnet + 64-bit interface ID**.
- 🟢 **Multiple addresses per interface.** Normal and expected; the OS picks a **source** per destination (RFC 6724).
- 🔵 **Special unicast (from 3.7):** unspecified `::`, loopback `::1` — not scoped host addresses.
- 🔵 **Deprecated:** site-local `fec0::/10` (RFC 3879) — replaced by ULA.

## 6. 🔧 How It Works — Under the Hood

### 6.1 🟢 Scope is the organising principle

Every IPv6 address advertises, by its **high-order bits**, how far it may travel. Routers enforce it: they **never** forward link-local off the link, and (by default) **never** advertise ULA (`fc00::/7`) across administrative boundaries (RFC 4193 §4.1). GUA flows anywhere. Match the tool to the distance.

### 6.2 🟢 Link-Local `fe80::/10` — the always-on bootstrap layer

The moment an interface enables IPv6, it **builds a link-local address by itself** — `fe80::` + a 64-bit interface ID (how that ID is formed = EUI-64/random, 3.10) — and verifies uniqueness with DAD (3.11). Properties:

- 🔗 **Link-scoped:** valid only on that segment; two hosts on one switch can talk LLA-to-LLA, but nothing beyond. Routers **never** forward it.
- 🧰 **It does real work:** NDP (router/neighbor discovery), the **default-gateway** address hosts learn from Router Advertisements, and **routing-protocol adjacencies** (OSPFv3, EIGRP for IPv6) all use link-local (§6.6).
- ♻️ **Not globally unique** — the *same* `fe80::1` can exist on every router interface. So you must **name the interface** when you use one: `fe80::1%eth0` (host) / `...via FE80::2 GigabitEthernet0/0` (router). This "zone ID" is mandatory, not optional.

### 6.3 🟢 Unique Local `fd00::/8` — private done right

ULA is the IPv6 answer to "I need internal addresses I control." Structure (RFC 4193):

```
   | 7 bits |L| 40 bits    | 16 bits | 64 bits      |
   |1111110 |1| Global ID  | Subnet  | Interface ID |
     prefix fc00::/7           ▲
     L=1 ⇒ leading byte "fd"   └ 40 RANDOM bits → near-zero collision chance
```

- 🎲 **Random Global ID → merge-safe.** Generate `fd` + 40 random bits once (e.g. `fd12:3456:789a::/48`) and you get **65,536 `/64` subnets** that almost certainly never clash with any other org's ULA. Contrast IPv4, where *everyone* uses `192.168.1.0/24` and mergers collide (3.5 §6.6).
- 🚫 **Internal only, but NO NAT.** ULA is *routable inside the site* and carried by internal routing protocols unchanged; exterior routing **ignores/doesn't advertise** `fc00::/7` by default. The intended model is **ULA for internal + GUA for external, both on the interface** — *not* ULA behind NAT66 (§11 trap).
- 🧊 **Only `fd00::/8` is real.** The `fc00::/8` half (L=0) was reserved for a possible central registry that never happened — so in practice you always see **`fd`**.

### 6.4 🟢 Global Unicast `2000::/3` — the internet identity

The routable, globally-unique type — a public address, but abundant. Typical hierarchy (3.7):

```
   2001:db8:acad : 0001 :: /64
   └── 48-bit ──┘  └16┘   └── 64-bit interface ID ──┘
   routing prefix   subnet
   (from your ISP)  (yours to plan)
```

- 🌍 `2000::/3` (i.e. `2000::` – `3fff::`) is the block currently delegated by IANA for global unicast; the rest of the space is reserved.
- 📄 `2001:db8::/32` is the **documentation** GUA (RFC 3849) used throughout these docs.
- Unlike IPv4 public addresses, there's no scarcity pressure — every site gets many subnets (a `/48` = 65,536 `/64`s).

### 6.5 🟢 Many addresses, one interface — and how the OS chooses

A single interface routinely carries **link-local + ULA + one-or-more GUAs** at the same time. When it sends a packet, the OS runs **default address selection (RFC 6724)** to pick a **source** that matches the destination's scope (link-local source for a link-local dest, GUA source for an internet dest, etc.). This is powerful but a common source of subtle "wrong source address" bugs — worth knowing the algorithm *exists* even before you master it (CCNP depth).

### 6.6 🕵️ Dirty Secret — your default gateway is a link-local address

IPv4-trained engineers expect the next-hop/gateway to be a "normal" (global) address. In IPv6 it usually **isn't**:

```
   show ipv6 route
     S  2001:db8:2::/64 [1/0]
         via FE80::2, GigabitEthernet0/0      ← next-hop is LINK-LOCAL, not global
   Host default gateway (from Router Advertisement) = fe80::<router-id>
   OSPFv3 / EIGRPv6 neighbors are listed by their fe80:: addresses
```

**Why on purpose?** The next hop is, by definition, **on the same link** — so a link-scoped address is the natural, most stable identifier for it. It keeps working even if the global prefix changes or isn't configured yet, and it decouples forwarding from provider addressing. Consequences you must handle:

- 🧭 A **static route to a link-local next-hop must also specify the exit interface** (`ipv6 route 2001:db8:2::/64 fe80::2 Gig0/0`) — because `fe80::2` alone is ambiguous across interfaces (§6.2).
- 🔎 When a route "looks wrong," check the **`fe80::` next-hop and its interface**, not a global address.
- 🛡️ Because link-local is load-bearing, attacks on it matter — **RA spoofing/guard** (3.11) is a real security topic, not trivia.

> **Engineer takeaway:** link-local is **not** disposable auto-configuration noise — it's the **control-plane substrate** of IPv6. The person who knows "the gateway is `fe80::…`, and I must pin the interface" debugs IPv6 routing in seconds; the person who ignores link-local stares at a broken route map for an hour.

## 7. ⚖️ Pros & Cons

| Type | ✅ Strengths | ❌ Watch-outs |
| ---- | ----------- | ------------ |
| **Link-Local** | Automatic, always present, powers NDP/gateway/routing | Not routable; not unique → must pin interface (zone ID) |
| **ULA** | Provider-independent, stable, merge-safe (random ID), **no NAT** | Not internet-routable; tempts people into wrong NAT66 designs |
| **GUA** | Globally unique, end-to-end, abundant | ISP-tied prefix (renumber if you change providers) |
| **(All together)** | Right scope for every job, simultaneously | Source-address selection can surprise you (RFC 6724) |

## 8. 🌿 Variants — Common → Specific

- 🟢 **Link-Local `fe80::/10`** (effectively `fe80::/64`) — the universal, automatic type.
- 🟢 **Unique Local `fd00::/8`** — locally assigned ULA (the only half in use).
- 🟢 **Global Unicast `2000::/3`** — internet-routable; `2001:db8::/32` reserved for docs.
- 🔵 **`fc00::/8` (L=0)** — undefined ULA half; recognise, never use.
- 🔵 **Special unicast:** unspecified `::/128`, loopback `::1/128` (3.7).
- ⚪ **Deprecated:** site-local `fec0::/10` (RFC 3879) — historical only.
- ➡️ **Other address *categories* (not unicast):** multicast `ff00::/8`, anycast (borrowed from unicast) → **3.9**.

## 10. ✅ Best Practices

- 🟢 **Let link-local be automatic** — don't fight it; rely on it for NDP/gateway/adjacencies.
- 🟢 **When referencing a link-local, always pin the interface** (`fe80::2%eth0` / `... fe80::2 Gig0/0`).
- 🟢 **Use GUA (`2000::/3`) for internet-facing hosts; use ULA (`fd00::/8`) for stable internal-only identity** — run **both** on the interface, no NAT.
- 🟢 **Generate ULA Global IDs randomly** (per RFC 4193) — don't hand-pick `fd00::` everywhere, or you re-create the collision problem you're trying to avoid.
- 🔵 **Mirror ULA and GUA subnet IDs** (same `/64` numbering) so internal addressing stays parallel and readable (RFC 4193 §4.1).
- 🔵 **Never advertise `fc00::/7` externally**; filter it at the border (usually the default).
- 🔵 **Deploy RA Guard** to protect the link-local control plane (3.11).

## 11. 🚫 No-Goes — Common Mistakes & Troubleshooting Traps

- ❌ **Trying to route a link-local address off its segment.** It's link-scoped by design; routers drop it.
- ❌ **Using a link-local next-hop without an exit interface.** `fe80::2` is ambiguous → route won't install/behaves oddly (§6.6).
- ❌ **Deploying ULA + NAT66 as "RFC 1918 for IPv6."** The intended model is **ULA internal + GUA external simultaneously, no NAT**. NAT66 re-imports IPv4's end-to-end problems.
- ❌ **Hand-assigning `fd00:0:0::/48` on every site.** Non-random Global IDs defeat the collision-avoidance purpose — merges will clash.
- ❌ **Using `fc00::/8` (L=0).** Undefined/unused — only `fd00::/8` is valid in practice.
- ❌ **Using site-local `fec0::/10`.** Deprecated (RFC 3879) — dead.
- 🕵️ **Trap — "why is my gateway `fe80::`?"** That's correct IPv6 behaviour, not a bug (§6.6). Debug the link-local next-hop + interface.
- 🕵️ **Trap — wrong source address.** A host with LLA+ULA+GUA may pick an unexpected source (RFC 6724) → apparent one-way failures. Check which source scope matches the destination.

## 13. 🧪 Practical Tasks

1. 🏷️ **Type-ID drill.** Classify each by scope: `fe80::a1`, `fd12:3456:789a:1::10`, `2001:db8:acad:1::10`, `fec0::1`, `fc00::1`, `::1`. Say routable-where for each.
2. 🎲 **Generate a ULA prefix.** Produce a random `fd` + 40-bit Global ID `/48`; list its first three `/64`s. (Never reuse `fd00:0:0::`.)
3. 🖥️ **Inspect your interface.** `ip -6 addr` / `ipconfig`: identify the `fe80::` link-local and any GUA. Note the interface has **several** IPv6 addresses at once.
4. 🧰 **Packet Tracer 8 — three types live.** On a router LAN interface configure a GUA (`2001:db8:acad:1::1/64`) and a ULA (`fd00:abcd:1::1/64`); note the auto `fe80::`. From a PC, ping all three and observe which work on-link vs off-link.
5. 🧭 **See the link-local gateway.** On a router with a static/RA default, run `show ipv6 route` and confirm the next-hop is `fe80::…`; build a static route to a link-local next-hop **with** the exit interface, and one **without**, and compare.
6. 🔬 **Wireshark.** Capture on an IPv6 link: identify NDP (RS/RA/NS/NA) using **link-local** sources; confirm ULA/GUA traffic uses the larger-scope addresses (preview 3.9/3.11).
7. 🤝 **Merge lab (🔵).** Two "sites" each with a *random* ULA `/48`; interconnect and show no collision — then repeat with both hand-set to `fd00:0:0::/48` and watch them clash.
