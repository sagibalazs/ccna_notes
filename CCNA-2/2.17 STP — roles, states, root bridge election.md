## 2️⃣ Visualization — Big Picture at a Glance

**Roles on a triangle: one root, one root port per switch, one designated port per segment, block the rest:**

```
                     SW1  ═ ROOT BRIDGE (lowest BID) ═
                    (all its ports = DESIGNATED / FWD)
                   DP ┌──────────────┐ DP
             cost 4  │                │  cost 4
                     │                │
               RP ┌──┴──┐        ┌────┴──┐ RP
               SW2 │     │══seg══│      │ SW3
               (FWD)│ DP  │       │ blk  │
                    └─────┘       └──────┘
                     SW2's port on the SW2–SW3 segment = DESIGNATED (lower BID)
                     SW3's port on that segment        = NON-DESIGNATED → BLOCKING (breaks loop)

   Each non-root switch: exactly ONE Root Port (best path to root).
   Each segment: exactly ONE Designated Port (best cost onto that segment).
   Everything else: BLOCKED (alternate/backup).
```

**Port ROLE vs port STATE — don't confuse them:**

| | **ROLE** (what it does in the tree) | **STATE** (its condition right now) |
|---|---|---|
| Options | Root · Designated · Alternate · Backup | Disabled · Blocking · Listening · Learning · Forwarding |
| Example | "This is the **Root Port**" | "…and it's currently **Forwarding**" |

**The 802.1D port-state walk (why legacy STP is slow):**

```
 Blocking ──(a role change needs it to forward)──▶ Listening ──15s──▶ Learning ──15s──▶ Forwarding
   │  receives BPDUs             │ BPDUs only        │ builds MAC table   │ FULL: data + MAC + BPDU
   │  no data, no MAC-learn      │ no data/no learn  │ no data yet         │
   └─ up to 20s (max age) to leave blocking on a change ──┘   TOTAL ≈ 30–50s
```

## 3️⃣ TL;DR

- 🟢 STP builds the tree in **four steps**: **(1)** elect the **root bridge**, **(2)** each non-root switch picks its **root port**, **(3)** each segment picks a **designated port**, **(4)** **block** everything else.
- 🟢 **Root bridge** = lowest **Bridge ID** (priority, default 32768, + VLAN + MAC). Set it deliberately with **`spanning-tree vlan X root primary`** (priority **24576**) / **`secondary`** (**28672**) — don't rely on the MAC tiebreaker.
- 🟢 **Root Port (RP):** the **one** port on each non-root switch with the **lowest cost to root**. **Designated Port (DP):** **one per segment** (lowest cost onto it); **all root-bridge ports are DP**. Everything else is **non-designated → blocking** (RSTP names it **Alternate** = backup path to root, or **Backup** = backup to a segment).
- 🟢 **Port ROLE ≠ port STATE.** Role = job in the topology (Root/Designated/Alternate); State = current condition (Forwarding/Blocking/Listening/Learning/Disabled). A Root Port is normally **Forwarding**.
- 🟢 **802.1D states:** Blocking → **Listening (15 s)** → **Learning (15 s)** → Forwarding, plus Disabled. Max age **20 s**. Total ≈ **30–50 s** — the slowness RSTP fixes (→ 2.18).
- 🟢 **Root-port cost math:** the root advertises cost **0**; each switch **adds its ingress port cost** (short mode: 1 G = **4**, 10 G = **2**). Lowest total wins.
- 🟢 **Tie-breaker cascade** (when costs tie): lowest **root BID** → lowest **root path cost** → lowest **sender (neighbor) BID** → lowest **sender port ID** (port-priority 128/step 16, then port number).
- 🟢 **Verify** with `show spanning-tree` — read each port's **Role / Sts / Cost / Prio.Nbr**.

## 4️⃣ Importance — The Problem First 🎯

**The underlying problem:** 2.16 told you *that* STP blocks redundant ports to form a loop-free tree. But **which** ports, on **which** switches, get blocked — and **why** — is not arbitrary. If you don't control it, STP will happily pick a **terrible root** (an old, slow access switch with the lowest MAC), route all your traffic through a suboptimal path, and block a **high-bandwidth** uplink while forwarding over a slow one. The tree *works* (no loops) but the network is *slow and fragile*.

So the real questions an engineer must answer:

1. ❓ *"Who should be the root, and how do I make it so?"* → **root election** + `root primary/secondary`.
2. ❓ *"Which of my switch's ports carries traffic toward the root?"* → the **root port**, chosen by **cost** (with a precise tie-breaker cascade).
3. ❓ *"Which port forwards onto each segment, and which gets blocked?"* → the **designated port** vs the **blocked/alternate** port.
4. ❓ *"Why can't my device pass traffic for 30 seconds after link-up?"* → the **port-state machine** (listening + learning delays).

**Why an engineer must own this cold:**

- 🔧 **Root placement is a top design decision.** The root should be a central, high-capacity distribution/core switch — chosen on purpose. A mis-elected root is a classic real-world performance/stability bug, and "set the root" is a guaranteed exam+interview task.
- 🔧 **Reading `show spanning-tree` fluently is core troubleshooting.** "Why is *this* port blocking?" / "Why is traffic taking *that* path?" is answered by the role/state/cost columns — you must map output to the algorithm instantly.
- 🔧 **The role-vs-state distinction trips people constantly**, and the exam tests it directly. A blocked port has a *role* (alternate) and a *state* (blocking) — conflating them muddles your mental model.
- 🔧 **The state timers explain real symptoms** — the ~30 s dead time on a freshly-connected port is *why* PortFast exists (→ 2.19) and *why* RSTP was created (→ 2.18). Understanding the mechanism makes those fixes obvious.

## 5️⃣ Description 📋

- 🟢 **Step 1 — Root Bridge election.** Every switch starts claiming to be root; on hearing a **lower Bridge ID (BID)** it concedes and forwards the superior BPDU. The switch with the **lowest BID** becomes root. **BID = priority (default 32768) + extended system ID (VLAN) + MAC**; **lowest priority wins, tie → lowest MAC**.
  - **Set it deliberately:** `spanning-tree vlan X root primary` (macro → priority **24576**), `... root secondary` (→ **28672**), or manual `spanning-tree vlan X priority <mult. of 4096>`. **Primary/secondary** gives a preferred root and a designated backup root.
  - The **root's timers govern the whole tree** (other switches adopt the root's hello/forward-delay/max-age).
- 🟢 **Step 2 — Root Port (RP) per non-root switch.** Each non-root switch selects the **one** port with the **lowest root path cost** as its RP (its path toward the root). **Every non-root switch has exactly one RP.**
- 🟢 **Step 3 — Designated Port (DP) per segment.** On every segment/link, the port with the **lowest cost to root** is the **DP** — it forwards onto that segment. **Every segment has exactly one DP**, and **all root-bridge ports are DP** (the root's cost to itself is 0, so it always wins).
- 🟢 **Step 4 — Block the rest.** Any port that is **neither RP nor DP** is **non-designated → blocking**, breaking the loop while still **listening to BPDUs** to take over on failure.
- 🟢 **Port roles (names):**
  - **Root Port (RP)** — best path to root (non-root switches).
  - **Designated Port (DP)** — forwarding port on a segment.
  - **Non-designated / Blocking (802.1D)** — the blocked loop-breaker. In **RSTP** this splits into:
    - **Alternate Port (AP)** — a backup **path to the root** (takes over if the RP fails).
    - **Backup Port (BP)** — a backup **to a designated port on the same segment** (needs a shared/hub segment; rare).
- 🟢 **Port ROLE vs STATE (critical):** the **role** is the port's job in the topology; the **state** is its operational condition at a moment. A Root Port is normally in **Forwarding** but passes through states during convergence.
- 🟢 **Port states (802.1D — five):**
  - **Disabled** — admin-shut; not participating.
  - **Blocking** — receives BPDUs; **no** data, **no** MAC learning. (Waits up to **max age 20 s** to react to a change.)
  - **Listening** — sends/receives BPDUs; **no** data, **no** learning. **Forward delay 15 s.**
  - **Learning** — builds the **MAC table**; still **no** data forwarding. **Forward delay 15 s.**
  - **Forwarding** — full operation: forwards data, learns MACs, processes BPDUs.
  - Transition **Blocking → Listening → Learning → Forwarding** ≈ **30 s** (or up to ~50 s including max age) — the legacy slowness.
  - 🔵 **RSTP** collapses these into **three** states (**Discarding / Learning / Forwarding**) for fast convergence (→ 2.18).
- 🟢 **Cost math (root path cost):** the root advertises **0**; each switch **adds the cost of its ingress port** (the port on which it *received* the BPDU). **Short-mode costs (Cisco default):** 10 Mbps **100**, 100 Mbps **19**, 1 Gbps **4**, 10 Gbps **2**. Lowest total = best path. *(Long mode uses a different scale — CCNP.)*
- 🟢 **Tie-breaker cascade** (applied in order when a decision is close):
  1. **Lowest Root Bridge ID** (who's the root — already settled network-wide).
  2. **Lowest Root Path Cost.**
  3. **Lowest Sender (upstream neighbor) Bridge ID.**
  4. **Lowest Sender Port ID** = **port priority** (default **128**, range 0–240 in steps of **16**) then **port number**.
  - 🧠 Tie-breakers 3–4 use the **neighbor's** BID/port — a common point of confusion. On **parallel links to the same neighbor**, only the **port priority/number** can break the tie.
- 🟢 **Influencing selection:** `spanning-tree vlan X cost <n>` (change a port's cost), `spanning-tree vlan X port-priority <0–240 step 16>` (change port priority).

## 6️⃣ How It Works — Under the Hood ⚙️

### A) 🗳️ The 4-step algorithm, walked on a topology

```
 Topology: SW1, SW2, SW3 in a triangle; all links 1 Gbps (cost 4). Default priorities.

 STEP 1 — ROOT: lowest BID wins. Say SW1 has the lowest MAC → SW1 = ROOT.
          → ALL of SW1's ports become DESIGNATED (cost 0, always wins).

 STEP 2 — ROOT PORT (each non-root switch, lowest cost to root):
          SW2: direct SW2→SW1 = cost 4;  via SW3 = 4+4 = 8  → RP = the port toward SW1 (cost 4).
          SW3: direct SW3→SW1 = cost 4;  via SW2 = 8         → RP = the port toward SW1 (cost 4).

 STEP 3 — DESIGNATED PORT on the SW2–SW3 segment (neither end is root here):
          both SW2 and SW3 have root path cost 4 → TIE on cost →
          tie-break on lowest SENDER BID → say SW2's BID < SW3's → SW2's port = DP.

 STEP 4 — BLOCK: SW3's port on the SW2–SW3 segment is neither RP nor DP → BLOCKING (Alternate).
          Loop broken. One path from every switch to root. ✔
```

### B) 🔢 Root-port cost math (add your ingress cost)

```
 Root advertises cost 0. Each switch ADDS the cost of the port it RECEIVED the BPDU on.

   SW1(root) ──1G(cost4)── SW2 ──1G(cost4)── SW3
      0                     0+4=4             4+4=8   (SW3 via SW2)
   SW1 ─────────1G(cost4)──────────────────── SW3
                                              0+4=4   (SW3 direct)

   SW3 compares its two paths: direct = 4  vs  via SW2 = 8 → picks DIRECT as RP (cost 4).
   (If both were 4, it'd fall to the tie-breakers: lower sender BID, then sender port ID.)
```

### C) ⏱️ The state machine & why it's ~30–50s

```
 A port that must start forwarding (e.g., after a failure promotes a blocked port) walks:

   BLOCKING ─(≤20s max age to notice the change)─▶ LISTENING ─15s─▶ LEARNING ─15s─▶ FORWARDING
     recv BPDU            elect roles again          BPDU only       build MAC        FULL

 Why the delays? LISTENING lets the tree re-settle before anyone forwards (prevents transient
 loops); LEARNING pre-populates the MAC table so forwarding doesn't start with a flood.
 Cost: users see ~30s (often up to ~50s) of dead time. → PortFast skips it on EDGE ports (2.19);
 RSTP replaces the whole timed walk with a fast handshake (2.18).
```

### D) 👑 Setting the root deliberately (don't trust the MAC tiebreaker)

```
! Make the core switch the root for VLAN 10, and a second switch the backup root:
CORE(config)#  spanning-tree vlan 10 root primary      ! → priority 24576 (or lower to win)
DIST2(config)# spanning-tree vlan 10 root secondary    ! → priority 28672

! Equivalent manual control (priority must be a multiple of 4096):
CORE(config)#  spanning-tree vlan 10 priority 24576

! Nudge a specific path (cost) or a parallel-link choice (port-priority):
SW2(config-if)# spanning-tree vlan 10 cost 3            ! prefer this port (lower cost)
SW2(config-if)# spanning-tree vlan 10 port-priority 112 ! lower = preferred (default 128, step 16)
```

### E) 🔍 Reading `show spanning-tree`

```
SW2# show spanning-tree vlan 10

VLAN0010
  Root ID    Priority   24586                 ← the ROOT's BID (24576 + VLAN 10)
             Address    aabb.cc00.0100
             Cost       4                      ← THIS switch's cost to root
             Port       1 (GigabitEthernet0/1) ← THIS switch's ROOT PORT
  Bridge ID  Priority   32778 (32768 sys-id-ext 10)   ← THIS switch's own BID
             Address    aabb.cc00.0200

Interface   Role Sts Cost   Prio.Nbr Type
----------- ---- --- ------ -------- ----
Gi0/1       Root FWD 4      128.1    P2p    ← root port, forwarding
Gi0/2       Desg FWD 4      128.2    P2p    ← designated on its segment
Gi0/3       Altn BLK 4      128.3    P2p    ← alternate role, BLOCKING state (loop-breaker)
             │    │                          
           ROLE  STATE   ← read BOTH: role = job, state = condition
```

> 🕵️ **Dirty secret — the lowest-MAC switch quietly becomes root, and it's usually the worst choice.** With default priorities everywhere (all 32768+VLAN), the tiebreaker is **lowest MAC** — and MAC address correlates with **age**, so the **oldest** switch (often a crusty access-layer box with slow uplinks) wins the root election. Now *all* inter-switch traffic detours through your weakest switch, and high-speed uplinks may sit **blocked**. Everything "works," so nobody notices until performance complaints pile up. **Always set the root explicitly** (`root primary`/`secondary`) on your intended core/distribution switches — never let the MAC decide your topology.

## 7️⃣ Pros & Cons ⚖️

| ✅ Pros of the mechanics | ❌ Cons / Limits |
|---|---|
| 🟢 **Deterministic** — lowest BID/cost + fixed tie-breakers = predictable tree. | 🔵 **Slow state walk** (~30–50 s) in 802.1D (RSTP fixes → 2.18). |
| 🟢 **Tunable** — priority/cost/port-priority steer root & paths. | ⚠️ **Bad defaults** — MAC tiebreaker picks a poor root if you don't set it. |
| 🟢 **Clear roles** — one RP/switch, one DP/segment, rest blocked. | 🔵 **Blocked links idle** (EtherChannel avoids → 2.15). |
| 🟢 **Self-healing** — alternate ports pre-computed for failover. | ⚠️ **Role/state confusion** leads to misreading `show spanning-tree`. |
| 🟢 **Primary/secondary** gives planned root + backup. | 🔵 **Per-VLAN** placement adds config surface (PVST+ → 2.18). |

## 8️⃣ Variants — Common → Specific 🌿

**Port roles:**
- 🟢 **Root Port** — best path to root (one per non-root switch).
- 🟢 **Designated Port** — segment forwarder (one per segment; all root ports).
- 🟢 **Non-designated / Blocking** (802.1D) → **Alternate** (backup to root) / **Backup** (backup to a segment) in RSTP.

**Port states:**
- 🟢 **802.1D (five):** Disabled · Blocking · Listening · Learning · Forwarding.
- 🔵 **RSTP (three):** Discarding · Learning · Forwarding (→ 2.18).

**Root control:**
- 🟢 **`root primary`/`secondary`** macros (24576 / 28672).
- 🟢 **Manual priority** (multiples of 4096).
- 🔵 **Per-VLAN root** placement for uplink load-sharing (→ 2.18).

**Cost modes:**
- 🟢 **Short** (default): 100/19/4/2.
- 🔵 **Long**: finer scale for high speeds (CCNP).

## 🔟 Best Practices ✅

- 🟢 **Explicitly set the root** on your intended core/distribution switch (`spanning-tree vlan X root primary`) and a backup (`root secondary`) — never rely on the MAC tiebreaker.
- 🟢 **Verify the actual root** with `show spanning-tree root` / `show spanning-tree vlan X` after any topology change — confirm it's who you intended.
- 🟢 **Read role AND state** together in `show spanning-tree` (Role = Root/Desg/Altn; Sts = FWD/BLK/LIS/LRN).
- 🔵 **Tune cost/port-priority** to steer paths intentionally (e.g., prefer a high-bandwidth uplink) rather than accepting defaults.
- 🔵 **Place per-VLAN roots** to load-share uplinks (make different switches root for different VLANs) (→ 2.18).
- 🟢 **Expect the ~30 s state walk** on legacy STP edge ports — and fix it with **PortFast** on end-device ports (→ 2.19) and **RSTP** network-wide (→ 2.18).
- 🔵 **Keep priorities as multiples of 4096** (extended-system-ID requirement) — the macros handle this for you.

## 1️⃣1️⃣ No-Goes — Common Mistakes & Troubleshooting Traps 🚫

- ❌ **Letting the MAC tiebreaker pick the root.** The oldest/slowest switch wins by default and sabotages your paths. Set the root.
- ❌ **Confusing role with state.** "Alternate" is a **role**; "Blocking" is a **state**. A port has both. The exam and `show spanning-tree` both test this.
- ⚠️ **Assuming a non-root switch can have two root ports.** It has **exactly one** RP. Multiple candidate paths → tie-breakers pick one; the others block.
- ⚠️ **Setting a priority that isn't a multiple of 4096.** Rejected (extended-system-ID uses the low 12 bits for the VLAN). Use the macros or valid steps.
- ⚠️ **Forgetting the root's timers rule the tree.** Changing forward-delay/max-age on a non-root switch does little — the **root** dictates timers.
- ⚠️ **Miscounting cost** by adding the *egress* port cost. You **add the ingress** (receiving) port cost as the BPDU arrives.
- 🔵 **Expecting instant failover in 802.1D.** A promoted blocked port still walks listening+learning (~30 s). Use RSTP (→ 2.18) for fast transitions.
- ⚠️ **Ignoring port-priority on parallel links.** With equal cost and the same neighbor, **port-priority (then port number)** decides — tune it if you care which link forwards.

## 1️⃣3️⃣ Practical Tasks 🛠️

> Listed briefly; expanded step-by-step later in context.

1. 🟢 **Identify roles/states (Packet Tracer 8 / GNS3).** Build a three-switch triangle; run `show spanning-tree vlan 1` on each; label every port's **Role** (Root/Desg/Altn) and **Sts** (FWD/BLK). Confirm one RP per non-root switch and one DP per segment.
2. 🟢 **Force the root.** `spanning-tree vlan 1 root primary` on your intended core; verify the root changed with `show spanning-tree root`. Set another switch `root secondary`; fail the primary and confirm the secondary takes over.
3. 🟢 **Do the cost math by hand, then check.** Predict each switch's root-path cost and root port; verify against `show spanning-tree` Cost/Port fields.
4. 🟢 **Break a cost tie with port-priority.** Create parallel equal-cost links to the same neighbor; observe which becomes RP; change `spanning-tree port-priority` and watch the RP move.
5. 🟢 **Watch the state walk.** On legacy STP, shut the root port and time a blocked port's transition through **listening → learning → forwarding** (~30 s).
6. 🔵 **Read `show spanning-tree interface`.** For one port, interpret Role/Sts/Cost/Prio.Nbr/Type; correlate to the algorithm.
7. 🔵 **Per-VLAN root (preview).** Make SW-A root for VLAN 10 and SW-B root for VLAN 20; observe uplink load-sharing (full mechanics → 2.18).
