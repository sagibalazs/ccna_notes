```
  Multicast:  224.0.0.5 (AllSPFRouters)  ·  224.0.0.6 (AllDRouters)   [v6: FF02::5 / ::6]
```

**The five packet types (how routers talk):**

| # | Packet | Job |
|---|---|---|
| 1 | **Hello** | Discover & maintain neighbours; carry the parameters that must match; elect DR/BDR |
| 2 | **DBD** (Database Description) | Trade a *summary* of each other's LSDB to find what's missing |
| 3 | **LSR** (Link-State Request) | "Send me the full details of these LSAs I'm missing" |
| 4 | **LSU** (Link-State Update) | The actual **LSAs** — this is the flooding |
| 5 | **LSAck** (Link-State Ack) | "Got it" — reliable delivery confirmation |

**The two single-area LSA types:**

| LSA | Name | Who makes it | Describes |
|---|---|---|---|
| **Type 1** | **Router LSA** | *every* router | its own links/interfaces within the area |
| **Type 2** | **Network LSA** | the **DR** (on multi-access) | the routers attached to that shared segment |

## 3. ⚡ TL;DR

- **OSPF** is *the* CCNA dynamic routing protocol: an **IGP**, **link-state**, open-standard (RFC 2328 for **OSPFv2/IPv4**; OSPFv3 for IPv6). Runs on **IP protocol 89**, **AD 110**. 🟢
- It works in **four stages**: ① **discover** neighbours (Hello), ② **synchronise** the database (DBD/LSR/LSU/LSAck), ③ **compute** shortest paths (Dijkstra/**SPF**), ④ **install** them into the RIB as `O [110/cost]`. 🟢
- Every router builds an **identical LSDB** from flooded **LSAs** — **Type 1 (Router)** = "my links," **Type 2 (Network)** = "who's on this shared segment." From that shared map, each runs **SPF rooted at itself**. 🟢🔵
- **Metric = cost = reference-bandwidth (default 100 Mbps) ÷ interface-bandwidth**, floored, minimum 1; a path's cost is the **sum of outbound-interface costs**. 🟢
- **Reference-bandwidth trap:** at the default 100 Mbps, **every link ≥ 100 Mbps is cost 1** — OSPF can't tell GigE from 100 GigE. Fix with `auto-cost reference-bandwidth`, set **identically on all routers**. 🟢🔵
- **Areas** bound the LSDB/flooding; **single-area** = everything in one area, normally **area 0 (backbone)**. Multi-area is CCNP. 🟢
- Five Hellos to **224.0.0.5**; timers **10 s Hello / 40 s Dead** on broadcast & P2P. Mismatched Hello parameters = **no adjacency** (detail in 4.9). 🟢

---

## 4. ❓ Importance (problem → solution)

### The problem 🚧
4.7 gave you the *paradigm* — link-state = "everyone builds the same map, then computes paths locally." But a paradigm doesn't route packets. You need a **real protocol** that:
- **discovers** which routers are its neighbours (without you configuring each one by hand),
- **reliably distributes** the map so every router's copy is **provably identical** (a divergent map = loops),
- **computes** the best path efficiently and **re-computes** fast when a link fails,
- **scales** — a flat map of 500 routers would mean a giant database and a punishing SPF on every change.

And the exam requires you to **configure and verify** exactly this — single-area OSPFv2 — and read its output. If OSPF is just a bag of acronyms (LSA, LSDB, SPF, DR, DBD…), you'll fumble both the config and the troubleshooting. 🔧

### The solution 🎯
OSPF is the concrete answer to every one of those needs, and each mechanism maps to a need:
- **Hello packets** → neighbour discovery + liveness.
- **DBD/LSR/LSU/LSAck** → *reliable, acknowledged* database sync (so maps are identical).
- **LSAs + LSDB** → the shared map itself, assembled from small per-router descriptions.
- **Dijkstra/SPF** → efficient local shortest-path computation.
- **Areas** → hierarchy to bound database size and flooding as you grow.

Learn the **pipeline once**, see each piece as *the answer to a specific problem*, and OSPF becomes a coherent machine you can configure, verify, and troubleshoot on sight. 🧠

## 5. 📖 Description

- 🟢 **OSPF (Open Shortest Path First):** open-standard, link-state IGP. **OSPFv2** = IPv4 (RFC 2328); **OSPFv3** = IPv6 (RFC 5340). AD **110**, IP protocol **89**.
- 🟢 **OSPF process:** an instance identified by a locally-significant **process ID** (`router ospf 1`) — *not* matched between routers (unlike EIGRP's AS number). (Config in 4.10.)
- 🟢 **Neighbour vs adjacency:** routers that *see* each other's Hellos are **neighbours**; those that *fully synchronise databases* are **adjacent**. (State machine in 4.9.)
- 🟢 **LSA (Link-State Advertisement):** a piece of the map. **Type 1 Router LSA** (every router's own links); **Type 2 Network LSA** (a DR's description of a multi-access segment). Higher types (3/4/5/7) are inter-area/external — CCNP. 🔵
- 🟢 **LSDB (Link-State Database):** the assembled map; **identical** across all routers in an area.
- 🟢 **SPF / Dijkstra:** the algorithm each router runs on the LSDB, rooted at itself, to build the **SPF tree** of shortest paths.
- 🟢 **Cost:** OSPF's metric — reference-BW ÷ interface-BW, summed along outbound interfaces. Lower = preferred.
- 🟢 **Area:** a flooding/LSDB boundary. **Area 0** is the backbone; **single-area** keeps it simple.
- 🟢 **Packet types:** Hello, DBD, LSR, LSU, LSAck (Types 1–5).

## 6. ⚙️ How It Works (under the hood)

### 6.1 ① Discover — Hello packets 🟢

OSPF sends **Hello** packets to multicast **224.0.0.5** (AllSPFRouters) out each OSPF-enabled interface, by default every **10 seconds** (broadcast & point-to-point). A Hello carries the **parameters that must match** for two routers to become neighbours:

```
Hello must agree on:  Area ID · Hello interval · Dead interval · authentication
                      · subnet mask (broadcast nets) · stub-area flag
   ── any mismatch → NO adjacency (the #1 "neighbours won't come up" cause) ──
```

If a neighbour's Hellos stop for the **Dead interval** (default **40 s** = 4× Hello), it's declared down and SPF re-runs. This is OSPF's **liveness detection**. (The full neighbour state machine — Down/Init/2-Way/… — and DR/BDR election live in **4.9**.) 🟢

### 6.2 ② Synchronise — build an identical LSDB 🟢🔵

Neighbour discovery is not enough; the maps must be **identical**, or SPF produces inconsistent (loop-prone) results. So adjacent routers run a reliable exchange:

```
 R1                                                         R2
  │── DBD  (Type 2) ──▶  "here's a SUMMARY of my LSDB"      │
  │◀── DBD  (Type 2) ──  "here's a summary of mine"         │
  │── LSR  (Type 3) ──▶  "send full detail of THESE LSAs    │
  │                       I'm missing / that are newer"      │
  │◀── LSU  (Type 4) ──  the actual LSAs (the flooding)     │
  │── LSAck (Type 5) ──▶  "received, thanks"  (reliability)  │
  ─────────────────────────────────────────────────────────
  Result: both LSDBs now IDENTICAL → they reach state FULL.
```

- **DBD** trades *headers* (a cheap summary) so each side learns what it lacks.
- **LSR/LSU** fetch the *full* missing LSAs; **LSAck** makes delivery reliable (OSPF doesn't ride TCP — it builds its own acknowledged flooding on IP protocol 89).
- Any new/changed LSA is later **re-flooded** to all — and only on **change**, not periodically. This is the link-state efficiency from 4.7: flood once, then stay quiet. 🔵

> 🕵️ **Dirty secret #1 — the MTU mismatch that hangs in ExStart/Exchange.** If two neighbours have **different interface MTUs**, the DBD exchange stalls and the adjacency gets **stuck in EXSTART/EXCHANGE** — never reaching FULL — even though Hellos worked and they're "neighbours." It's a maddening, silent failure that passes every ping-the-neighbour test. **Symptom → check MTU on both ends** (or `ip ospf mtu-ignore` as a workaround). This is *the* classic OSPF gotcha. 🔵

### 6.3 🧩 The LSDB — assembled from LSAs 🟢🔵

The map isn't one big object; it's built from small per-router pieces:

- **Type 1 — Router LSA:** **every** OSPF router generates one, describing **its own** links (which networks it connects to, at what cost), flooded **within its area**. Stack up everyone's Router LSAs and you have the topology.
- **Type 2 — Network LSA:** on a **multi-access** segment (Ethernet), the elected **DR** generates one describing **which routers are attached** to that shared segment — so the map represents the segment as a single "pseudonode" instead of a mess of point-to-point links. (DR/BDR mechanics → 4.9.)

```
   Area 0 LSDB (identical on all routers) =
     R1's Router-LSA  ∪  R2's Router-LSA  ∪  R3's Router-LSA  ∪ …
     +  DR's Network-LSA for each shared segment
   → a complete, consistent graph of routers + links + costs
```

Higher LSA types (Type 3 inter-area summary, Type 4 ASBR-summary, Type 5 external, Type 7 NSSA) only appear with **multiple areas / external redistribution** — **out of single-area CCNA scope**, noted so you recognise them later. 🔵

### 6.4 ③ Compute — Dijkstra / SPF 🟢

With an identical LSDB, each router independently runs **Dijkstra's Shortest Path First** algorithm, **rooted at itself**, producing an **SPF tree**: the lowest-cost path from *this* router to every network. Because everyone runs the *same* algorithm on the *same* map, the results are mutually consistent (no rumour, no count-to-infinity — the 4.7 promise).

The chosen paths install into the RIB as OSPF routes:
```
O   10.2.2.0/24 [110/3] via 10.0.12.2, 00:05:11, Gi0/0
    │           │   │
    │           │   └─ metric = total OSPF COST of the path
    │           └───── AD 110
    └─────────────── code O = OSPF (intra-area)
```

### 6.5 💰 The metric — OSPF cost (the big teachable) 🟢🔵

OSPF's metric is **cost**, and it's the one number you must be able to compute by hand:

```
                 reference bandwidth (default 100 Mbps = 100,000 kbps)
   COST  =  ─────────────────────────────────────────────────────────   (floored, min 1)
                        interface bandwidth
```

**Worked default-reference values** (Cisco floors/truncates, minimum 1):

| Interface | Bandwidth | Cost = 100,000 ÷ BW(kbps) |
|---|---|---|
| Ethernet | 10 Mbps | 100000 ÷ 10000 = **10** |
| FastEthernet | 100 Mbps | 100000 ÷ 100000 = **1** |
| GigabitEthernet | 1 Gbps | 100000 ÷ 1000000 = 0.1 → **1** (floored to min) |
| 10 GigE | 10 Gbps | → **1** |
| Serial T1 | 1.544 Mbps | 100000 ÷ 1544 = 64.7 → **64** |
| Serial 128 kbps | 128 kbps | 100000 ÷ 128 = 781.25 → **781** |

A **path's** cost is the **sum of the outbound-interface costs** along it (incoming interfaces don't count). Lowest total cost wins; **equal totals → ECMP** (from 4.2/4.3).

> 🕵️ **Dirty secret #2 — the default reference bandwidth is stuck in 1998.** The 100 Mbps default means **FastEthernet, GigE, 10GigE, and 100GigE all compute to cost 1** — OSPF **cannot tell a 100 Mbps copper drop from a 100 Gbps backbone.** It'll then pick paths by hop count instead of bandwidth, routing your traffic over the slow link. **Fix:** `router ospf 1 → auto-cost reference-bandwidth 10000` (or higher than your fastest link, in Mbps) — and it **must be identical on every router in the domain**, or costs are inconsistent and paths go weird. This is one of the most common real-world OSPF misconfigurations. 🔵
>
> You can also override per interface with `ip ospf cost <n>` for traffic engineering. 🔵

### 6.6 🗂️ Areas — why they exist 🟢🔵

A single flat LSDB across hundreds of routers would be **huge**, and *any* link flap anywhere would force *every* router to re-run SPF over the whole map. **Areas** solve this by **bounding flooding**: LSAs (Type 1/2) flood only **within** an area; changes inside area 51 don't force area 0 routers to re-run full SPF. **Area 0** is the **backbone** — every other area must connect to it.

```
                     ┌──────── Area 0 (backbone) ────────┐
                     │            R2 ── R3                │
                     └──────┬───────────────────┬────────┘
                    ┌───────┴──────┐     ┌───────┴──────┐
                    │   Area 1     │     │   Area 2     │   ← ABRs join areas to area 0
                    │  R1 (LSDB    │     │  R4 (own     │
                    │   local)     │     │   LSDB)      │
                    └──────────────┘     └──────────────┘
```

**CCNA scope = single area** — put every router/interface in **one area (normally area 0)** and skip the inter-area machinery (ABRs, Type 3/4/5 LSAs, stub areas). Just know areas *exist to scale the link-state model* — that's the 🔵 bridge to CCNP. 🟢

### 6.7 🔄 Convergence recap 🟢

On a link change: the affected router floods an updated Type 1 LSA (LSU) → neighbours ack (LSAck) and re-flood → every router updates its LSDB and re-runs SPF → new best paths install. Sub-second to a few seconds — the fast, loop-resistant convergence link-state promised in 4.7. 🟢

## 7. ⚖️ Pros & Cons

| | 👍 Pros | 👎 Cons |
|---|---|---|
| **OSPF (vs other IGPs)** | Open standard (multi-vendor); fast convergence; loop-resistant; cost metric reflects bandwidth; scales via areas; VLSM/CIDR native; huge deployment base | More CPU/RAM (holds full LSDB); more complex than RIP/static; default reference-bandwidth misleads on modern links; areas add design burden |
| **vs RIP** | Faster convergence, no 15-hop limit, bandwidth-aware, scalable | Heavier, steeper learning curve |
| **vs EIGRP** | Open standard (EIGRP is Cisco-origin); well-understood | EIGRP often converges faster (feasible successors); EIGRP config simpler |

## 10. ✅ Best Practices

- 🟢 **Raise the reference bandwidth** (`auto-cost reference-bandwidth`) to exceed your fastest link, and set it **identically on every router** — otherwise GigE+ links are indistinguishable and paths go suboptimal.
- 🟢 **Keep single-area designs in area 0** and consistent; when you outgrow it, add areas hanging off the backbone (CCNP).
- 🔵 **Match MTU on OSPF links** to avoid the ExStart/Exchange hang (dirty secret #1).
- 🟢 **Ensure Hello/Dead/area/auth match** on both ends of every link before expecting an adjacency (detail 4.9).
- 🟢 **Use interface `bandwidth` values that reflect reality** (especially on serial/sub-rate links) so cost is meaningful; use `ip ospf cost` for deliberate traffic engineering.
- 🔵 **Read the LSDB** (`show ip ospf database`) to *see* the shared map — it's the fastest way to confirm all routers agree.

## 11. 🚫 No-Goes (mistakes & troubleshooting traps)

- ❌ **Leaving the default reference bandwidth** in a GigE+ network → all fast links cost 1; OSPF routes by hops, not bandwidth. 🔵
- ❌ **Inconsistent reference bandwidth** across routers → asymmetric costs, suboptimal/oscillating paths. 🟢
- 🔧 **Adjacency stuck in EXSTART/EXCHANGE** → **MTU mismatch** (dirty secret #1). Fix MTU or `mtu-ignore`.
- 🔧 **Neighbours never form (stuck Down/Init)** → mismatched **Hello/Dead timers, Area ID, subnet mask, or authentication** (deep dive 4.9).
- ❌ **Confusing process ID with an AS number.** The OSPF **process ID is locally significant** — `router ospf 1` on R1 and `router ospf 5` on R2 can still be neighbours. (EIGRP's AS number *must* match; OSPF's process ID need not.) 🟢
- ❌ **Expecting OSPFv2 to route IPv6.** Use **OSPFv3** for IPv6 — separate instance/address family. 🟢
- ❌ **Thinking incoming-interface cost counts.** Only **outbound** interface costs sum into a path's total. 🔵
- 🔧 **Trap: routes present but "wrong" path chosen** → almost always a **cost/reference-bandwidth** issue, not a bug. Verify with `show ip ospf interface` (per-interface cost).

## 13. 🧪 Practical Tasks

> Goal: *watch* the four-stage pipeline happen and compute cost by hand.

1. **🟢 Minimal single-area OSPF (Packet Tracer 8).** Three routers, all interfaces in **area 0**. Bring OSPF up (full config is 4.10) and confirm `O` routes appear as `[110/cost]`. Then trace each stage below.

2. **🔬 See the packets (Wireshark).** Capture on an OSPF link and identify all five types in sequence: periodic **Hello** to 224.0.0.5, then **DBD → LSR → LSU → LSAck** during initial sync. Watch Hellos continue every **10 s** afterward. This *is* section 6.1–6.2 on screen. 📸

3. **🟢 Inspect the shared map.** `show ip ospf database` on two different routers → confirm the **LSDBs are identical** (Type 1 Router LSAs from each router; Type 2 Network LSA on the Ethernet segment). Prove the "everyone has the same map" claim.

4. **🟢 Compute cost by hand, then verify.** Predict the cost of a FastEthernet (1), an Ethernet (10), and a serial T1 (64) interface. Check with `show ip ospf interface <int> | include Cost`. Then `show ip route ospf` and confirm a path's total = **sum of outbound costs**.

5. **🔵 The reference-bandwidth fix.** On a GigE topology, note every fast link shows **cost 1**. Apply `auto-cost reference-bandwidth 10000` on **all** routers → watch GigE become cost 10, distinguishable from faster links. Apply it on **only one** router → observe the inconsistency/suboptimal routing (then fix it everywhere).

6. **🔧 MTU-mismatch repro (dirty secret #1).** Set different MTUs on two ends of an OSPF link → watch the adjacency **hang in EXSTART/EXCHANGE** (`show ip ospf neighbor`). Fix MTU (or `ip ospf mtu-ignore`) → it reaches **FULL**. Unforgettable once you've seen it.
