## 2. 🗺️ Visualization — The Whole Picture at a Glance

**One big network → sliced into several smaller ones by borrowing host bits.**

```
 BEFORE (one flat Class C, /24):                AFTER (borrow 2 host bits → /26):
 ┌───────────────────────────────┐             ┌───────┬───────┬───────┬───────┐
 │  192.168.1.0/24               │             │ .0/26 │ .64/26│.128/26│.192/26│
 │  ONE network                  │    ✂️  →    │  sub1 │ sub2  │ sub3  │ sub4  │
 │  254 hosts                    │             │ 62 ea │ 62 ea │ 62 ea │ 62 ea │
 │  ONE broadcast domain 📣      │             │ 4 separate broadcast domains  │
 └───────────────────────────────┘             └───────┴───────┴───────┴───────┘
```

**The subnet mask is the "cut line" — `1`s mark network, `0`s mark host:**

```
  Address :  192 . 168 .   1 .  10        11000000 10101000 00000001 00001010
  Mask /26:  255 . 255 . 255 . 192        11111111 11111111 11111111 11000000
                                          └──────── network ───────┘└┘└─host─┘
                                                            borrowed ↑↑ (2 bits)
```

**How a device decides "same subnet or not?" → bitwise AND:**

```
   My addr  AND my mask  = MY network
   Dest addr AND my mask = DEST's network
        same?  ── yes → deliver directly on the LAN  (ARP + switch, Block 2)
               └─ no  → send to the DEFAULT GATEWAY (a router)  🚪
```

> 🧭 **The one idea to hold onto:** subnetting doesn't add bits — it **moves the network/host boundary rightward**, trading host bits for more networks.

## 3. ⚡ TL;DR

- 🟢 **Subnetting = borrowing bits from the host portion** of an address to create multiple smaller networks out of one. The mask marks the new boundary (`1`=network, `0`=host).
- 🟢 It exists to fix three pains of flat/classful addressing: **wasted addresses**, **oversized broadcast domains**, and **exploding routing tables**.
- 🟢 The **subnet mask** (or `/prefix` in CIDR) is what tells every device *where* the boundary sits. Without it an address is meaningless (see 3.1 §6.4).
- 🟢 Devices use a **bitwise AND** of address ∧ mask to answer *"is this destination local, or do I send it to my gateway?"* — this single test drives all IPv4 forwarding at the host.
- 🟢 Standardised in **RFC 950 (Aug 1985)**, proposed in **RFC 917 (Oct 1984)** — born when organisations needed *many* LANs under *one* assigned network number.
- 🔵 🕵️ The **all-zeros ("subnet zero")** and all-ones subnets were originally *forbidden* — a rule whose ghost (`ip subnet-zero`) wasted the first/last subnet on Cisco gear for years.

---

## 4. 🎯 Importance — The Problem First

**The problem:** In 3.1 you saw that classful addressing gives you exactly three sizes — /8 (16M hosts), /16 (65K hosts), /24 (254 hosts). Now imagine you're Stanford in 1984 with **eighteen separate LAN cables** but only **one** assigned network number. You face three walls at once:

### 🧨 Pain 1 — One network = one giant broadcast domain
Every host on a single IP network shares a **broadcast domain** (Block 2). Broadcasts (ARP, DHCP discovery, etc.) hit *every* device. Put 60,000 hosts on one /16 and a single broadcast storm can flatten the whole thing. Flat networks don't just waste addresses — they **don't contain failure**. 📣💥

### 🗑️ Pain 2 — Grotesque address waste
Need 300 hosts? A /24 (254) is too small, so classful forces you up to a /16 — and you **strand ~65,000 addresses**. Multiply that across every organisation on Earth and you get the **IPv4 exhaustion crisis** of the 1990s.

### 📈 Pain 3 — Routing-table explosion
If every organisation grabbed a fresh network number for each LAN, the **global routing tables** would balloon with entries that mean nothing outside that company. Early gateways literally didn't have the memory. *(This is the pain RFC 917 opens with.)*

**The solution — subnetting.** Take *one* assigned network number and **internally slice it** into as many right-sized pieces as you need, by borrowing bits from the host field. The outside world still sees **one** network (small routing footprint 🎯); inside, each subnet is its **own broadcast domain** (contained failure 🛡️) sized to fit (no waste ♻️). One tool, all three pains addressed.

> **Why this is the hinge of the whole block:** subnetting is where an IP address stops being a fixed thing you *read* and becomes a resource you *design*. Every later topic — VLSM (3.3), CIDR (3.4), private addressing (3.5), even IPv6 prefixes (3.7) — is a variation on "move the boundary to fit the need."

## 5. 📖 Description

- 🟢 **Subnet.** A logically visible sub-section of a single IP network — its own broadcast domain, reachable via a router.
- 🟢 **Borrowing bits.** Subnetting steals bits from the **left of the host field** and reassigns them as **subnet bits**. Host bits ↓, network (subnet) bits ↑. Total stays 32.
- 🟢 **Three-level hierarchy.** Classful was 2-level `<network><host>`. Subnetting makes it 3-level: `<network><subnet><host>` (RFC 950).
- 🟢 **Subnet mask.** A 32-bit companion value: contiguous `1`s (network/subnet) then contiguous `0`s (host). It is the *only* thing that reveals the boundary — never guess it.
- 🟢 **CIDR `/prefix` notation.** Shorthand for the count of `1`s in the mask: `/24` = `255.255.255.0`. Introduced here; formalised in **3.4**.
- 🟢 **Default gateway.** The router address a host sends to whenever the destination is **not** on its own subnet. The AND test (below) decides.
- 🟢 **More subnet bits ↔ fewer host bits** — a permanent trade-off. Every subnet you gain costs you host capacity per subnet. (Quantified in 3.3.)
- ⚪ **Trade in one sentence:** *borrow bits → more subnets, smaller each.*

## 6. 🔧 How It Works — Under the Hood

### 6.1 🟢 Borrowing bits — moving the cut line

Start with Class C `192.168.1.0`, default `/24`. Borrow **2** host bits for subnetting:

```
   /24 default:  11111111 11111111 11111111 00000000   → 1 net, 254 hosts
   /26 borrowed: 11111111 11111111 11111111 11000000   → 4 subnets, 62 hosts each
                                            └┘ 2 borrowed bits = 2² = 4 subnets
```

Two borrowed bits give `2² = 4` subnet combinations (`00 01 10 11`), and the remaining 6 host bits give `2⁶ − 2 = 62` usable hosts each. *(The −2 and the full table are 3.3's job — here, just see that the boundary moved.)*

### 6.2 🟢 The subnet mask = the boundary marker

The mask is **not** an address — it's a stencil. Line it up under the address; wherever the mask shows `1`, that bit belongs to the **network/subnet**; wherever `0`, it belongs to the **host**.

```
   Addr :  192.168.1.10   = 11000000 10101000 00000001 00001010
   Mask :  /26            = 11111111 11111111 11111111 11000000
                            └──────── network+subnet ────────┘└─host─┘
```

### 6.3 🟢 The bitwise AND — the single most important operation in IPv4

Every host, on every packet, must answer: *"Is the destination on my LAN, or do I hand it to my gateway?"* It answers with a **bitwise AND** (bit ∧ bit: `1∧1=1`, everything else `0`):

```
   Step 1 — my network:
      192.168.1.10   00000001 00001010
    ∧ /26 mask       11111111 11000000     (last two octets shown)
    ─────────────────────────────────
    = 192.168.1.0    00000001 00000000     ← MY subnet = .0

   Step 2 — destination's network (using MY mask):
      dest 192.168.1.70    ∧ /26  = 192.168.1.64     ← different! (.64 ≠ .0)

   Decision: destinations don't match → NOT local → send to DEFAULT GATEWAY 🚪
```

If Step 1 and Step 2 produce the **same** network number → the host is local: resolve its MAC with ARP and let the **switch** deliver it (Block 2). If **different** → it's remote: frame it to the **gateway's** MAC and let the **router** forward it (Block 4). *This one comparison is the entire host-side forwarding logic.*

### 6.4 🟢 What each subnet costs you — two "unusable" addresses

Inside every subnet, two host patterns are reserved (same rule as 3.1, now per-subnet):

```
   host bits all 0  → the SUBNET (network) address   → names the subnet, not a host
   host bits all 1  → the BROADCAST address          → "everyone on this subnet"
```

That's why **usable hosts = 2^(host bits) − 2** — fully derived and drilled in **3.3**.

### 6.5 🔵 Why the mask must travel separately

Recall 3.1 §6.4: the packet carries **no mask**. So a subnetted network only works if the mask reaches every device by other means:

- **Statically** typed on each interface, or handed out by **DHCP** (Block 6), and
- **Carried in routing updates** by *classless* protocols (OSPF, EIGRP, RIPv2, BGP) — which is precisely what *classful* protocols (RIPv1) fail to do, causing the auto-summary breakage from 3.1 §6.5.

### 6.6 🕵️ Dirty Secret — "Subnet zero" and the subnet you weren't allowed to use

When RFC 950 defined subnetting in 1985, it **prohibited the all-zeros subnet** (the first one, whose subnet bits are all `0`) and the **all-ones subnet** (the last one). The fear: a classful router couldn't tell the *all-zeros subnet* `192.168.1.0/26` apart from the *whole network* `192.168.1.0/24` — both look like ".0".

The real-world consequence lasted **decades**:
- Old Cisco IOS **disabled subnet zero by default**. You had to enter `ip subnet-zero` to reclaim the first (and effectively the last) subnet — otherwise you **lost 2 of every 4 subnets** on a /26, a brutal tax.
- Legacy certification questions used the formula **`2ˢ − 2` for number of subnets** (subtracting the two forbidden ones). Modern IOS enables subnet zero by default, so **CCNA today uses `2ˢ`** (no subtraction) for subnets — but you *subtract 2 for hosts* every time.

> **Engineer takeaway:** if you ever meet ancient gear (or an exam item citing `2ˢ − 2` for subnets), it's the subnet-zero ghost. On anything modern: **all subnets are usable** (`2ˢ`), but **hosts are still `2ʰ − 2`**. Don't cross the two rules — that swap is the classic subnetting-exam trap (3.3 §No-Goes).

## 7. ⚖️ Pros & Cons

| ✅ Pros of subnetting | ❌ Cons / costs |
| -------------------- | -------------- |
| **Contains broadcast domains** → smaller failure blast-radius 🛡️ | Adds design + documentation overhead (you must *plan* it) |
| **Right-sizes allocations** → far less address waste ♻️ | Each subnet loses 2 addresses (network + broadcast) |
| **Keeps global routing small** — outside sees one network 🎯 | Every borrowed subnet bit halves hosts-per-subnet |
| **Improves security & policy** — segment = enforcement point 🔒 | Mis-sized masks are painful to re-plan later |
| **Enables VLSM** — different-sized subnets from one block (3.3) | Requires classless routing to advertise correctly |

---

## 8. 🌿 Variants — Common → Specific

- 🟢 **FLSM — Fixed-Length Subnet Masking.** Every subnet uses the *same* mask (all /26, say). Simple, but wastes space when subnets differ wildly in size. The default mental model.
- 🟢 **VLSM — Variable-Length Subnet Masking.** *Different* masks for different subnets from the **same** parent block — e.g. /30 for point-to-point router links (2 hosts) and /24 for a user LAN. The efficient, real-world method. **Full treatment + math in 3.3.**
- 🔵 **Route summarisation (supernetting).** The *inverse* of subnetting — merging many small networks into one advertised prefix to shrink routing tables. Covered in **3.4**.
- ⚪ **Subnetting vs VLANs.** A VLAN (Block 2) is an **L2** broadcast domain; a subnet is its **L3** address range. In practice they're paired **1 VLAN ↔ 1 subnet**, joined by inter-VLAN routing — but they are *different layers* solving *different halves* of the same "segmentation" goal.

## 10. ✅ Best Practices

- 🟢 **Size for growth, then pick the mask.** Count required hosts *and* subnets first; choose the boundary second. (Method in 3.3.)
- 🟢 **One VLAN ↔ one subnet.** Keep L2 and L3 segmentation aligned — it makes troubleshooting and ACLs sane.
- 🟢 **Always configure the trio together:** address **+** mask **+** default gateway. A missing mask or gateway is the most common "it can ping local but not the internet" fault.
- 🔵 **Use VLSM from day one** — /30 (or /31, RFC 3021) for point-to-point links, right-sized LANs elsewhere. FLSM everywhere is a waste you'll regret.
- 🔵 **Reserve a documented block for growth** and keep an IPAM/spreadsheet — subnet plans that live only in someone's head rot fast.
- 🔵 **Design contiguous subnets** so they can later be summarised (3.4) into clean supernets — discontiguous plans block summarisation.

## 11. 🚫 No-Goes — Common Mistakes & Troubleshooting Traps

- ❌ **Confusing the two "minus-two" rules.** Modern subnets: **`2ˢ` subnets** (no −2) but **`2ʰ − 2` hosts** (always −2). Swapping them is *the* classic error (§6.6).
- ❌ **Quoting an address with no mask.** `10.1.1.5` alone is undecidable — the same digits are a host in a /24 and a network in a /16.
- ❌ **Assuming class still sets the boundary.** Once subnetted, the *mask* rules — not the leading bits (3.1). A /26 on a Class C is normal.
- ❌ **Putting host and gateway in different subnets.** If the AND test says the gateway isn't local, the host can never reach it → no off-net traffic at all.
- 🕵️ **Trap — silent subnet-zero loss on legacy gear.** Missing `ip subnet-zero` quietly removes your first/last subnet; addresses "vanish" with no error (§6.6).
- 🕵️ **Trap — mask mismatch between neighbours.** Two ends of a link with *different* masks (e.g. /24 vs /25) each compute a *different* "local" range; one side thinks a host is local while the other routes it → intermittent, one-directional failures. Always verify masks match on both ends.
- ❌ **Overlapping subnets.** Two subnets whose ranges intersect (bad planning) cause ambiguous routing and duplicate-address chaos. VLSM planning (3.3) prevents this.

## 13. 🧪 Practical Tasks *(listed now, expanded/drilled in 3.3)*

1. 🖐️ **AND-test by hand.** For `192.168.1.10 /26` and destinations `192.168.1.50`, `192.168.1.70`, `192.168.2.10`: AND each with the mask and state *local* or *via gateway*. Prove your answer in binary.
2. 🎨 **Draw the cut line.** Take `172.16.0.0/16` and sketch what borrowing 3 bits does — how many subnets, where the boundary lands (concept only; exact hosts in 3.3).
3. 🧰 **Packet Tracer 8 — see the gateway decision.**
   - Two PCs, same switch, `192.168.1.10/26` and `192.168.1.70/26` (different /26 subnets), **no router**. Ping → **fails** (different subnets, no gateway).
   - Add a router-on-a-stick / L3 switch as each subnet's gateway → ping **succeeds**. Observe *why* the AND test forced traffic to the router.
4. 🔬 **Wireshark — watch the boundary in action.** Capture the failed ping above: see the host **ARP for the gateway** (remote dest) vs **ARP for the host directly** (local dest). The AND test is visible in *who gets ARPed*.
5. 🖥️ **Read a real mask.** On your machine (`ipconfig` / `ip addr`), note your mask, convert to `/prefix`, and AND your own IP with it to find your subnet address by hand.
6. 🧨 **(🔵 stretch)** In Packet Tracer, set mismatched masks on a point-to-point link (/24 one end, /25 the other) and observe the one-directional reachability failure from §11.
