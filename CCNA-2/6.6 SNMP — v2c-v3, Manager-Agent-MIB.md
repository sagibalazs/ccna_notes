## 2️⃣ Visualization — The Whole Picture at a Glance

**The model — one manager, many agents, a shared dictionary (MIB):**

```
        ┌──────────────────────────┐                       ┌──────────── managed device ───────────┐
        │      MANAGER / NMS        │   GET/GETNEXT/GETBULK │   AGENT (software on the device)       │
        │  (SolarWinds, LibreNMS,   │  ───── UDP/161 ─────▶ │   ┌──────────────────────────────┐    │
        │   PRTG, Zabbix, Grafana)  │  ◀──── RESPONSE ───── │   │   MIB  (the object database) │    │
        │                           │        SET (write)    │   │   OIDs = named metrics/knobs │    │
        │      :162 listener        │  ◀── TRAP / INFORM ── │   └──────────────────────────────┘    │
        └──────────────────────────┘     UDP/162 (async)    └────────────────────────────────────────┘
              polls on a schedule            pushes on events
```

**Two traffic directions — polling vs pushing:**

```
   POLLING (manager-driven, UDP/161)              PUSHING (agent-driven, UDP/162)
   ────────────────────────────────              ──────────────────────────────
   "What's the CPU? interface counters?"          "linkDown just happened!"
   scheduled every N seconds/minutes              instant, the moment the event occurs
   BLIND SPOT: a 90-sec flap between two            closes the polling blind spot
   5-min polls is invisible                         (trap = fire&forget, inform = acknowledged)
```

**The MIB is a tree; an OID is a path down it:**

```
                       1  iso
                       └─3  org
                         └─6  dod
                           └─1  internet
                     ┌───────┴────────┐
                  2  mgmt           4  private
                  └─1  mib-2        └─1  enterprises
              ┌──────┴──────┐          └─9  cisco  (1.3.6.1.4.1.9)
           1 system      2 interfaces
           └─ sysName = 1.3.6.1.2.1.1.5 . 0     ← ".0" = the scalar instance
              sysUpTime = 1.3.6.1.2.1.1.3.0
              ifTable   = 1.3.6.1.2.1.2 …        ← per-interface counters
```

**The three versions — pick by security:**

| Version | Security | Adds | Verdict |
|---|---|---|---|
| 🟠 **v1** | community string (cleartext) | the original GET/SET/TRAP | legacy only |
| 🟡 **v2c** | community string (**still cleartext**) | **GETBULK, INFORM, Counter64** | OK *only* on an isolated mgmt VLAN + ACL |
| 🟢 **v3** | **users + auth + encryption** | USM, VACM, engine ID | **the deployable answer** (use `authPriv`) |

**v3 security levels:**

| Level | Auth? | Encrypt? | Meaning |
|---|---|---|---|
| `noAuthNoPriv` | ✗ | ✗ | username only — barely better than v2c |
| `authNoPriv` | ✅ (MD5/SHA) | ✗ | integrity, but readable on the wire |
| 🟢 `authPriv` | ✅ (MD5/SHA) | ✅ (DES/AES) | **authenticated *and* encrypted — use this** |

## 3️⃣ TL;DR

**SNMP (Simple Network Management Protocol) is how a management station monitors and manages network devices** — a **manager (NMS)** polls **agents** on devices for objects defined in a **MIB** (a tree of **OIDs**), on **UDP/161**, and agents push unsolicited **traps/informs** back on **UDP/162** when events occur. **v1/v2c** authenticate with a cleartext **community string** (a shared password) — insecure; **v2c** at least adds **GETBULK**, **INFORM** (acknowledged trap), and **64-bit counters**. **v3** replaces community strings with real **users, authentication (SHA/MD5) and encryption (AES/DES)** — three security levels, of which **`authPriv`** is the only one to deploy anywhere exposed. Polling gives you steady metrics; **traps close the blind spot** between polls. On Cisco it's one line for v2c (`snmp-server community … RO`) or a `group`+`user` pair for v3, always locked down with an **ACL** to the NMS.

## 4️⃣ Importance — The Problem First 🎯

**The problem — you can't manage what you can't see, and you can't watch everything by hand.** A network has hundreds or thousands of devices. You need to know, continuously: *Is that interface up? What's the CPU? Is the link saturated? Did a device just reboot?* And when something breaks at 3 a.m., **someone or something must be told immediately**.

- 👁️ **Manual checking is impossible at scale.** Logging into 500 devices to run `show interface` is a non-starter. You need a *central* station that gathers state automatically.
- 📈 **You need history and trends, not just snapshots.** Capacity planning, "is this link growing?", "when did errors start?" all require **regularly sampled** metrics stored over time.
- 🚨 **Some events can't wait for the next poll.** A link that flaps for 90 seconds between two 5-minute polls is **invisible** to polling alone. Critical failures must **push** an alert the instant they happen.
- 🗣️ **Every vendor's device must speak a *common* language.** A Cisco router, a Juniper switch, a printer, and a UPS all expose different internals — but the manager needs **one standard way** to ask "what's your status?"

**The solution — SNMP (RFC 1157 and successors, 1990→):** a simple, standardised **manager/agent** model. Each device runs an **agent** exposing its state as a **MIB** — a standardised, hierarchical dictionary of **objects** (OIDs). A central **manager** *polls* those objects on a schedule (UDP/161) to build metrics and trends, and agents *push* **traps** (UDP/162) for events that can't wait. One protocol, one object model, every vendor — that's how a single NMS monitors an entire heterogeneous network.

**Why the versions matter:** v1/v2c shipped with a fatal flaw — the "password" (community string) travels **in cleartext in every packet**, and grants read (or worse, write) access to anyone who sniffs or guesses it. That's why **v3** exists: real per-user authentication and encryption. Understanding this progression is understanding why "SNMP is insecure" is only true if you deploy it wrong.

**Why an engineer cares:**
- SNMP is the backbone of **every monitoring dashboard** you'll ever look at — knowing manager/agent/MIB/OID is knowing how your NMS actually gets its numbers.
- **RW community strings and `noAuthNoPriv`** are real, exploited security holes. You'll be the one who has to lock SNMP down (v3 authPriv + ACL) or explain why the audit flagged it.
- The **trap-vs-poll** trade-off (and the **inform** acknowledgement) is a daily design decision for reliable alerting.

## 5️⃣ Description 📋

- **SNMP** = a manager/agent framework for **monitoring and managing** devices over IP.
- **Manager (NMS)** — the central station that polls agents and receives notifications.
- **Agent** — software on the managed device that answers polls and emits traps/informs.
- **MIB (Management Information Base)** — the hierarchical **database of manageable objects** on a device; standardised (mib-2) plus vendor extensions.
- **OID (Object Identifier)** — the dotted-number **path** to a specific object in the MIB tree (e.g. `sysName = 1.3.6.1.2.1.1.5.0`).
- **Ports:** agent listens on **UDP/161** (polling); manager listens on **UDP/162** (traps/informs).
- **Operations:** `GET` (read one), `GETNEXT` (walk), `GETBULK` (v2c+, bulk read), `SET` (write), `RESPONSE`, `TRAP` (unsolicited), `INFORM` (v2c+, acknowledged trap), `REPORT` (v3).
- **v1/v2c authentication = community string** — a cleartext shared secret; **RO** (read-only) or **RW** (read-write).
- **v2c improvements over v1:** `GETBULK`, `INFORM`, and **64-bit counters (Counter64)** — but *not* security.
- **v3 = security overhaul:** **USM** (users, auth MD5/SHA, privacy DES/AES) + **VACM** (which OIDs a group may see) + **engine ID** (per-agent identity for key localisation).
- **v3 security levels:** `noAuthNoPriv` < `authNoPriv` < `authPriv` (auth **and** encryption — the target).
- **Trap vs inform:** trap = fire-and-forget (may be lost); inform = acknowledged (retransmitted until ack).

## 6️⃣ How It Works — Under the Hood ⚙️

### 6.1 The MIB tree & OIDs 🔬🟢

Every manageable value lives at a fixed address in a global tree. The path from the root spells the OID:

```
  1.3.6.1        = iso.org.dod.internet
  1.3.6.1.2.1    = mib-2         → standard objects every device implements
  1.3.6.1.2.1.1  = system        → sysDescr, sysName, sysUpTime, sysContact, sysLocation
  1.3.6.1.2.1.2  = interfaces    → ifTable (per-interface status & counters)
  1.3.6.1.4.1    = enterprises   → vendor-private space
  1.3.6.1.4.1.9  = cisco         → Cisco's private MIBs
```

- A **scalar** object is queried with a trailing **`.0`** (`sysName.0`). **Table** objects append a row index (`ifInOctets.3` = octets on interface index 3).
- The **MIB file** is just a human-readable definition (written in **SMI**) that maps names ↔ OIDs so tools show `sysName` instead of `1.3.6.1.2.1.1.5.0`. If the manager lacks the MIB, you use the **numeric OID** directly.

🧠 **Key idea:** the OID *is* the address. The manager doesn't "browse" the device — it names an exact OID and the agent returns that object's value. `GETNEXT`/`GETBULK` let it *walk* the tree without knowing every OID in advance.

### 6.2 The operations, in motion 🟢

```
  GET      manager → agent :161   "value of sysName.0?"          agent → RESPONSE "R1"
  GETNEXT  manager → agent :161   "the OID after this one?"      → walks a table one step
  GETBULK  manager → agent :161   "next N objects" (v2c+)        → whole ifTable in one shot
  SET      manager → agent :161   "set ifAdminStatus.3 = down"   → writes (needs RW / v3 write)
  TRAP     agent → manager :162   "linkDown on Gi0/1!"           → unsolicited, no reply
  INFORM   agent → manager :162   "linkDown!" (v2c+)             → manager RESPONSE ack; retransmit if none
```

🕵️ **Why GETBULK matters:** walking a 48-port switch's interface table with `GETNEXT` is dozens of round trips. `GETBULK` says "give me the next *max-repetitions* objects in one response" — dramatically fewer packets, essential on big devices. It's the headline v2c feature.

### 6.3 Trap vs Inform — reliability trade-off 🔵

- **Trap:** the agent sends and forgets. Over UDP, if it's lost (congestion, NMS down), **the event is gone** — no retry. Cheap, but not guaranteed.
- **Inform:** the agent sends and **waits for an acknowledgement**; no ack → **retransmit**. Guaranteed delivery, at the cost of agent state and extra traffic.

Design rule: use **informs for events you cannot afford to miss** (a device rebooting, a security event); traps are fine for high-volume, lower-criticality signals.

### 6.4 The polling blind spot 🕵️🔵

Polling samples state **every N minutes**. Anything shorter-lived than the interval can happen **entirely between two polls** and never appear in your graphs:

```
  poll ───────────── flap (90s) ───────────── poll
   ▲  interface counters normal   ▲  back to normal → the outage is INVISIBLE to polling
```

**Traps close this gap** by pushing the event the instant it occurs. Good monitoring uses **both**: polling for trends/baselines, traps/informs for immediate events.

### 6.5 SNMPv3 security — USM & VACM 🔬🔵

v3 splits security into two models:

- **USM (User-based Security Model, RFC 3414)** — per-user **authentication** (HMAC with **MD5** or **SHA**) proves the message wasn't forged/altered, and optional **privacy** (**DES/3DES/AES**) encrypts the payload. Keys are **localised** to the agent's **engine ID**, so a stolen key from one device can't be replayed against another.
- **VACM (View-based Access Control Model, RFC 3415)** — defines **which OIDs** a given group may read/write (a "view"), so a monitoring user can be limited to read-only, specific subtrees.

**The three levels** decide how much of USM is applied:

| Level | Auth | Priv | On the wire |
|---|---|---|---|
| `noAuthNoPriv` | — | — | username in the clear; no integrity |
| `authNoPriv` | MD5/SHA | — | tamper-proof but **readable** |
| **`authPriv`** | MD5/SHA | DES/AES | tamper-proof **and encrypted** ✅ |

### 6.6 Cisco configuration 🟢

**SNMPv2c (read-only, locked to the NMS):**
```
Router(config)# ip access-list standard SNMP-NMS
Router(config-std-nacl)#  permit host 10.0.0.100        ! only the NMS
Router(config)# snmp-server community S3cretRO RO SNMP-NMS
Router(config)# snmp-server location "DC1 - Rack 12"
Router(config)# snmp-server contact noc@example.com
Router(config)# snmp-server host 10.0.0.100 version 2c S3cretRO
Router(config)# snmp-server enable traps                 ! send traps for events
```

**SNMPv3 (authPriv — the real-world choice):**
```
Router(config)# snmp-server group MONITOR v3 priv read READVIEW access SNMP-NMS
Router(config)# snmp-server view READVIEW iso included
Router(config)# snmp-server user noc-user MONITOR v3 auth sha <AuthPass> priv aes 128 <PrivPass>
Router(config)# snmp-server host 10.0.0.100 version 3 priv noc-user
```

> 🔒 **Harden:** IOS auto-creates open `v1default` / `v2cdefault` groups — remove them (`no snmp-server group v2cdefault v2c`) in secure builds.

**Verify:**
```
show snmp                 ! chassis, contact, location, trap stats, packet counts
show snmp community       ! configured communities + their ACLs
show snmp group           ! v3 groups, security model/level, views
show snmp user            ! v3 users, auth/priv protocols
show snmp host            ! configured trap/inform destinations
```

### 6.7 Counter64 — why 32 bits isn't enough 🔵

v1's interface counters are **32-bit**. A 32-bit octet counter wraps at ~**4 GB**; on a **1 Gbps** link that's every **~34 seconds**, so two polls 5 minutes apart can't tell how many times it rolled over → the measurement is **useless** on fast interfaces. **v2c's Counter64** (e.g. `ifHCInOctets`) fixes this. Always poll the **high-capacity (HC) 64-bit** counters on gigabit+ interfaces.

## 7️⃣ Pros & Cons ⚖️

| ✅ Pros | ❌ Cons / Costs |
|---|---|
| **Standard, vendor-neutral** monitoring language | **v1/v2c cleartext community** = trivially sniffed/guessed |
| **Central visibility** across the whole network | **RW communities / `noAuthNoPriv`** = remote-config risk |
| **Polling** builds trends & capacity data | **Polling blind spot** between intervals |
| **Traps/informs** give instant event alerts | **Traps can be lost** (UDP, fire-and-forget) |
| **v3** adds real auth + encryption (`authPriv`) | **v3 config is fiddlier** (users, engine ID, views) |
| **GETBULK / Counter64** scale to big/fast devices | **MIB sprawl** — vendor MIBs to load & maintain |
| Lightweight (UDP) | An **attack/recon surface** if left open (info leak, amplification) |

## 8️⃣ Variants — Common → Specific 🧬

- 🟠 **SNMPv1** — original; community strings; GET/GETNEXT/SET/TRAP; no GETBULK/Counter64. Legacy.
- 🟡 **SNMPv2c** — community-based; adds **GETBULK, INFORM, Counter64**; still cleartext. The old default.
- 🟢 **SNMPv3** — **USM + VACM**; users, auth (MD5/SHA), privacy (DES/3DES/AES); the secure standard.
  - `noAuthNoPriv` / `authNoPriv` / **`authPriv`** security levels.
- 🔵 **Trap** — unsolicited, unacknowledged notification.
- 🔵 **Inform** — acknowledged notification (v2c+); reliable delivery.
- 🔵 **SNMP over (D)TLS** — ports **10161/10162**; transport-layer security alternative.
- 🔵 **RMON** — Remote MONitoring MIB extensions (thresholds/alarms on the agent).
- 🔵 **Modern successors** — **NETCONF/RESTCONF + YANG** and **model-driven streaming telemetry** (push, structured) increasingly replace SNMP polling in automation-heavy networks (Block 10 / CCNP).

## 🔟 Best Practices ✅

- 🟢 **Use SNMPv3 `authPriv`** anywhere remotely sensitive. Treat v2c as acceptable *only* on an isolated management VLAN behind strict ACLs.
- 🚫 **Avoid RW access** unless you truly need SNMP writes — most monitoring is read-only. If you must, lock it to v3 authPriv + ACL.
- 🔒 **ACL every SNMP entry** to the NMS IP(s) — `snmp-server community … <ACL>` / `access <ACL>` on the v3 group.
- 🧹 **Remove default groups** (`v1default`, `v2cdefault`) and never leave `public`/`private` community strings.
- 📈 **Poll 64-bit (HC) counters** on gigabit+ interfaces; poll at a sensible interval (trend vs load).
- 🔔 **Use informs (not traps) for must-not-miss events**; enable only the trap types you actually consume.
- 🕰️ **Sync NTP first** (6.5) so poll samples and trap timestamps line up across devices.
- 🧭 **Set `sysLocation`/`sysContact`** — future-you (and the NMS map) will thank you.
- 🛡️ **Firewall UDP/161-162** to the management plane; SNMP left open to the world is recon + amplification bait.

## 1️⃣1️⃣ No-Goes — Mistakes & Troubleshooting Traps 🚫

**Security mistakes**
- ❌ **Leaving `public` / `private` community strings** → anyone who guesses them can read (or with RW, reconfigure) the device.
- ❌ **Using v2c across untrusted links** → the community string is sniffable in cleartext; treat it as compromised.
- ❌ **RW community with no ACL** → remote configuration takeover via `SET`.
- ❌ **v3 `noAuthNoPriv`** thinking "it's v3 so it's secure" → it isn't; you need **authPriv**.
- ❌ **No ACL on SNMP** → open recon surface (device inventory, interfaces, uptime, sometimes secrets) and amplification abuse.

**Config / operational mistakes**
- ❌ **UDP/161 or 162 blocked** by a firewall/ACL → polling times out or traps never arrive (SNMP's failure mode is **silence**).
- ❌ **`snmp-server host` version/community/user mismatch** with the NMS → notifications silently dropped.
- ❌ **v3 auth/priv passphrase or protocol mismatch** (SHA vs MD5, AES vs DES) → association fails; often an **engine ID** cache issue on the NMS after a device rebuild.
- ❌ **Polling only, no traps** → short flaps between polls are invisible.
- ❌ **Polling 32-bit counters on gigabit links** → wrap-around makes throughput numbers nonsense; use Counter64.

**Diagnostic signatures**
- 🔍 **NMS shows device "down"/no data, ping works** → SNMP path issue: community/user mismatch, ACL, or UDP/161 filtered. `show snmp` counters stay flat.
- 🔍 **`show snmp` request counters increment but responses don't** → ACL denying the source, or wrong view (v3 can't see the OID).
- 🔍 **Traps not received** → check `snmp-server host`, `snmp-server enable traps`, UDP/162 path, and v3 user match on the receiver.
- 🔍 **Bizarre/negative throughput graphs** → 32-bit counter wrap; switch to HC counters.
- 🔍 **v3 works then breaks after a reload** → engine ID changed / stale cached credentials on the NMS.

**Conceptual traps**
- ❌ Thinking the **community string is encrypted** — it's cleartext in v1/v2c.
- ❌ Believing **any v3 = secure** — only `authPriv` gives both integrity and confidentiality.
- ❌ Confusing **poll (161) with trap (162)** direction — polling is manager→agent on 161; notifications are agent→manager on 162.
- ❌ Assuming a **trap is guaranteed** — it isn't; use **informs** for reliability.

## 1️⃣3️⃣ Practical Tasks 🧪

*(listed briefly here — expanded with full walkthroughs later in context)*

1. **🧩 Packet Tracer 8 / lab — v2c read-only:**
   - Configure `snmp-server community … RO <ACL>`, `snmp-server host`, `snmp-server enable traps`.
   - Point a MIB browser / NMS at the device; poll `sysName`, `sysUpTime`, walk `ifTable`.
2. **🔐 SNMPv3 authPriv:**
   - Build a `group` (priv, read view) + `user` (SHA + AES). Verify with `show snmp group` / `show snmp user`.
   - Deliberately mismatch the priv protocol and watch the poll fail — then fix it.
3. **🐧 CLI tooling:** `snmpget -v3 -l authPriv -u noc-user -a SHA -A <auth> -x AES -X <priv> <ip> sysName.0`; compare with `snmpwalk` of `1.3.6.1.2.1.2` (interfaces). Repeat with `-v2c -c <community>` and note the difference.
4. **🦈 Wireshark:** capture v2c and observe the **community string in cleartext**; capture v3 authPriv and observe the payload is **encrypted**. Identify GET on **161** vs trap on **162**.
5. **🔔 Trap vs inform:** trigger a `linkDown` (shut an interface); confirm the trap arrives on 162. Switch the host to `informs` and capture the **acknowledgement**; drop the receiver and watch the **retransmit**.
6. **🔬 Stretch (engineer):** stand up **LibreNMS/Zabbix**, add the device over v3, graph interface throughput using **HC (64-bit)** counters, set a **threshold alert**, and correlate a trap-driven alert against the polled graph — then compare the same visibility via **streaming telemetry (gNMI)** to see where SNMP is heading.
