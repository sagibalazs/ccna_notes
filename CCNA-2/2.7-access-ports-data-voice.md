## 2️⃣ Visualization — Big Picture at a Glance

**A plain access port vs a voice-enabled access port:**

```
   PLAIN ACCESS PORT (one VLAN, untagged)        VOICE-ENABLED ACCESS PORT (two VLANs)
   ───────────────────────────────────────       ─────────────────────────────────────────
      PC ── untagged Ethernet ── Gi0/1               PC ─untagged─┐
                                  │ (access VLAN 10)              │ (data/access VLAN 10, UNTAGGED)
                              ┌───┴───┐                    ┌──────┴──────┐
                              │ SWITCH │                   │  IP PHONE   │  ← built-in 3-port switch
                              └───────┘                    │ (3-port sw) │
      • host sees NO VLAN tag                              └──────┬──────┘
      • switch tags internally = VLAN 10                          │ phone tags its OWN voice frames
      • one MAC (usually) on the port                             │ 802.1Q → VOICE VLAN 40, CoS 5
                                                              Gi0/1 (ONE cable, ONE physical port)
                                                                 │
                                                             ┌───┴───┐
                                                             │ SWITCH │  access vlan 10 + voice vlan 40
                                                             └───────┘  ⚠ still an ACCESS port, NOT a trunk
```

**Who tags what on the voice port:**

| Traffic | Source | Tagged? | Lands in | QoS mark |
|---|---|:---:|---|---|
| 🟢 **PC data** | PC (behind phone) | ❌ untagged | **data/access VLAN** (10) | none (default) |
| 🟢 **Phone voice** | IP phone | ✅ 802.1Q | **voice VLAN** (40) | CoS 5 / DSCP 46 (EF) |

**The default VLAN in one line:** every port starts in **VLAN 1**; an access port stays there until `switchport access vlan <id>` moves it.

```
  show vlan brief   (a voice port appears in BOTH VLANs)
  VLAN Name       Status  Ports
  1    default    active  Gi0/13, Gi0/14 ...        ← untouched ports still in VLAN 1
  10   DATA       active  Gi0/1                      ← access (data) VLAN
  40   VOICE      active  Gi0/1                      ← same port, voice VLAN  ✅ expected
```

## 3️⃣ TL;DR

- 🟢 An **access port** connects an **end device** and carries **exactly one VLAN's traffic, untagged**. The host never sees a VLAN tag — the switch handles VLAN membership internally.
- 🟢 Configure with `switchport mode access` **then** `switchport access vlan <id>` (order from 2.6). Ingress untagged frames → the port's **access VLAN**; egress frames leave **untagged**.
- 🟢 **Default VLAN = VLAN 1.** Every port belongs to VLAN 1 until reassigned; a reset/unconfigured access port is in VLAN 1. Best practice: **don't leave users/management on VLAN 1.**
- 🟢 **Voice VLAN** lets **one access port carry two VLANs**: **PC data (untagged)** in the access VLAN, **IP-phone voice (802.1Q-tagged)** in the voice VLAN. Add `switchport voice vlan <id>`.
- 🟢 The switch tells the phone which voice VLAN to use via **CDP** (Cisco phones) or **LLDP-MED** (standards/non-Cisco). The phone **tags** voice with the voice VLAN + **CoS 5** (and DSCP 46/EF at L3).
- ⚠️ **A voice port is still an ACCESS port, not a trunk** — even though it carries two VLANs. Classic exam distractor.
- 🔵 Real-world combo on a voice port: **PoE** powers the phone, **PortFast** speeds host bring-up, **port security max 2** (phone + PC), and **DHCP Option 150** points the phone at its call manager.

## 4️⃣ Importance — The Problem First 🎯

**The underlying problem:** VLANs (2.6) segment the network — but *most ports on a network face end devices*, and those devices don't speak VLAN. A PC, printer, or camera sends plain, untagged Ethernet. So we need a port type that:

1. ❓ *"How do I put an unaware end host into a VLAN?"* → the **access port**: the switch stamps every frame from that port into the port's **access VLAN**, and strips any VLAN identity before sending back to the host.
2. ❓ *"What VLAN is a port in if I never configured it?"* → the **default VLAN (1)** — which is *why* an out-of-box switch "just works" as one flat network, and why forgetting to assign VLANs is a security gap.
3. ❓ *"How do I put a desk phone **and** the PC behind it on the same cable, but in different VLANs with different priority?"* → the **voice VLAN**: two VLANs on one access port, voice tagged and prioritized, data untagged.

**Why an engineer must own this cold:**

- 🔧 **Access ports are ~90% of your switch ports.** Getting the access VLAN right (and off VLAN 1) is the single most common, most consequential switch task.
- 🔧 **Voice deployments are everywhere** and combine *five* features on one port — VLANs, QoS, PoE, CDP/LLDP, port security. Understanding how they interlock is core to real campus work and a favorite exam scenario.
- 🔧 **The "access port with two VLANs" fact trips people constantly.** Knowing a voice port is *not* a trunk (and why) separates people who memorized from people who understand.
- 🔧 **Default-VLAN mistakes are security holes** — hosts or management left on VLAN 1, or an "unused" port silently live in VLAN 1, are classic findings in an audit.

## 5️⃣ Description 📋

- 🟢 **Access port:** a switch port set to `switchport mode access`, connecting to a **single end device**, carrying the traffic of **one VLAN (the "access VLAN") with no VLAN tag**. The device is unaware of VLANs.
  - **Ingress:** an untagged frame arrives → the switch internally associates it with the **access VLAN** of that port.
  - **Egress:** the switch removes any VLAN identity → the frame leaves **untagged** to the host.
  - If a **tagged** frame arrives on a normal access port, it's generally **dropped** (a host shouldn't be tagging).
- 🟢 **Default VLAN (VLAN 1):** created automatically; **every port is in VLAN 1 by default**; can't be deleted/renamed (from 2.6). An access port with no `switchport access vlan` command is in VLAN 1. **Access VLAN ≠ default VLAN necessarily** — "access VLAN" is *whatever VLAN this access port is assigned to*; it merely *defaults* to 1.
  - ⚠️ **Default VLAN vs Native VLAN:** both **default to VLAN 1**, but they're different roles — **default VLAN** = the VLAN unconfigured ports land in; **native VLAN** = the *untagged* VLAN on a **trunk** (→ 2.9). Don't conflate them.
- 🟢 **Voice VLAN:** a feature that lets **one access port serve two VLANs** — a **data (access) VLAN** for an attached PC and a **voice VLAN** for a Cisco/compatible IP phone.
  - The **IP phone contains a small 3-port switch**: uplink to the switch, the phone itself, and a **passthrough port for a daisy-chained PC**.
  - **PC data** flows **untagged** through the phone → the switch puts it in the **access/data VLAN**.
  - **Phone voice** is **802.1Q-tagged** with the **voice VLAN ID** and a **Layer-2 CoS** value → kept separate and prioritized.
  - The switch **advertises the voice VLAN to the phone via CDP** (Cisco) **or LLDP-MED** (non-Cisco). **CDP must be enabled** on the port for Cisco phones (it's on by default).
  - Configured with **`switchport voice vlan <id>`** *in addition to* `switchport access vlan <id>`. The voice VLAN feature is **disabled by default**.
  - 🔵 Variants of the command: `voice vlan <id>` (tagged voice VLAN — normal), `voice vlan dot1p` (voice in access VLAN via 802.1p priority, VLAN 0 tag), `voice vlan untagged` (untagged voice in access VLAN), `voice vlan none` (phone uses its own config). **Use a specific VLAN ID** for production.
- 🟢 **QoS on voice:** voice frames carry **CoS 5** (Layer 2, the 802.1p priority bits in the 802.1Q tag) and **DSCP 46 / EF** (Layer 3). The switch must **trust** those markings (e.g., `mls qos trust cos` / AutoQoS) or it rewrites them; **untrusted is the default** (tagged traffic gets CoS 0 unless trust is set). Deep QoS → IP Services.
- 🟢 **The port is still an access port** (Cisco sometimes: a *multi-VLAN access port*), **not a trunk** — it just additionally accepts the tagged voice VLAN. It does **not** run trunk negotiation for arbitrary VLANs.
- 🔵 **Companion features on a real voice port:** **PoE** (802.3af 15.4 W / 802.3at 30 W) powers the phone; **PortFast** brings the host up fast (→ 2.19); **port security `maximum 2`** allows phone + PC; **DHCP Option 150** hands the phone its TFTP/call-manager address; **`switchport nonegotiate`** disables DTP to harden against VLAN hopping (→ 2.8/Block 9).

## 6️⃣ How It Works — Under the Hood ⚙️

### A) 🔌 Plain access port — tag on, tag off

```
Host ↔ access port (access VLAN 10):

  INGRESS (host → switch):
     untagged frame arrives on Gi0/1
        → switch tags it internally as VLAN 10 (based on the port's access VLAN)
        → learn/forward/flood happen ONLY within VLAN 10 (2.4)

  EGRESS (switch → host):
     switch has a VLAN-10 frame to send out Gi0/1
        → STRIP the VLAN identity → deliver plain untagged Ethernet
        → host is blissfully unaware VLANs exist

  A tagged frame arriving on a normal access port → dropped (hosts don't tag).
```

### B) 🧾 Configuration (data + voice on one port)

```
! Create the VLANs (2.6)
Switch(config)# vlan 10
Switch(config-vlan)#  name DATA
Switch(config)# vlan 40
Switch(config-vlan)#  name VOICE

! The access port for a phone + daisy-chained PC
Switch(config)# interface Gi0/1
Switch(config-if)#  switchport mode access            ← it's an access port…
Switch(config-if)#  switchport access vlan 10          ← PC (untagged) data VLAN
Switch(config-if)#  switchport voice vlan 40           ← phone voice VLAN (phone will 802.1Q-tag)
Switch(config-if)#  spanning-tree portfast             ← host port: skip STP listen/learn (→ 2.19)
Switch(config-if)#  switchport port-security maximum 2 ← phone + PC (→ Block 9)
Switch(config-if)#  switchport nonegotiate             ← no DTP (harden vs VLAN hopping)
```

### C) 📣 How the phone learns its voice VLAN (CDP / LLDP-MED)

```
 1. Phone powers on (via PoE) and links up on Gi0/1.
 2. Switch sends CDP (Cisco phone) or LLDP-MED (standards phone) that says:
        "Voice VLAN = 40. Tag your voice with 802.1Q + CoS 5."
 3. Phone starts tagging its VOICE frames → VLAN 40, CoS 5 (DSCP 46 at L3).
 4. PC plugged into the phone's passthrough port sends UNTAGGED frames
        → phone forwards them untouched → switch puts them in VLAN 10 (data).
 5. Switch, if trusting CoS/DSCP, gives voice priority end-to-end (QoS → IP Services).

  ⚠ If CDP/LLDP is off on the port, the phone may not learn the voice VLAN
     → voice fails or lands in the wrong VLAN. (CDP is on by default.)
```

### D) 🔎 Verifying — the voice port's dual identity

```
Switch# show interfaces Gi0/1 switchport
  Administrative Mode: static access
  Operational Mode: static access          ← still ACCESS, even with voice
  Access Mode VLAN: 10 (DATA)
  Voice VLAN: 40 (VOICE)                    ← the two VLANs, side by side

Switch# show vlan brief
  10  DATA   active  Gi0/1                   ← same port…
  40  VOICE  active  Gi0/1                   ← …appears in BOTH VLANs ✅

Switch# show cdp neighbors detail            ← confirm the phone & advertised voice VLAN (Cisco)
Switch# show lldp neighbors detail           ← same for non-Cisco (LLDP-MED)
Switch# show power inline                     ← confirm PoE is feeding the phone
Switch# show port-security interface Gi0/1    ← phone + PC (max 2) accounting
```

> 🕵️ **Dirty secret — the "two VLANs but not a trunk" trap.** A voice port shows a MAC and traffic in *two* VLANs, so people call it a trunk and try to troubleshoot it as one. It isn't. Its **operational mode is `static access`**; it only accepts the *one* specifically-configured voice VLAN as tagged, plus the untagged access VLAN. Treating it as a trunk (allowed-VLAN lists, native VLAN, DTP) sends you down the wrong path. This is one of the most common CCNA distractors *and* a real field confusion.

### E) 🧱 Why the default VLAN is a quiet risk

```
Out of the box: ALL ports = VLAN 1 = one flat domain (works, but flat).

Risks of leaving things on VLAN 1:
  • An "unused" port is LIVE in VLAN 1 → plug in = instant network access (no segmentation).
  • Management (SSH/SNMP) on VLAN 1 → shares the user broadcast domain → bigger attack surface.
  • VLAN 1 is often the default NATIVE VLAN on trunks too (→ 2.9) → VLAN-hopping exposure.

Best practice: assign every access port a deliberate VLAN; shut unused ports (or park them
in an unused "black-hole" VLAN); move management off VLAN 1; change the native VLAN (→ 2.9).
```

## 7️⃣ Pros & Cons ⚖️

**Access ports:**

| ✅ Pros | ❌ Cons / Limits |
|---|---|
| 🟢 **Dead simple** for end hosts — no VLAN awareness needed on the device. | 🔵 **One VLAN only** (plus the voice exception) — can't carry multiple data VLANs. |
| 🟢 **Clear security boundary** — the port's access VLAN pins the host. | ⚠️ **Default VLAN 1 footgun** — forget to assign, and the host is in VLAN 1. |
| 🟢 **Fast host bring-up** with PortFast. | ⚠️ A **tagged frame on a bare access port is dropped** — surprises misconfigured devices. |

**Voice VLAN:**

| ✅ Pros | ❌ Cons / Limits |
|---|---|
| 🟢 **One cable, two VLANs** — phone + PC without a second drop. | 🔵 **More features to align** (CDP/LLDP, QoS trust, PoE, port-security max 2). |
| 🟢 **Voice isolation + priority** (own VLAN, own subnet, CoS 5/EF). | ⚠️ **Depends on CDP/LLDP** — off = phone may not get the voice VLAN. |
| 🟢 **Still an access port** — simpler/safer than a full trunk to the desk. | ⚠️ **"Looks like a trunk"** confusion during troubleshooting. |

## 8️⃣ Variants — Common → Specific 🌿

**Port roles (this doc's family):**
- 🟢 **Data access port** — one VLAN, untagged (the everyday port).
- 🟢 **Voice-enabled access port** — data (untagged) + voice (tagged) (the phone case).
- 🟢 **Trunk port** (contrast) — many VLANs, tagged (→ 2.8). *Not* an access port.

**`switchport voice vlan` modes (common → edge):**
- 🟢 **`voice vlan <id>`** — dedicated voice VLAN, 802.1Q-tagged (production default).
- 🔵 **`voice vlan dot1p`** — voice in access VLAN, prioritized via 802.1p (VLAN 0 tag).
- 🔵 **`voice vlan untagged`** — voice untagged in access VLAN.
- 🔵 **`voice vlan none`** — phone uses its own configuration.

**VLAN-1 / default-VLAN handling:**
- 🟢 **Leave on VLAN 1** (out-of-box) — flat, discouraged for production.
- 🟢 **Deliberate access VLAN** per port — the norm.
- 🔵 **Unused ports** → `shutdown` and/or a **black-hole VLAN**.

## 9️⃣ Devices / Media / Protocols 🧰

**Devices:**
- 🟢 **[Endpoint / NIC](./devices/endpoint-nic.md)** — PC/printer/server on an access port; VLAN-unaware.
- 🟢 **IP Phone** — the voice case; contains a **3-port switch**, tags voice, passes PC data.
- 🟢 **[Layer-2 Switch](./devices/switch.md)** — enforces access/voice VLANs; advertises voice VLAN via CDP/LLDP; supplies PoE.
- 🟢 **[Access Point](./devices/access-point.md)** — often on an access port (or trunk for multi-SSID).

**Protocols / features:**
- 🟢 **[CDP](./protocols/cdp.md) / [LLDP-MED](./protocols/lldp.md)** — tell the phone its voice VLAN & QoS (→ 2.13/2.14).
- 🟢 **[802.1Q](./protocols/dot1q.md)** — the tag the phone uses for voice (anatomy → 2.8).
- 🔵 **PoE (802.3af/at)** — powers the phone over the same cable (Block 1, 1.2).
- 🔵 **QoS (CoS 5 / DSCP 46 EF, trust)** — voice prioritization (→ IP Services 4.7).
- 🔵 **DHCP Option 150** — TFTP/call-manager address for phones (→ IP Services DHCP).
- 🔵 **[STP PortFast](./protocols/stp.md)** — on access/voice ports for fast bring-up (→ 2.19).
- 🔵 **Port security** — `maximum 2` on voice ports (→ Block 9).

## 🔟 Best Practices ✅

- 🟢 **Assign every access port a deliberate VLAN** — never rely on VLAN 1 for user traffic. Set `switchport mode access` explicitly.
- 🟢 **Move management off VLAN 1** and change the trunk **native VLAN** (→ 2.9) to reduce attack surface.
- 🟢 **Shut or black-hole unused ports** so a random plug-in doesn't get VLAN-1 access.
- 🟢 **On voice ports, configure both** `switchport access vlan` (data) **and** `switchport voice vlan` (voice), and keep **CDP/LLDP enabled** so the phone learns its VLAN.
- 🔵 **Trust QoS from the phone** (`mls qos trust`/AutoQoS) so CoS 5 / DSCP 46 survives — otherwise voice loses priority.
- 🔵 **`port-security maximum 2`** on voice ports (phone + PC); add **PortFast** for host bring-up and **`switchport nonegotiate`** to disable DTP.
- 🟢 **Verify with `show interfaces <int> switchport`** — confirm operational mode is `static access` and both Access VLAN and Voice VLAN are correct.

## 1️⃣1️⃣ No-Goes — Common Mistakes & Troubleshooting Traps 🚫

- ❌ **Calling a voice port a trunk.** It's a **static access** port that additionally carries one tagged voice VLAN. Don't apply trunk logic (allowed lists, native VLAN, DTP) to it.
- ❌ **Confusing default VLAN with native VLAN.** Default VLAN = where unconfigured ports live (access side). Native VLAN = the untagged VLAN on a **trunk** (→ 2.9). Both default to 1, but they're different roles.
- ⚠️ **Forgetting the voice VLAN must exist and be carried on trunks.** Create VLAN 40 and allow it on every switch-to-switch trunk, or voice breaks between switches.
- ⚠️ **Disabling CDP/LLDP on a phone port.** The phone may never learn its voice VLAN → voice lands in the data VLAN or fails. CDP is on by default — keep it on phone ports.
- ⚠️ **Not trusting QoS.** With untrusted default, the switch may zero the phone's CoS → voice loses priority and gets choppy under load.
- ⚠️ **`port-security maximum 1` on a voice port.** The phone *and* the PC are two MACs → a violation kills the port. Use `maximum 2` (or more with allowances).
- 🔵 **Leaving DTP enabled** (`dynamic auto/desirable`) on access/voice ports — a VLAN-hopping risk; set `switchport mode access` + `switchport nonegotiate` (→ 2.8/Block 9).
- ⚠️ **Deleting the data or voice VLAN** while the port uses it → the port's traffic for that VLAN goes inactive (2.6 trap) — reassign first.

## 1️⃣3️⃣ Practical Tasks 🛠️

> Listed briefly; expanded step-by-step later in context.

1. 🟢 **Build a data access port (Packet Tracer 8 / GNS3).** Put a PC on `Gi0/1` in VLAN 10; verify with `show interfaces Gi0/1 switchport` (operational mode `static access`, Access VLAN 10) and `show vlan brief`.
2. 🟢 **Prove the default VLAN.** Show that a brand-new port sits in VLAN 1 (`show vlan brief`), then reassign it and watch it move; `no switchport access vlan` returns it to VLAN 1.
3. 🟢 **Add voice (Packet Tracer supports IP phones).** Configure `switchport access vlan 10` + `switchport voice vlan 40`; attach an IP phone with a PC daisy-chained; confirm the port shows in **both** VLAN 10 and 40, and operational mode is still `static access`.
4. 🟢 **Confirm phone discovery.** `show cdp neighbors detail` (or `show lldp neighbors detail`) to see the phone and the advertised voice VLAN. Disable CDP on the port and observe voice VLAN learning break.
5. 🔵 **QoS trust check.** Inspect voice marking (CoS 5 / DSCP 46) and configure the port to trust it; reason about what happens under congestion if trust is missing.
6. 🔵 **Voice port hardening.** Apply `spanning-tree portfast`, `switchport port-security maximum 2`, `switchport nonegotiate`; verify with `show port-security interface` and confirm phone + PC both work.
7. 🔵 **Default-VLAN hygiene.** Identify all ports still in VLAN 1; `shutdown` unused ports or move them to a black-hole VLAN; move a mock management interface off VLAN 1.
