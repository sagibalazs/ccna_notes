**Where each tool belongs — edge vs core:**

```
                         ROOT / DISTRIBUTION (core)
                    ┌───────────────────────────────┐
                    │  toward switches you DON'T      │
   ROOT GUARD ─────▶│  want to become root:           │
                    │    spanning-tree guard root      │
                    │  root/alternate ports (P2P):     │
   LOOP GUARD ─────▶│    spanning-tree guard loop      │
                    └───────────────┬───────────────┘
                                    │ trunks (switch↔switch)
                    ┌───────────────┴───────────────┐
                    │           ACCESS switch         │
   host-facing ports (to PCs / servers / printers):   │
   PORTFAST   ─────▶│  spanning-tree portfast          │  (instant forwarding, no TCN)
   BPDU GUARD ─────▶│  spanning-tree bpduguard enable  │  (BPDU seen → err-disable)
                    └──────────────┬──┬──┬────────────┘
                                   PC PC Server   (should NEVER send BPDUs)
```

**The three "reactions" — know which feature does which:**

| Feature | Trigger | Reaction | Recovery |
|---|---|---|---|
| 🟢 **BPDU Guard** | a **BPDU arrives** on the (edge) port | **err-disable** (port shut) | manual / `errdisable recovery` |
| 🟢 **Root Guard** | a **superior BPDU** arrives | **root-inconsistent** (blocked) | **auto** when superior BPDUs stop |
| 🟢 **Loop Guard** | BPDUs **stop arriving** on a root/alt port | **loop-inconsistent** (blocked) | **auto** when BPDUs resume |

**Toolkit at a glance:**

| Tool | Job | Applied on |
|---|---|---|
| 🟢 **PortFast** | skip listening/learning → instant forward; no TCN | **host/edge** ports |
| 🟢 **BPDU Guard** | shut a port that unexpectedly receives a BPDU | **host/edge** ports (with PortFast) |
| 🟢 **BPDU Filter** | suppress BPDUs (⚠ global ≠ interface behavior) | rarely; edge (global) |
| 🟢 **Root Guard** | stop a port from becoming root port | **designated** ports toward untrusted switches |
| 🟢 **Loop Guard** | block instead of forwarding when BPDUs vanish | **root/alternate** ports (P2P, switch↔switch) |

## 3️⃣ TL;DR

- 🟢 **PortFast** makes a host port **forward immediately** (skips listening/learning) and stops it from triggering **topology changes** on flap. **Host ports only — never switch↔switch** (loop risk). In RSTP a PortFast port = an **edge** port.
- 🟢 **BPDU Guard** protects PortFast ports: if a **BPDU is received** on one (meaning a switch/hub got plugged into a "host" port), the port is **err-disabled (shut)**. A PortFast port should *never* see a BPDU.
- 🟢 **BPDU Filter** suppresses BPDUs — **and its two forms behave very differently**: **global** (`spanning-tree portfast bpdufilter default`) stops sending on PortFast ports but **reverts to normal STP if a BPDU is received** (safer); **interface** (`spanning-tree bpdufilter enable`) **fully disables BPDUs (send + receive)** on the port → effectively **turns STP off there** → **dangerous** (can cause loops).
- 🟢 **Root Guard** enforces **root placement**: if a **superior BPDU** arrives on a Root-Guard port, it goes **root-inconsistent (blocked)** until the superior BPDUs stop — then **auto-recovers**. Use toward switches you **don't** want becoming root (access layer, partner networks).
- 🟢 **Loop Guard** protects against **unidirectional-link** loops: if a **root/alternate** port **stops receiving BPDUs**, instead of (wrongly) transitioning to forwarding it goes **loop-inconsistent (blocked)**, then **auto-recovers** when BPDUs return. Use on **switch↔switch root/alternate** ports — **not** on PortFast ports.
- 🟢 **Reactions differ:** BPDU Guard → **err-disable**; Root Guard → **root-inconsistent**; Loop Guard → **loop-inconsistent**. (Only BPDU Guard shuts the port.)
- 🔵 **You can't enable Root Guard and Loop Guard on the same port.** **UDLD** is Loop Guard's cousin (detects unidirectional links via its own protocol, great on fiber).

## 4️⃣ Importance — The Problem First 🎯

**The underlying problem:** Base STP/RSTP (2.16–2.18) keeps the network loop-free — but it leaves two gaps a real network must close:

- ⏱️ **Edge speed:** even with RSTP, a host port that isn't marked **edge** can churn the topology, and on legacy STP it makes users wait ~30 s to get on the network. Every user/printer/server port needs to forward **instantly** and never disturb the tree.
- 🛡️ **Trust & failure safety:** STP **trusts every BPDU it hears** and **trusts that a blocked port keeps hearing BPDUs**. Both assumptions are attackable/breakable:
  - Someone plugs a **rogue switch** into a wall jack → it injects BPDUs → it could become **root** (rerouting/black-holing traffic) or form a **loop**.
  - A **unidirectional link** (fiber miswire, dying transceiver — up/up but BPDUs only flow one way) makes a **blocked** port **stop hearing BPDUs**, so it wrongly transitions to **forwarding** → instant **loop**.

The toolkit closes both gaps:

- ❓ *"How do host ports forward instantly without destabilizing STP?"* → **PortFast** (edge).
- ❓ *"How do I stop a rogue switch on an access port?"* → **BPDU Guard** (shut it) — and **Root Guard** (deny it root) where switches legitimately connect.
- ❓ *"How do I prevent a unidirectional link from creating a loop?"* → **Loop Guard** (block instead of forward) / **UDLD**.

**Why an engineer must own this cold:**

- 🔧 **This is the difference between STP that *works in a lab* and STP that *survives production*.** A campus without PortFast+BPDU Guard on access ports and Root/Loop Guard in the right places is one wall-jack or one bad fiber away from an outage.
- 🔧 **These are explicit CCNA objectives (2.5.c–d)** and constant interview questions: "What does BPDU Guard do vs Root Guard? Where do you put each? What's the difference between global and interface BPDU Filter?"
- 🔧 **The reactions are commonly confused** (err-disable vs root-inconsistent vs loop-inconsistent), and the **BPDU Filter global/interface trap** genuinely causes outages. Precision here is what separates safe engineers from dangerous ones.
- 🔧 **It's the capstone of the STP family** — it operationalizes everything from 2.16–2.18 into a deployable, hardened design.

## 5️⃣ Description 📋

- 🟢 **PortFast (2.5.c):** lets an **access port to an end device** transition **straight to forwarding**, skipping listening/learning, and **prevents it from generating topology-change (TCN)** notifications when it flaps (so a rebooting PC doesn't flush MAC tables network-wide). In **RSTP**, a PortFast port is an **edge** port. **Only on host-facing ports — never switch-to-switch** (that risks a loop). If a PortFast port **receives a BPDU**, it should lose edge/PortFast status (a switch was connected).
  - Config: interface `spanning-tree portfast`; global (all access ports) `spanning-tree portfast default`.
- 🟢 **BPDU Guard (2.5.d):** the **enforcement partner** of PortFast. A PortFast port should **never** receive a BPDU; if BPDU Guard is on and a **BPDU arrives**, the switch **err-disables (shuts) the port** rather than letting it join STP. This stops a rogue switch/hub on an access port from creating loops or hijacking the root.
  - Config: interface `spanning-tree bpduguard enable`; global (all PortFast ports) `spanning-tree portfast bpduguard default`.
  - **Recovery:** manual `shutdown`/`no shutdown`, or automatic via `errdisable recovery cause bpduguard` + `errdisable recovery interval <sec>`.
- 🟢 **BPDU Filter (2.5.d):** **suppresses BPDUs** on a port — but the two forms are **critically different**:
  - **Global** (`spanning-tree portfast bpdufilter default`): applies to **PortFast** ports; **stops sending** BPDUs on them, but **if a BPDU is received, PortFast is removed** and the port **reverts to normal STP** → relatively safe (STP re-engages if a switch appears).
  - **Interface** (`spanning-tree bpdufilter enable`): **completely disables BPDUs (send AND receive)** on that port → **effectively disables STP on the port** → **DANGEROUS** (a switch connected there can form an undetected loop). Use almost never.
- 🟢 **Root Guard (2.5.d):** **enforces root-bridge placement** by preventing a port from becoming a **root port** (forces it to stay **designated**). If a **superior BPDU** (one claiming a better root) is received, the port goes to **root-inconsistent** state (blocked, listening-equivalent) and **stays blocked until the superior BPDUs stop**, then **auto-recovers**. It does **not** err-disable. Applied on **designated ports toward switches that must not become root** — classic case: **connecting your managed network to one you don't control** (partner/customer), or toward the access layer.
  - Config: interface `spanning-tree guard root`. Verify: `show spanning-tree inconsistentports`.
- 🟢 **Loop Guard (2.5.d):** protects against loops caused by **unidirectional links**. A **root/alternate (non-designated)** port normally **receives** BPDUs; if it **stops** receiving them (a one-way link failure — the port can send but not receive), plain STP would age out the info and **transition the port to forwarding** → a **loop**. Loop Guard instead puts the port into **loop-inconsistent** (blocked) state, and **auto-recovers** when BPDUs resume. Applied on **switch↔switch root/alternate ports** (point-to-point); **do NOT enable on PortFast ports** (it conflicts with edge logic).
  - Config: interface `spanning-tree guard loop`; global (recommended) `spanning-tree loopguard default`.
  - ⚠️ **You cannot enable Root Guard and Loop Guard on the same port.**
- 🔵 **UDLD (context):** Unidirectional Link Detection — sends its **own** protocol packets (every ~15 s) expecting an echo; no echo within ~45 s → **err-disables** the port. Overlaps with Loop Guard (both catch unidirectional links) but uses a dedicated protocol; especially useful on **fiber** (patch-panel miswires → up/up but BPDUs lost). Often deployed **alongside** Loop Guard.

## 6️⃣ How It Works — Under the Hood ⚙️

### A) ⚡ PortFast — instant edge forwarding

```
 Normal access port (no PortFast):  link up → LISTENING → LEARNING → FORWARDING (~30s on STP)
 PortFast port (edge):              link up → FORWARDING immediately ✅  + no TCN on flap

 Why safe? A host can't create a switching loop by itself, so skipping the delay is fine.
 Why host-only? If you PortFast a switch↔switch link, both sides forward instantly with no
   listening/learning safety window → INSTANT LOOP. PortFast is for END DEVICES only.
```

### B) 🛡️ BPDU Guard — the enforcement that makes PortFast safe

```
 A PortFast port should NEVER hear a BPDU (hosts don't send them). So:

   [someone plugs a rogue SWITCH into an access port]
        → that switch sends a BPDU into the PortFast port
        → BPDU GUARD: "a BPDU here?! misconfiguration/threat" → ERR-DISABLE (shut the port) 🔒
        → %SPANTREE-2-BLOCK_BPDUGUARD … port put into err-disabled state

 This is a HARD stop (port down). Recovery is deliberate (manual or errdisable-recovery timer),
 forcing an engineer to notice the rogue device. Belt-and-suspenders with PortFast on every
 access port: portfast for speed, bpduguard for safety.
```

### C) ⚠️ BPDU Filter — the global/interface trap

```
 GLOBAL  (spanning-tree portfast bpdufilter default):
   • on PortFast ports, STOP SENDING BPDUs (don't leak STP to hosts)
   • but if a BPDU is RECEIVED → drop PortFast → resume NORMAL STP on that port  ✅ safe-ish

 INTERFACE (spanning-tree bpdufilter enable):
   • STOP sending AND ignore received BPDUs entirely on that port
   • = STP is effectively OFF on this port → a connected switch can loop UNDETECTED  ❌ dangerous

 🕵️ Same feature name, opposite risk. Global filter reverts to STP on danger; interface filter
    blindfolds STP. Most "why did we get a loop with BPDU filter on?" incidents are the INTERFACE
    form applied to a switch link. Prefer BPDU GUARD at the edge; use interface BPDU filter almost never.
```

### D) 👑 Root Guard — locking down who can be root

```
 You set your core as root (2.17). A downstream/partner switch with a lower priority could
 send a SUPERIOR BPDU and STEAL the root role → traffic reroutes through it (or black-holes).

 Root Guard on the designated port facing that switch:
   superior BPDU received → port → ROOT-INCONSISTENT (blocked) → traffic on that port stops
   superior BPDUs stop     → port → auto-recovers to forwarding

 Note: Root Guard does NOT shut the port (unlike BPDU Guard) — it blocks only while the threat
 is present. Put it on designated ports toward switches that must NEVER become root.
```

### E) 🔁 Loop Guard — the unidirectional-link loop preventer

```
 SW-A(root) ── SW-B ── SW-C, with SW-C's port to SW-B BLOCKED (alternate).
 A unidirectional failure: SW-C can SEND to SW-B but no longer RECEIVES SW-B's BPDUs.

  WITHOUT loop guard: SW-C's blocked port stops hearing BPDUs → after max age it thinks the
     path is clear → transitions to FORWARDING → LOOP forms. 💥
  WITH loop guard: the port that stops hearing BPDUs goes LOOP-INCONSISTENT (stays blocked)
     → no loop. When BPDUs return, it auto-recovers.

 Apply on ROOT and ALTERNATE (non-designated) ports on switch↔switch P2P links. NOT on PortFast.
 (UDLD does the same job with its own keepalive protocol — great on fiber; often used together.)
```

### F) 🛠️ Putting it together — a hardened design

```
!── ACCESS ports (to hosts): speed + safety ──────────────────────
Switch(config)# spanning-tree portfast default             ! all access ports = edge
Switch(config)# spanning-tree portfast bpduguard default    ! err-disable on rogue BPDU
! (or per-interface:)
Switch(config-if)#  spanning-tree portfast
Switch(config-if)#  spanning-tree bpduguard enable

!── TRUNK toward a switch that must NOT become root ───────────────
Switch(config-if)#  spanning-tree guard root

!── ROOT/ALTERNATE ports on switch↔switch links: loop safety ──────
Switch(config)# spanning-tree loopguard default             ! network-wide (recommended)
! (or per-interface:)
Switch(config-if)#  spanning-tree guard loop

!── Auto-recover err-disabled BPDU-Guard ports ───────────────────
Switch(config)# errdisable recovery cause bpduguard
Switch(config)# errdisable recovery interval 300

!── Verify ───────────────────────────────────────────────────────
Switch# show spanning-tree summary                 ! which features are default-on
Switch# show spanning-tree inconsistentports        ! root-/loop-inconsistent ports
Switch# show spanning-tree interface Gi0/1 detail   ! portfast/guard status per port
Switch# show errdisable recovery                     ! recovery causes + timer
```

> 🕵️ **Dirty secret — the two loop-prevention tools defend *opposite* failures, and mixing them up leaves a hole.** **BPDU Guard** defends against **extra** BPDUs (a rogue device *sending* them) → it **shuts the port**. **Loop Guard** defends against **missing** BPDUs (a link that *stops delivering* them) → it **blocks the port**. Put BPDU Guard on a switch↔switch link and a normal neighbor BPDU err-disables your uplink. Put Loop Guard on a host port and it fights the edge logic. **Edge ports get PortFast + BPDU Guard; switch links get Loop Guard (and Root Guard where trust ends).** Match the tool to the port role or you either break good links or leave loops open.

## 8️⃣ Variants — Common → Specific 🌿

**Edge features:**
- 🟢 **PortFast** (interface / `default` global) — edge speed.
- 🟢 **BPDU Guard** (interface / `portfast bpduguard default` global) — edge enforcement.
- 🟢 **BPDU Filter** — **global** (safe-ish, PortFast) vs **interface** (dangerous).

**Topology-protection features:**
- 🟢 **Root Guard** (interface only) — enforce root placement (**root-inconsistent**).
- 🟢 **Loop Guard** (interface / `loopguard default` global) — unidirectional-link loops (**loop-inconsistent**).
- 🔵 **UDLD** (normal / aggressive) — dedicated unidirectional-link detection.

**Reaction types (know the trio):**
- 🟢 **err-disable** (BPDU Guard) · **root-inconsistent** (Root Guard) · **loop-inconsistent** (Loop Guard).

**Recovery:**
- 🟢 **Manual** (`shut`/`no shut`) · **auto** (`errdisable recovery`) · **auto on condition clearing** (Root/Loop Guard).

## 🔟 Best Practices ✅

- 🟢 **Every access (host) port: PortFast + BPDU Guard.** Speed *and* protection — the standard edge template. Use the `default` globals to apply everywhere.
- 🟢 **Never PortFast a switch↔switch link.** That's an instant-loop generator. Edge = end devices only.
- 🟢 **Root Guard toward switches that must not become root** — the access layer and any network you don't control (partners/customers). Enforce your chosen root (from 2.17).
- 🟢 **Loop Guard on switch↔switch root/alternate ports** (global `loopguard default` is the clean way) — and **not** on PortFast ports.
- 🔵 **Add UDLD on fiber** for fast unidirectional-link detection alongside Loop Guard.
- 🟢 **Prefer BPDU *Guard* over interface BPDU *Filter*** at the edge. Reserve interface BPDU Filter for rare, well-understood cases — it disables STP on the port.
- 🔵 **Configure `errdisable recovery cause bpduguard`** (with a sane interval) so a transient rogue-BPDU event self-heals — but investigate *why* it fired.
- 🟢 **Verify** with `show spanning-tree summary`, `show spanning-tree inconsistentports`, and `show spanning-tree interface … detail`.

## 1️⃣1️⃣ No-Goes — Common Mistakes & Troubleshooting Traps 🚫

- ❌ **PortFast on a switch/trunk link.** Skips the safety window on both sides → instant loop. Host ports only.
- ❌ **Interface BPDU Filter on a switch link.** Disables STP on that port → undetected loop. This is a top real-world cause of "we had filter on and *still* looped."
- ⚠️ **Confusing the reactions.** BPDU Guard → **err-disable** (shut); Root Guard → **root-inconsistent** (block, auto-recover); Loop Guard → **loop-inconsistent** (block, auto-recover). Only BPDU Guard shuts the port.
- ⚠️ **BPDU Guard on a switch↔switch port.** A normal neighbor BPDU will err-disable your uplink. Guard belongs on **edge** ports.
- ⚠️ **Loop Guard on PortFast ports.** Conflicts with edge/root-port logic — don't. Loop Guard is for switch links.
- ⚠️ **Enabling Root Guard *and* Loop Guard on the same port.** Not allowed — they're mutually exclusive per port.
- ⚠️ **Root Guard on UplinkFast backup interfaces.** They'd be forced root-inconsistent and never forward — breaks UplinkFast.
- 🔵 **Forgetting the global BPDU Filter's revert behavior.** Global filter *re-engages STP* on BPDU receipt (safe); people assume it behaves like the interface form and mis-deploy. Know which form you're using.
- ⚠️ **BPDU-Guard err-disabled port stuck down.** Expected — recover manually or via `errdisable recovery`, but first find the **rogue device** that sent the BPDU.

## 1️⃣3️⃣ Practical Tasks 🛠️

> Listed briefly; expanded step-by-step later in context.

1. 🟢 **PortFast timing (Packet Tracer 8 / GNS3).** Compare a normal access port (watch listening/learning delay) vs one with `spanning-tree portfast` (instant forwarding). Verify with `show spanning-tree interface … portfast`.
2. 🟢 **Trigger BPDU Guard.** Enable PortFast + BPDU Guard on an access port; plug a switch into it; watch the port **err-disable** (`show interfaces status err-disabled`, `%SPANTREE-2-BLOCK_BPDUGUARD`). Recover with `shut`/`no shut`, then set up `errdisable recovery cause bpduguard`.
3. 🔵 **BPDU Filter global vs interface.** Apply the **global** form and confirm a received BPDU reverts the port to normal STP; then (in a lab only) apply the **interface** form to a switch link and observe STP go silent there — understand the loop risk. Remove it.
4. 🟢 **Root Guard.** On a designated port toward a lower-priority "rogue" switch, enable `spanning-tree guard root`; make the rogue send a superior BPDU; confirm the port goes **root-inconsistent** (`show spanning-tree inconsistentports`) and auto-recovers when the superior BPDUs stop.
5. 🔵 **Loop Guard (unidirectional sim).** On a switch↔switch alternate port, enable `spanning-tree guard loop`; simulate BPDU loss; confirm the port goes **loop-inconsistent** instead of forwarding; restore BPDUs and watch auto-recovery.
6. 🟢 **Hardened-edge template.** Apply the globals (`portfast default`, `portfast bpduguard default`, `loopguard default`) + Root Guard on the right trunks; verify the whole posture with `show spanning-tree summary`.
7. 🔵 **UDLD on fiber (if available).** Enable UDLD; simulate a one-way failure; observe UDLD err-disable the port faster than STP would loop.
