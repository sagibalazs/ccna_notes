## 2️⃣ Visualization — The Whole Picture at a Glance

**The core problem & the five-tool pipeline:**

```
   Congested link (more traffic than bandwidth) — SOMETHING has to give.
   Without QoS: FIFO — voice, backups, email all share one queue → voice breaks up. 🎙️💥

   WITH QoS, at each hop:
   ┌────────────┐   ┌──────────┐   ┌───────────────────┐   ┌─────────────────────┐
   │ CLASSIFY   │──▶│  MARK    │──▶│  QUEUE (manage) +   │──▶│  POLICE / SHAPE     │
   │ "what is   │   │ set DSCP │   │  AVOID (WRED)       │   │  enforce a rate     │
   │  this?"    │   │ /CoS     │   │  who goes first?    │   │  (drop vs buffer)   │
   └────────────┘   └──────────┘   └───────────────────┘   └─────────────────────┘
      ACL/NBAR       trust at edge     LLQ voice ahead of      police=drop excess
                                       everything else         shape=delay excess
```

**PHB — Per-Hop Behavior: each router independently reads the mark and treats the packet:**

```
   packet marked DSCP EF (46) ──▶ Router A: put in priority queue ─▶ Router B: priority queue ─▶ …
   (the mark is END-TO-END; each hop makes its OWN decision based on it — no reservation, no state)
```

**The four PHBs & their DSCP values (memorise these):**

| PHB | DSCP | Binary | Use | RFC |
|---|---|---|---|---|
| 🟢 **EF** (Expedited Fwd) | **46** | 101110 | **Voice** — low latency/jitter/loss | 3246 |
| 🟢 **AF** (Assured Fwd) | AF11=10 … AF43=38 | see formula | video/data w/ guarantees + drop tiers | 2597 |
| 🟢 **CS** (Class Selector) | CS0=0 … CS7=56 (×8) | xxx000 | IP-Precedence back-compat; signalling CS3 | 2474 |
| 🟢 **Default / BE** | **0** | 000000 | best-effort | 2474 |

**The DS field — where the mark lives (IPv4 ToS byte / IPv6 Traffic Class):**

```
   0   1   2   3   4   5   6   7        (the old ToS byte, RFC 791 → redefined by RFC 2474)
 ┌───┬───┬───┬───┬───┬───┬───┬───┐
 │        DSCP (6 bits)      │  ECN  │   DSCP 0–63   ·   ECN = congestion notify (RFC 3168)
 └───────────────────────────┴───────┘
   └── first 3 bits = class ──┘ next 3 = drop-precedence (AF)     ToS byte = DSCP × 4  (EF 46→184/0xB8)
```

**AF naming — `AFxy` → DSCP = 8x + 2y** (x = class 1–4, y = drop precedence 1–3, higher y drops first):

```
        drop→  y=1(low)  y=2(med)  y=3(high)
   class x=1 │   AF11=10   AF12=12   AF13=14
   class x=2 │   AF21=18   AF22=20   AF23=22
   class x=3 │   AF31=26   AF32=28   AF33=30
   class x=4 │   AF41=34   AF42=36   AF43=38     (higher class = better queue; higher y = dropped sooner)
```

**Policing vs Shaping — the classic distinction:**

```
   POLICING (cop with a ticket)              SHAPING (funnel with a buffer)
   ─────────────────────────────            ──────────────────────────────
   excess → DROP or RE-MARK                  excess → BUFFER & delay (smooth)
   no delay added, output BURSTY             adds delay/jitter, output SMOOTH
   in OR out                                 OUT only
   TCP sees drops → retransmits              TCP flows nicely, fewer drops
   use: enforce a hard cap                   use: match a slower provider/CIR rate
```

## 3️⃣ TL;DR

**QoS decides which traffic wins when a link is congested** — because on a full link, *something* must be delayed or dropped, and you'd rather it be a file backup than a phone call. It works as a **per-hop** pipeline: **classify** (identify the traffic), **mark** it (set **DSCP** at L3 / **CoS** at L2 so every downstream hop trusts the decision), **queue** it (multiple queues + a scheduler; **LLQ** puts voice ahead of everything), **avoid congestion** (**WRED** drops early to prevent TCP meltdown), and **condition** the rate with **policing** (drop/re-mark excess, bursty) or **shaping** (buffer/smooth excess, adds delay). Marks map to standard **PHBs**: **EF (DSCP 46)** for voice, **AF** (four classes × three drop tiers, `AFxy`=8x+2y), **CS** for back-compat, **default (0)** best-effort. The model is **DiffServ** (edge marks, core just honours the mark) — scalable, stateless, end-to-end. Voice targets: **< 150 ms latency, < 30 ms jitter, < 1 % loss**.

## 4️⃣ Importance — The Problem First 🎯

**The problem — a link has finite bandwidth, and not all traffic is equal.** When more traffic arrives than a link can send, packets **queue**; if the queue fills, they're **dropped**. By default (**FIFO**, first-in-first-out) every packet is treated identically:

- 🎙️ **Real-time traffic can't tolerate delay.** A voice call needs each packet within ~20 ms of the last. If a **500 MB file transfer** fills the queue ahead of the voice packets, the call gets **choppy, laggy, or drops** — even though the *link isn't broken*, it's just **contended**.
- ⏳ **Delay, jitter, and loss hurt different apps differently.** A file download doesn't care if a packet arrives 200 ms late (TCP just retransmits). A voice/video stream **can't** wait — a late packet is a **useless** packet. Treating them the same guarantees the sensitive one suffers.
- 📈 **You can't just "add bandwidth."** Bursts always exist; WAN links are expensive and finite; and even a fat link congests during a spike. During those moments of contention — which is *exactly* when it matters — you need a **policy** for who wins.
- 🌐 **Per-flow reservations don't scale.** You could try to *reserve* bandwidth for every important flow (that's **IntServ/RSVP**) — but tracking state for millions of flows across the core is impossible.

**The solution — QoS, specifically the DiffServ model (RFC 2474/2475):** instead of reserving per-flow, you **classify traffic into a few classes, mark each packet's class into its header (DSCP)**, and let **every hop independently** give that class the right treatment (**Per-Hop Behavior**). The **edge** does the expensive work (classify + mark + police); the **core** just reads the mark and forwards accordingly. Voice gets a **priority queue** (**EF**), business apps get **assured bandwidth** (**AF**), bulk traffic gets **best-effort** — all without per-flow state. That's how a network guarantees a clean phone call over a congested link.

**Why the tools exist, in order:**
- **Classify** first — you can't treat traffic specially until you can *identify* it.
- **Mark** so you classify **once** at the edge and every downstream hop **trusts the label** instead of re-inspecting.
- **Queue** because that's *where the actual prioritisation happens* — the scheduler decides who transmits next.
- **Police/shape** to enforce rates — either a hard cap (police) or a smooth rate (shape) matching a provider contract.

**Why an engineer cares:**
- **VoIP quality tickets** ("calls break up when someone runs backups") are pure QoS. You'll design the policy that fixes them.
- **Policing vs shaping** is a real decision (and a favourite exam trap): match a provider's **CIR** with shaping, enforce a customer cap with policing.
- **Trust boundaries** are a security/quality issue — trust a phone's marking, *don't* trust a random PC that marks all its traffic EF to jump the queue.

## 5️⃣ Description 📋

- **QoS** = a set of mechanisms that give different traffic classes different **forwarding treatment** under congestion — managing **bandwidth, delay, jitter, and loss**.
- **PHB (Per-Hop Behavior)** = the treatment a **single node** gives a class based on its marking. QoS is a **chain of independent per-hop decisions**, not an end-to-end reservation.
- **The five tools (blueprint):**
  - **Classification** — identify traffic (ACL, **NBAR**, incoming DSCP/CoS, interface).
  - **Marking** — write the class into the header: **DSCP** (L3, 6 bits, end-to-end) or **CoS** (L2, 3 bits, per-link) — so downstream hops trust it.
  - **Queuing (congestion management)** — multiple queues + a **scheduler**; decides transmit order. **LLQ** gives voice a strict-priority queue.
  - **Congestion avoidance** — **WRED** drops packets *early/selectively* before the queue is full, preventing TCP global synchronisation.
  - **Policing & shaping (traffic conditioning)** — enforce a rate: **policing drops/re-marks** excess (no delay, bursty); **shaping buffers** excess (smooth, adds delay).
- **DiffServ** (the deployed model): edge classifies/marks/polices; core does simple PHB by DSCP → **scalable & stateless**.
- **IntServ** (legacy alt): **RSVP** per-flow reservations → guaranteed but **doesn't scale**.
- **Standard PHBs:** **EF (46)** voice, **AF** (4 classes × 3 drop tiers), **CS** (back-compat), **Default (0)** best-effort.
- **Trust boundary** — the point where markings are believed; set it at the edge (phones), not on untrusted hosts.
- **Voice SLA targets:** one-way **latency < 150 ms**, **jitter < 30 ms**, **loss < 1 %**.

## 6️⃣ How It Works — Under the Hood ⚙️

### 6.1 The marking fields — DSCP vs CoS vs IP Precedence 🔬🟢

**Layer 3 — DSCP (the modern standard):** the IPv4 **ToS byte** (RFC 791) was redefined by **RFC 2474** into the **DS field**: the **upper 6 bits = DSCP** (64 values), the **lower 2 bits = ECN**. IPv6 uses the equivalent **Traffic Class** byte. DSCP is **end-to-end** — it rides in the IP header and **survives every routing hop**.

```
   ToS byte = DSCP × 4   →   EF (DSCP 46) = 184 decimal = 0xB8
   (first 3 DSCP bits = "class", so CS/IP-Precedence stay backward compatible)
```

**Layer 2 — CoS (802.1p):** 3 bits (PCP) inside the **802.1Q** VLAN tag (values 0–7). **CoS is per-link only** — it's **lost the moment the 802.1Q tag is stripped** (e.g. leaving a trunk, crossing a router). That's *why* you re-mark to **DSCP** at the L3 edge: to carry the decision end-to-end.

**IP Precedence:** the legacy 3-bit L3 marking (0–7); the first 3 bits of DSCP = the old IP Precedence, which is how **CS** values stay compatible.

🧠 **Key mental model:** **CoS = local (per hop/link), DSCP = global (end-to-end).** Trust and translate CoS→DSCP at the edge switch, then let DSCP carry the class across the whole path.

### 6.2 The four PHBs, decoded 🔬🟢

- **Default / Best-Effort (DSCP 0)** — no special treatment; the FIFO default.
- **CS (Class Selector, CS0–CS7 = 0,8,16,24,32,40,48,56)** — multiples of 8; **backward compatible with IP Precedence** (only the first 3 bits set). Signalling often marked **CS3 (24)**; network control **CS6 (48)**.
- **AF (Assured Forwarding, RFC 2597)** — **4 classes × 3 drop precedences**. Naming **`AFxy`**: **x** = class (1–4, higher = better queue), **y** = drop precedence (1–3, **higher = dropped first**). Formula: **DSCP = 8x + 2y**.
  ```
  AF11=10  AF12=12  AF13=14     ← class 1
  AF21=18  AF22=20  AF23=22     ← class 2
  AF31=26  AF32=28  AF33=30     ← class 3
  AF41=34  AF42=36  AF43=38     ← class 4
  ```
  Within a class, when the queue fills, **AFx3** packets are dropped **before** AFx2 before AFx1 — that's the "drop precedence."
- **EF (Expedited Forwarding, RFC 3246, DSCP 46 = 101110)** — **low loss, low latency, low jitter, assured bandwidth**. For **voice**. Implemented as a **strict-priority (LLQ) queue**, but **policed** so it can't starve everything else.

### 6.3 The pipeline, per hop 🟢

**① Classification — "what is this packet?"**
Match on an ACL, **NBAR** (deep app recognition), an incoming DSCP/CoS, or the ingress interface. Groups traffic into a **class** (a "Behavior Aggregate").

**② Marking — "tag it once, trust it after."**
Set DSCP/CoS so downstream nodes don't re-inspect. Do it **at the edge**, inside the **trust boundary**. Example: an IP phone marks its RTP **EF/CoS 5**; the access switch **trusts** that and it becomes DSCP EF end-to-end.

**③ Queuing (congestion management) — "who transmits next?"**
This is **where prioritisation actually happens.** Traffic goes into multiple queues; a **scheduler** picks the order:
- **FIFO** — one queue, no priority (the problem).
- **WFQ** — fair share by flow.
- **CBWFQ** — guarantees **bandwidth per class**.
- **LLQ** — CBWFQ **+ a strict-priority queue** serviced first → **voice (EF)** always jumps ahead. LLQ is *the* voice mechanism; it's policed so the priority queue can't starve the rest.

**④ Congestion avoidance — "drop early, drop smart."**
A tail-drop queue that fills drops *everything* at once → many TCP flows back off together, then ramp up together (**global synchronisation**), causing throughput oscillation. **WRED** drops packets **probabilistically before** the queue is full, and drops **higher-drop-precedence (AFx3) first** — smoothing TCP behaviour.

**⑤ Policing / shaping — "enforce the rate."** (§6.4)

### 6.4 Policing vs Shaping — the core distinction 🔬🟢

Both **limit a traffic rate**, but handle **excess** oppositely:

| | **Policing** 👮 | **Shaping** 🌊 |
|---|---|---|
| Excess traffic | **Dropped or re-marked** | **Buffered & delayed** |
| Delay added | **None** | **Yes** (queues excess) |
| Output shape | **Bursty** (hard chops) | **Smooth** (paced to rate) |
| Direction | **inbound or outbound** | **outbound only** |
| TCP effect | sees drops → **retransmits** | flows smoothly → **fewer drops** |
| Buffer needed | no | **yes** |
| Typical use | enforce a **hard cap** / SLA ceiling; re-mark out-of-contract | **match a provider CIR** / slower downstream to avoid *their* drops |

🕵️ **The classic real-world use:** you have a 100 Mbps physical port into a provider who only guarantees **20 Mbps (CIR)**. If you send bursts at 100, the **provider polices and drops** your excess (you can't control *their* drops). So **you shape outbound to 20** — buffering your own bursts smoothly — so nothing hits the provider's policer. **Shape to match a rate you don't control; police to enforce a rate you do.**

### 6.5 DiffServ vs IntServ 🔵

- **IntServ (Integrated Services)** — **RSVP** signals a **per-flow reservation** end-to-end; every router holds state for every flow. **Guaranteed**, but **doesn't scale** (millions of flows in the core).
- **DiffServ (Differentiated Services)** — no per-flow state. Traffic is **classified into a few classes, marked (DSCP)**, and each hop applies a **PHB** by class. **Edge = complex (classify/mark/police); core = simple (honour DSCP).** This edge/core split is *why DiffServ scales* and is what virtually all enterprise QoS uses.

### 6.6 Cisco MQC — the config framework 🟢🔵

Cisco QoS uses the **Modular QoS CLI (MQC)**: three steps.

```
! ① class-map — CLASSIFY
class-map match-all VOICE
 match dscp ef
class-map match-all BUSINESS
 match dscp af31

! ② policy-map — the PER-HOP ACTIONS (mark / queue / police / shape)
policy-map WAN-OUT
 class VOICE
  priority percent 10           ! LLQ: strict-priority queue for voice, capped at 10%
 class BUSINESS
  bandwidth percent 30          ! CBWFQ: guaranteed 30% for business apps
 class class-default
  fair-queue
  random-detect                 ! WRED on best-effort

! ③ service-policy — APPLY to the interface (direction)
interface g0/1
 service-policy output WAN-OUT
```

**Shaping example** (match a 20 Mbps CIR):
```
policy-map SHAPE-20M
 class class-default
  shape average 20000000
```
**Verify:** `show policy-map interface g0/1` (per-class packets, drops, queue depth), `show mls qos` / `show class-map` / `show policy-map`.

## 7️⃣ Pros & Cons ⚖️

| ✅ Pros | ❌ Cons / Costs |
|---|---|
| **Protects real-time traffic** (voice/video) under congestion | **Complex** to design end-to-end (classes, marks, per-hop policy) |
| **DiffServ scales** — stateless core, mark-once edge | **Only helps during congestion** — no free bandwidth |
| **End-to-end DSCP** survives routing hops | **Every hop must honour the mark** — one un-QoS'd hop breaks it |
| **LLQ** gives voice deterministic low latency | **Mismarking / untrusted marks** can be abused to jump the queue |
| **Shaping** avoids provider drops; **policing** enforces SLAs | **Misconfig starves** traffic (priority queue too big, wrong class) |
| Flexible tools (queue/police/shape/WRED) | **CoS lost** off-trunk → must re-mark to DSCP |

## 8️⃣ Variants — Common → Specific 🧬

**QoS models:** 🟢 Best-effort (none) · 🟢 **DiffServ** (marked classes, PHB — the standard) · 🔵 **IntServ/RSVP** (per-flow reservation).

**Marking:** 🟢 **DSCP** (L3, end-to-end) · 🟢 **CoS/802.1p** (L2, per-link) · 🔵 IP Precedence (legacy) · 🔵 **MPLS EXP/TC** (in provider cores).

**PHBs:** 🟢 **EF (46)** · 🟢 **AF11–AF43** · 🟢 **CS0–CS7** · 🟢 **Default (0)** · 🔵 **LE (Lower Effort, RFC 8622)** for scavenger/bulk.

**Queuing:** 🟢 FIFO · 🔵 WFQ · 🔵 **CBWFQ** · 🟢 **LLQ** (voice priority) · 🔵 PQ/CQ (legacy).

**Congestion avoidance:** 🔵 tail-drop (default) · 🔵 **WRED** · 🔵 ECN (marks instead of drops, RFC 3168).

**Conditioning:** 🟢 **Policing** (single/dual-rate, in/out) · 🟢 **Shaping** (average/peak, out).

**Trust:** 🔵 trust boundary at access edge; conditional trust for IP phones (mark voice, re-mark PC traffic).

## 🔟 Best Practices ✅

- 🎙️ **Mark voice EF and give it LLQ** (strict-priority), but **cap the priority queue** (~10 %) so it can't starve everything else.
- 🏷️ **Classify & mark once, at the edge**, inside a **trust boundary**; the core should just honour DSCP.
- 🔄 **Re-mark CoS → DSCP** at the L3 edge so the class survives beyond the trunk.
- 🧮 **Use AF classes with WRED** for TCP data — guaranteed bandwidth per class, graceful drop under load.
- 🌊 **Shape outbound to the provider CIR** so *your* buffer smooths bursts instead of *their* policer dropping them.
- 👮 **Police to enforce ceilings** (e.g. cap scavenger/bulk, re-mark out-of-contract) where drops are acceptable.
- 🚫 **Don't trust host markings** — a PC marking everything EF must be re-marked, or it hijacks the priority queue.
- 📐 **Follow a consistent class model** (e.g. Cisco/RFC 4594 4-, 8-, or 12-class) end-to-end; QoS is only as good as the *weakest* hop.
- 📊 **Verify with `show policy-map interface`** — watch per-class drops; rising priority-queue drops = voice is starving.

## 1️⃣1️⃣ No-Goes — Mistakes & Troubleshooting Traps 🚫

**Design / config mistakes**
- ❌ **QoS on one hop only** → the class is honoured there and ignored everywhere else; a single un-QoS'd/oversubscribed hop **breaks the whole chain**.
- ❌ **Priority (LLQ) queue too large / no policer** → voice starves data, *or* too much "EF" oversubscribes the priority queue and voice **still** breaks.
- ❌ **Trusting untrusted host markings** → users mark bulk traffic EF and jump the queue.
- ❌ **Relying on CoS end-to-end** → CoS dies when the 802.1Q tag is stripped; must re-mark to DSCP.
- ❌ **Policing where you should shape** (toward a provider CIR) → you drop your own bursts instead of smoothing them; TCP suffers.
- ❌ **Shaping inbound** → not possible; shaping is **outbound only**.
- ❌ **Marking but never queuing** → marks with no scheduling action change nothing under congestion.

**Diagnostic signatures**
- 🔍 **Voice fine when idle, breaks during backups/large transfers** → textbook **missing/insufficient QoS** on the congested link.
- 🔍 **`show policy-map interface` shows priority-queue drops** → too much EF or priority cap too low → voice loss.
- 🔍 **Class marked correctly but not prioritised downstream** → a hop that doesn't honour DSCP (trust/config gap) — check every hop.
- 🔍 **Provider dropping your traffic despite "having bandwidth"** → you're bursting past **CIR**; **shape** to their rate.
- 🔍 **TCP throughput oscillates/saw-tooths** → tail-drop global synchronisation → apply **WRED**.
- 🔍 **High jitter on voice** → shaping/queuing delay variation, or voice not in the priority queue.

**Conceptual traps**
- ❌ Thinking **QoS creates bandwidth** — it only **allocates** existing bandwidth **during congestion**; a saturated link with no priority traffic gains nothing.
- ❌ Believing **higher DSCP number = always better** — AF drop precedence is *inverse* (**AFx3 dropped first**); it's the **class** that ranks queues.
- ❌ Confusing **policing (drop, bursty, in/out)** with **shaping (buffer, smooth, out-only)** — the #1 exam trap.
- ❌ Treating **PHB as an end-to-end guarantee** — it's a **per-hop** decision; consistency across hops is *your* job (DiffServ), unlike IntServ's reservation.

## 1️⃣3️⃣ Practical Tasks 🧪

*(listed briefly here — expanded with full walkthroughs later in context)*

1. **🧮 DSCP fluency drill:** by hand, convert AF11/AF21/AF31/AF41 and AF13/AF43 to DSCP (8x+2y); convert EF and the CS values; convert DSCP 46 to the ToS byte (×4 = 184/0xB8). Verify in a Wireshark capture's DS field.
2. **🧩 Packet Tracer 8 / lab — voice priority (MQC):**
   - Build `class-map` for EF voice and AF31 business; a `policy-map` with `priority percent 10` (LLQ) + `bandwidth percent 30` (CBWFQ) + `class-default fair-queue random-detect`; apply `service-policy output` on the WAN link.
   - Generate voice + a bulk transfer; confirm voice stays clean; read `show policy-map interface`.
3. **🌊 Policing vs shaping:**
   - On a link, `police` to a rate and observe **drops** and bursty output; then `shape average` to the same rate and observe **buffering/smoothing** and added delay. Diff the two behaviours.
4. **🦈 Wireshark:** capture RTP voice, inspect the **DS field = EF (0xB8)**; capture 802.1Q frames and read the **CoS/PCP** bits; watch CoS disappear once the tag is stripped at an L3 boundary.
5. **👮 Trust boundary:** mark a PC's traffic EF (simulate abuse); show it jumping the queue; then set the access switch to **re-mark** untrusted host traffic and confirm the abuse is neutralised.
6. **🔬 Stretch (engineer):** deploy a full **RFC 4594-style class model** across two routers, trigger congestion, and measure **latency/jitter/loss** on the voice class with and without QoS (an IP SLA probe) — prove the < 150 ms / < 30 ms / < 1 % targets are met only *with* the policy.
