## 2️⃣ Visualization — Big Picture at a Glance

**The five modes and what DTP does with each:**

```
  MODE                     DTP behavior
  ─────────────────────    ────────────────────────────────────────────────
  access                   permanent ACCESS; won't form a trunk
  trunk                    permanent TRUNK; ⚠ STILL sends DTP (add nonegotiate!)
  dynamic auto             PASSIVE — trunks only if the OTHER side asks   ◀ default (modern Catalyst)
  dynamic desirable        ACTIVE  — actively TRIES to form a trunk
  (+ switchport nonegotiate)  turns DTP frames OFF entirely (mode access/trunk only)
```

**The negotiation matrix — what forms when two sides meet (✅ = trunk):**

```
                     │  trunk    desirable   auto      access
  ───────────────────┼──────────────────────────────────────────
  trunk              │  ✅ trunk  ✅ trunk   ✅ trunk   ⚠ mismatch
  dynamic desirable  │  ✅ trunk  ✅ trunk   ✅ trunk   access
  dynamic auto       │  ✅ trunk  ✅ trunk   ❌ access  access     ◀ auto+auto = ACCESS
  access             │ ⚠ mismatch  access    access    access
```

**Two rules to memorize:**

| Rule | Why it matters |
|---|---|
| 🟢 **auto + auto = access** | two passive ports → neither initiates → no trunk |
| 🟢 **desirable/trunk initiates** → trunk with auto/desirable/trunk | one active side is enough to trunk |
| ⚠️ **`mode trunk` does NOT disable DTP** | add **`switchport nonegotiate`** to actually turn DTP off |

## 3️⃣ TL;DR

- 🟢 **DTP is Cisco's proprietary protocol that auto-negotiates a link into an access port or a trunk** — so you *don't* have to configure both ends. It runs **point-to-point** between directly connected switches.
- 🟢 **Five settings:** `access`, `trunk`, `dynamic auto`, `dynamic desirable`, plus `switchport nonegotiate` (turns DTP off).
- 🟢 **Matrix essentials:** **auto+auto = access** (neither initiates); **desirable or trunk on one side → trunk** (with auto/desirable/trunk); **access + trunk = mismatch** (broken).
- 🟢 **Default on modern Catalyst = `dynamic auto`** — DTP is **on** but passive. Two defaults connected stay **access**, yet the port is still *willing* to trunk if asked — that's the exposure.
- ⚠️ **`switchport mode trunk` does NOT disable DTP** — the port keeps sending DTP frames. You must add **`switchport nonegotiate`**.
- 🔓 **Switch-spoofing VLAN hopping:** an attacker speaks DTP as `dynamic desirable`, negotiates a **trunk** with a default (`dynamic auto`) port, and gains access to **all VLANs**. (The *other* hop, double-tagging, was 2.9.)
- 🛡️ **Best practice: hardcode everything + `nonegotiate`.** Access ports: `switchport mode access` + `switchport nonegotiate`. Trunks: `switchport mode trunk` + `switchport nonegotiate`. Never leave ports in a dynamic mode.
- 🔵 DTP frames go to `01:00:0c:cc:cc:cc` every **30 s** on **VLAN 1**; DTP only works Cisco-to-Cisco.

## 4️⃣ Importance — The Problem First 🎯

**The underlying problem:** In 2.8 you configured a trunk with `switchport mode trunk` on **both** ends. Cisco wanted to save that effort: *"What if a switch could figure out on its own whether a link should be a trunk?"* — plug two switches together and let them **negotiate**. That convenience is **DTP**.

But convenience at Layer 2 is dangerous. DTP answers a real question — *"Should this link trunk?"* — by **trusting whatever the neighbor claims**. And "trusting the neighbor" on an access port that faces users is exactly how attacks happen.

- ❓ *"How do trunks form when I didn't hardcode both ends?"* → DTP negotiated it based on the two modes.
- ❓ *"Why did a port I thought was access suddenly carry many VLANs?"* → it was in a **dynamic** mode and DTP formed a trunk with a compatible neighbor.
- ❓ *"How can an attacker reach VLANs they shouldn't?"* → **switch-spoofing** — pretend to be a switch, speak DTP, and negotiate a trunk out of a default `dynamic auto` port.

**Why an engineer must own this cold:**

- 🔧 **DTP explains the "admin ≠ operational" mystery from 2.8.** A port's *operational* mode is whatever DTP negotiated — which may not be what you intended. Reading DTP state is core trunk troubleshooting.
- 🔧 **It's a named security exposure.** Switch-spoofing is one of the two CCNA VLAN-hopping attacks; "why disable DTP?" is a guaranteed exam/interview question.
- 🔧 **Defaults bite.** Modern Catalyst ships `dynamic auto` — DTP **on**. Doing nothing leaves every port *willing* to be trunked by a suitably-configured (or malicious) neighbor. Security is opt-*out* here, not opt-in.
- 🔧 **DTP is Cisco-only.** Any link to a non-Cisco switch **must** be hardcoded — so you need to know how to turn negotiation off regardless.

## 5️⃣ Description 📋

- 🟢 **What DTP is:** a **Cisco-proprietary Layer-2 protocol** that **automatically negotiates** whether a directly-connected link becomes a **trunk** or stays an **access** port (and, on ISL-capable platforms, the encapsulation). It's **point-to-point** and Cisco-to-Cisco only.
- 🟢 **The five `switchport mode` settings:**
  - **`access`** — permanent **access** port; will **not** form a trunk. (Effectively stops trunk negotiation; for full DTP-off add `nonegotiate`.)
  - **`trunk`** — permanent **trunk**; ⚠️ **still sends DTP frames** — configuring trunk does **not** disable DTP.
  - **`dynamic auto`** — **passive**: forms a trunk **only if the neighbor initiates** (neighbor is `trunk` or `dynamic desirable`). Will not initiate itself.
  - **`dynamic desirable`** — **active**: **actively tries** to form a trunk; trunks with a neighbor in `auto`, `desirable`, or `trunk`.
  - **`switchport nonegotiate`** — **disables DTP frame transmission** entirely. Valid only with `mode access` or `mode trunk` (not with dynamic modes).
- 🟢 **The negotiation matrix (which combos trunk):**
  - **auto + auto → access** (both passive; nobody initiates).
  - **desirable + auto → trunk** · **desirable + desirable → trunk** · **desirable/auto + trunk → trunk**.
  - **trunk + trunk → trunk**.
  - **access + anything → access** on the access side (access never trunks).
  - ⚠️ **trunk + access → mismatch** (one side trunks, one doesn't → broken link, not a working trunk).
- 🟢 **Default mode:** on modern Cisco Catalyst (2960/3650-class), the default is **`dynamic auto`** — DTP **enabled**, passive. (Some older switches defaulted to `dynamic desirable`.)
- 🔵 **DTP frame mechanics:** sent to the Cisco reserved multicast **`01:00:0c:cc:cc:cc`** (EtherType `0x2004`), **every 30 seconds**, on **VLAN 1** — carrying the VTP **domain**, the port's **trunk status**, and duplex. Frames go out even before the port is fully active, which is why trunks form seconds after you connect a cable. Trunk formation also requires **matching VTP domains** (→ 2.12).
- 🔓 **Switch-spoofing (VLAN hopping):** an attacker connects a device that **emulates a switch and speaks DTP** as `dynamic desirable`. If the switch port is `dynamic auto`/`dynamic desirable` (the default!), DTP **negotiates a trunk** to the attacker → the attacker's link now carries **all (allowed) VLANs** → they can **see and inject** into any VLAN. This is the second VLAN-hopping method (double-tagging → 2.9).
- 🛡️ **Hardening:** **hardcode** modes and **disable DTP**. Access ports → `switchport mode access` + `switchport nonegotiate`. Trunks → `switchport mode trunk` + `switchport nonegotiate`. Never leave a user-facing port in a dynamic mode.

## 6️⃣ How It Works — Under the Hood ⚙️

### A) 🤝 The negotiation exchange

```
 Two directly-connected ports exchange DTP frames (every 30s, to 01:00:0c:cc:cc:cc, on VLAN 1),
 each advertising its own mode/desire:

   SW1 (dynamic desirable) ──"I want to TRUNK"──▶ SW2 (dynamic auto)
   SW2 (dynamic auto)      ──"I'll trunk if asked"──▶ SW1
        │
        ▼
   Result: TRUNK forms (an active desirable met a willing auto).

   But:  auto ──"I'll trunk if asked"──▶ auto ──"I'll trunk if asked"──▶
        neither ASKS → no trunk → both stay ACCESS.
```

### B) 🧮 Reading the matrix (the two questions)

```
 Q1: Is EITHER side actively pushing a trunk?  (trunk or dynamic desirable)
        NO  → the link stays ACCESS  (auto+auto, auto+access, access+access …)
        YES → go to Q2
 Q2: Will the OTHER side agree?  (trunk / desirable / auto all agree; access refuses)
        agrees  → TRUNK forms
        access  → MISMATCH (one trunk, one access → broken)

 So: you need at least one INITIATOR (trunk/desirable) AND a non-access partner.
```

### C) 🔓 Switch-spoofing attack — step by step

```
 Default port state: SW port = dynamic auto (DTP on, willing).

 1. Attacker's PC runs software (e.g. Yersinia) that EMULATES a switch and sends DTP
    "dynamic desirable" frames into the access port.
 2. The switch port (dynamic auto) hears an initiator → NEGOTIATES A TRUNK.
 3. The attacker's link is now a TRUNK → it receives frames for ALL allowed VLANs.
 4. The attacker can sniff every VLAN and inject traffic into any of them.  😈

  Root cause: a USER-FACING port left in a DTP-negotiating mode.
  Fix: switchport mode access + switchport nonegotiate  → no trunk can ever form here.
```

> 🕵️ **Dirty secret — `switchport mode trunk` leaves DTP wide open.** People assume "I set it to trunk, so it's locked." Wrong: a `mode trunk` port **keeps emitting DTP frames**. An attacker (or a misconfigured neighbor) can still negotiate, and the DTP frames themselves **leak switch info** onto the wire. **Trunking is not the same as *not negotiating*.** Only **`switchport nonegotiate`** (or `mode access`) actually silences DTP. Always pair `mode trunk` with `nonegotiate`.

### D) 🛠️ Configuration & hardening

```
!── ACCESS port (user-facing) — the secure default ────────────────
Switch(config)# interface Gi0/1
Switch(config-if)#  switchport mode access
Switch(config-if)#  switchport nonegotiate         ! no DTP — kills switch-spoofing here

!── TRUNK port (switch-to-switch) — hardcode + silence DTP ─────────
Switch(config)# interface Gi0/24
Switch(config-if)#  switchport trunk encapsulation dot1q   ! (ISL-capable gear)
Switch(config-if)#  switchport mode trunk
Switch(config-if)#  switchport nonegotiate         ! ⚠ REQUIRED — trunk mode alone keeps DTP on

! (Range-apply access hardening to all user ports)
Switch(config)# interface range Gi0/1 - 23
Switch(config-if-range)#  switchport mode access
Switch(config-if-range)#  switchport nonegotiate
```

### E) 🔍 Verification — what DTP actually did

```
Switch# show interfaces Gi0/24 switchport
  Administrative Mode: trunk               ← what YOU set
  Operational Mode: trunk                  ← what DTP/negotiation RESULTED in (read THIS)
  Negotiation of Trunking: Off             ← Off = nonegotiate worked (DTP silenced)

Switch# show dtp interface Gi0/24
  DTP information for GigabitEthernet0/24:
    Negotiation of Trunking:   Off          ← DTP disabled here
    Status:                    TRUNK

Switch# show interfaces trunk               ← confirm the trunk is up and carrying VLANs
```

> 🧠 **Admin vs operational (from 2.8) explained:** the **operational** mode is whatever negotiation produced. `dynamic auto` (admin) meeting a plain host (no DTP) → **operational = static access**. `dynamic desirable` meeting `trunk` → **operational = trunk**. Always trust the **operational** line + `Negotiation of Trunking`.

## 7️⃣ Pros & Cons ⚖️

| ✅ Pros of DTP | ❌ Cons / Risks |
|---|---|
| 🟢 **Convenience** — trunks form without configuring both ends. | 🔓 **Switch-spoofing** VLAN hopping if user ports negotiate. |
| 🟢 **Auto-recovers** trunk state on reconnection. | ⚠️ **Unpredictable** — a port becomes a trunk you didn't intend. |
| 🟢 Can auto-pick encapsulation on ISL-capable gear. | ⚠️ **`mode trunk` doesn't disable it** — false sense of safety. |
| | ⚠️ **Cisco-only** — useless (and must be off) to non-Cisco peers. |
| | ⚠️ **On by default** (`dynamic auto`) — insecure unless you act. |

> **Net:** DTP's convenience rarely outweighs its risk in production. The professional default is to **turn it off** and hardcode.

## 8️⃣ Variants — Common → Specific 🌿

**The modes (by DTP behavior):**
- 🟢 **`access`** — never trunks (secure user-port choice, pair with `nonegotiate`).
- 🟢 **`trunk`** — always trunks (pair with `nonegotiate`).
- 🟢 **`dynamic auto`** — passive negotiate (**default**; the exposure).
- 🟢 **`dynamic desirable`** — active negotiate.
- 🟢 **`nonegotiate`** — DTP off (with access/trunk).

**Negotiation outcomes:**
- 🟢 **Trunk** (initiator + willing partner).
- 🟢 **Access** (auto+auto, or any access side).
- ⚠️ **Mismatch** (trunk vs access) → broken.

**VLAN-hopping methods (context):**
- 🔓 **Switch-spoofing** — abuses **DTP** (this doc).
- 🔓 **Double-tagging** — abuses the **native VLAN** (→ 2.9).

## 🔟 Best Practices ✅

- 🟢 **Disable DTP in production.** Hardcode every link and add `switchport nonegotiate`.
- 🟢 **User/access ports:** `switchport mode access` + `switchport nonegotiate` — kills switch-spoofing at the edge.
- 🟢 **Trunk ports:** `switchport mode trunk` + `switchport nonegotiate` — remember trunk mode alone leaves DTP on.
- 🟢 **Never leave ports in `dynamic auto`/`dynamic desirable`**, especially anything user-facing.
- 🔵 **Links to non-Cisco gear:** hardcode both ends (DTP won't help; it only talks Cisco).
- 🟢 **Verify the *operational* mode** and `Negotiation of Trunking: Off` with `show interfaces switchport` / `show dtp interface` — don't trust admin intent alone.
- 🔵 **Pair with edge hardening** (BPDU guard, port security → Block 9) for defense in depth on access ports.

## 1️⃣1️⃣ No-Goes — Common Mistakes & Troubleshooting Traps 🚫

- ❌ **Assuming `switchport mode trunk` turns DTP off.** It doesn't — the port keeps negotiating and leaking DTP. Add `switchport nonegotiate`.
- ⚠️ **Leaving ports at the `dynamic auto` default.** Convenient, but every such port is *willing* to be trunked — the switch-spoofing doorway. Hardcode to access.
- ⚠️ **auto + auto and wondering why there's no trunk.** Two passive ports never initiate → the link stays **access**. Set one side to `trunk`/`desirable` (or better, hardcode both to `trunk` + `nonegotiate`).
- ⚠️ **trunk + access mismatch.** One end trunk, the other access → the link doesn't work as a trunk. Match both ends.
- 🔓 **Trusting DTP on user-facing ports.** That's the switch-spoofing exposure. Access + `nonegotiate` everywhere users plug in.
- 🔵 **Expecting DTP to work to a non-Cisco switch.** It won't — hardcode those trunks on both ends.
- ⚠️ **Trying `nonegotiate` in a dynamic mode.** It's only valid with `mode access` or `mode trunk` — set the mode first.
- ⚠️ **Reading only the admin mode.** The **operational** mode is what negotiation produced; that's the one that matters for troubleshooting.

## 1️⃣3️⃣ Practical Tasks 🛠️

> Listed briefly; expanded step-by-step later in context.

1. 🟢 **Prove auto+auto = access (Packet Tracer 8 / GNS3).** Two switches, both default (`dynamic auto`); confirm with `show interfaces trunk` (no trunk) and `show interfaces switchport` (Operational: static access). Then set one side `dynamic desirable` and watch a trunk form.
2. 🟢 **Walk the matrix.** Try `desirable+auto`, `desirable+desirable`, `trunk+auto`, `trunk+access`; predict then verify each outcome with `show dtp interface`.
3. 🟢 **Prove trunk mode keeps DTP on.** Set `switchport mode trunk` (no nonegotiate); check `show dtp interface` → `Negotiation of Trunking: On`. Add `switchport nonegotiate` → confirm it flips to `Off` while the trunk stays up.
4. 🔵 **Simulate switch-spoofing (isolated lab).** Set a switch port to `dynamic auto`; from a Kali host use Yersinia to send DTP desirable frames; observe the port become a trunk (`show interfaces trunk`). Then apply `mode access` + `nonegotiate` and confirm the attack fails.
5. 🟢 **Harden a whole switch.** `interface range` all user ports → `switchport mode access` + `switchport nonegotiate`; hardcode uplinks → `mode trunk` + `nonegotiate`; verify `Negotiation of Trunking: Off` everywhere.
6. 🔵 **Read admin vs operational.** For each experiment, contrast `Administrative Mode` and `Operational Mode` in `show interfaces switchport` and explain the negotiated result.
