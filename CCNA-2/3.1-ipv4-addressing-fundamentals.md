## 2. 🗺️ Visualization — The Whole Picture at a Glance

**One IPv4 address = 32 bits = 4 octets = 4 numbers 0–255 joined by dots.**

```
        192       .       168        .        10         .        1
   ┌──────────┐      ┌──────────┐       ┌──────────┐       ┌──────────┐
   │ 11000000 │  .   │ 10101000 │   .   │ 00001010 │   .   │ 00000001 │
   └──────────┘      └──────────┘       └──────────┘       └──────────┘
     octet 1           octet 2            octet 3            octet 4
     8 bits            8 bits             8 bits             8 bits
   └──────────────────────── 32 bits total ────────────────────────┘

   Positional value of each bit inside ONE octet:
    128   64   32   16    8    4    2    1     ← add the "on" bits to get 0–255
     1    1    0    0     0    0    0    0     = 128+64            = 192
```

**Classful map — read the FIRST octet, know the class instantly:**

```
 First octet   Leading bits   Class   Purpose              Default mask   Split (N=net H=host)
 ───────────   ────────────   ─────   ──────────────────   ────────────   ────────────────────
   1 – 126        0......      A 🅰️   Huge networks        /8  255.0.0.0   N.H.H.H
 128 – 191        10.....      B 🅱️   Medium networks      /16 255.255.0.0 N.N.H.H
 192 – 223        110....      C 🅲    Small networks       /24 255.255.255.0 N.N.N.H
 224 – 239        1110...      D 📡   Multicast (groups)   — (no mask)    entire addr = group
 240 – 255        1111...      E 🧪   Reserved/experimental — (no mask)    unused

   ⛔ 127 = the gap → 127.0.0.0/8 is loopback, carved out of Class A space
```

> 🧭 **The single most useful skill on this page:** look at the first octet → know the class, the default mask, and the network/host split — without touching the other 3 octets.

## 3. ⚡ TL;DR

- 🟢 An **IPv4 address is 32 bits**, written as **4 octets** (0–255 each) in **dotted-decimal** notation, e.g. `192.168.10.1`. Defined in **RFC 791 (Sept 1981)**.
- 🟢 Every address splits into a **network portion** (which network) and a **host portion** (which device on it). The boundary is set by a **subnet mask** (detailed in 3.2).
- 🟢 **Classful addressing** (A/B/C/D/E) was the *original* way to find that boundary automatically from the **leading bits** of the first octet. Classes A/B/C = unicast, D = multicast, E = reserved.
- 🟢 Classful is **history** — it was replaced by **CIDR (classless)** in **1993 (RFC 1519)**. You still memorise A/B/C/D/E for the exam and old IOS behaviours, but real networks are classless.
- 🔵 The "class" was **never a field in the packet** — it was inferred from leading bits. That's *why* CIDR could replace it without ever changing the 32-bit packet format.

## 4. 🎯 Importance — The Problem First

**The problem:** You have millions of devices across the planet that need to talk to each other. A device needs an identifier that answers two questions at once:

1. **"Which network are you on?"** → so routers can forward toward the right neighbourhood (like a **city + street**).
2. **"Which specific device are you?"** → so the last hop can deliver to the exact host (like a **house number**).

A flat, random ID (like a MAC address — see Block 2) **cannot** answer question 1. MAC addresses have no geography baked in, so a router would need a table entry for *every device on Earth*. That doesn't scale.

**The solution — a hierarchical, splittable address.** IPv4 packs *both* answers into 32 bits: a **network part** (shared by everyone on the same segment) + a **host part** (unique per device). Routers only need to know how to reach **networks**, not individual hosts — collapsing billions of hosts into a manageable number of routes. 🏙️

**Why classes existed at all:** In 1981 there was no subnet-mask field carried with routes. Engineers needed a *deterministic* rule so any host could look at an address and instantly know where the network/host boundary sat. The rule: **encode the split in the leading bits**. That's classful addressing. It was elegant, and it was also wasteful — which is the whole reason subnetting (3.2), CIDR (3.4), and private addressing (3.5) had to be invented afterwards. This document is the *foundation* that makes all of those make sense.

## 5. 📖 Description

- 🟢 **32-bit logical address.** Layer 3 (Network layer). Unlike a MAC address (L2, burned-in, flat), an IP address is **assigned/configurable** and **hierarchical**.
- 🟢 **Dotted-decimal notation.** Humans read `192.168.10.1`; the wire carries `11000000 10101000 00001010 00000001`. The dots are purely a human convenience to break 32 bits into 4 readable chunks.
- 🟢 **Octet.** One of the four 8-bit groups. 8 bits → range **0–255** (2⁸ = 256 values). This is why you never see `.256` or higher.
- 🟢 **Network portion + host portion.** The address is a **prefix (network) + suffix (host)**. The prefix is shared by every device on the segment; the suffix is unique.
- 🟢 **Subnet mask.** The tool that marks *where* the network/host boundary sits (`1`s = network, `0`s = host). Introduced here conceptually; the math lives in **3.2 / 3.3**.
- 🟢 **Classful addressing (historical).** Five classes:
  - **A / B / C** → **unicast** (one-to-one host addressing), with fixed default masks /8, /16, /24.
  - **D** → **multicast** (one-to-many group addressing; no host split, no mask — the whole address names a group).
  - **E** → **reserved/experimental** (never deployed for public use).
- 🟢 **Classless (CIDR) reality.** Modern addressing ignores class boundaries and lets the mask be *any* length (e.g. `/26`, `/30`). Covered in **3.4**.
- ⚪ **Two addresses that are never a normal host:** the **network address** (all host bits `0`) and the **broadcast address** (all host bits `1`) — which is why usable hosts = 2^(host bits) **− 2** (fully derived in 3.3).

## 6. 🔧 How It Works — Under the Hood

### 6.1 🟢 Decimal ⇄ Binary (the core engineer skill)

Every octet is 8 bit-positions with fixed positional weights:

```
   bit weight →  128   64   32   16    8    4    2    1
```

**Decimal → binary** (greedy subtraction): take the number, subtract the largest weight that fits, mark a `1`, repeat.

```
   168 ?
   168 ≥ 128 → 1, remainder 40
    40 <  64 → 0
    40 ≥  32 → 1, remainder 8
     8 <  16 → 0
     8 ≥   8 → 1, remainder 0
     0 <   4 → 0
     0 <   2 → 0
     0 <   1 → 0
   ───────────────────────────
   168 = 1 0 1 0 1 0 0 0  = 10101000  ✅
```

**Binary → decimal:** add the weights wherever there's a `1`.

```
   11000000 = 128 + 64 = 192 ✅
```

> 🧠 **Memory anchor — the "magic 8" line `128 64 32 16 8 4 2 1`.** Write it once at the top of every subnetting problem for the rest of your career. Every subnet mask, every host count, every class boundary falls out of this line.

### 6.2 🟢 Reading the class from leading bits

The class is decided *only* by how the **first octet begins in binary**:

```
   0xxxxxxx  → Class A   (first octet 0–127)
   10xxxxxx  → Class B   (first octet 128–191)
   110xxxxx  → Class C   (first octet 192–223)
   1110xxxx  → Class D   (first octet 224–239)  📡 multicast
   1111xxxx  → Class E   (first octet 240–255)  🧪 reserved
```

Why those decimal boundaries? Because fixing the leading bits *fixes the possible range*:

```
   Class B first octet: 10000000 (=128)  … up to …  10111111 (=191)
                         └ locked "10" ┘             └ locked "10" ┘
```

### 6.3 🟢 The classful network/host split

Once you know the class, you know the default boundary:

```
   Class A  N . H . H . H     /8    →  net bits 8,  host bits 24
   Class B  N . N . H . H     /16   →  net bits 16, host bits 16
   Class C  N . N . N . H     /24   →  net bits 24, host bits 8
```

**Counting what each class holds** (raw math, refined in 3.3):

| Class | # Networks | Hosts per network (2^host − 2) |
| ----- | ---------- | ------------------------------ |
| A | 2⁷ − 2 = **126** (0 & 127 reserved) | 2²⁴ − 2 = **16,777,214** |
| B | 2¹⁴ = **16,384** | 2¹⁶ − 2 = **65,534** |
| C | 2²¹ = **2,097,152** | 2⁸ − 2 = **254** |

### 6.4 🔵 Where "class" actually lives — nowhere on the wire

Open an IPv4 packet (you'll dissect the full header in a later routing doc). You will find **exactly two 32-bit address fields** — source and destination — and **no "class" field and no "mask" field**. The class was *always* a convention that hosts and routers **inferred locally** from the leading bits. Two consequences:

- 🔵 CIDR (3.4) could abolish classes in 1993 **without touching the packet format** — because there was never anything class-shaped in the packet to change.
- 🔵 A subnet mask must be **configured or learned separately** (statically, via DHCP, or carried by classless routing protocols) — it is *not* discoverable from the address alone once you're classless.

### 6.5 🕵️ Dirty Secret — Classful is "dead," but its ghost still breaks networks

Classful addressing was officially retired in 1993, yet its **default-boundary logic is still baked into legacy IOS behaviour**:

- **Auto-summarisation.** RIPv1, and *classic-mode* EIGRP with `auto-summary` on, will silently summarise your carefully-planned subnets **back to their classful boundary** when advertising across a major-network edge. Your `10.1.1.0/24` and `10.2.2.0/24` both get flattened to `10.0.0.0/8` — and if those subnets are **discontiguous** (separated by a different major network), routing **breaks with no error message**. The fix in the real world is `no auto-summary`.
- **`ip classless` vs `no ip classless`.** Old IOS could *refuse* to use a default route for an unknown subnet of a known major network, purely because of classful assumptions.
- **The 127.0.0.0/8 waste.** An **entire Class A block — 16,777,216 addresses — is spent on loopback**, virtually all of it never used, because in 1981 nobody imagined address exhaustion. That single design decision is a microcosm of *why* classful had to die.

> **Engineer takeaway:** memorise A/B/C/D/E for the exam and for reading old configs — but treat "class" as a **historical lens**, not how forwarding actually works today. When something summarises unexpectedly, `auto-summary` is your first suspect.

## 7. ⚖️ Pros & Cons

**Classful addressing**

| ✅ Pros (why it was invented) | ❌ Cons (why it died) |
| ----------------------------- | --------------------- |
| Zero-config boundary — mask inferred from leading bits | Grotesque waste: a company needing 300 hosts got a whole /16 (65,534) |
| Simple to teach and reason about | Only 3 usable sizes (/8, /16, /24) — no middle ground |
| Fast local lookup (just check first bits) | Class B exhaustion drove the mid-1990s IPv4 crisis |
| Deterministic — same address → same class everywhere | Can't summarise across class boundaries → routing-table bloat |

**IPv4 addressing itself (the 32-bit model)**

| ✅ Pros | ❌ Cons |
| ------ | ------ |
| Hierarchical → routers store *routes to networks*, not hosts | Only ~4.29 billion total addresses (2³²) — exhausted |
| Human-readable dotted decimal | Requires separate mask to be meaningful |
| Universally supported, decades of tooling | Needs NAT (3.5) + IPv6 (3.7+) to survive scarcity |

## 8. 🌿 Variants — Common → Specific

- 🟢 **Unicast (Classes A/B/C).** One-to-one. The everyday host address. 99% of what you configure.
- 🟢 **Multicast (Class D, 224.0.0.0–239.255.255.255).** One-to-many. The whole address names a **group**, not a host — no network/host split, no mask. Detail in **3.9 (IPv6 multicast)** and used heavily by routing protocols (OSPF `224.0.0.5`, EIGRP `224.0.0.10`, RIPv2 `224.0.0.9`).
- 🟢 **Reserved / Experimental (Class E, 240.0.0.0–255.255.255.255).** Never deployed publicly. `255.255.255.255` is the **limited broadcast** exception (all hosts on *this* segment).
- 🟢 **Public vs Private (RFC 1918).** A carve-out *within* A/B/C for non-routable internal use (`10/8`, `172.16/12`, `192.168/16`) — full treatment in **3.5**.
- ⚪ **Special-purpose ranges** — loopback `127/8`, APIPA/link-local `169.254/16`, `0.0.0.0` — collected in **3.6**.

## 10. ✅ Best Practices

- 🟢 **Learn the first-octet class table cold.** `A 1–126 · B 128–191 · C 192–223 · D 224–239 · E 240–255`. It's free marks and a fast sanity check.
- 🟢 **Always pair an address with its mask.** An IPv4 address without a mask is *meaningless* in a classless world — never quote `10.0.0.5` without `/8` (or whatever the real mask is).
- 🟢 **Write the `128 64 32 16 8 4 2 1` line first** on every binary/subnetting task. It removes guesswork.
- 🔵 **Think in networks, not hosts.** When designing or troubleshooting, ask "what network is this?" before "what host?" — it matches how routers actually decide.
- 🔵 **Assume classless everywhere by default**; only invoke "class" when reading legacy configs or explaining auto-summarisation symptoms.
- 🔵 **On any classic routing protocol, verify `no auto-summary`** before trusting your subnet advertisements.

## 11. 🚫 No-Goes — Common Mistakes & Troubleshooting Traps

- ❌ **Writing an octet > 255** (e.g. `192.300.1.1`). 8 bits cap at 255. Instant invalid.
- ❌ **Confusing L2 and L3 identity.** MAC (Block 2) is flat/burned-in; IPv4 is hierarchical/assigned. They coexist per packet — one doesn't replace the other.
- ❌ **Assuming "class" determines forwarding today.** It doesn't. Routers use the **longest-prefix match** on the mask, not the leading bits. (Forwarding logic lives in Block 4.)
- ❌ **Treating `127.0.0.1` as a network you can route.** All of `127/8` is **loopback** — traffic never leaves the host (3.6).
- ❌ **Forgetting the "−2".** Network address (host bits all `0`) and broadcast (host bits all `1`) are **not assignable hosts**. Overcounting here is the #1 subnetting error (3.3).
- 🕵️ **Troubleshooting trap:** two subnets of the same major network can't reach each other across a third network → check for **auto-summarisation** collapsing them to a classful boundary (§6.5). No log message will tell you; you have to know to look.
- 🕵️ **Trap:** an address in `169.254.x.x` means the host **failed to get DHCP** (APIPA) — it's a symptom, not a config (3.6).

## 13. 🧪 Practical Tasks *(listed now, expanded in later lab docs)*

1. 🖐️ **Binary drill (no calculator).** Convert by hand, both directions:
   `10.55.240.3` → binary · `11000000.10101000.00011001.00000001` → dotted decimal · check each octet with the magic-8 line.
2. 🏷️ **Class ID drill.** For `10.0.0.1`, `172.16.5.9`, `192.168.1.1`, `224.0.0.5`, `240.1.1.1`: name the class from the first octet *and* justify it from the leading bits.
3. 🖥️ **Read your own machine.**
   - Windows: `ipconfig /all` — find your IPv4, mask, gateway; convert the IPv4 to binary.
   - Linux/macOS: `ip addr` / `ifconfig` — same exercise.
   - (Full cross-OS verification is doc **3.12**.)
4. 🧰 **Packet Tracer 8.** Put two PCs on a switch, assign `192.168.10.10` and `192.168.10.11` **without typing a mask** — observe PT auto-fill the **classful default** `/24`. Note *why* (Class C leading bits). Then change one to `10.0.0.10` and watch the default jump to `/8`.
5. 🔬 **Wireshark.** Capture any traffic → open one packet → **Internet Protocol Version 4** → locate the **Source** and **Destination** 32-bit fields. Confirm there is **no "class" and no "mask"** field present (§6.4). Toggle Wireshark's bit view to see the leading bits.
6. 🧨 **(🔵 stretch)** In Packet Tracer, build two `10.x` subnets separated by a `172.16` link running classic EIGRP; enable `auto-summary` and watch reachability break, then `no auto-summary` and watch it heal (§6.5 dirty secret).
