## 2️⃣ Visualization — Big Picture at a Glance

**The three ways VLANs get routed:**

```
 ① LEGACY (one router port PER VLAN — doesn't scale)
    VLAN10 ─ access ─ Router Gi0/0 (10.10.10.1)
    VLAN20 ─ access ─ Router Gi0/1 (10.20.20.1)     ← 1 physical port + 1 switch port per VLAN 😤

 ② ROUTER-ON-A-STICK (one trunked router interface, subinterfaces)
    ┌────────┐   802.1Q trunk    ┌──────── Router ───────┐
    │ SWITCH │══════════════════│ Gi0/0 (no ip)          │
    │ VLAN10 │  VLAN10,20 tagged │  .10  encap dot1q 10 → 10.10.10.1  (GW VLAN10)
    │ VLAN20 │                   │  .20  encap dot1q 20 → 10.20.20.1  (GW VLAN20)
    └────────┘                   └───────────────────────┘
       ⚠ ALL inter-VLAN traffic rides the ONE trunk (in tagged, out tagged) = bottleneck

 ③ LAYER-3 SWITCH + SVIs (the modern/enterprise answer)
    ┌───────────── Multilayer Switch (ip routing ON) ─────────────┐
    │  interface Vlan10 → 10.10.10.1   (GW VLAN10)                 │
    │  interface Vlan20 → 10.20.20.1   (GW VLAN20)                 │
    │  routing happens INTERNALLY in hardware (ASIC), line rate    │
    │  VLAN10 access ports        VLAN20 access ports              │
    └─────────────────────────────────────────────────────────────┘
       ✅ no trunk bottleneck — nothing leaves the chassis to route
```

**Method cheat-sheet:**

| Method | Gateway lives on | Forwarding | Bottleneck | Best for |
|---|---|---|---|---|
| 🟢 Legacy | separate router **physical** ports | router CPU (SW) | ports don't scale | (historical) |
| 🟢 **ROAS** | router **subinterfaces** (trunk) | router CPU (SW) | **single trunk** | small / remote sites |
| 🟢 **L3-switch SVI** | **`interface vlan`** | **ASIC (HW)**, line rate | none | enterprise campus |
| 🔵 Routed port | **`no switchport`** physical | ASIC (HW) | n/a (P2P L3 link) | L3 uplinks to router/FW |

## 3️⃣ TL;DR

- 🟢 VLANs are **separate subnets** and **isolated at L2** (2.6–2.9) — traffic between them **must be routed** at Layer 3. A host reaches other VLANs via its **default gateway**.
- 🟢 **Router-on-a-stick (ROAS):** one router physical interface trunked to the switch, split into **subinterfaces** — one per VLAN — each with `encapsulation dot1q <vid>` and an IP that is that VLAN's **gateway**.
- 🟢 **ROAS native VLAN:** either put the IP on the **physical** interface (no `encapsulation`), or use `encapsulation dot1q <vid> native` on a subinterface — and match the switch's native VLAN.
- 🟢 **Layer-3 switch (SVI):** create `interface vlan <id>` gateways and enable **`ip routing`** (mandatory — without it the switch won't route between VLANs). Routing happens **internally, in hardware, at line rate** — no trunk bottleneck.
- 🟢 **SVI is up/up only when** the VLAN **exists in the DB**, has **≥1 active port** in it, and the SVI has **`no shutdown`** (autostate).
- 🔵 **Routed port:** `no switchport` on a physical L3-switch port → a router-style L3 interface for point-to-point uplinks (no VLAN).
- 🟢 **Verify** with `show ip route` (a connected route per gateway subnet), `show ip interface brief`, and a **cross-VLAN ping**.
- 🧠 **Every routed hop rewrites the L2 header** (new src/dst MAC) while the L3 addresses stay end-to-end — the core routing-vs-switching idea from 2.1.

## 4️⃣ Importance — The Problem First 🎯

**The underlying problem:** We spent 2.6–2.9 deliberately **isolating** VLANs — separate broadcast domains, separate subnets, no L2 path between them (that was the *point*, and even the native-VLAN "bridge" was a bug to prevent). But real users still need to reach each other: Sales (VLAN 10) must talk to the Servers (VLAN 30); everyone needs the internet.

So: *"How do two hosts in different VLANs / different subnets communicate, given that a switch will never forward a frame between VLANs?"*

- A host only speaks directly to devices **in its own subnet**. For anything else, it sends the packet to its **default gateway** — an IP address that lives on a **Layer 3 device**.
- That L3 device (**router** or **L3 switch**) has an interface (or gateway) **in each VLAN**, so it can **receive from one VLAN and forward into another** — this is **inter-VLAN routing**.

**Why an engineer must own this cold:**

- 🔧 **This is where L2 and L3 finally meet.** It's the single most common "everything is configured but nothing works" scenario — VLANs fine, trunks fine, yet hosts can't cross VLANs because routing (or a gateway) is missing.
- 🔧 **The design choice (ROAS vs SVI) is real and consequential.** ROAS is cheap and fine for a small/remote site; a busy campus needs L3-switch SVIs for hardware line-rate routing. Picking wrong creates a bottleneck or wastes money.
- 🔧 **Troubleshooting inter-VLAN routing exercises the whole stack** — VLAN existence, trunk allowed lists, native VLAN, subinterface encapsulation, `ip routing`, SVI autostate, and host default gateways. Mastering it means you truly understand Blocks 2–3 together.
- 🔧 **It's the foundation of every routed campus** and the launchpad into Block 4 (routing tables, static/dynamic routing) and FHRP gateway redundancy.

## 5️⃣ Description 📋

- 🟢 **Why routing is required:** each VLAN is its **own subnet**; a switch forwards **within** a VLAN only. Crossing VLANs = crossing subnets = a **Layer 3 (routing) decision**. The router/L3 switch needs a presence (an IP **gateway**) in **every** VLAN it routes.
- 🟢 **① Legacy inter-VLAN routing:** a router with **one physical interface per VLAN**, each cabled to a switch **access** port in that VLAN, each holding that VLAN's gateway IP. Simple but **doesn't scale** (a port pair per VLAN). Historical baseline.
- 🟢 **② Router-on-a-stick (ROAS):** collapses the legacy design onto **one physical router interface** connected by an **802.1Q trunk** to the switch:
  - Physical interface: **`no ip address`**, **`no shutdown`** (if the physical is down, **all** subinterfaces are down).
  - **Subinterface per VLAN** (`interface Gi0/0.10`): **`encapsulation dot1q <vid>`** (respond to that VLAN's tag) + **`ip address`** (the VLAN's **default gateway**, on a **unique subnet**).
  - Subinterface number is **arbitrary** (best practice: match the VID for readability).
  - **Native VLAN** options: (a) IP on the **physical** interface with **no** `encapsulation` → router treats it as native; or (b) `encapsulation dot1q <vid> native` on a subinterface. Must **match the switch trunk's native VLAN**.
  - Switch side: a **trunk** allowing all routed VLANs.
- 🟢 **③ Layer-3 (multilayer) switch with SVIs:** one device doing **both** L2 switching and L3 routing:
  - Enable **`ip routing`** globally — **mandatory**; without it, SVIs answer pings on their own subnet but **won't route between VLANs**.
  - **`interface vlan <id>`** (an **SVI** = Switched Virtual Interface) + **`ip address`** + **`no shutdown`** → the VLAN's gateway.
  - Routing happens **internally in hardware (ASIC) at line rate** — inter-VLAN traffic **never leaves the chassis** → **no trunk bottleneck**.
  - 🟢 **SVI up/up conditions (autostate):** (1) the **VLAN exists** in the DB (`vlan <id>` — note `interface vlan <id>` does **not** create the VLAN), (2) **≥1 active** (up, non-STP-blocked) access/trunk port is in that VLAN, and (3) the SVI is **`no shutdown`**. Miss any → the SVI stays **down** even with a correct IP.
  - 🔵 SVIs also serve as the **switch management interface** and host **DHCP relay** (`ip helper-address`) per VLAN.
- 🔵 **Routed port:** on an L3 switch, **`no switchport`** on a physical port converts it to a **router-style L3 interface** (assign an IP directly). **No VLAN membership** — used for **point-to-point L3 uplinks** to a router/firewall/another L3 switch. Comes up/down faster than an SVI (it's physical).
- 🧠 **Packet flow (universal):** the sending host frames the packet to its **gateway's MAC** (dst MAC = gateway; found via ARP). The L3 device **strips the L2 header, makes a routing decision, and builds a brand-new L2 header** (new src MAC = its egress interface, new dst MAC = the destination host, via ARP) into the target VLAN. **L3 addresses stay end-to-end; L2 addresses change every hop** — exactly the routing-vs-switching principle from 2.1.

## 6️⃣ How It Works — Under the Hood ⚙️

### A) 🚦 Packet flow: VLAN 10 host → VLAN 20 host (the gateway hop)

```
PC-A (VLAN10, 10.10.10.50, GW 10.10.10.1)  ──▶  PC-B (VLAN20, 10.20.20.50)

 1. PC-A: "10.20.20.50 is NOT my subnet → send to my DEFAULT GATEWAY 10.10.10.1."
    ARP for the gateway → build frame:  [dst MAC = GATEWAY][src MAC = PC-A][IP dst=10.20.20.50]
 2. L3 device receives on VLAN 10, STRIPS L2, routes: "10.20.20.0/24 is connected via my VLAN20 GW."
 3. It BUILDS A NEW frame into VLAN 20:  [dst MAC = PC-B][src MAC = GATEWAY][IP dst=10.20.20.50]
    (ARPs for PC-B if needed) → delivers into VLAN 20.
 4. PC-B replies, mirror image, back through the gateway.

  L3 (IP) src/dst NEVER change. L2 (MAC) src/dst change at EVERY hop.  ← core idea from 2.1
```

### B) 🥢 ROAS — one trunk doing double duty (the bottleneck)

```
        ┌────────┐        802.1Q trunk        ┌──── Router ────┐
 PC-A ─►│ SWITCH │══════════════════════════►│ Gi0/0 (no ip)   │
 VLAN10 │        │  ① frame IN, tagged VLAN10 │  .10 → 10.10.10.1│
        │        │◄═════════════════════════ │  .20 → 10.20.20.1│
 PC-B ◄─│        │  ② frame OUT, tagged VLAN20 └─────────────────┘
 VLAN20 └────────┘

 The SAME physical link carries the frame UP (VLAN10 tagged) and back DOWN (VLAN20 tagged).
 Every inter-VLAN packet crosses the trunk TWICE → the single link is a BANDWIDTH BOTTLENECK,
 and a software router does the work. Fine for small sites; painful under campus load.
```

### C) 🛠️ Configuration — the three methods

```
!── ② ROUTER-ON-A-STICK ────────────────────────────────────────────────
! Switch: trunk toward the router, allow the routed VLANs
Switch(config)# interface Gi0/1
Switch(config-if)#  switchport trunk encapsulation dot1q   ! (ISL-capable gear)
Switch(config-if)#  switchport mode trunk
Switch(config-if)#  switchport trunk allowed vlan 10,20,99
Switch(config-if)#  switchport trunk native vlan 99

! Router: physical up but no IP; one subinterface per VLAN
Router(config)# interface Gi0/0
Router(config-if)#  no ip address
Router(config-if)#  no shutdown
Router(config)# interface Gi0/0.10
Router(config-subif)#  encapsulation dot1q 10
Router(config-subif)#  ip address 10.10.10.1 255.255.255.0     ! GW for VLAN 10
Router(config)# interface Gi0/0.20
Router(config-subif)#  encapsulation dot1q 20
Router(config-subif)#  ip address 10.20.20.1 255.255.255.0     ! GW for VLAN 20
Router(config)# interface Gi0/0.99
Router(config-subif)#  encapsulation dot1q 99 native           ! native VLAN (match switch)
Router(config-subif)#  ip address 10.99.99.1 255.255.255.0

!── ③ LAYER-3 SWITCH (SVI) ─────────────────────────────────────────────
Switch(config)# ip routing                        ! ← MANDATORY, or no inter-VLAN routing
Switch(config)# vlan 10
Switch(config)# vlan 20                            ! the VLANs must EXIST in the DB
Switch(config)# interface vlan 10
Switch(config-if)#  ip address 10.10.10.1 255.255.255.0
Switch(config-if)#  no shutdown
Switch(config)# interface vlan 20
Switch(config-if)#  ip address 10.20.20.1 255.255.255.0
Switch(config-if)#  no shutdown

!── ROUTED PORT (L3 uplink, no VLAN) ───────────────────────────────────
Switch(config)# interface Gi1/0/24
Switch(config-if)#  no switchport                  ! becomes an L3 interface
Switch(config-if)#  ip address 10.0.0.2 255.255.255.252
Switch(config-if)#  no shutdown
```

### D) 🔍 Verification & the connected-route check

```
Switch# show ip route
  C  10.10.10.0/24 is directly connected, Vlan10      ← one connected route per gateway
  L  10.10.10.1/32 is directly connected, Vlan10      ← the local /32 (the gateway IP itself)
  C  10.20.20.0/24 is directly connected, Vlan20
  L  10.20.20.1/32 is directly connected, Vlan20

Router# show ip route            ! ROAS: connected routes via Gi0/0.10, Gi0/0.20 …
Switch/Router# show ip interface brief   ! SVI/subinterface up/up + IPs
Switch# show interfaces Vlan10           ! SVI state, MAC (the gateway MAC)
Switch# ping 10.20.20.50 source Vlan10   ! cross-VLAN reachability
```

> 🕵️ **Dirty secret #1 — the SVI that won't come up.** You configure `interface vlan 20` with a perfect IP, but it's stuck **down/down**. Why? **Autostate:** the SVI needs the VLAN to **exist** (`vlan 20`, not just `interface vlan 20`) **and** at least one **active port** in VLAN 20. A freshly-built SVI with no host plugged in (or its only port STP-blocked) sits down — correct config, no link. Plug in a host or (in a lab) use `no autostate`.

> 🕵️ **Dirty secret #2 — `ip routing` is off by default on many L3 switches.** Build all the SVIs you want; without **`ip routing`**, the switch answers pings *on each SVI's own subnet* but **refuses to forward between them**. "SVIs are up, hosts can ping their gateway, but not each other" = you forgot `ip routing`. It's the **first** thing to check.

### E) 🧮 ROAS vs SVI — why campuses moved to SVIs

```
 ROAS:  external router, software forwarding, EVERY inter-VLAN packet crosses ONE trunk twice.
        → trunk bandwidth + router CPU cap your inter-VLAN throughput.
 SVI :  one multilayer switch, ASIC hardware forwarding, traffic NEVER leaves the chassis.
        → line-rate routing, scales to campus loads, no trunk bottleneck.

 Choose ROAS for small/remote sites (reuse an existing router, few VLANs, low traffic).
 Choose L3-switch SVIs for anything with real inter-VLAN volume (the enterprise default).
```

## 7️⃣ Pros & Cons ⚖️

**Router-on-a-Stick:**

| ✅ Pros | ❌ Cons |
|---|---|
| 🟢 **Cheap** — one router + one L2 switch; reuse existing gear. | 🔵 **Single-trunk bottleneck** (traffic crosses it twice). |
| 🟢 **Simple** for a handful of VLANs / small sites. | 🔵 **Software forwarding** on router CPU — limited throughput. |
| 🟢 Good for **remote/branch** offices. | ⚠️ One physical interface = a **single point of failure**. |

**Layer-3 Switch (SVI):**

| ✅ Pros | ❌ Cons |
|---|---|
| 🟢 **Hardware line-rate** routing (ASIC). | 🔵 **Pricier** than a plain L2 switch. |
| 🟢 **No trunk bottleneck** — routes internally. | ⚠️ **`ip routing` + autostate gotchas** trip people. |
| 🟢 **One device**, scales to campus. | 🔵 Feature set varies by platform/license. |
| 🟢 SVIs also do **mgmt + DHCP relay**. | |

## 8️⃣ Variants — Common → Specific 🌿

**Inter-VLAN routing methods:**
- 🟢 **ROAS** — trunked router + subinterfaces (small sites).
- 🟢 **L3-switch SVI** — `interface vlan` gateways (enterprise default).
- 🟢 **Legacy** — one router port per VLAN (historical).
- 🔵 **Routed port** — `no switchport` L3 interface (P2P uplinks, no VLAN).

**Gateway interface types:**
- 🟢 **Subinterface** (`.<n>`, `encapsulation dot1q`).
- 🟢 **SVI** (`interface vlan <id>`).
- 🔵 **Routed physical port** (`no switchport`).

**Native-VLAN handling (ROAS):**
- 🟢 **`encapsulation dot1q <vid> native`** on a subinterface.
- 🟢 **IP on the physical interface** (implicit native).

**Redundancy (→ Block 4):**
- 🔵 **FHRP** (HSRP/VRRP/GLBP) — a virtual gateway across two L3 devices so the default gateway survives a failure.

## 🔟 Best Practices ✅

- 🟢 **Use L3-switch SVIs for campus inter-VLAN routing**; reserve ROAS for small/remote sites or when reusing an existing router.
- 🟢 **On L3 switches, remember `ip routing`** — it's the #1 forgotten command; verify it's on.
- 🟢 **Match subinterface encapsulation VIDs to the switch VLANs**, and ensure each VLAN is in the **trunk allowed list** (the most common ROAS break).
- 🟢 **Handle the native VLAN explicitly on ROAS** (native subinterface or physical-interface IP) and match the switch trunk's native VLAN.
- 🟢 **Give hosts the correct default gateway** (the subinterface/SVI IP) — wrong gateway = no inter-VLAN routing even if the network is perfect.
- 🔵 **Verify with connected routes** (`show ip route` → one C route per gateway subnet) and a cross-VLAN ping.
- 🔵 **Plan gateway redundancy (FHRP)** for SVIs that are critical default gateways (→ Block 4).
- 🔵 **Use routed ports for L3 uplinks** (to routers/firewalls) rather than an access-port-in-a-transit-VLAN hack.

## 1️⃣1️⃣ No-Goes — Common Mistakes & Troubleshooting Traps 🚫

- ❌ **Forgetting `ip routing` on the L3 switch.** SVIs come up, hosts ping their own gateway, but **nothing routes between VLANs**. Check this first.
- ⚠️ **SVI stuck down (autostate).** `interface vlan 20` does **not** create VLAN 20 — you also need `vlan 20`, plus **an active port** in it. No port up ⇒ SVI down despite a correct IP.
- ⚠️ **VLAN missing from the trunk allowed list (ROAS).** The router subinterface is perfect, but the VLAN never reaches it → dead. Check `show interfaces trunk`.
- ⚠️ **Native-VLAN mismatch on ROAS.** The native VLAN's frames arrive **untagged**; a subinterface expecting a tag won't process them. Use `native` (or physical-interface IP) and match the switch (→ 2.9).
- ⚠️ **Wrong host default gateway.** The single most common "it's all configured but hosts can't cross VLANs." Fix the host, not the network.
- 🔵 **Assigning an IP to a port still in switchport mode.** On an L3 switch you must `no switchport` **before** `ip address` on a routed port.
- ⚠️ **Physical interface shut on ROAS.** If `Gi0/0` is down, **every** subinterface is down. `no shutdown` the physical.
- 🔵 **Expecting ROAS to scale.** All inter-VLAN traffic funnels through one trunk twice — under campus load, move to L3-switch SVIs.
- ⚠️ **Ignoring the connected route.** If `show ip route` doesn't list a `C` route for a VLAN's subnet, that gateway isn't up/routing — start there.

## 1️⃣3️⃣ Practical Tasks 🛠️

> Listed briefly; expanded step-by-step later in context.

1. 🟢 **Build ROAS (Packet Tracer 8 / GNS3).** Two VLANs, two PCs, one switch, one router. Trunk to the router; subinterfaces `.10`/`.20`; verify cross-VLAN ping. Confirm the trunk allowed list includes both VLANs.
2. 🟢 **Add the native subinterface.** Set native VLAN 99 on the trunk and a `.99 native` subinterface (or physical-interface IP); verify it matches and untagged frames route.
3. 🟢 **Build the same with an L3 switch (SVI).** `ip routing`, `vlan 10/20`, `interface vlan 10/20` gateways; verify cross-VLAN ping. Then **omit `ip routing`** and observe hosts pinging their own gateway but **not** each other — then add it back.
4. 🔵 **Trigger the autostate trap.** Configure `interface vlan 30` with an IP but no host/port in VLAN 30; observe it **down**; plug in a host (or `no autostate` in lab) to bring it up.
5. 🟢 **Read the routing evidence.** `show ip route` (one `C` per gateway subnet + `L` /32s), `show ip interface brief`, `show interfaces vlan10`. Shut an SVI and watch its connected route disappear.
6. 🔵 **Create a routed port.** `no switchport` + IP on an uplink to a router/another L3 switch; verify with `show ip interface brief` it's no longer a VLAN/access port.
7. 🔵 **Compare paths.** In ROAS, use simulation mode to watch a VLAN-10→VLAN-20 packet cross the trunk **twice**; then do the same on the L3 switch and note routing happens **internally** with no trunk traversal.
