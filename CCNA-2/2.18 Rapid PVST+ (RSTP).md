## 2️⃣ Visualization — Big Picture at a Glance

**Five states → three; RSTP decouples "what the port is" from "what it's doing":**

```
   802.1D (5 states)              RSTP / Rapid PVST+ (3 states)
   ──────────────────            ────────────────────────────
   Disabled  ┐
   Blocking  ├──────────────▶    DISCARDING   (no data, no MAC learn, BPDU only)
   Listening ┘
   Learning  ───────────────▶    LEARNING     (builds MAC table, no data yet)
   Forwarding ──────────────▶    FORWARDING   (full: data + MAC + BPDU)

   ROLE (root / designated / ALTERNATE / BACKUP) is now a SEPARATE variable from STATE.
```

**The star trick — proposal/agreement replaces the 30-second timer walk:**

```
   ROOT(SW1) ══P2P══ SW2 ══P2P══ SW3

   1. SW1's new designated port is DISCARDING → sends BPDU with PROPOSAL bit set ──▶ SW2
   2. SW2 SYNCS: blocks its other non-edge designated ports, makes this port its Root Port,
      sends AGREEMENT ──▶ SW1
   3. SW1 sees AGREEMENT → its port jumps straight to FORWARDING (no timers!)
   4. SW2 now proposes to SW3 … the handshake WAVE rolls toward the edge → sub-second convergence
```

**RSTP vs 802.1D at a glance:**

| | 802.1D STP | 🟢 **RSTP / Rapid PVST+** |
|---|---|---|
| Standard | 802.1D | **802.1w** (per-VLAN = Rapid PVST+) |
| States | 5 | **3** (discarding/learning/forwarding) |
| Convergence | **30–50 s** (timers) | **sub-second** (handshake) |
| Who sends BPDUs | root only (others relay) | **every switch**, every 2 s |
| Failure detect | max-age **20 s** | **3 missed hellos = ~6 s** |
| Rapid transition on | — | **edge ports + point-to-point links** |
| Roles | root/designated/blocking | + **alternate / backup** |
| Cisco default | no | **YES (`rapid-pvst`)** |

## 3️⃣ TL;DR

- 🟢 **RSTP (802.1w)** is STP that **converges in under a second** instead of 30–50 s. **Rapid PVST+** is Cisco's **default** — RSTP running as a **separate instance per VLAN**.
- 🟢 **Three states** (Discarding / Learning / Forwarding) replace the five 802.1D states (Disabled + Blocking + Listening all collapse into **Discarding**), and **role is decoupled from state**.
- 🟢 **Speed comes from the proposal/agreement handshake** on **point-to-point** links: a discarding designated port sets a **proposal** bit; the neighbor **syncs** (blocks its other non-edge designated ports) and replies **agreement**; the port then jumps straight to **forwarding** — **no timers**. The handshake **wave** rolls to the edge.
- 🟢 **Link types matter:** **point-to-point** (full-duplex → rapid), **shared** (half-duplex → falls back to slow 802.1D), **edge** (to an end device → immediate forwarding = **PortFast**).
- 🟢 **Every switch originates BPDUs** every hello (2 s) — they're **keepalives**; **3 missed = neighbor down (~6 s)**, far faster than 802.1D's 20 s max-age.
- 🟢 **Roles** add **Alternate** (pre-computed backup path to root — takes over instantly) and **Backup** (backup to a designated port on a shared segment).
- 🟢 **PVST+ = one instance per VLAN** → you can place **different roots per VLAN** to **load-share uplinks** (both links forward, for different VLANs) — at the cost of more CPU as VLAN count grows (MST fixes that → CCNP).
- 🟢 **Config:** `spanning-tree mode rapid-pvst` (default). **RSTP is backward-compatible** — it falls back to 802.1D toward legacy neighbors.

## 4️⃣ Importance — The Problem First 🎯

**The underlying problem:** 802.1D works — but it's **agonizingly slow**. After any topology change, a port that must start forwarding crawls through **listening (15 s) → learning (15 s)**, and a failure can take **max-age (20 s)** just to notice — so **30–50 seconds** of outage. In a 1990s LAN, tolerable. In a modern network carrying voice, video, storage, and real-time apps, **half a minute of blackout is unacceptable** — a VoIP call drops, a storage session times out, an app throws errors.

RSTP was built to answer one question: *"How do we keep STP's loop-free guarantee but converge in **milliseconds**?"*

- ❓ *"Why wait out timers if two switches can just **agree**?"* → the **proposal/agreement handshake** negotiates a safe transition directly, no timers.
- ❓ *"Why should a failure take 20 s to detect?"* → make BPDUs **keepalives**; **3 misses (~6 s)** = neighbor down.
- ❓ *"Why re-learn a backup path from scratch on failure?"* → **pre-compute** it as an **Alternate** port, ready to take over instantly.
- ❓ *"Why should end-device ports ever block?"* → mark them **edge** ports (PortFast) and forward immediately.

**Why an engineer must own this cold:**

- 🔧 **Rapid PVST+ is the Cisco default and what you'll actually run.** CCNA 2.5 literally says "interpret basic operations of **Rapid PVST+**." Legacy 802.1D is the teaching foundation; RSTP is production reality.
- 🔧 **The handshake explains real behavior** — why a switch uplink recovers in a blink on modern gear, and why a **half-duplex** or non-edge misconfig silently drops you back to 30-second convergence. Diagnosing "why is convergence slow?" means checking **link type**.
- 🔧 **Per-VLAN roots are a core design lever.** Placing different roots per VLAN turns idle blocked uplinks into **active load-shared** paths — a standard campus optimization and a favorite exam scenario.
- 🔧 **It sets up the toolkit (2.19).** Edge ports = PortFast; BPDU Guard protects them; Root Guard protects the root election. RSTP's concepts are the ground the protective features stand on.

## 5️⃣ Description 📋

- 🟢 **RSTP (IEEE 802.1w):** an evolution of 802.1D providing **rapid convergence** after topology changes, with **UplinkFast/BackboneFast-equivalent** behavior built in natively. **Backward-compatible** — on a port facing a legacy 802.1D bridge, RSTP **falls back** to the slow timer-based method for that link.
- 🟢 **PVST+ / Rapid PVST+ (Cisco):** **PVST+** runs a **separate spanning-tree instance per VLAN**; **Rapid PVST+** is PVST+ using **RSTP** — Cisco's **default** (`spanning-tree mode rapid-pvst`).
- 🟢 **Three port states** (down from five): **Discarding** (no data, no MAC learning, BPDU only — merges 802.1D **disabled + blocking + listening**), **Learning** (builds MAC table, no data), **Forwarding** (full).
- 🟢 **Role/state decoupling:** in 802.1D you couldn't tell a **root** from a **designated** port once both were "forwarding" — the state-based naming was ambiguous. RSTP makes the **role** an explicit variable **separate** from the **state**.
- 🟢 **Port roles:** **Root** and **Designated** (as before), plus **Alternate** (a **blocked backup path to the root** — receives superior BPDUs from **another** bridge; takes over instantly if the root port fails) and **Backup** (a **blocked backup to a designated port on the same segment** — receives superior BPDUs from the **same** bridge; only on shared/hub segments). *(Roles introduced in 2.17.)*
- 🟢 **Link types** (RSTP decides rapid vs slow per link):
  - **Point-to-point** — a **full-duplex** link (auto-assumed); the handshake works → **rapid**.
  - **Shared** — a **half-duplex** link; **no rapid handshake** → falls back to **802.1D** convergence.
  - **Edge** — connects to an **end device**; transitions to **forwarding immediately** (= **PortFast**), and **doesn't generate a topology change** on flap. ⚠️ An edge port that **receives a BPDU loses edge status** (becomes a normal port).
- 🟢 **Every switch originates BPDUs** every **hello (2 s)** — not just the root. These act as **keepalives**: if **3 BPDUs are missed (~6 s)**, the neighbor is considered **down** and its info is aged immediately (vs 802.1D waiting **max-age 20 s**).
- 🟢 **Proposal/Agreement handshake (the sync process):**
  1. A new/changed link: both ports start **Designated + Discarding**.
  2. A designated port in **discarding/learning** sets the **proposal** bit on its BPDUs.
  3. The receiving (inferior) bridge **syncs**: it **blocks all its non-edge designated ports**, makes the receiving port its **Root Port (forwarding)**, and sends back an **agreement**.
  4. On receiving the agreement, the superior port moves **straight to forwarding** — **no timers**.
  5. The inferior bridge then **proposes downstream**; the **handshake wave** propagates toward the network edge → **sub-second** convergence.
  6. 🔵 If **no agreement** arrives (legacy neighbor / blocked port / shared link), the port **falls back** to the slow 802.1D listening/learning walk.
- 🟢 **Topology-change (TC) handling — much better:** in 802.1D a change **bubbles up to the root** (TCN), then the root floods a TC down, and switches **flush the whole MAC table**. In RSTP, **only a non-edge port moving to forwarding** is a TC; the detecting switch **floods TC directly to neighbors** (no round-trip to the root) and flushes MACs more **selectively** → faster, less disruptive. **Edge-port flaps don't cause a TC.**
- 🟢 **BPDU:** RSTP uses **BPDU version 2, type 2**, using all flag bits (role/state/proposal/agreement/TC/TCA). Legacy bridges **drop** v2 BPDUs, which is how RSTP **detects legacy neighbors**.
- 🟢 **Per-VLAN load-sharing:** because each VLAN has its own instance, set **different root bridges per VLAN** (e.g., SW-A root for VLAN 10, SW-B root for VLAN 20) so **both uplinks forward** (each for different VLANs) instead of one sitting blocked. ⚠️ Cost: **CPU/memory scale with VLAN count** — many VLANs = many instances (**MST** groups VLANs into a few instances to fix this → CCNP).

## 6️⃣ How It Works — Under the Hood ⚙️

### A) ⚡ The proposal/agreement handshake (sync) — step by step

```
   ROOT(SW1) ═══════ SW2 ═══════ SW3   (all point-to-point, full-duplex)

 t0  SW1's port toward SW2 is Designated + DISCARDING → sends BPDU with PROPOSAL=1.
 t1  SW2 receives the proposal. To transition SAFELY it must "sync":
        • block ALL its other non-edge designated ports (temporarily) — guarantees no loop
        • make the port toward SW1 its ROOT PORT → FORWARDING
        • send AGREEMENT=1 back to SW1
 t2  SW1 gets the agreement → its port → FORWARDING immediately (NO 15s+15s timers).
 t3  SW2 now sends PROPOSAL toward SW3 → SW3 syncs → agreement → forwarding …
        the WAVE rolls outward to the edge. Whole tree converges in well under a second.

 ⚠ On a SHARED (half-duplex) link or toward a LEGACY bridge, no agreement comes back →
   the port falls back to the slow 802.1D listening→learning walk. Link type is decisive.
```

### B) 🩺 Faster failure detection (BPDUs as keepalives)

```
 802.1D: waits MAX AGE (20s) with no BPDU before aging out a neighbor's info. Slow.
 RSTP  : each switch SENDS BPDUs every 2s; they're KEEPALIVES.
         miss 3 in a row (≈6s) → "neighbor down" → age out immediately → converge fast.

 Plus: an ALTERNATE port is a PRE-COMPUTED backup path to root. When the root port dies,
 the alternate is promoted to root and forwards almost instantly — no fresh calculation.
```

### C) 🔌 Link types decide rapid vs slow

```
 FULL-DUPLEX link  → RSTP calls it POINT-TO-POINT → handshake works → RAPID ✅
 HALF-DUPLEX link  → RSTP calls it SHARED         → no handshake     → 802.1D slow ❌
 Link to a HOST    → mark it EDGE (PortFast)       → forward instantly, no TC ✅

 🕵️ This is why you HARDCODE speed/duplex on trunks: if autoneg lands on half-duplex,
    RSTP treats the trunk as SHARED and you silently lose rapid convergence.
```

### D) 🔀 Per-VLAN load-sharing (the PVST+ payoff)

```
 Two access→distribution uplinks. With ONE tree, one uplink is blocked (idle). Wasteful.

 Rapid PVST+ = one instance PER VLAN → place roots deliberately:
   VLAN 10 root = DIST-A  → VLAN 10 forwards on the A-uplink, blocks the B-uplink
   VLAN 20 root = DIST-B  → VLAN 20 forwards on the B-uplink, blocks the A-uplink

 Result: BOTH uplinks carry traffic (different VLANs) → no idle link → ~2× effective bandwidth.
   (Blocked-per-VLAN, not blocked overall.)  Cost: an STP instance per VLAN = more CPU.
```

### E) 🛠️ Configuration & verification

```
! Set the mode (rapid-pvst is the modern default; shown for clarity)
Switch(config)# spanning-tree mode rapid-pvst

! Per-VLAN root placement for load-sharing
DIST-A(config)# spanning-tree vlan 10 root primary       ! A = root for VLAN 10
DIST-B(config)# spanning-tree vlan 20 root primary       ! B = root for VLAN 20

! Make a trunk explicitly point-to-point (guarantee rapid on a possibly-autoneg link)
Switch(config-if)# spanning-tree link-type point-to-point

! Edge port for a host (= PortFast → immediate forwarding; detail in 2.19)
Switch(config-if)# spanning-tree portfast

! Verify
Switch# show spanning-tree
  VLAN0010
  Spanning tree enabled protocol rstp        ← 'rstp' = Rapid PVST+ running
Switch# show spanning-tree summary
  Switch is in rapid-pvst mode                ← confirms the mode
Switch# show spanning-tree vlan 10            ← per-VLAN roles/states (Altn/Back visible), Type P2p/Shr/Edge
```

> 🕵️ **Dirty secret — a duplex mismatch doesn't just hurt throughput, it *silently kills rapid convergence*.** If one end of a trunk auto-negotiates to **half-duplex**, RSTP classifies that link as **shared**, skips the proposal/agreement handshake entirely, and quietly reverts to the **30–50 s 802.1D** timers on that link — while `show spanning-tree` still says you're in `rapid-pvst mode`. You *think* you have sub-second failover; you actually have half-a-minute outages on that path. **Hardcode speed/duplex on trunks** (or explicitly set `link-type point-to-point`) so RSTP stays rapid. (This is the duplex-mismatch monster from 2.3 wearing a spanning-tree costume.)

## 7️⃣ Pros & Cons ⚖️

**RSTP vs 802.1D:**

| ✅ RSTP Pros | ❌ Cons / Caveats |
|---|---|
| 🟢 **Sub-second convergence** (handshake, no timers). | ⚠️ **Needs point-to-point (full-duplex)** — shared links fall back to slow. |
| 🟢 **Fast failure detection** (3 missed BPDUs ≈ 6 s). | 🔵 **Backward-compat fallback** to 802.1D loses the speed on legacy links. |
| 🟢 **Pre-computed alternates** → instant failover. | ⚠️ **Edge misconfig** (no PortFast) causes TCs / MAC flushes. |
| 🟢 **Better TC handling** (no root round-trip, selective flush). | |
| 🟢 **Default & standard** — just works. | |

**Rapid PVST+ (per-VLAN):**

| ✅ | ❌ |
|---|---|
| 🟢 **Per-VLAN roots → uplink load-sharing.** | 🔵 **CPU/memory scale with VLAN count** (MST fixes → CCNP). |
| 🟢 **Fine per-VLAN control** of the topology. | 🔵 More config surface than a single instance. |

## 🔟 Best Practices ✅

- 🟢 **Run `spanning-tree mode rapid-pvst`** (it's the default) — don't leave a network on legacy PVST+/802.1D.
- 🟢 **Keep inter-switch links full-duplex/point-to-point.** Hardcode speed/duplex on trunks (or set `link-type point-to-point`) so RSTP stays rapid.
- 🟢 **Mark host ports as edge (PortFast)** so they forward instantly and don't trigger topology changes (→ 2.19).
- 🟢 **Place per-VLAN roots deliberately** to load-share uplinks (different root per VLAN) — and set a `secondary` per VLAN too.
- 🔵 **Watch instance count** as VLANs grow; consider **MST** when per-VLAN CPU becomes a concern (CCNP).
- 🟢 **Verify the mode & link types** with `show spanning-tree summary` / `show spanning-tree vlan X` (confirm `rstp`, and `Type = P2p` on trunks).
- 🔵 **Protect the edge** with BPDU Guard so an edge port that unexpectedly sees a BPDU is caught (→ 2.19).

## 1️⃣1️⃣ No-Goes — Common Mistakes & Troubleshooting Traps 🚫

- ⚠️ **Duplex mismatch silently disabling rapid convergence.** Half-duplex ⇒ **shared** link ⇒ RSTP falls back to 30–50 s, while the mode still reads `rapid-pvst`. Hardcode duplex / set point-to-point.
- ❌ **Assuming RSTP fixes everything even toward legacy switches.** On a link to an 802.1D bridge, RSTP **falls back** to slow convergence for *that* link. Upgrade or expect the slowdown there.
- ⚠️ **Forgetting edge (PortFast) on host ports.** Non-edge access ports flapping generate **topology changes** and **MAC flushes** — needless churn. Mark them edge.
- ⚠️ **An edge port receiving a BPDU.** It **loses edge status** (a switch/hub was plugged into a "host" port). Investigate — and this is exactly what **BPDU Guard** catches (→ 2.19).
- ⚠️ **Not placing per-VLAN roots.** All VLANs default to the same root → one uplink blocked for everything (no load-sharing). Set per-VLAN roots.
- 🔵 **Ignoring instance scaling.** Hundreds of VLANs × per-VLAN STP = real CPU. Plan MST if needed.
- ⚠️ **Mismatched modes** across switches (one pvst, one rapid-pvst) → interop falls to the slower behavior. Standardize on `rapid-pvst`.
- 🔵 **Reading `protocol ieee` as RSTP.** `show spanning-tree` showing `protocol ieee` = legacy 802.1D/PVST+; `protocol rstp` = Rapid PVST+. Check which you're actually running.

## 1️⃣3️⃣ Practical Tasks 🛠️

> Listed briefly; expanded step-by-step later in context.

1. 🟢 **Confirm the mode (Packet Tracer 8 / GNS3).** `show spanning-tree summary` → "rapid-pvst mode"; `show spanning-tree vlan 1` → `protocol rstp`. Switch to `spanning-tree mode pvst` and observe `protocol ieee`, then back.
2. 🟢 **Time the convergence difference.** On the same triangle topology, fail the root port under **pvst** (time ~30–50 s) vs **rapid-pvst** (sub-second). Feel the difference with a continuous ping.
3. 🟢 **Identify RSTP roles/states/types.** `show spanning-tree vlan 1` → find **Altn/BLK** ports and the **Type** column (**P2p / Shr / Edge**).
4. 🔵 **Prove the shared-link penalty.** Force a trunk to **half-duplex**; observe the link become **Shr** and convergence slow down; restore full-duplex and watch rapid return.
5. 🟢 **Per-VLAN load-sharing.** Make SW-A root for VLAN 10 and SW-B root for VLAN 20; verify each uplink forwards for one VLAN and blocks for the other (`show spanning-tree vlan 10` vs `vlan 20`).
6. 🔵 **Watch the handshake (debug/sim).** In simulation mode, observe proposal/agreement BPDUs propagate as a wave when a link comes up.
7. 🔵 **Edge port behavior.** Mark a host port edge (PortFast); confirm instant forwarding and that flapping it causes **no** topology change; then plug a switch into it and watch it **lose edge status** (segue to 2.19).
