> 🎯 **Two delivery models beyond unicast.** 3.8 covered one-to-one (unicast). This doc covers **one-to-group (multicast)** and **one-to-nearest (anycast)** — and the crucial fact that IPv6 has **no broadcast at all**: multicast does that job, far more surgically.

## 2. 🗺️ Visualization — The Whole Picture at a Glance

**IPv6's three delivery models (broadcast is GONE):**

```
 UNICAST     one → one         (3.8)          ●──────▶●
 MULTICAST   one → group       ff00::/8        ●──────▶●●●   (only joiners)
 ANYCAST     one → nearest     (unicast space) ●──────▶◉ (of several identical ◉)
 ┌─ no BROADCAST ─┐  its job → multicast "all-nodes" ff02::1
```

**Multicast address anatomy (`ff00::/8`):**

```
   ff    │ 0RPT │ scope │        group ID (112 bits)
   8 bits│ flags│ 4 bits│
   1111…1│ └T=0 well-known / T=1 transient
          └ R=RP-embedded, P=prefix-based (RFC 3956/3306)
   scope:  1 interface · 2 LINK · 4 admin · 5 site · 8 org · e GLOBAL
   e.g.   ff02 ::1   =  ff, flags 0, scope 2 (link), group "all-nodes"
```

**Well-known groups you must recognise (link-local scope `ff02::`):**

```
 ff02::1   all nodes        ff02::9   RIPng          ff02::12  VRRP
 ff02::2   all routers      ff02::a   EIGRP for IPv6 ff02::16  MLDv2 routers
 ff02::5   OSPFv3 all       ff02::d   PIM routers    ff02::fb  mDNS
 ff02::6   OSPFv3 DR/BDR    ff02::1:2 DHCPv6 relay/srv  ff05::1:3 DHCPv6 servers (site)
 ff02::1:ffXX:XXXX  ← SOLICITED-NODE (NDP's ARP replacement)
```

**Solicited-node multicast — built from the low 24 bits of your address:**

```
   unicast   2001:db8:acad:1: 0000:0000:1234:5678
                                          └──24 bits──┘
   sol-node  ff02::1:ff34:5678          (ff02::1:ff + 34:5678)
   L2 MAC    33:33:ff:34:56:78          (33:33 + last 32 bits)
```

> 🧭 **One idea:** multicast delivers **only to those who joined**, and IPv6 uses a **per-address solicited-node group** so "who has this address?" wakes (almost) only the *one* target — the elegance that lets NDP replace ARP's shout-to-everyone.

## 3. ⚡ TL;DR

- 🟢 **IPv6 has no broadcast.** Its work is done by **multicast `ff00::/8`** — e.g. "all nodes on this link" = **`ff02::1`**, "all routers" = **`ff02::2`**.
- 🟢 **Multicast address = `ff` + 4-bit flags (`0RPT`) + 4-bit scope + 112-bit group ID.** **Scope** (`2`=link, `5`=site, `e`=global) controls reach; **T=0** = well-known (IANA), **T=1** = transient.
- 🟢 **Solicited-node multicast `ff02::1:ffXX:XXXX`** = `ff02::1:ff` + the **low 24 bits** of a unicast/anycast address. **NDP** uses it to resolve addresses — replacing ARP's broadcast (3.11).
- 🟢 **L2 mapping:** IPv6 multicast → MAC **`33:33` + the last 32 bits** of the group (RFC 2464).
- 🟢 **Anycast** = **one address on several nodes**; routed to the **nearest** by routing metric. Syntactically **identical to unicast** — you can't tell them apart by looking. Used for DNS roots, CDNs.
- 🟢 The **subnet-router anycast** address (prefix + **all-zero** interface ID) is reserved on every `/64` → never assign it to a host.
- 🔵 🕵️ **Solicited-node multicast is why IPv6 neighbour discovery is quieter than ARP** — a "who has X?" query interrupts (almost) only the target's NIC, not every host on the wire (§6.7).

---

## 4. 🎯 Importance — The Problem First

**The problem — "send to everyone" is wasteful, and "send to the nearest of many" was impossible.** Two distinct delivery needs:

1. 📣 **One-to-many, but only to the interested.** A router must reach "all OSPF routers on this link," a host must find "any router here," DHCPv6 must reach "the servers." **IPv4 used broadcast** for the crude version — and broadcast **hits every device on the segment**, forcing every NIC to interrupt its CPU to inspect a frame it usually doesn't care about (the cost you met in Block 2 and 3.6). It doesn't scale and it's noisy.
2. 🧭 **One-to-nearest-of-many.** Thirteen DNS root "servers" are actually hundreds of machines worldwide sharing the *same* address; your query should reach the **closest** one automatically. IPv4 had no first-class model for this.

**The solution — multicast everywhere, plus anycast.**
- **Multicast** delivers **only to nodes that explicitly joined the group** (via MLD), so an "all-routers" message never disturbs the printers. IPv6 makes this the *primary* group-delivery mechanism and **drops broadcast entirely**. It even builds a **per-address "solicited-node" group** so address-resolution queries reach essentially just the intended target — turning ARP's shout into a whisper.
- **Anycast** lets **many nodes share one address**; ordinary routing carries each packet to the **topologically nearest** instance — the foundation of resilient, low-latency global services (DNS, CDN).

> **Why this matters at engineer depth:** these two models are the plumbing under everything IPv6 "just does" — neighbour discovery, router discovery, DHCPv6, routing-protocol hellos, and internet-scale service resilience. Recognising `ff02::1` / `ff02::5` / `ff02::1:ffXX:XXXX` in a capture, and understanding *why* solicited-node is efficient, is the difference between reading IPv6 fluently and guessing.

## 5. 📖 Description

- 🟢 **Multicast (`ff00::/8`).** One-to-group; a **destination-only** address naming a set of **joined** receivers.
- 🟢 **Flags (`0RPT`).** High bit reserved(0); **R** = Rendezvous-Point embedded (RFC 3956); **P** = prefix-based (RFC 3306); **T** = Transient (1) vs well-known (0). (R⇒P,T also 1.)
- 🟢 **Scope (4 bits).** Reach limit: `1` interface-local, `2` link-local, `4` admin-local, `5` site-local, `8` organisation-local, `e` global.
- 🟢 **Well-known groups.** Permanent IANA assignments (T=0): all-nodes `ff02::1`, all-routers `ff02::2`, protocol groups (`ff02::5/6/9/a/d/12/16`), service groups (`ff02::fb`, `ff02::1:2`, `ff05::1:3`).
- 🟢 **Solicited-node multicast (`ff02::1:ffXX:XXXX`).** Auto-joined per unicast/anycast address; **low 24 bits** appended to `ff02::1:ff00::/104`. Powers NDP address resolution.
- 🟢 **Anycast.** One unicast-format address on **multiple** nodes; delivered to the **nearest** by routing. **Not syntactically distinguishable** from unicast.
- 🟢 **Subnet-Router anycast.** Prefix + **all-zero** interface ID; every router on a subnet answers it (RFC 4291 §2.6.1).
- 🔵 **MLD (Multicast Listener Discovery).** ICMPv6-based join/leave — the IPv6 analogue of IGMP (3.6).
- 🔵 **L2 mapping.** IPv6 multicast → MAC `33:33` + low 32 bits (RFC 2464); NICs hardware-filter on it.

## 6. 🔧 How It Works — Under the Hood

### 6.1 🟢 Three delivery models (and the missing fourth)

```
   UNICAST    one specific interface           (3.8)
   MULTICAST  every interface that JOINED the group   ff00::/8
   ANYCAST    the NEAREST of several interfaces sharing one address
   BROADCAST  —— does not exist in IPv6 —— (ff02::1 does the "all" job)
```

A multicast address is **only ever a destination** — a node never *sources* traffic from `ff…`. Membership is dynamic: nodes **join/leave** groups (MLD), and switches with **MLD snooping** forward a group's frames only out ports that joined (just like IGMP snooping, 3.6).

### 6.2 🟢 Multicast address anatomy

```
   |   8    |  4   |  4   |            112 bits            |
   |  1…1   |0RPT | scope |           group ID            |
   |  0xff  |flags|       |                               |
```

- **Read it fast:** `ff` → multicast; **2nd hex digit** = flags (usually `0`); **3rd hex digit** = **scope**; the rest names the group. So `ff05::1:3` = well-known, **site-local** (5), DHCPv6 servers.
- **Scope is enforced by routers:** a `scope 2` (link) group never crosses a router; `scope 5` stays in the site; `scope e` can go global. This is how "all-routers" stays on the wire while a global multicast stream can traverse the internet.

### 6.3 🟢 Well-known groups & scopes

| Group | Meaning | | Group | Meaning |
| ----- | ------- |-| ----- | ------- |
| `ff01::1` | all-nodes (interface) | | `ff02::a` | EIGRP for IPv6 |
| `ff02::1` | all-nodes (**link**) | | `ff02::d` | PIM routers |
| `ff02::2` | all-routers (link) — RS target | | `ff02::12` | VRRP |
| `ff02::5` | OSPFv3 all routers | | `ff02::16` | MLDv2 routers |
| `ff02::6` | OSPFv3 DR/BDR | | `ff02::fb` | mDNS |
| `ff02::9` | RIPng | | `ff02::1:2` | DHCPv6 relay/servers (link) |
| `ff02::1:ffXX:XXXX` | **solicited-node** | | `ff05::1:3` | DHCPv6 servers (site) |

> 🧠 **Anchor:** `::1` = nodes, `::2` = routers, and the protocol you know from IPv4 keeps a similar tail — RIP `::9` (like `224.0.0.9`), and the IPv6 newcomers OSPFv3 `::5/6`, EIGRP `::a`.

### 6.4 🟢 Solicited-node multicast — the surgical group

Every interface **auto-joins**, for **each** of its unicast/anycast addresses, a solicited-node group formed from that address's **low 24 bits**:

```
   take addr   2001:db8:acad:1::1234:5678
   low 24 bits =            34:5678
   sol-node   = ff02::1:ff + 34:5678  →  ff02::1:ff34:5678     (RFC 4291)
   RFC example: 4037::01:800:200E:8C6C → ff02::1:ff0e:8c6c
```

When a node needs the L2 address for `2001:db8:acad:1::1234:5678`, NDP sends a **Neighbor Solicitation to `ff02::1:ff34:5678`** — **not** a broadcast. Only interfaces whose address shares those **low 24 bits** are even listening, so realistically just the **target** processes it (24 bits ⇒ ~16.7M combinations ⇒ collisions rare). The full NS/NA exchange is **3.11**; here, the point is the **address** and why it's efficient.

### 6.5 🟢 Layer-2 mapping (`33:33`)

IPv6 multicast maps to a destination MAC of **`33:33`** followed by the **last 32 bits** of the IPv6 group (RFC 2464):

```
   ff02::1              → 33:33:00:00:00:01
   ff02::1:ff34:5678    → 33:33:ff:34:56:78
```

NIC hardware **filters** on this MAC, so a host's CPU is only interrupted for groups it joined — the L2 half of multicast's efficiency. (Contrast IPv4's `01:00:5E` 23-bit map with its 32:1 overlap, 3.6 — IPv6's 32-bit map is cleaner.)

### 6.6 🟢 Anycast — one address, nearest node

Anycast assigns **the same address to multiple nodes**; the routing system, seeing several paths to that prefix, forwards each packet to the **topologically nearest** instance (lowest metric). Key facts:

- 👀 **Indistinguishable from unicast.** There's no "anycast bit"; it's a *deployment*, not a format (RFC 4291 §2.6). A receiver may not know it's anycast.
- 🧭 **"Nearest" = routing metric, not geography.** The closest instance by hop/cost wins — which usually *correlates* with geography but isn't guaranteed.
- 🧱 **Subnet-Router anycast** — the address with the **interface ID all zeros** (e.g. `2001:db8:acad:1::`) is a reserved anycast that **every router on that `/64` answers**; used so a host can reach "a router on my subnet." Never assign it to a host.
- 🌍 **Real uses:** the DNS **root/TLD servers**, **CDNs**, and time services deploy one anycast address across many global sites for **resilience + low latency**.
- 🔵 **Caveat (stateful protocols):** because different packets *could* land on different instances, anycast suits **stateless/short** exchanges (DNS/UDP) best; TCP anycast works only because a given flow's path is stable enough for its duration — a routing change mid-flow can break it. (Design nuance, CCNP.)

### 6.7 🕵️ Dirty Secret — solicited-node multicast is why NDP out-classes ARP

IPv4 **ARP** asks "who has 192.168.1.50?" by **broadcasting** to `ff:ff:ff:ff:ff:ff` — **every NIC on the segment** receives it, interrupts its CPU, inspects the packet, and (usually) discards it. On a busy VLAN with thousands of hosts, ARP is a constant, wasteful background roar. 📣

IPv6 **NDP** replaces that broadcast with a **solicited-node multicast**:

```
   "who has 2001:db8::1234:5678?"  →  NS to ff02::1:ff34:5678  →  MAC 33:33:ff:34:56:78
   Only NICs whose address ends in ...34:5678 are subscribed / hardware-listening.
   ⇒ ~1 host wakes its CPU, not all N.   Broadcast roar → targeted whisper. 🤫
```

**Why it's clever:** the group is derived from the *target's own low 24 bits*, so the querier can compute exactly which group to hit **without** already knowing the target's MAC — solving ARP's bootstrap problem *and* its noise problem at once. NIC hardware filtering on the `33:33:ff:xx:xx:xx` MAC means non-target hosts drop the frame **in silicon**, never bothering the OS.

> **Engineer takeaway:** this is a concrete answer to "why is IPv6 better, not just bigger?" The same instinct that makes **switching faster than flooding** (Block 2) drives IPv6's design: **replace broadcast with precisely-scoped multicast**. When you see `ff02::1:ffXX:XXXX` in a capture, you're watching ARP's noisy shout replaced by a targeted multicast — efficiency by design, not accident.

## 7. ⚖️ Pros & Cons

| Model | ✅ Strengths | ❌ Watch-outs |
| ----- | ----------- | ------------ |
| **Multicast** | Delivers only to joiners; scoped; kills broadcast noise 🤫 | Needs MLD (+ snooping) to prune; misconfig = flooding or black holes |
| **Solicited-node** | Near-surgical address resolution; solves ARP's bootstrap+noise | 24-bit overlap means *rare* extra listeners (not truly 1:1) |
| **Anycast** | Resilience + low latency at global scale 🌍 | "Nearest" = metric not geography; stateful/TCP flows need care |
| **(No broadcast)** | Cleaner, quieter L2 | Mental re-tooling for IPv4-trained engineers |

## 8. 🌿 Variants — Common → Specific

- 🟢 **Multicast scopes:** interface `ff01::` · **link `ff02::`** (by far the most common) · site `ff05::` · global `ff0e::`.
- 🟢 **Well-known vs transient:** T=0 IANA groups (`ff02::1`, `ff02::5`…) vs T=1 app-assigned (`ff15::…`).
- 🟢 **Solicited-node** `ff02::1:ffXX:XXXX` — the per-address NDP group.
- 🔵 **Prefix-based / RP-embedded multicast** (P/R flags, RFC 3306/3956) — advanced multicast (CCNP+).
- 🟢 **Anycast:** subnet-router anycast (all-zero interface ID) · service anycast (DNS/CDN).
- ⚪ **Compare IPv4 (3.6):** `224.0.0.0/4` + `01:00:5E` map; IPv6 modernises both.

## 10. ✅ Best Practices

- 🟢 **Recognise groups on sight** — `ff02::1` all-nodes, `ff02::2` all-routers, `ff02::5/6` OSPFv3, `ff02::1:ffXX:XXXX` solicited-node.
- 🟢 **Read scope from the 3rd hex digit** to know how far a group travels (`2` link, `5` site, `e` global).
- 🟢 **Enable MLD snooping** on switches so multicast doesn't degrade into flooding.
- 🟢 **Never assign the all-zero-interface-ID address** (subnet-router anycast) to a host.
- 🔵 **Use anycast for stateless, resilient services** (DNS/NTP/CDN); design carefully before putting long-lived TCP on anycast.
- 🔵 **Filter multicast at scope boundaries** deliberately — don't let site/org groups leak globally.

## 11. 🚫 No-Goes — Common Mistakes & Troubleshooting Traps

- ❌ **Expecting broadcast in IPv6.** There is none — use `ff02::1` for "all nodes."
- ❌ **Using a multicast address as a source.** Multicast is destination-only.
- ❌ **Assigning the subnet-router anycast (`…::`) to a host.** It's reserved for routers on the `/64`.
- ❌ **Assuming solicited-node is perfectly 1:1.** It's the low **24 bits** — rare overlaps mean an occasional extra listener (still vastly better than broadcast).
- ❌ **Assuming anycast "nearest" = closest city.** It's the lowest **routing metric**; topology, not geography, decides.
- 🕵️ **Trap — multicast "works then floods."** Missing/ misbehaving **MLD snooping** turns a joined group into segment-wide flooding → check snooping and the MLD querier.
- 🕵️ **Trap — NDP resolution fails but ping-by-MAC works.** Suspect a **solicited-node group not joined** (address mis-add, DAD failure 3.11) or an L2 filter dropping `33:33:ff:xx:xx:xx`.
- ❌ **Confusing scope with flags.** 3rd hex digit = scope; 2nd = flags. `ff05::` is site-scope, not a flag setting.

## 13. 🧪 Practical Tasks

1. 🧮 **Solicited-node drill ×5.** Compute the solicited-node group **and** its `33:33` MAC for: `2001:db8::1`, `fe80::21d:a1ff:fe8b:36d0`, `2001:db8:acad:1::abcd:1234`.
2. 🔎 **Decode multicast addresses.** For `ff02::1`, `ff05::1:3`, `ff0e::abcd`, `ff12::7`: state flags, scope, and whether it's well-known or transient.
3. 🖥️ **See joined groups.** On a host: `ip -6 maddr show` (Linux) — identify `ff02::1` and your solicited-node group(s). On Cisco: `show ipv6 interface` → the **Joined group address(es)** list (`FF02::1`, `FF02::1:FFxx:xxxx`, and `FF02::2` if it's a router).
4. 🧰 **Packet Tracer 8 — anycast subnet-router.** Configure two routers on one `/64`; from a host, target the all-zero-interface-ID address and observe a router answering. Confirm hosts must **not** use it.
5. 🔬 **Wireshark — NDP vs ARP.** Capture IPv6 neighbour resolution: find the **NS to `ff02::1:ffXX:XXXX`** at L3 and **`33:33:ff:xx:xx:xx`** at L2. Compare with an IPv4 ARP broadcast (`ff:ff:ff:ff:ff:ff`) — literally see whisper vs shout (deepens in 3.11).
6. 📡 **MLD snooping (🔵).** In PT/GNS3, enable then disable MLD snooping on a switch carrying a multicast stream; observe flooding appear/disappear on non-member ports.
7. 🌍 **Anycast in the wild (🔵).** Trace/`ping` a public anycast DNS resolver from two different networks and note different responding sites for the *same* address.
