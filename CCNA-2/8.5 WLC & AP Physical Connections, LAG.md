## 3. ⚡ TL;DR

- **Local-mode lightweight AP → switch ACCESS port** (one VLAN). All client traffic is **CAPWAP-tunneled** to the WLC, so the AP only carries its *own* management VLAN — it doesn't tag client VLANs.
- **Autonomous AP → TRUNK port.** **FlexConnect (local switching) AP → TRUNK port.** Both drop client traffic onto **multiple local VLANs**, so the switch must trunk them.
- **WLC → 802.1Q TRUNK port** (always). VLAN separation for all WLANs happens *at the WLC*, via **dynamic interfaces**.
- **WLC logical interfaces:** **Management** (in-band mgmt + CAPWAP + AAA), **AP-manager** (L3 to APs; folded into mgmt on newer WLCs), **Virtual** (guest web-auth, DHCP relay, mobility — a non-routable IP like **192.0.2.1**, shared across a mobility group), **Service-port** (out-of-band mgmt, separate subnet), **Dynamic** (each maps a WLAN→VLAN, like a switch SVI; up to 512).
- **WLC physical ports:** **Distribution system** (data to switch), **Service** (OOB mgmt), **Console** (CLI), **Redundancy** (HA SSO).
- **LAG (IEEE 802.3ad):** bundles all distribution ports into **one EtherChannel** → more bandwidth, load-balancing, redundancy, simpler mapping. 🚨 **AireOS WLCs don't do LACP/PAgP → switch must be `mode on` (static).** One LAG per controller; enabling it reboots the WLC. *(Catalyst 9800 supports LACP.)*

## 4. 🎯 Importance — The Problem First

**The problem:** Everything logical is in place — the WLC is the brain (8.3), APs have roles (8.4), CAPWAP tunnels are ready. Now you have to *physically cable it into the wired network*, and that forces two concrete questions with non-obvious answers:

**Question 1 — "What switchport does an AP need?"**
Your instinct says: an AP serves Corp + Guest + IoT SSIDs, that's three VLANs, so obviously it needs a **trunk**, right?

**Wrong** — and *why* it's wrong is the whole point of this topic. A **local-mode lightweight AP tunnels ALL client traffic inside CAPWAP** back to the WLC (8.3). On the wire between the AP and its switch, there is only **one** kind of traffic: the CAPWAP tunnel itself, living in **one** management VLAN. The AP never puts a client's Corp or Guest frame directly onto the wire — it wraps them in CAPWAP and ships them to the WLC. So the AP needs just an **access port**. The VLAN sorting happens later, **at the WLC**, which *is* on a trunk.

Flip the AP to **FlexConnect local switching** or make it **autonomous**, and everything changes: now the AP drops client frames straight onto local VLANs, so it's back to needing a **trunk**. The port type literally encodes *where the client traffic exits the tunnel*.

**Question 2 — "How does the WLC connect, and is one link enough?"**
The WLC carries *all* wireless traffic for potentially thousands of clients across dozens of VLANs. One 1 Gbps uplink is a bottleneck and a single point of failure. **LAG** bonds several physical WLC ports into one logical pipe — more bandwidth *and* automatic failover. But WLC LAG has a sharp edge: on AireOS it **doesn't negotiate** (no LACP), so a mismatched switch config silently breaks every AP join.

Why an engineer must own this:
- **It's the #1 "APs won't join / clients can't reach their VLAN" root cause.** Wrong port type, wrong native VLAN, wrong LAG mode — all physical-layer mistakes.
- **The access-vs-trunk logic reveals how CAPWAP actually works.** If you understand *why* a local-mode AP uses an access port, you truly understand tunneling. It's a litmus test.
- **Design & security:** trunk-to-AP is a security exposure (unplug the AP → attacker gets every VLAN); interface planning (management/dynamic/virtual) determines how clients reach services and how guests get portals.

> 🕵️ **Dirty secret (the big one):** The device that presents the *most* networks (the AP, with all its SSIDs) needs the *simplest* port (single-VLAN access), while the device you might think is "just a controller" (the WLC) needs the **trunk**. Everyone gets this backwards at first. The rule to burn in: **client traffic is tagged where it *leaves the CAPWAP tunnel*** — at the WLC in central mode (so WLC = trunk, AP = access), or at the AP in FlexConnect/autonomous (so AP = trunk).

## 5. 📖 Description

### AP-side connections 🟢
- **Local-mode lightweight AP → access port.** Carries only the CAPWAP tunnel in one VLAN; client VLANs are invisible on this link. *(An access port for VLAN X is functionally equivalent to a trunk whose native VLAN is X, for the AP's own traffic.)*
- **Autonomous AP → trunk port.** Bridges each SSID to its VLAN locally; the switch must carry all those tagged VLANs.
- **FlexConnect AP (local switching) → trunk port.** Switches client traffic locally onto tagged VLANs; needs a **native VLAN** for its own CAPWAP/management plus tagged VLANs for clients.

### WLC logical interfaces (AireOS model) 🟢
- **Management interface** — *mandatory*. In-band management (GUI/SSH/SNMP), AAA/RADIUS connectivity, and **CAPWAP termination** / Layer-2 comms with APs. The address APs are usually pointed at.
- **AP-manager interface** — handles **Layer 3 CAPWAP** communication with lightweight APs. On **older** AireOS it was a separate interface; on **newer** WLCs the **management interface performs this role** (no separate AP-manager needed).
- **Virtual interface** — a **non-routable, "fake" IP** (recommended **192.0.2.1**, RFC 5737 documentation range; historically `1.1.1.1`), identical across all controllers in a **mobility group**. Used for **client web/guest authentication redirect**, **DHCP relay** (it's the DHCP server address clients see), and **mobility management**.
- **Service-port interface** — bound to the physical **service port**; **out-of-band** management, recovery/maintenance. **Must be on a different subnet** than the management interface. Optional (small models lack it).
- **Dynamic interfaces** — user-created; each is analogous to a switch **SVI**, mapping a **WLAN → a VLAN + subnet**. This is **where client traffic egresses onto the wired network**. Up to **512** per controller; can serve as the **DHCP relay** address for its VLAN.

### WLC physical ports 🟢
- **Distribution system ports** — the high-speed **data ports** (1G/10G, copper or SFP) to the switch; **default 802.1Q trunk**; aggregatable via **LAG**.
- **Service port** — dedicated **10/100 out-of-band** management port (recovery/maintenance).
- **Console port** — serial/USB CLI access.
- **Redundancy port** — links two WLCs for **HA SSO** (stateful failover).

### LAG — Link Aggregation 🟢
- Per **IEEE 802.3ad**, bundles **all** distribution-system ports into **one logical EtherChannel/port-channel**. Benefits: **aggregate bandwidth**, **load-balancing** across links, **port redundancy**, and **simpler** interface-to-port mapping.

## 6. 🔧 How It Works — Under the Hood

### 6.1 Why local-mode AP = access, WLC = trunk 🟢

```
   CENTRAL (LOCAL-MODE) FORWARDING
   ───────────────────────────────
   client's Corp frame ─► AP wraps it in CAPWAP ─► ACCESS port (1 VLAN)
        ─► across the network (any routed path) ─► WLC
        ─► WLC unwraps, places frame on VLAN 21 (Corp) via dynamic iface
        ─► out the WLC's TRUNK to the wired core

   The wire from AP→switch never sees VLAN 21. It only sees the CAPWAP
   tunnel in, say, VLAN 11 (AP-management). One VLAN → ACCESS port.
   The WLC is where Corp/Guest/IoT split apart → TRUNK.
```

```
   FLEXCONNECT / AUTONOMOUS (LOCAL SWITCHING)
   ──────────────────────────────────────────
   client's Corp frame ─► AP tags it VLAN 21 directly ─► TRUNK port
        ─► onto the local wired VLAN (no trip to WLC)

   Now the AP↔switch wire carries VLAN 11 (native, for CAPWAP mgmt)
   + VLAN 21/22 (tagged client traffic) → must be a TRUNK.
```

The port type is a direct readout of **where the CAPWAP tunnel ends**. Central mode ends it at the WLC (AP=access); FlexConnect/autonomous ends it at the AP (AP=trunk).

### 6.2 The WLC interfaces in action 🟢

```
   ┌──────────────────────── WLC ────────────────────────┐
   │ Management  10.0.10.5  ─ APs join here, admin GUI     │
   │ Virtual     192.0.2.1  ─ guest portal / DHCP relay    │
   │ Dynamic-Corp 10.0.21.1 (VLAN 21) ─ WLAN "Corp" egress │
   │ Dynamic-Guest 10.0.22.1(VLAN 22) ─ WLAN "Guest" egress│
   │ Service-port 172.16.9.5 ─ OOB recovery (own subnet)   │
   └───────────────────┬──────────────────────────────────┘
                       │ 802.1Q TRUNK (VLANs 10,21,22,…)
                 ┌─────┴─────┐
                 │  switch   │
```
- A **WLAN** on the WLC = an SSID mapped to a **dynamic interface** (→ VLAN). Create "Corp" → map to Dynamic-Corp → clients land on VLAN 21. That's how one WLC fans wireless SSIDs out to wired VLANs.
- The **virtual interface's** 192.0.2.1 is never routed — it's a consistent internal anchor so guest web-auth and DHCP relay behave identically as clients roam across controllers in a mobility group.

### 6.3 LAG — bonding the uplinks 🟢

```
   WLC  P1 ═╗
            ╠══ one logical EtherChannel ══► switch Port-channel
   WLC  P2 ═╝   (e.g. 2×1G = 2 Gbps, redundant)

   Switch side (AireOS WLC):
     interface range Gi1/0/1 - 2
      channel-group 1 mode on        ◄── MUST be "on" (static). NO LACP/PAgP!
     interface Port-channel1
      switchport mode trunk
      switchport trunk allowed vlan 10,21,22
```
- **Enable LAG on the WLC** (Controller → LAG mode → enable) → **requires a reboot**.
- On enable: **dynamic AP-manager interfaces and untagged interfaces are deleted**; **all** interfaces now ride the **single LAG**; no per-interface primary/backup port mapping needed (redundancy is inherent).
- **Only ONE LAG group** per controller.
- 🚨 **AireOS WLCs support neither LACP nor PAgP** → the switch **must** use `mode on` (unconditional). Configure LACP on the switch and the bundle won't form → APs won't join.
- **Without LAG:** each interface is pinned to a **primary** distribution port, with an optional **backup** port; if the primary fails, the interface fails over to the backup. (More manual, less bandwidth.)

> 🕵️ **Dirty secret:** The **Catalyst 9800** (IOS-XE) generation **does** support **LACP** (and behaves much more like normal EtherChannel). So "WLC LAG = static/mode-on only" is an **AireOS** truth that's fading — but AireOS gear is everywhere and it's exactly the kind of version-specific gotcha the CCNA loves. Know both: *AireOS → `mode on`; 9800 → LACP OK.*

### 6.4 Trunk-to-AP: a security note 🔵
A trunk port to a FlexConnect/autonomous AP is convenient but exposes **every allowed VLAN** if someone unplugs the AP and plugs in a laptop. Mitigate with **802.1X on the switchport** (the AP authenticates; on success the port becomes a trunk), plus `spanning-tree portfast [trunk]` + **BPDU guard** on AP access ports for fast, safe bring-up.

## 7. ⚖️ Pros & Cons

**Access port to AP (local mode)**
✅ Simple, one VLAN, safer (no VLAN exposure) · ✅ Matches central CAPWAP forwarding
❌ Only works when client traffic is tunneled (not FlexConnect/autonomous)

**Trunk port to AP (FlexConnect/autonomous)**
✅ Enables local switching (no WAN hairpin), multiple client VLANs at the AP
❌ Security exposure if unsecured · ❌ More config (native VLAN, allowed list)

**LAG on the WLC**
✅ Bandwidth aggregation, load-balancing, port redundancy, simpler mapping
❌ **No LACP/PAgP on AireOS** (switch must be `mode on`) · ❌ One group only · ❌ Enable/disable needs reboot

**No LAG (primary/backup mapping)**
✅ Fine for small/single-link WLCs · ✅ Per-interface backup port failover
❌ No bandwidth aggregation · ❌ Manual interface-to-port planning

## 8. 🔀 Variants (Common → Specific)

- **AP switchport:** Access (local mode) → Trunk (FlexConnect local switching / autonomous). 🟢
- **WLC interfaces:** Management → AP-manager → Virtual → Service-port → Dynamic. 🟢
- **WLC physical ports:** Distribution system → Service → Console → Redundancy. 🟢
- **Uplink resilience:** Single link → primary/backup port mapping → **LAG (EtherChannel)**. 🟢
- **LAG negotiation:** AireOS **static `mode on`** vs Catalyst 9800 **LACP-capable**. 🔵
- **Forwarding that sets AP port type:** Central (tunnel to WLC) vs Local (FlexConnect/autonomous). 🟢

## 9. 🧩 Devices / Media / Protocols

- **Lightweight AP** — access port (local) or trunk (FlexConnect); speaks CAPWAP to the WLC.
- **Autonomous AP** — trunk port; bridges SSID↔VLAN locally.
- **WLC** — trunk-connected; logical interfaces (mgmt/AP-mgr/virtual/service/dynamic) + physical ports (distribution/service/console/redundancy).
- **Access/Distribution switch** — provides the access/trunk ports, EtherChannel/Port-channel, PoE (Block 1) to power APs.
- **Protocols/standards:** **802.1Q** (trunk tagging), **802.3ad** (LAG), **CAPWAP** (the tunnel deciding port type), **LACP/PAgP** (negotiation — *not* on AireOS), **HA SSO** (redundancy port).
- **Related:** DHCP relay (via dynamic/virtual interface), 802.1X (secure AP switchport), PortFast/BPDU guard.

## 10. ✅ Best Practices

- **Local-mode APs → access ports**; **FlexConnect/autonomous APs → trunk ports** with a correct **native VLAN** for management.
- **Always trunk the WLC** with only the needed VLANs allowed (management + each client VLAN).
- **Use LAG** on multi-port WLCs for bandwidth + redundancy; on **AireOS set the switch to `mode on`** (no LACP); on **9800**, LACP is fine.
- **Keep the service port on its own subnet**, separate from management, for true out-of-band recovery.
- **Give the virtual interface a non-routable doc-range IP (192.0.2.1)**, identical across the mobility group.
- **Secure AP switchports** with 802.1X (especially trunked FlexConnect ports) and apply **PortFast + BPDU guard** for fast, safe AP bring-up.
- **Plan dynamic interfaces = client VLANs** up front; map each WLAN to the right one.

## 11. 🚫 No-Goes & Troubleshooting Traps

- ❌ **Trunking a local-mode AP "because it has many SSIDs"** — unnecessary; it only needs an access port (client traffic is tunneled). The extra VLANs are a security exposure.
- ❌ **Access-porting a FlexConnect/autonomous AP that switches locally** — its tagged client VLANs have nowhere to go; clients break.
- ❌ **Wrong native VLAN on a trunked AP** — AP can't reach the WLC / won't join (a very common FlexConnect join failure).
- ❌ **Configuring LACP on the switch for an AireOS WLC LAG** — bundle never forms; APs won't join. Use **`mode on`**.
- ❌ **Expecting more than one LAG group** on a WLC — only one is supported.
- ❌ **Service port on the same subnet as management** — not allowed; breaks OOB.
- ❌ **Forgetting LAG enable/disable reboots the WLC** — schedule it.
- ❌ **Leaving trunked AP ports unsecured** — unplug-and-pivot gives an attacker every VLAN.

**Troubleshooting map — "AP won't join / client can't reach its VLAN":**
```
   AP won't join?
     ├─ Local mode  → is the port an ACCESS port in the AP-mgmt VLAN? IP/DHCP ok?
     ├─ FlexConnect → is the port a TRUNK with the right NATIVE VLAN? allowed list?
     └─ Reachability to WLC mgmt IP? (CAPWAP/UDP 5246 — see 8.3)
   Joined but clients get no IP / wrong network?
     ├─ WLAN mapped to the right DYNAMIC interface (VLAN)?
     ├─ WLC trunk allows that VLAN? DHCP relay set on the dynamic interface?
   WLC uplink flaky / low throughput?
     └─ LAG mismatch: switch must be "mode on" (AireOS). One LAG only. Reboot applied?
```

## 13. 🛠️ Practical Tasks (expanded later in context)

1. **Packet Tracer 8 — full stack:** L3 switch + WLC + 2 lightweight APs. Configure: AP ports as **access** (AP-mgmt VLAN), the **WLC port as an 802.1Q trunk** (mgmt + 2 client VLANs), DHCP scopes, and WLC **dynamic interfaces** per WLAN. Verify a client on "Corp" lands on VLAN 21 and "Guest" on VLAN 22.
2. **Access-vs-trunk proof:** with a local-mode AP on an **access** port, sniff the AP↔switch link — confirm you see **only CAPWAP** in one VLAN, never client VLAN tags. Then (lab) convert to FlexConnect local switching and watch tagged client VLANs appear → now it needs a **trunk**.
3. **WLC interface tour:** on a real/CML WLC, identify the **management, virtual (192.0.2.1), service-port, and dynamic** interfaces; map each WLAN to its dynamic interface; note which physical port each lands on.
4. **LAG build:** enable **LAG** on the WLC (observe the reboot + AP-manager interface deletion), then configure the switch `Port-channel` with **`channel-group X mode on`** and `switchport mode trunk`. Verify the bundle is up and APs re-join. Then deliberately set the switch to **LACP** and watch it **break** — the AireOS gotcha, live.
5. **Native-VLAN failure drill:** trunk a FlexConnect AP but set the **wrong native VLAN**; confirm the join fails; fix the native VLAN and confirm recovery.
6. **Interface-type flashcards:** from memory, list the 5 WLC logical interfaces + 4 physical ports and one purpose each; and state the AP port type for local / FlexConnect / autonomous. Direct exam patterns.
