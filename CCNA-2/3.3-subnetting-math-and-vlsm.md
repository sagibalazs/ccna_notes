## 2. 🗺️ Visualization — The Master Reference (memorise this)

**The subnetting cheat-table. Everything below /24 flows from these 8 rows:**

```
 Prefix  Mask (last octet)  Block   Subnets(/24)  Host bits  Usable hosts
 ──────  ─────────────────  ─────   ────────────  ─────────  ─────────────
  /24    .0    (255...0)     256          1            8         254
  /25    .128  (11111111>7)  128          2            7         126
  /26    .192               64            4            6          62
  /27    .224               32            8            5          30
  /28    .240               16           16            4          14
  /29    .248                8           32            3           6
  /30    .252                4           64            2           2
  /31    .254                2          128            1        2 🅁🄵🄲3021*
  /32    .255                1          256            0        1 (host route)
```
`* /31 = 2 usable, NO network/broadcast — point-to-point only (§6.6)`

**The two lines you write at the top of EVERY subnet problem:**

```
   bit value :  128  64  32  16   8   4   2   1     ← the "magic 8"
   powers 2ⁿ :   2   4   8  16  32  64 128 256      ← subnets / block sizes
```

**The whole method on one napkin:**

```
   ① block size = 256 − (mask value in the interesting octet)
   ② subnets are MULTIPLES of the block size
   ③ NETWORK   = the multiple the host falls into (round DOWN)
   ④ BROADCAST = next multiple − 1
   ⑤ HOSTS     = everything between network+1 and broadcast−1
```

> 🧭 **The core trick:** you never work in 32 bits. You find the **one "interesting octet"** (where the mask isn't 0 or 255) and do simple base-10 arithmetic there. That's the whole game.

## 3. ⚡ TL;DR

- 🟢 **Subnets = `2ˢ`** (s = borrowed bits). **Usable hosts = `2ʰ − 2`** (h = host bits). *Never* swap the −2 (from 3.2 §6.6).
- 🟢 **Block size = `256 − mask value`** in the interesting octet. Subnets land on multiples of it; that's the fast method.
- 🟢 For any host: **round down to the block multiple = network**, **next multiple − 1 = broadcast**, everything between = usable hosts.
- 🟢 **VLSM** = assign different masks from one block, **largest requirement first**, so subnets align and never overlap.
- 🟢 **Mask ⇄ prefix:** add the octet bit-values (`128+64=192` = /26). **Wildcard** = `255 − mask` per octet (for ACLs/OSPF, 🔵).
- 🔵 🕵️ **/31 breaks the −2 rule** — RFC 3021 gives **2 usable** addresses on a P2P link with no network/broadcast, halving link cost vs /30.

## 4. 🎯 Importance — The Problem First

**The problem:** 3.2 gave you the *idea* of moving the boundary. But an engineer doesn't get to say "somewhere around here." Given `10.20.30.200/27`, you must state — instantly and correctly — the **network**, **broadcast**, **usable range**, and **whether two hosts can talk without a router**. Get it wrong and you assign an address that's actually a broadcast, or a gateway outside the subnet, and the link silently dies.

Two failure modes make this a *skill*, not a lookup:
- 🐢 **Too slow.** Converting all 32 bits by hand for every question wastes minutes you don't have on a timed exam or a 2 a.m. outage.
- 🗑️ **Too wasteful.** Using one fixed mask (FLSM) everywhere strands thousands of addresses — a point-to-point link that needs **2** addresses shouldn't consume a **/24**.

**The solution — a fast, octet-local method + VLSM.** The block-size method (§2) collapses the work into one octet of base-10 math, so any subnet question is ~10 seconds on paper. **VLSM** then lets you right-size *every* segment from a single parent block — big LANs get big subnets, router links get /30 or /31 — with zero overlap and minimal waste. Master these two and subnetting stops being scary maths and becomes muscle memory.

> **Why it's worth over-learning:** this exact skill reappears in **CIDR summarisation (3.4)**, **OSPF wildcard masks (Block 4)**, **ACLs (Block 9)**, and **IPv6 prefixes (3.7)**. Subnetting fluency is leverage across the entire certification and the job.

## 5. 📖 Description

- 🟢 **Interesting octet.** The single octet where the mask is neither `0` nor `255` — the only place you do arithmetic.
- 🟢 **Block size (a.k.a. magic number).** `256 − mask value` in that octet; the "step" between consecutive subnets.
- 🟢 **Network address.** Host bits all `0`; the first address of a subnet; names the subnet, not a host.
- 🟢 **Broadcast address.** Host bits all `1`; the last address; "all hosts on this subnet."
- 🟢 **Usable / valid host range.** Network+1 … broadcast−1. Count = `2ʰ − 2`.
- 🟢 **FLSM (Fixed-Length).** One mask for all subnets. Simple, wasteful.
- 🟢 **VLSM (Variable-Length).** Different masks per subnet from one block; assign **largest-first**.
- 🟢 **Prefix ⇄ mask.** `/n` = n leading `1`s. Add bit-values in the interesting octet to get the dotted mask.
- 🔵 **Wildcard mask.** Inverse of the subnet mask (`255 − each octet`); used by ACLs and OSPF `network` statements.
- 🔵 **/31 & /32.** `/31` = 2 usable on P2P (RFC 3021); `/32` = a single host route (loopbacks, host ACLs).

## 6. 🔧 How It Works — Under the Hood (the methods)

### 6.1 🟢 Convert prefix ⇄ mask in your head

The prefix counts `1`s left-to-right. Fill octets 8 at a time; the leftover bits fill the **interesting octet** using the magic-8 line:

```
   /26 → 8 + 8 + 8 + 2   → 255.255.255.(128+64) = 255.255.255.192
   /19 → 8 + 8 + 3       → 255.255.(128+64+32).0 = 255.255.224.0
   /29 → 8+8+8+5         → 255.255.255.(128+64+32+16+8) = 255.255.255.248
```

Mask-octet ↔ prefix quick map (worth memorising): `128=/x+1, 192=+2, 224=+3, 240=+4, 248=+5, 252=+6, 254=+7, 255=+8`.

### 6.2 🟢 The block-size method — WORKED EXAMPLE ①  *"find everything"*

> **Given `192.168.10.100 /26` — find network, broadcast, usable range.**

```
   ① mask /26 = 255.255.255.192  → interesting octet = 4th, value 192
      block size = 256 − 192 = 64
   ② multiples of 64:  0, 64, 128, 192
   ③ 100 falls between 64 and 128 → round DOWN → NETWORK = 192.168.10.64
   ④ next multiple 128, minus 1  → BROADCAST = 192.168.10.127
   ⑤ USABLE = 192.168.10.65  →  192.168.10.126     (62 hosts, = 2⁶−2)
```

Answer in ~10 seconds, no binary needed. ✅

### 6.3 🟢 Sizing a subnet — WORKED EXAMPLE ②  *FLSM "I need N subnets"*

> **Given `172.16.0.0/16` — carve into at least 6 equal subnets.**

```
   need ≥ 6 subnets → 2ˢ ≥ 6 → s=3 gives 2³=8 ✅ (s=2 gives 4 ✗)
   borrow 3 bits from /16  → new prefix /19
   /19 = 255.255.224.0  → interesting octet = 3rd, value 224
   block size = 256 − 224 = 32   (step in the 3rd octet)

   Subnet   Network        Broadcast        Usable range
   1        172.16.0.0     172.16.31.255    172.16.0.1  – 172.16.31.254
   2        172.16.32.0    172.16.63.255    172.16.32.1 – 172.16.63.254
   3        172.16.64.0    172.16.95.255    ...
   ...      (step 32)                       hosts each = 2¹³−2 = 8190
   8        172.16.224.0   172.16.255.255
```

Two of every octet-arithmetic problem uses the *same* five steps — only the interesting octet moves.

### 6.4 🟢 VLSM — WORKED EXAMPLE ③  *the real-world one (largest-first)*

> **You own `192.168.1.0/24`. Address these, minimum waste:**
> **LAN A = 50 hosts · LAN B = 25 hosts · LAN C = 10 hosts · Link 1 = 2 hosts · Link 2 = 2 hosts.**

**Rule: sort requirements largest → smallest, then hand out blocks in order.**

```
 Need  Hosts formula      Prefix  Block  Assigned subnet     Bcast          Usable range
 ────  ─────────────────  ──────  ─────  ──────────────────  ─────────────  ─────────────────────
  50   2⁶−2=62 ✅ (32✗)    /26     64     192.168.1.0/26      192.168.1.63   .1   – .62   (LAN A)
  25   2⁵−2=30 ✅ (14✗)    /27     32     192.168.1.64/27     192.168.1.95   .65  – .94   (LAN B)
  10   2⁴−2=14 ✅ (6✗)     /28     16     192.168.1.96/28     192.168.1.111  .97  – .110  (LAN C)
   2   2²−2=2  ✅          /30      4     192.168.1.112/30    192.168.1.115  .113 – .114  (Link 1)
   2   2²−2=2  ✅          /30      4     192.168.1.116/30    192.168.1.119  .117 – .118  (Link 2)
```

- ✅ Everything fits in **.0 – .119**; **.120 – .255 stays free** for growth.
- 🧠 **Why largest-first?** Big blocks must land on their own natural boundary (a /26 can only start at .0/.64/.128/.192). Placing a tiny /30 first at .0 would **block** the /26 and force overlap or waste. Descending order keeps every block aligned automatically.

### 6.5 🔵 Wildcard mask (bonus, used in Block 4 & 9)

The **wildcard** is the bit-inverse of the subnet mask — `255 − value` per octet:

```
   /26 subnet mask  255.255.255.192
   /26 wildcard     0.  0.  0. 63       (256−192−1 = 63, i.e. 255−192)
   /30 wildcard     0.  0.  0.  3
```

OSPF `network 192.168.1.0 0.0.0.63 area 0` and ACLs use this form. Same block-size logic, mirrored.

### 6.6 🕵️ Dirty Secret — /31 breaks the "always minus two" rule

Every subnet you've drilled reserves **2** addresses (network + broadcast) → `usable = 2ʰ − 2`. A **/30** for a router-to-router link therefore "wastes" **2 of its 4** addresses. Across a service-provider core with thousands of links, that's tens of thousands of addresses gone.

**RFC 3021 (2000)** fixes it for **point-to-point links only**: a **/31** has 1 host bit → 2 addresses, and on a P2P link there is **no broadcast** (whatever one end sends, the other receives — a "broadcast" is meaningless). So RFC 3021 **abolishes the network/broadcast reservation** and makes **both addresses usable**:

```
   /30 link 10.0.0.0/30 → .0 network, .3 broadcast, usable .1/.2   (2 of 4 used)
   /31 link 10.0.0.0/31 → .0 and .1 are BOTH usable hosts          (2 of 2 used) ✅
```

**Caveats (the trap):**
- **Both ends must support /31.** Mismatch (one end /31, other /30 or /24) → the link may come up but forward inconsistently → intermittent, one-directional failures.
- **/31 is P2P-only.** Never on a multi-access LAN — there you genuinely need a broadcast address.
- Cisco IOS supports it; if a device balks, **fall back to /30 and verify with ping**.

> **Engineer takeaway:** on serial/router-to-router links, reach for **/30 by default, /31 when you're squeezing address space and both ends support it**. Knowing /31 exists (and *why* the −2 vanishes) is a classic "separates the memoriser from the engineer" moment.

## 7. ⚖️ Pros & Cons

| Approach | ✅ Pros | ❌ Cons |
| -------- | ------ | ------ |
| **Block-size method** | Fast, octet-local, no full binary | Must still know powers of 2 cold |
| **FLSM** | Dead simple, uniform, easy to document | Strands huge address space on small segments |
| **VLSM** | Minimal waste, right-sized everywhere | Needs careful largest-first planning; classless routing required |
| **/30 links** | Universally supported, unambiguous | "Wastes" 50% (2 of 4 addresses) |
| **/31 links** | Zero waste on P2P (2 of 2) | Both ends must support it; P2P-only |

## 8. 🌿 Variants — Common → Specific

- 🟢 **Classful-boundary subnetting** — borrowing within a /8, /16, /24 (the everyday case; Examples ①–③).
- 🟢 **VLSM** — mixed masks from one parent (Example ③); the professional default.
- 🔵 **/31 point-to-point** (RFC 3021) — 2-usable links (§6.6).
- 🔵 **/32 host routes** — a single address; loopbacks, `Null0` blackholes, host-specific ACL/route entries.
- 🔵 **Supernetting / summarisation** — the *reverse* (merge subnets into one prefix) → **3.4**.
- ⚪ **"Subnetting a subnet"** — recursively borrowing again inside an already-subnetted block; exactly VLSM, applied repeatedly.

## 10. ✅ Best Practices

- 🟢 **Write the two reference lines first** (magic-8 + powers of 2) on every problem. Speed and accuracy both come from this.
- 🟢 **VLSM largest requirement first, always.** It's the difference between a clean plan and an overlapping mess.
- 🟢 **Add head-room:** size to `required hosts + growth`, then round up to the next prefix — don't fit exactly and regret it.
- 🟢 **Router/gateway = first or last usable, consistently.** Pick a convention (e.g. `.1` = gateway) and never break it.
- 🔵 **Keep subnets contiguous & aligned** so they summarise cleanly later (3.4).
- 🔵 **Prefer /31 on P2P links** where both ends support it; otherwise /30. Document which.
- 🔵 **Verify by hand, confirm with a calculator** — never the reverse. The exam gives you no calculator.

## 11. 🚫 No-Goes — Common Mistakes & Troubleshooting Traps

- ❌ **Swapping the two rules.** Subnets = `2ˢ` (no −2); hosts = `2ʰ − 2` (always −2). The single most-tested trap (3.2 §6.6).
- ❌ **Assigning a network or broadcast address to a host.** `192.168.1.64/26` is a *network*, `.127` is a *broadcast* — neither can be a host or gateway. Silent link death.
- ❌ **Gateway outside the subnet.** If the configured gateway fails the AND test, hosts can't reach it → no off-net traffic.
- ❌ **VLSM out of order.** Small blocks first → fragmentation → overlap. Descend by size.
- ❌ **Ignoring the interesting octet, brute-forcing 32 bits.** Correct but slow — you'll time out. Use §2's method.
- 🕵️ **Trap — /31 mask mismatch.** One end /31, other end /30 → link up but broken forwarding. Match masks on *both* ends; fall back to /30 + ping test (§6.6).
- 🕵️ **Trap — off-by-one on broadcast.** Broadcast is `next multiple − 1`, **not** the next multiple. `192.168.10.128` is the *next network*, `.127` is the broadcast. Confusing them puts your broadcast in the wrong subnet.
- ❌ **Forgetting subnet zero is fine on modern gear.** Don't drop the first subnet unless you're on legacy IOS without `ip subnet-zero` (3.2 §6.6).

## 13. 🧪 Practical Tasks *(this is where the skill is built — drill these)*

1. 🏎️ **Speed drill — "find everything" ×20.** For each, give network / broadcast / first / last / #hosts in <15 s:
   `10.1.1.77/28` · `172.16.20.200/27` · `192.168.5.130/25` · `10.10.10.33/29` · `203.0.113.66/26` … (generate 20; time yourself).
2. 🧩 **Reverse drill — "which subnet?"** Given a host + prefix, state only the network address, fast: `192.168.3.219/27` → ? `10.0.5.140/26` → ?
3. 🏗️ **VLSM build.** Given `10.50.0.0/22`, address: 500-host LAN, 200-host LAN, two 60-host LANs, four /30 links. Largest-first; list every subnet, broadcast, and range; report leftover space.
4. 🔁 **Prefix ⇄ mask ⇄ wildcard.** Fill a table for /25–/30: dotted mask, block size, wildcard. No calculator.
5. 🧰 **Packet Tracer 8 — validate a VLSM plan.** Build Example ③ live: 3 LANs + 2 P2P links on a router/L3-switch, assign your VLSM addresses, confirm intra-subnet and inter-subnet ping. Deliberately assign a **broadcast address** to one host and watch it fail — then fix it.
6. 🧪 **/30 vs /31 lab (🔵).** Configure a router-to-router link first as `/30`, then re-address as `/31` (RFC 3021); verify ping both ways. Then set a **mask mismatch** (/31 vs /30) and observe the failure from §6.6/§11.
7. 🔬 **Wireshark — see network vs broadcast.** Ping a subnet's broadcast address from a host; capture and observe every host on the subnet receiving/responding — proving why that address can't be a host.
8. 🧮 **Loopback /32 (🔵).** In Packet Tracer, add a `Loopback0` with a `/32`, advertise it, and confirm it appears as a host route — motivating 3.4's summarisation.
