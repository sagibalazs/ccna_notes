## 2️⃣ Visualization — Big Picture at a Glance

**CDP builds a map of *directly-connected* Cisco neighbors — one hop only:**

```
   R1 ═══════ SW1 ═══════ SW2 ═══════ R2
   │           │           │           │
   └─ R1 sees only SW1      └─ SW2 sees SW1 and R2 (its direct links)
      SW1 sees R1 and SW2
   ⚠ CDP is NOT forwarded → R1 never "sees" SW2 or R2 through SW1.
     Each device only knows its OWN directly-attached neighbors.
```

## 3️⃣ TL;DR

- 🟢 **CDP is Cisco's proprietary Layer-2 protocol that discovers directly-connected Cisco neighbors** — no configuration needed; it's **on by default**.
- 🟢 Devices send CDP advertisements every **60 s** to multicast **0100.0CCC.CCCC**; a neighbor is kept for the **180 s holdtime** (3× the timer) after its last message.
- 🟢 **CDP is not forwarded** — the receiver processes and discards it. So you only ever see **one hop** away.
- 🟢 Because it's **Layer 2**, CDP works **even with no IP address** — making it a superb **troubleshooting** and **documentation** tool (find a neighbor's IP so you can SSH to it).
- 🟢 **`show cdp neighbors`** gives six fields: **Device ID, Local Interface, Holdtime, Capability, Platform, Port ID**. **`show cdp neighbors detail`** adds IP, IOS version, native VLAN, VTP domain, duplex, serial.
- 🟢 **CDPv2** (default) adds native VLAN, VTP domain, duplex, PoE, and **native-VLAN-mismatch** detection (→ 2.9).
- 🟢 **Config:** `no cdp run` (global off) vs `no cdp enable` (per-interface off) — **know the difference** (classic exam point).
- ⚠️ **Security:** CDP **leaks** device model, IOS version, and IPs — great for you, great for attackers. **Disable it on user-/internet-facing ports** (but keep it where IP phones need voice-VLAN info).

## 4️⃣ Importance — The Problem First 🎯

**The underlying problem:** You walk into an undocumented network — dozens of switches and routers, a rat's nest of cables, and no diagram. *"What's plugged into this port? Which switch is upstream? What's that device's IP so I can log into it?"* Physically tracing cables is slow and error-prone. And often the neighbor **has no IP configured yet** (a brand-new switch), so you can't even ping it.

CDP answers all of this **automatically**:

- ❓ *"Who is directly connected to me, and on which ports?"* → CDP neighbor table (**local port ↔ neighbor + its port**).
- ❓ *"What kind of device is it, and what's its IP/IOS?"* → `show cdp neighbors detail`.
- ❓ *"How do I reach a device with no IP yet?"* → CDP runs at L2, so you learn *about* it even before it's IP-reachable, then configure/reach it.

**Why an engineer must own this cold:**

- 🔧 **CDP is your #1 "where am I / what's around me" tool.** In troubleshooting, `show cdp neighbors` instantly maps the local topology and hands you the IPs/ports you need — without touching a cable.
- 🔧 **It works below IP.** When L3 is broken or unconfigured, CDP still tells you L2 is alive and who's on the other end — a powerful diagnostic that isolates "is this an L1/L2 problem or an L3 problem?"
- 🔧 **It powers real features:** IP phones learn their **voice VLAN** and negotiate **PoE** via CDP (from 2.7); CDPv2 flags **native-VLAN mismatches** (from 2.9). Disable it carelessly and phones break.
- 🔧 **It's a security double-edge.** The same info that helps you helps an attacker fingerprint your gear. Knowing *when to disable it* (edge/user/internet ports) vs *keep it* (infra/phone ports) is real design judgment — and a guaranteed exam topic (`no cdp run` vs `no cdp enable`).

## 5️⃣ Description 📋

- 🟢 **What CDP is:** a **Cisco-proprietary Layer-2** protocol that lets Cisco devices (routers, switches, firewalls, IP phones) **automatically discover directly-connected Cisco neighbors** and exchange basic device info. **Enabled by default.**
- 🟢 **Directly connected only:** CDP frames go to the Cisco multicast **0100.0CCC.CCCC**, and receivers **process and discard** them — **they are never forwarded**. So CDP only ever reveals **one-hop** neighbors.
- 🟢 **Layer-2 operation:** CDP uses **SNAP** encapsulation and runs on SNAP-capable media (Ethernet, HDLC, PPP, Frame Relay, ATM, FDDI, Token Ring). Because it's L2, it works **with no IP address configured** — a key troubleshooting advantage.
- 🟢 **Timers:** advertisements every **60 s** (`cdp timer`); **holdtime 180 s** (`cdp holdtime`) = **3× the advertise interval**. If no advert arrives within the holdtime, the neighbor is aged out of the table.
- 🟢 **Versions:**
  - **CDPv1** — original; basic device info only.
  - **CDPv2** (default) — adds **native VLAN**, **VTP domain**, **duplex**, **PoE/power**, and **native-VLAN-mismatch** detection.
- 🟢 **Information CDP shares** (visible in `show cdp neighbors detail`): **Device ID** (hostname), **management/IP address**, **platform** (model), **capabilities** (router/switch/etc.), **local & remote interface** (Port ID), **IOS version**, **VTP domain**, **native VLAN**, **duplex**, **serial number**, and **power** info.
- 🟢 **`show cdp neighbors` six fields:** **Device ID · Local Intrfce · Holdtme · Capability · Platform · Port ID.** Capability codes: **R** Router, **S** Switch, **H** Host, **I** IGMP, **T** Trans Bridge, **B** Source-Route Bridge, **r** Repeater, **P** Phone.
- 🟢 **Configuration knobs:**
  - **`cdp run` / `no cdp run`** — **global** on/off (default on).
  - **`cdp enable` / `no cdp enable`** — **per-interface** on/off (default on).
  - `cdp timer <sec>`, `cdp holdtime <sec>`, `cdp advertise-v2`.
- 🟢 **Real-world roles:** topology **documentation**, **troubleshooting**, telling **IP phones** their **voice VLAN** and doing **PoE** negotiation (→ 2.7), and flagging **native-VLAN mismatches** (→ 2.9).
- ⚠️ **Security downside:** CDP **advertises sensitive details** (model, IOS version, IPs, native VLAN) in clear L2 frames. An attacker on a port can **fingerprint** your gear (and known-vulnerable IOS versions). **Disable CDP on untrusted / user-facing / internet-facing ports.**
- 🔵 **CDP vs LLDP (preview):** CDP is **Cisco-only** and **on by default**; **LLDP** is the **IEEE 802.1AB open standard**, multi-vendor, and **off by default** (`lldp run`). Full comparison → **2.14**.

## 6️⃣ How It Works — Under the Hood ⚙️

### A) 📢 Advertise & hold — the neighbor lifecycle

```
 Every 60s, each device MULTICASTS a CDP advert (to 0100.0CCC.CCCC) out every up interface.
 A neighbor that hears it:
    1. Parses the TLVs (device ID, port, platform, IP, VLAN, …).
    2. Stores/refreshes an entry in its CDP neighbor table, holdtime = 180s.
    3. DISCARDS the frame (never forwards it).

 Holdtime countdown (no new advert):
    180 → 120 → 60 → 0  → entry AGED OUT (neighbor considered gone)
    (a fresh advert at any point resets it back to 180)

 So a link that just went down still shows the neighbor for up to ~180s (stale entry) — and a
 new neighbor can take up to ~60s to appear. CDP is a periodic snapshot, not instant.
```

### B) 🧾 Reading `show cdp neighbors` vs `detail`

```
Switch# show cdp neighbors                 ← the quick topology map (6 fields)
  Device ID  Local Intrfce  Holdtme  Capability  Platform  Port ID
  R1         Gig0/1         145      R S I       C3845     Gig0/1.10

Switch# show cdp neighbors detail          ← the deep dive per neighbor
  Device ID: R1
  Entry address(es): IP address: 10.1.1.1          ← the IP you SSH to
  Platform: Cisco C3845,  Capabilities: Router Switch IGMP
  Interface: GigabitEthernet0/1,  Port ID (outgoing port): GigabitEthernet0/1.10
  Version: Cisco IOS Software … Version 15.x        ← IOS version (also a security leak)
  Native VLAN: 1     Duplex: full     VTP Domain: ACME
```

> 🔑 **Local Intrfce vs Port ID:** *Local Intrfce* = **my** port facing the neighbor; *Port ID* = **the neighbor's** port facing me. Confusing these mid-troubleshoot sends you to the wrong cable end.

### C) 🩺 CDP as a troubleshooting scalpel (works below IP)

```
 Problem: "R1 can't reach R2." Is it L1/L2 or L3?

 R1# show cdp neighbors
   → SW1 appears on Gig0/1  ⇒ L1/L2 to SW1 is UP (cable good, port up, framing works).
   → nothing on Gig0/2      ⇒ L1/L2 problem on that link (cable/port/duplex) — check L1 first.

 Because CDP needs NO IP, a neighbor showing up proves the physical + data-link path is alive,
 even if IP is misconfigured. That instantly splits "L2 problem" from "L3 problem."
 Bonus: 'detail' hands you the neighbor's IP so you can SSH over and keep digging.
```

### D) 🛠️ Configuration — global vs per-interface (the exam trap)

```
! Global (whole device)
Switch(config)# no cdp run          ! turns CDP OFF entirely (all interfaces)
Switch(config)# cdp run             ! back on (default)

! Per-interface (just this port) — e.g. a user/internet-facing port
Switch(config)# interface Gi0/1
Switch(config-if)# no cdp enable    ! CDP off on THIS port only
Switch(config-if)# cdp enable       ! back on (default)

! Timers
Switch(config)# cdp timer 30        ! advertise every 30s
Switch(config)# cdp holdtime 90     ! hold neighbors 90s

! Verify state
Switch# show cdp                    ! global: timers, version, on/off
Switch# show cdp interface Gi0/1    ! per-interface CDP status + timers
```

> 🕵️ **Dirty secret — `no cdp run` vs `no cdp enable` is a favorite exam trap and a real ops mistake.** `no cdp run` kills CDP **device-wide** (you lose *all* neighbor visibility — and break phone voice-VLAN/PoE signaling everywhere). `no cdp enable` disables it **on one interface** (surgical — perfect for a user/internet port while keeping infra links discoverable). Mixing these up either blinds your whole NOC or leaves an exposed edge port advertising your gear.

### E) 🔓 The security leak, made concrete

```
 A CDP frame on a port broadcasts, in clear L2:
    • Platform/model  (e.g. "Cisco C9300")
    • IOS version     (e.g. "15.2(4)…")  ← attacker maps this to known CVEs
    • Management IP   (a target to attack)
    • Native VLAN / VTP domain (recon for VLAN hopping → 2.9/2.11)

 On a user desk port or an internet-facing link, that's free reconnaissance for an attacker.
 → Disable CDP there (no cdp enable). Keep it on infra links (ops need it) and on PHONE ports
   (phones need CDP for the voice VLAN + PoE, → 2.7). Balance visibility vs exposure per port.
```

## 8️⃣ Variants — Common → Specific 🌿

**Versions:**
- 🟢 **CDPv2** — default; native VLAN, VTP, duplex, PoE, mismatch detection.
- 🔵 **CDPv1** — legacy, basic info only.

**Scope of disable:**
- 🟢 **Global** — `no cdp run` (whole device).
- 🟢 **Per-interface** — `no cdp enable` (one port).

**`show cdp …` family:**
- 🟢 **neighbors** — summary table (6 fields).
- 🟢 **neighbors detail** / **entry `<name>`** — full per-neighbor info.
- 🟢 **interface** — per-port CDP status/timers.
- 🔵 **traffic** — CDP packet counters; **`clear cdp table/counters`**, **`debug cdp`**.

**Discovery protocol family (context):**
- 🟢 **CDP** — Cisco, default-on (this doc).
- 🟢 **LLDP** — IEEE 802.1AB, multi-vendor, default-off (→ 2.14).

## 🔟 Best Practices ✅

- 🟢 **Use `show cdp neighbors [detail]` as your first topology/troubleshooting move** on any unfamiliar or broken segment.
- 🟢 **Disable CDP on user-facing and internet-facing ports** (`no cdp enable`) to cut information leakage — but **keep it on IP-phone ports** (voice VLAN/PoE) and infrastructure links.
- 🟢 **Know `no cdp run` (global) vs `no cdp enable` (interface)** and use the surgical one for edge hardening; don't blind your whole NOC.
- 🔵 **Leave default timers** (60/180) unless you have a specific reason; faster timers add overhead for little gain.
- 🔵 **Correlate CDP with your documentation** — treat `show cdp neighbors detail` as ground truth for what's actually plugged in where.
- 🔵 **Pair with LLDP** in mixed-vendor environments so non-Cisco gear is also discoverable (→ 2.14).
- 🟢 **Remember stale entries** (~180 s) when reading the table right after a change — a neighbor may linger or lag.

## 1️⃣1️⃣ No-Goes — Common Mistakes & Troubleshooting Traps 🚫

- ❌ **Expecting to see devices more than one hop away.** CDP is **not forwarded** — you only ever see **directly-connected** neighbors. Two hops = invisible.
- ❌ **Confusing `no cdp run` with `no cdp enable`.** Global vs per-interface. Running the global one to "secure a port" blinds the **entire device**.
- ⚠️ **Trusting the table instantly after a change.** A downed neighbor lingers up to **~180 s** (stale), and a new one takes up to **~60 s** to appear. Not real-time.
- ⚠️ **Mixing up Local Intrfce and Port ID.** Local = *your* port; Port ID = *neighbor's* port. Swapping them sends you to the wrong cable end.
- ⚠️ **Leaving CDP on internet-/user-facing ports.** Free reconnaissance (model, IOS version → CVEs, IPs). Disable per-interface there.
- ⚠️ **Disabling CDP on IP-phone ports.** Phones may lose their **voice VLAN**/PoE signaling (→ 2.7). Keep CDP (or LLDP-MED) on phone ports.
- 🔵 **Assuming CDP works to non-Cisco gear.** It doesn't — that neighbor simply won't appear. Use **LLDP** (→ 2.14).
- 🔵 **Forgetting CDP needs no IP.** If a neighbor shows in CDP but you "can't ping it," that's an **L3** problem — L1/L2 is proven up. Great isolation clue, don't misread it.

## 1️⃣3️⃣ Practical Tasks 🛠️

> Listed briefly; expanded step-by-step later in context.

1. 🟢 **Map a topology (Packet Tracer 8 / GNS3).** Two routers + two switches, no L3 on the switches. Run `show cdp neighbors` on each; sketch who-connects-to-whom from Local Intrfce ↔ Port ID.
2. 🟢 **Dig into a neighbor.** `show cdp neighbors detail` — read the neighbor's **IP, IOS version, platform, native VLAN, VTP domain, duplex**. SSH to the discovered IP.
3. 🟢 **Prove one-hop scope.** On R1 (connected only to SW1), confirm SW2/R2 do **not** appear — CDP isn't forwarded.
4. 🟢 **Global vs per-interface disable.** `no cdp enable` on one port → confirm only that neighbor disappears; then `no cdp run` globally → confirm the whole table clears. Restore both.
5. 🟢 **Watch the holdtime age out.** Note a neighbor's Holdtme; shut its link; watch the entry count down and disappear after ~180 s (`show cdp neighbors`).
6. 🔵 **Troubleshoot L2-vs-L3.** Break IP on a link but leave L1/L2 up; confirm the neighbor still shows in CDP (proving L2 works) while ping fails — isolate it as an L3 issue.
7. 🔵 **Security pass.** Identify user/internet-facing ports; `no cdp enable` on them; verify with `show cdp interface` while keeping CDP on phone/infra ports.
