> 🎯 We now **leave hand-typed routes behind.** Static routing (4.4–4.6) gave you total control and zero automation. This doc explains the trade you make to get automation back: routers that **learn paths from each other** and **re-route themselves** when the network changes. It's the conceptual map for OSPF (4.8–4.10) and every protocol beyond.

## 3. ⚡ TL;DR

- **Dynamic routing** = routers **learn** networks from each other and **automatically re-route** when topology changes — solving static routing's two big weaknesses (no scale, no auto-failover). 🟢
- **IGP vs EGP:** IGPs (OSPF, EIGRP, RIP, IS-IS) run *inside* one **autonomous system**; EGP (BGP) runs *between* autonomous systems. 🟢
- **Distance-vector** ("routing by rumour"): a router only knows **direction + distance** from what neighbours tell it; runs **Bellman-Ford**; sends periodic table dumps; **slow, loop-prone**. RIP is the example (hop-count metric, **max 15**, 16 = unreachable). 🟢🔵
- **Link-state** ("everyone builds the map"): every router **floods** its links, all build an **identical topology database (LSDB)**, then each runs **Dijkstra/SPF** independently; **fast, loop-resistant**. **OSPF** is the example (cost metric). 🟢
- **EIGRP** = advanced-DV/hybrid (Cisco, **DUAL** algorithm, loop-free); **BGP** = path-vector (uses AS-path). 🔵
- **Loop prevention** differs: DV needs a whole arsenal (**split horizon, route poisoning/poison reverse, hold-down, triggered updates, max hop count**); link-state mostly avoids loops by design. 🔵
- When protocols disagree about the *same* prefix, **Administrative Distance** (from 4.1) picks the winner. **CCNA's dynamic focus is single-area OSPFv2.** 🟢

## 4. ❓ Importance (problem → solution)

### The problem 🚧
Static routing (4.4–4.6) is precise and cheap — but it has **two fatal limits at scale**:

1. **It doesn't scale.** In a network of 50 routers and 200 subnets, *every* path to *every* network must be typed **by hand on every router** — thousands of lines, all maintained manually. Add one subnet and you edit dozens of devices. Humanly impossible past a handful of routers. 🔧
2. **It doesn't react.** A static route knows nothing about remote topology. If a link three hops away fails, static routers keep cheerfully forwarding into the black hole. Floating statics (4.6) help a little, but only for pre-planned backups, and only if you bolt on IP SLA tracking. There's no **awareness**. 🔧

You could solve scale *or* failover with heroic manual effort — but not both, and not as the network grows and changes daily. 🚧

### The solution 🎯
Let the routers **talk to each other** and figure it out themselves. A **dynamic routing protocol** makes each router:
- **Discover** networks automatically by exchanging information with neighbours — no manual per-path config.
- **Adapt** automatically — when a link fails, the protocol **re-computes** and installs a new best path within seconds.

The trade: you give up some control and spend CPU/RAM/bandwidth, and you inherit new failure modes (adjacencies, loops, convergence). To reason about *any* dynamic protocol — and to understand *why OSPF works the way it does* — you first need the **two paradigms**: the "rumour" model (distance-vector) and the "shared map" model (link-state). Everything in OSPF (LSAs, the LSDB, SPF, DR/BDR, areas) is a direct consequence of it being **link-state**. Learn the paradigm and OSPF stops being a pile of acronyms. 🧠

## 5. 📖 Description

- 🟢 **Dynamic routing protocol:** software by which routers advertise/learn reachability and auto-select best paths, populating the routing table without per-route human config. Source codes: `O` (OSPF), `D` (EIGRP), `R` (RIP), `B` (BGP), `i` (IS-IS).
- 🟢 **Autonomous System (AS):** a network (or set of networks) under one administrative control, identified by an **AS number**. The IGP/EGP boundary.
- 🟢 **IGP (Interior Gateway Protocol):** runs *within* an AS — OSPF, EIGRP, RIP, IS-IS.
- 🟢 **EGP (Exterior Gateway Protocol):** runs *between* ASes — **BGP** (the only one used today).
- 🟢 **Distance-vector:** a router knows only **how far** and **in which direction** a network is, learned from neighbours' advertisements (Bellman-Ford). Metric = distance (RIP: hops).
- 🟢 **Link-state:** every router learns the **entire topology** (flooded link-state info → LSDB) and computes paths itself (Dijkstra/SPF). Metric = cost (OSPF: bandwidth-based).
- 🔵 **Advanced-DV / hybrid:** EIGRP — DV foundations + link-state-like features, DUAL algorithm, fast + loop-free.
- 🔵 **Path-vector:** BGP — carries the full **AS-path**, chooses by policy/attributes, prevents loops by rejecting paths containing its own AS.
- 🟢 **Convergence:** the time for all routers to agree on a consistent, loop-free view after a change. Lower = better.

## 6. ⚙️ How It Works (under the hood)

### 6.1 🌍 The boundary — Autonomous Systems, IGP vs EGP 🟢

An **Autonomous System** is one administrative routing domain (a company, an ISP), tagged with an **AS number**. This boundary defines *which kind* of protocol you run:

```
     ┌──────────── AS 65001 (your company) ────────────┐   ┌──── AS 65002 (partner) ───┐
     │   R1 ── R2 ── R3   ◀── IGP (OSPF/EIGRP/RIP) ──▶  │   │   R7 ── R8                │
     │            │                                     │   │                           │
     │           R4 ─────────── BGP (EGP) ──────────────┼───┼──▶ R7                     │
     └─────────────────────────────────────────────────┘   └───────────────────────────┘
        IGP = "how do I get around INSIDE my network?"
        EGP = "how do I reach OTHER organisations' networks?" (the Internet is BGP between ASes)
```

- **IGPs** optimise for **fast convergence and best path** inside your trusted network.
- **EGP (BGP)** optimises for **policy, scale, and stability** between untrusting organisations — it doesn't care about "shortest," it cares about "which path my policy prefers." 🔵

### 6.2 📻 Distance-vector — "routing by rumour" 🟢🔵

A distance-vector router is like asking for directions and **trusting the answer without seeing the map**. It knows only two things per destination: **which neighbour to hand it to** (vector/direction) and **how far** (distance/metric). It learns this by neighbours periodically **advertising their entire routing table**:

```
 A ── B ── C ── (network X)
 
 C tells B: "I can reach X, distance 1."
 B adds its own hop → tells A: "I can reach X, distance 2."
 A believes B without ever seeing C or X directly.  ← "rumour"
```

- **Algorithm:** distributed **Bellman-Ford**. Each router computes `my cost = neighbour's advertised cost + link cost` and keeps the lowest.
- **Updates:** classically **periodic** — RIP broadcasts its whole table **every 30 seconds** whether or not anything changed. Wasteful and slow.
- **Metric:** simple — RIP uses **hop count**, capped at **15** (16 = "infinity" = unreachable). That cap is itself a loop-prevention hack (below).

**The Achilles' heel — count-to-infinity:** because routers trust rumours, a failed network can echo around a loop, each router incrementing the metric, "counting to infinity":

```
 X fails at C.  Before C's bad news reaches A, A still advertises "I can reach X, dist 2."
 B hears A: "oh, X is reachable via A at dist 2, so via me it's 3." ← WRONG, X is dead
 A hears B's new 3: "then via B it's 4." ... 5 ... 6 ... climbing toward infinity 🌀
 The loop persists, packets circle, until the metric hits the cap (16 in RIP) = "dead."
```

**The distance-vector loop-prevention arsenal** (each patches a hole Bellman-Ford leaves open):
| Mechanism | What it does |
|---|---|
| **Split horizon** 🔵 | Don't advertise a route back out the interface you learned it on (stops 2-router loops) |
| **Route poisoning / poison reverse** 🔵 | Advertise a failed route with **infinite** metric (RIP=16) to actively kill it, fast |
| **Hold-down timers** 🔵 | After a route fails, ignore "it's back!" rumours for a while (let the bad news settle) |
| **Triggered updates** 🔵 | Send an update **immediately** on change instead of waiting for the 30s timer |
| **Max hop count** 🔵 | The 15-hop cap bounds count-to-infinity (16 = give up) |

🔑 The very *existence* of this arsenal is the signature of distance-vector: **it's fundamentally trusting rumours, so it needs many safety nets.** (Only EIGRP's DUAL guarantees loop-free DV operation without the count-to-infinity risk. 🔵)

### 6.3 🗺️ Link-state — "everyone builds the same map" 🟢

A link-state router refuses to route on rumour. Instead, **every router describes its own directly-connected links** and **floods** that description to *every other router in the area*. Result: **every router assembles an identical picture of the whole topology** — the **Link-State Database (LSDB)** — and then **computes the best paths itself**:

```
 STEP 1  Each router builds a description of ITS links (a Link-State Advertisement, LSA).
 STEP 2  Flood LSAs to all routers in the area (reliable, once).
 STEP 3  Every router now holds the SAME LSDB = a full map of the network.
 STEP 4  Each router independently runs DIJKSTRA (SPF) on the map,
         rooted at ITSELF, to compute the shortest path to every network.
 STEP 5  Install the SPF results into the routing table.
 After that: stay QUIET — re-flood only when a link actually CHANGES.
```

- **Algorithm:** **Dijkstra's Shortest Path First (SPF)** — computed locally on the shared map.
- **Metric:** **cost**, derived from bandwidth (OSPF: reference-BW ÷ interface-BW) — so faster links are preferred, unlike RIP's blunt hop count.
- **Convergence:** **fast** — everyone already has the map, so on a change they re-flood the *delta* and re-run SPF, agreeing quickly.
- **Loop resistance:** because each router computes paths on a **complete, consistent map**, the count-to-infinity rumour problem largely **doesn't arise** within an area — so link-state needs *none* of the DV loop-prevention arsenal (inside an area).

🧠 **This is why OSPF looks the way it does.** LSAs, the LSDB, the SPF calculation, the concept of an **area** (to bound the size of the map/database), DR/BDR (to reduce flooding on multi-access links) — **all of it exists to make the "shared map" model scale.** You're not memorising trivia in 4.8; you're seeing link-state mechanics.

### 6.4 🧬 The other two families (context) 🔵

- **Advanced-DV / hybrid — EIGRP (Cisco):** keeps DV's efficiency (talks to neighbours, doesn't hold a full map) but adds link-state-like smarts. Its **DUAL** algorithm pre-computes a loop-free backup ("feasible successor") so failover is near-instant and **provably loop-free** — the only DV-family protocol that escapes count-to-infinity. Metric = bandwidth + delay. 🔵
- **Path-vector — BGP (EGP):** advertises the **entire list of ASes** a route traverses (the **AS-path**). Loop prevention is trivial: *if I see my own AS in the path, reject it.* Chooses paths by **policy and attributes**, not shortest-metric — because between organisations, business relationships matter more than hop count. This is what stitches the global Internet together. 🔵

### 6.5 ⚖️ When protocols disagree — Administrative Distance again 🟢

A router may run several protocols at once. If OSPF and RIP both offer `10.1.1.0/24`, the router can't compare an OSPF cost to a RIP hop count (incomparable metrics), so it falls back to **Administrative Distance** (from 4.1): OSPF (110) beats RIP (120), installed. AD is the **cross-protocol referee**; each protocol's **metric** is the **within-protocol** tie-break (exactly the 4.3 model). 🔑

### 6.6 ⏱️ Convergence — the number that matters 🔵

**Convergence** = time for every router to reach a consistent, loop-free view after a change. It's the practical scorecard:
- **Distance-vector (RIP):** slow — periodic timers + hold-downs can mean *minutes*.
- **Link-state (OSPF):** fast — sub-second to a few seconds; flood-the-delta + re-SPF.
- **EIGRP (DUAL):** often fastest — a feasible successor may be **instant**.

> 🕵️ **Dirty secret — "it works in the lab" hides convergence pain.** In a 3-router Packet Tracer topology, *every* protocol converges instantly and looks equivalent. The differences (RIP's minutes vs OSPF's seconds, loop storms, LSDB scaling) only appear at real scale, under real churn. Engineers pick link-state/EIGRP over RIP not because RIP "doesn't work," but because RIP's convergence and 15-hop ceiling make it **unusable** in a network of any size. The exam quietly encodes this: RIP is legacy/background, **OSPF is the CCNA dynamic protocol.** 🔵

## 7. ⚖️ Pros & Cons

### Dynamic vs static (the meta-trade)
| | 👍 Pros | 👎 Cons |
|---|---|---|
| **Dynamic** | Auto-discovers + auto-reroutes; scales; low manual effort | CPU/RAM/bandwidth overhead; adjacencies can be attacked; more failure modes to troubleshoot |
| **Static** (4.4–4.6) | Zero overhead; total control; secure; predictable | No scale; no real auto-failover; manual per-path |

### Distance-vector vs link-state
| | Distance-vector | Link-state |
|---|---|---|
| 👍 | Simple, light on CPU/RAM, easy to configure | Fast convergence, loop-resistant, best-path on real cost, scales with areas |
| 👎 | Slow convergence, loop-prone (needs safety nets), crude metric, hop caps | Heavier CPU/RAM (full map), more complex, needs hierarchy (areas) to scale |

## 10. ✅ Best Practices

- 🟢 **Match the tool to the job:** static for stubs/defaults; a dynamic IGP for any network that must scale and self-heal; BGP only at the AS edge.
- 🟢 **Prefer link-state (OSPF) or EIGRP over RIP** for real networks — RIP's convergence and 15-hop ceiling are disqualifying at scale.
- 🟢 **One IGP, consistently deployed** beats a patchwork; run BGP only where you exchange routes with other organisations.
- 🔵 **Understand convergence for your protocol** — it's the metric that decides real-world resilience, not "does it work in the lab."
- 🟢 **Know that AD referees between protocols** — don't expect a router to blend OSPF and RIP metrics; it picks one source by AD.
- 🔵 **Design for hierarchy** with link-state (areas) to keep the LSDB and SPF cost bounded as you grow.

## 11. 🚫 No-Goes (mistakes & troubleshooting traps)

- ❌ **Comparing metrics across protocols.** OSPF cost vs RIP hops is meaningless — that's why **AD** exists as the referee (from 4.3). 🟢
- ❌ **Thinking distance-vector "sees" the network.** It only knows **direction + distance from rumours** — it never holds a map. This is *why* it loops. 🔵
- ❌ **Expecting RIP to scale.** The **15-hop** ceiling makes any destination 16+ hops away simply **unreachable** — by design. 🟢
- ❌ **Assuming link-state can't loop, ever.** Within an area it's loop-resistant; **between** areas OSPF adds distance-vector-like behaviour and needs a loop-free (hub-and-spoke area) design. 🔵
- 🔧 **Trap: "route flaps / takes minutes to recover."** Suspect a **distance-vector** protocol's timers (hold-down, periodic) — classic RIP behaviour. Link-state/EIGRP converge far faster.
- ❌ **Confusing IGP and EGP roles.** Don't run BGP as your internal IGP for a small campus, or OSPF across the public Internet between organisations. Wrong tool, wrong layer. 🔵
- ❌ **Forgetting IPv6 needs its own instance.** Running OSPFv2 doesn't route IPv6 — you need **OSPFv3** (or the IPv6 address family). 🟢

## 13. 🧪 Practical Tasks

> Goal: *see* the two paradigms behave differently — rumour vs map, slow vs fast.

1. **🟢 RIP-vs-OSPF convergence race (Packet Tracer 8).** Build the same 4-router topology twice. Run **RIPv2** on one, **OSPF** on the other. Break a link and time how long each takes to restore connectivity (`ping` in a loop). Feel RIP's timers vs OSPF's speed.

2. **🔵 Watch a distance-vector update.** With RIP running, capture in Wireshark and observe the **periodic 30-second** RIPv2 updates carrying the router's routes — literally "here's my whole table" rumour, on a timer.

3. **🟢 See the shared map.** With OSPF running, run `show ip ospf database` on two different routers → confirm the **LSDBs are identical** (everyone has the same map). Then `show ip route` → note each router computed *its own* shortest paths from that shared map. This is the link-state model made visible.

4. **🔵 Count-to-infinity in slow motion.** On a small RIP triangle, disable split horizon, break a network, and watch (via `debug ip rip`) the metric **climb toward 16** before the route is declared dead — the loop the safety nets exist to bound.

5. **🟢 AD referee.** Enable **both** RIP and OSPF for the same networks on one router. `show ip route` → confirm only the **OSPF** (`O`, AD 110) routes install, not RIP (AD 120). Shut OSPF → watch RIP take over. Proves AD arbitration (4.1/4.3) with live protocols.

6. **🟢 `show ip protocols` tour.** Run it with each protocol enabled — read off what's running, its metric, its AD, and its advertised networks. Your one-command "what dynamic routing is this router doing?" tool.
