## 3. ⚡ TL;DR

- Wi-Fi security = **authentication** (who may join) **+ encryption** (hide the traffic). WPA/WPA2/WPA3 bundle both.
- **Cipher evolution:** **WEP → RC4** (broken, minutes) → **WPA → TKIP** (still RC4, stopgap, broken) → **WPA2 → CCMP/AES-128** (solid, still dominant) → **WPA3 → GCMP** (+192-bit enterprise).
- **Two auth modes, independent of cipher:** **Personal (PSK)** = one shared passphrase; **Enterprise (802.1X/EAP)** = per-user credentials via a **RADIUS** server (EAP-TLS, PEAP…).
- **WPA2-Personal 4-way handshake** derives per-session keys from the passphrase: **PMK → PTK** (unicast) + **GTK** (broadcast), using **ANonce/SNonce**. **The password is never transmitted.**
- 🚨 **WPA2's weakness:** the captured 4-way handshake can be **cracked offline** against weak passphrases. **WPA3 fixes this with SAE** (Dragonfly) — forward secrecy + no offline dictionary attack.
- **WPA3 also mandates PMF** (802.11w) — finally protecting the **deauth/management frames** that made the deauth attack (8.2) possible.
- **WEP is prohibited. TKIP is deprecated.** Use **WPA2-AES** minimum, **WPA3** where supported.

## 4. 🎯 Importance — The Problem First

**The problem:** Wired Ethernet has *physical* security — to sniff or inject, an attacker must **plug into your cable**. Wi-Fi has none of that. Every frame is **broadcast into the air**, readable by anyone with a $20 adapter within hundreds of metres, through walls, from the parking lot. Two catastrophes follow immediately:

1. **Eavesdropping** — without encryption, every password, email, and packet is in the clear to anyone listening. The medium *is* the vulnerability.
2. **Unauthorized access** — without authentication, anyone in range joins your network, consuming bandwidth and pivoting to internal systems.

So wireless **must** solve, in the air, what a cable gave for free: **confidentiality** (encrypt so listeners hear noise) and **access control** (authenticate so only authorized devices join). And it must do both *without a pre-shared secure channel* — the client and AP have to agree on encryption keys **over the very medium the attacker is watching.**

The history of Wi-Fi security is a history of getting this **wrong, then less wrong**:
- **WEP** tried and failed so badly it's crackable in minutes — a cautionary tale in *how not* to use a cipher (IV reuse, no real key management).
- **WPA** was a rushed software patch to buy time on existing hardware — better, but still built on the broken RC4 foundation.
- **WPA2** finally did it right with **AES** — and reigned for 13+ years, still the most-deployed standard.
- **WPA3** closes WPA2's last big hole: the offline-crackable handshake and unprotected management frames.

Why an engineer must own this cold:
- **It's the difference between a secure network and an open door.** Choosing WEP or leaving TKIP on is a fireable mistake.
- **Troubleshooting "can't connect" almost always lands here** — wrong passphrase, PSK vs Enterprise mismatch, cipher/PMF incompatibility with old clients, RADIUS failures.
- **Every wireless attack you'll defend against** (evil twin, deauth, handshake capture, KRACK) attaches to the mechanisms in this document.
- **Real design decisions:** Personal vs Enterprise, WPA2 vs WPA3, transition mode, PMF — all require understanding *why*, not just *which checkbox*.

> 🕵️ **Dirty secret (the one that matters most):** With **WPA2-Personal**, an attacker doesn't need to break AES. They passively capture the **4-way handshake** (or send a **deauth** to force a client to re-handshake — 8.2!), take it home, and run an **offline dictionary attack**. AES is never touched — the *passphrase* is the weak point. Your entire network's security collapses to the strength of one shared word. This single flaw is *the* reason WPA3/SAE exists.

## 5. 📖 Description

**The four generations** 🟢:

- **WEP (Wired Equivalent Privacy, 1997)** — **RC4** stream cipher, static 40- or 104-bit keys, weak 24-bit **IV**, CRC-32 integrity. Fatally flawed (IV reuse → FMS/PTW attacks). **Cracked in minutes** (Aircrack-ng). **Prohibited** — IEEE deprecated it in 2004.
- **WPA (Wi-Fi Protected Access, 2003)** — interim fix runnable as a **software update on WEP hardware**. Uses **TKIP**: still **RC4**, but adds **per-packet key mixing**, a 48-bit sequence counter (anti-replay), and a **MIC (Michael)** for integrity. Better, but now also **weak/deprecated**.
- **WPA2 (2004, IEEE 802.11i)** — the real fix. **CCMP** (Counter Mode with CBC-MAC Protocol) built on the **AES** block cipher (128-bit). Mandatory for Wi-Fi certification since 2006. **Still the most-deployed standard.** Weakness: **offline handshake cracking**, **KRACK** (2017, patched), **PMKID**.
- **WPA3 (2018)** — modernization. Keeps **AES** but moves **CCMP → GCMP**; **SAE** replaces the vulnerable PSK handshake; **PMF mandatory**; **forward secrecy**; WPA3-Enterprise adds an optional **192-bit** (GCMP-256, CNSA) mode. **Mandatory for new certifications since 2020.**

**Two authentication modes (independent of the cipher)** 🟢:
- **Personal (Pre-Shared Key, PSK)** — a single **passphrase** on the AP and every client. Simple; for homes/small business. Everyone shares one secret. *(WPA3-Personal replaces the PSK exchange with **SAE**.)*
- **Enterprise (802.1X/EAP)** — **per-user** credentials validated by a central **RADIUS/AAA server** (e.g., Cisco ISE). No shared secret; individual accounts, revocable. For corporate networks. Uses **EAP** methods (EAP-TLS, PEAP, EAP-TTLS, EAP-FAST).

**Encryption ciphers** 🟢🔵:
- **RC4** — stream cipher (WEP, WPA/TKIP). Weak.
- **TKIP** — Temporal Key Integrity Protocol; RC4 + per-packet keying + Michael MIC (WPA). Deprecated.
- **CCMP** — Counter Mode CBC-MAC Protocol; **AES-128** (WPA2). Strong.
- **GCMP** — Galois/Counter Mode Protocol; AES, **GCMP-256** in WPA3-Enterprise 192-bit. Strongest, faster.

**Protected Management Frames (PMF / 802.11w)** 🟢 — encrypts/protects management frames (deauth, disassoc), defeating the deauth attack from 8.2. **Optional in WPA2, mandatory in WPA3.**

**OWE (Opportunistic Wireless Encryption / "Enhanced Open")** 🔵 — WPA3-era; encrypts **open** (passwordless) networks via Diffie-Hellman, so "open" no longer means "plaintext."

## 6. 🔧 How It Works — Under the Hood

### 6.1 The key hierarchy 🟢🔵

Wi-Fi never encrypts with the passphrase directly. It builds a **tree of keys**:

```
   PASSPHRASE  ──PBKDF2(passphrase, SSID, 4096, 256)──►  PSK
        (personal)                                        │
                                                          ▼
   ┌──────────────────── PMK (Pairwise Master Key, 256-bit) ─────────────┐
   │  personal: PMK = PSK   ·   enterprise: PMK from 802.1X/EAP (RADIUS)  │
   └───────────────────────────────┬─────────────────────────────────────┘
        4-way handshake derives ►   │
   ┌────────────────────────────────▼────────────────────────────────────┐
   │  PTK (Pairwise Transient Key)  = PRF(PMK, ANonce, SNonce, AP-MAC,    │
   │                                       STA-MAC)   → protects UNICAST   │
   │   partitioned into:                                                   │
   │     • KCK (128b) — integrity of handshake (MIC)                       │
   │     • KEK (128b) — encrypt EAPOL-Key data                             │
   │     • TK  (128b) — encrypt actual data frames                         │
   ├──────────────────────────────────────────────────────────────────────┤
   │  GMK → GTK (Group Temporal Key)  → protects BROADCAST/MULTICAST       │
   │        generated by AP, shared to all clients                         │
   └──────────────────────────────────────────────────────────────────────┘
```
- **PMK** — the root. Same on both sides *before* the handshake (from the shared PSK, or delivered by RADIUS after EAP).
- **PTK** — unique **per client, per session**; encrypts that client's unicast traffic.
- **GTK** — shared; encrypts broadcast/multicast (one copy the AP sends to everyone).
- **ANonce / SNonce** — fresh random numbers from AP and client each session → so keys differ every time even with the same password.

### 6.2 The 4-way handshake (WPA2-Personal) 🟢

This is the heart of it — how both sides *prove they know the PMK and derive fresh keys* **without sending the password**:

```
   Client (Supplicant)                         AP (Authenticator)
   both already hold PMK (from the PSK)
        │                                              │
        │  ①  ◄──────────── ANonce ─────────────────  │  AP picks ANonce
        │  now has PMK+ANonce+SNonce+both MACs         │
        │  → derives PTK                               │
        │                                              │
        │  ②  ──── SNonce + MIC ──────────────────►    │  AP now has all inputs
        │                                              │  → derives PTK, checks MIC
        │                                              │
        │  ③  ◄──────── GTK + MIC (install) ─────────  │  deliver group key
        │  install PTK + GTK                           │
        │                                              │
        │  ④  ──────────── ACK ──────────────────►     │  confirm; keys installed
        ▼                                              ▼
                   🔒 encrypted unicast (PTK) + broadcast (GTK) flow
   (all four are EAPOL-Key frames)
```
1. **AP → client: ANonce.** Client now has everything → computes **PTK**.
2. **client → AP: SNonce + MIC.** AP now has everything → computes **PTK**, validates the **MIC** (proves the client knew the PMK).
3. **AP → client: GTK + MIC.** Delivers the group key; signals "install."
4. **client → AP: ACK.** Confirms. Data encryption begins.

> 🕵️ **Dirty secret:** Messages ① and ② are enough for an attacker to run an **offline dictionary attack** — capture ANonce, SNonce, MACs, and the MIC, then guess passphrases at home until the computed MIC matches. That's why weak passphrases die instantly and why **forcing a deauth to re-capture the handshake** is step one of every WPA2 crack. AES stays unbroken; the *password* is the door.

### 6.3 Enterprise: 802.1X / EAP 🟢

Personal shares one secret; **Enterprise** gives every user their own, checked by a server:

```
   Supplicant  ──►  Authenticator  ──►  Authentication Server
   (client)         (AP / WLC)          (RADIUS / Cisco ISE)
      │  EAP over LAN (EAPOL)  │  RADIUS  │
      └────────── 802.1X exchange (EAP method) ──────────┘
   On success: server + client derive the PMK  →  RADIUS hands PMK to the AP
                                                 →  normal 4-way handshake runs
```
- Roles: **Supplicant** (client), **Authenticator** (AP/WLC relays), **Authentication Server** (RADIUS).
- **EAP methods:** **EAP-TLS** (mutual **certificates** — gold standard), **PEAP** (server cert + inner MSCHAPv2 password), **EAP-TTLS**, **EAP-FAST**.
- Benefits over PSK: **per-user** accounts (revoke one without changing everyone's key), no shared secret to leak, central policy.

> 🕵️ **Dirty secret:** "Enterprise" isn't automatically safer. If clients use **PEAP** but **don't validate the RADIUS server certificate**, an attacker stands up a fake RADIUS + evil-twin AP and harvests credentials. **EAP-TLS** (both sides present certs) removes the shared-password target entirely — which is why it's the real gold standard.

### 6.4 WPA3 SAE — closing the offline-crack hole 🟢🔵

**SAE (Simultaneous Authentication of Equals)**, a.k.a. the **Dragonfly** handshake, replaces the PSK exchange:
- Both sides prove knowledge of the password through a **live, interactive** exchange — an attacker can't test guesses **offline** from a captured trace. Each guess needs a **fresh live interaction** with the AP (rate-limitable).
- Provides **forward secrecy**: capturing today's traffic and *later* learning the password does **not** decrypt past sessions (WPA2 had no such protection).
- Still uses AES/GCMP for the data; SAE only replaces the *authentication/key-agreement* step.

### 6.5 PMF / 802.11w — protecting management frames 🟢
Recall the **deauth attack** (8.2): management frames were unprotected, so anyone could forge a "disconnect" and kick clients (or force handshake re-capture). **PMF** cryptographically protects unicast and multicast management frames. **Optional in WPA2, mandatory in WPA3** — this is a direct fix to a flaw we flagged two documents ago.

## 7. ⚖️ Pros & Cons

**WPA2-Personal (PSK + AES)**
✅ Simple, universal client support · ✅ Strong cipher (AES) · ✅ No server needed
❌ **Offline handshake cracking** on weak passphrases · ❌ Shared secret (can't revoke one user) · ❌ No forward secrecy

**WPA2-Enterprise (802.1X + AES)**
✅ Per-user accounts, revocable, auditable · ✅ No shared passphrase · ✅ Central policy (ISE)
❌ Needs RADIUS/PKI infrastructure · ❌ Cert/credential complexity · ❌ Misconfigured PEAP = credential theft

**WPA3-Personal (SAE + AES)**
✅ **No offline dictionary attack** · ✅ Forward secrecy · ✅ PMF mandatory
❌ Older clients don't support it · ❌ Transition mode is downgrade-attackable · ❌ Early **Dragonblood** side-channels (patched)

**WEP / WPA / TKIP**
✅ (historical only) · ❌ **Broken — never use.** WEP crackable in minutes; TKIP deprecated.

## 8. 🔀 Variants (Common → Specific)

- **Generations:** WEP → WPA → WPA2 → WPA3. 🟢
- **Auth modes:** Personal (PSK / SAE) vs Enterprise (802.1X/EAP). 🟢
- **Ciphers:** RC4 → TKIP → CCMP (AES-128) → GCMP (AES-256/192-bit). 🟢🔵
- **EAP methods:** EAP-TLS (certs, mutual) → PEAP (server cert + MSCHAPv2) → EAP-TTLS → EAP-FAST. 🔵
- **Open-network options:** truly Open → **OWE / Enhanced Open** (encrypted, no password). 🔵
- **Deployment modes:** pure WPA3 vs **WPA2/WPA3 transition (mixed) mode**. 🔵
- **Management protection:** PMF disabled → optional (WPA2) → mandatory (WPA3). 🟢

## 9. 🧩 Devices / Media / Protocols

- **AP / WLC** — the **Authenticator**; enforces the WLAN's security policy, runs the 4-way handshake, holds keys per client.
- **Client (Supplicant)** — holds the PSK or user credentials; derives PTK/GTK.
- **RADIUS server (Cisco ISE / FreeRADIUS)** — the **Authentication Server** in Enterprise; validates users, delivers the PMK.
- **Protocols:** **802.11i** (WPA2 basis), **802.1X** (port-based auth framework), **EAP/EAPOL** (auth transport), **802.11w** (PMF), **SAE/Dragonfly**, **OWE**.
- **Ciphers/algorithms:** RC4, **AES**, TKIP, **CCMP**, **GCMP**, PBKDF2 (PSK derivation), Diffie-Hellman (SAE/OWE).
- **Attack/tools (defensive awareness):** Aircrack-ng (WEP/handshake), KRACK, PMKID, evil twin, deauth flood.

## 10. ✅ Best Practices

- **Minimum WPA2 with AES (CCMP).** Never WEP; disable TKIP (and WPA1). Prefer **WPA3** where clients support it.
- **Use WPA2/WPA3 transition mode** only during migration; move to **pure WPA3** as soon as the fleet allows.
- **Enable PMF** (mandatory in WPA3; enable "optional/required" in WPA2) to stop deauth attacks.
- **Personal:** use a **long, random passphrase** (the whole network's security depends on it). Rotate on staff changes.
- **Enterprise for corporate:** deploy **802.1X with a RADIUS server**; prefer **EAP-TLS** (mutual certs). If PEAP, **enforce server-certificate validation** on clients.
- **Separate SSIDs/VLANs** for Corp / Guest / IoT (ties to 8.2/8.5) with appropriate security each.
- **Never rely on hidden SSID or MAC filtering as security** (8.2) — they're trivially bypassed.

## 11. 🚫 No-Goes & Troubleshooting Traps

- ❌ **Using WEP or TKIP** — broken; WEP cracks in minutes, TKIP is deprecated. AES only.
- ❌ **Weak WPA2-Personal passphrase** — the captured handshake is dictionary-cracked offline; AES won't save you.
- ❌ **Confusing the terms:** **CCMP = protocol**, **AES = cipher inside it**; "WPA2" is the *certification*. Saying "AES vs WPA2" is a category error.
- ❌ **Assuming WPA=TKIP, WPA2=AES rigidly** — both can technically do either; **WPA2 mandates CCMP/AES support** but mixed mode can fall back to TKIP (which weakens it — avoid).
- ❌ **PEAP without server-cert validation** — evil-twin RADIUS harvests credentials. Validate the cert or use EAP-TLS.
- ❌ **Leaving PMF off** — deauth attacks (8.2) work; forced re-handshake enables offline cracking.
- ❌ **Trusting WPA3 transition mode blindly** — an attacker can force a **WPA2 downgrade**; the network is only as safe as its weakest allowed mode.

**Troubleshooting map — "client can't connect to a secured WLAN":**
```
   Associates then fails?        → security gate (State 3→4)
     ├─ Personal: wrong passphrase? → 4-way handshake MIC fails (msg ②)
     ├─ Enterprise: RADIUS reachable? user creds valid? cert trust? → EAP failure
     ├─ Cipher/PMF mismatch → old client can't do AES/PMF → check WLAN security & client caps
     └─ WPA3-only WLAN + legacy client → client can't do SAE → enable transition or WPA2
   Connects but insecure?        → WEP/TKIP enabled, PMF off, weak PSK → harden
```

## 13. 🛠️ Practical Tasks (expanded later in context)

1. **Handshake capture (your own lab network):** in monitor mode, capture your own WPA2 join and identify the **four EAPOL-Key messages**; locate **ANonce (msg 1)**, **SNonce+MIC (msg 2)**, **GTK (msg 3)**. Confirm the passphrase never appears in the trace.
2. **Cipher inspection:** in a Wi-Fi scanner, list nearby networks' security (WPA2-PSK-AES, WPA3-SAE, Open, etc.). Find any still advertising **TKIP** or **WEP** and note why they're risky.
3. **Personal vs Enterprise sort:** given (RADIUS server, one passphrase, per-user revocation, EAP-TLS, home use, Cisco ISE), sort each into **Personal** vs **Enterprise**. Direct exam pattern.
4. **Key-hierarchy drill:** from memory, draw PSK→PMK→PTK(+KCK/KEK/TK)→data and GMK→GTK→broadcast, and state what each key protects.
5. **PMF demo (lab):** on a WPA2 WLAN with **PMF off**, observe a (lab-only) deauth disconnect; enable **PMF required** and confirm the forged deauth no longer works — the 8.2 attack, closed.
6. **WPA3 transition thought lab:** describe how an evil twin forces a **WPA2 downgrade** against a transition-mode SSID, and what pure-WPA3 + PMF changes. Sets up secure design decisions.
