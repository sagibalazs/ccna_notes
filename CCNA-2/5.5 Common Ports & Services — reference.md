## 3) ⚡ TL;DR

- 🎯 A useful port fact is always a **triple**: `service + transport + number`. "Port 53" is incomplete — it's **DNS on both 53/UDP and 53/TCP**, and those are *different sockets* (separate namespaces, 5.4).
- 📋 The **CCNA know-cold set** is ~20 numbers (table above). Learn each with its **transport** and its **secure sibling** (Telnet→SSH, HTTP→HTTPS, LDAP→LDAPS, POP3→POP3S).
- 🔢 **Server = well-known port; client = ephemeral** (5.1). This table lists the *server-side* well-known ports.
- ⚠️ **Cleartext legacy → secure replacement** is an exam *and* real-world theme: Telnet 23 → SSH 22, HTTP 80 → HTTPS 443, FTP → SFTP/FTPS, SNMPv1/2c → SNMPv3, RADIUS → RadSec.
- 🕵️ **Biggest trap:** things like **OSPF (89), EIGRP (88), ESP (50), AH (51), GRE (47), VRRP (112)** are **IP protocol numbers**, *not* ports — they live in the **IP header's Protocol field**, not in a TCP/UDP header. You cannot "allow OSPF on port 89."

## 4) ❓ Importance — the problem *before* the solution

**The problem.** You now understand transports (5.2–5.4). But every day the *specific numbers* decide whether things work:

- 🔥 **Writing an ACL / firewall rule:** permit the wrong number and you've either blocked production or opened a hole. Permit `tcp/23` thinking it's SSH and you've allowed **cleartext Telnet** while SSH (22) stays blocked — a real, common mistake.
- 🔍 **Reading a capture / troubleshooting:** a flow to `:53` tells you "DNS," to `:123` "someone's syncing time," to `:161` "SNMP polling" — *if* you know the map. Without it, packet captures are noise.
- 🛡️ **Hardening a device:** you can't disable what you can't name. "Is 23, 80, 161-with-v2c, and 69 open?" is a security question you answer with this table.
- 🧾 **Config every day:** `ip tacacs`, `snmp-server`, `ntp server`, `logging host`, `ip ssh` — each assumes you know the port it rides.

**Why memorization alone fails.** A flat list of 60 numbers doesn't stick and doesn't transfer. What sticks is the **structure**: the transport that goes with each (which you can often *derive* from 5.4 — one-shot/real-time → UDP, correctness-critical → TCP), the **secure/insecure pairs**, the **functional groupings**, and the **traps** (separate namespaces, protocol-numbers-aren't-ports).

**The solution — a structured reference.** This document organizes the numbers so they're both **lookup-able** (the tables) and **memorable** (groupings + mnemonics + the TCP/UDP logic). It's the anchor you return to while doing ACLs, captures, and hardening — and the memory scaffold for the exam. 💡

## 5) 📋 Description — how to *read* a port fact

- **Every entry is `service · transport · port`.** Missing the transport is the #1 error (see DNS, HTTPS which span both). 🟢
- **These are server-side, well-known ports** (0–1023 mostly; a few registered like 1812, 3389, 8080). The *client* side is ephemeral (5.1). 🟢
- **TCP and UDP namespaces are independent** — `X/TCP ≠ X/UDP`; a service opens each socket separately. 🔵
- **Secure vs insecure pairs matter** — the modern default is the encrypted sibling. 🟢
- **Some "ports" you'll see quoted are actually IP protocol numbers** — a different field entirely (see §6.3). 🔵
- **A port is a convention, not a law** — anything can bind any port; classification by port is a hint, not proof (why NGFWs inspect, Block 9). 🕵️

### 6.2 · The secure/insecure pairs (the hardening story) 🔒

```
   Telnet 23    ──▶  SSH 22            (cleartext CLI  → encrypted CLI)
   HTTP 80      ──▶  HTTPS 443         (cleartext web  → TLS web)
   FTP 20/21    ──▶  SFTP 22 / FTPS 990
   SNMP v1/v2c  ──▶  SNMP v3           (community strings → auth+privacy)
   Syslog 514/UDP ─▶ Syslog 6514/TCP-TLS
   LDAP 389     ──▶  LDAPS 636
   POP3 110/IMAP143 ▶ 995 / 993
   RADIUS 1812  ──▶  RadSec 2083/TLS
```

> 🎯 On real gear the whole job of "device hardening" is often just: **turn off the left column, turn on the right.** 🟢

### 6.3 · 🚨 Ports vs IP Protocol Numbers — the trap that catches everyone 🔬

Some things you'll hear called "ports" are **IP protocol numbers** — an **8-bit field in the IP header** (the same field that says 6=TCP, 17=UDP from 5.1). They are **not** L4 ports and **cannot** appear in a `eq <port>` ACL match:

| # | Protocol | Why it's not a port |
|---:|---|---|
| 1 | **ICMP** | Rides directly on IP; no ports at all (has type/code instead) |
| 2 | IGMP | Multicast group mgmt; on IP directly |
| 6 | **TCP** | *This is the field that then contains ports* |
| 17 | **UDP** | ″ |
| 47 | GRE | Tunnel; no ports |
| 50 / 51 | **ESP / AH** | IPsec payload/auth — **protocol numbers**, not ports (that's why NAT breaks IPsec → NAT-T on UDP 4500) |
| 88 | **EIGRP** | ⚠️ same number as *Kerberos port 88* — but this is a **protocol number** |
| 89 | **OSPF** | On IP directly — you **can't** "permit tcp eq 89" |
| 103 | PIM | Multicast routing |
| 112 | **VRRP** | FHRP — protocol number (contrast HSRP/GLBP which *do* use UDP ports) |

> 🕵️ **Classic exam & ACL trap:** an ACL to permit OSPF is `permit ospf …` (or `permit 89`), **never** `permit tcp/udp eq 89`. Same for EIGRP (88), ESP (50), GRE (47). Mixing the IP-Protocol field with the L4-port field is the single most common L3/L4 confusion. 🎓

### 6.4 · 🧠 Mnemonics (make them stick)

- **20 before 21** → FTP **data** before **control** ("data's got to move first").
- **22, 23** sequential → **SSH** came after **Telnet** (higher number = newer/better).
- **25** → SMTP, "**25** letters to send a letter" (alphabet-ish).
- **53** → DNS, just brand it in. "**5-3**, name-to-IP."
- **67/68** → DHCP, consecutive; **server = lower (67)**, client = 68.
- **69** → TFTP (tiny, trivial — no auth).
- **80 / 443** → HTTP / HTTPS, the two you'll never forget.
- **123** → NTP counts **1-2-3** like a clock ticking. ⏱️
- **161/162** → SNMP: **poll first (161)**, trap second (162).
- **179** → BGP, "**the 1 routing protocol on TCP**."
- **514** → Syslog: "**S**yslog" and the number starts the log stream.
- **1812** → RADIUS auth ("War of 1812" — a *fight* to authenticate); **1813** accounting.
- **Secure = usually the bigger sibling:** 443>80, 993>143, 995>110, 636>389, 990>21.

## 7) ⚖️ Pros & Cons — of relying on well-known ports

| 👍 Pros | 👎 Cons |
|---|---|
| **Predictable** — clients find services without discovery 🟢 | **Predictable to attackers too** — 22/3389/445 are brute-force magnets 🕵️ |
| **Simple firewalling** — "allow 443" is legible 🟢 | **Port ≠ protocol** — anything can squat a port; false sense of security 🕵️ |
| **Fast triage** — a capture's ports narrate the traffic 🟢 | **Non-standard ports** (SSH on 2222) break assumptions/tools 🔵 |
| **Standard configs** — every vendor agrees on 53/123/161 🟢 | **Encrypted-on-443 everything** hides apps from port-based control 🔵 |

## 9) 🧩 Devices / Media / Protocols — where these show up on Cisco gear

- **Routers/switches (mgmt plane)** 🟢 — SSH 22, Telnet 23 (off!), HTTP/HTTPS 80/443, SNMP 161/162, NTP 123, syslog 514, TACACS+/RADIUS 49 / 1812-1813, TFTP 69 (IOS images), NETCONF 830.
- **WLC ↔ AP** 🔵 — CAPWAP 5246/5247 UDP (§2.6/2.7 wireless).
- **Firewalls/ACLs** 🟢 — match on these ports *and* on IP protocol numbers (OSPF 89, ESP 50) — don't confuse the two (§6.3, Block 9).
- **Servers** 🟢 — DNS 53, DHCP 67/68, web 80/443, mail 25/587/993/995, directory 389/636.
- **Automation controllers** 🟢 — NETCONF 830, RESTCONF 443 (Block 10 / §6).
- **Protocol numbers live in the IP header**; **ports live in the TCP/UDP header** (5.1 §6.4 two-stage demux).

## 10) ✅ Best Practices

- 🎯 **Always cite the transport with the port.** "DNS 53/UDP (53/TCP for large)" — never bare "53."
- 🔒 **Default to the secure sibling** and disable the cleartext one: SSH not Telnet, HTTPS not HTTP, SNMPv3 not v2c, SCP/SFTP not TFTP/FTP where feasible.
- 🧾 **Write ACLs by function, and get the field right** — `permit ospf` / `permit esp` for protocol numbers, `eq 22 / eq 443` for ports. Never `eq 89` for OSPF.
- 🔍 **When troubleshooting, map ports first** — `show ip sockets`, `netstat/ss`, or Wireshark's port column tells you *what* before *why*.
- 🚪 **Change nothing security-relevant to "obscure" ports as your only defense** — moving SSH to 2222 reduces log noise, not real risk.
- 📚 **Keep IANA as the tiebreaker.** Vendor cheat-sheets drift; the [IANA registry](https://www.iana.org/assignments/service-names-port-numbers/service-names-port-numbers.xhtml) is authoritative.

## 11) 🚫 No-Goes — common mistakes & traps

- ❌ **Quoting a port without its transport.** 53, 443, and others span **both** — the transport is part of the fact. 🟢
- ❌ **Treating `X/TCP` and `X/UDP` as one rule.** Separate namespaces → separate ACL lines. 🔵
- ❌ **`permit tcp eq 89` for OSPF (or 88 EIGRP, 50 ESP, 47 GRE, 112 VRRP).** Those are **IP protocol numbers** — wrong field entirely. 🕵️
- ❌ **Confusing EIGRP protocol 88 with Kerberos port 88.** Same number, different universes. 🔵
- ❌ **Allowing 23 when you meant 22** (or 80 when you meant 443) — you just enabled cleartext. 🟢
- ❌ **Assuming an open port = a known/safe app.** Port is a convention; verify with inspection. 🕵️
- ❌ **Forgetting FTP's second data channel** — active/passive modes use *extra* ephemeral ports, which is why FTP is a firewall headache and SFTP (single port 22) is preferred. 🔵
- ❌ **Using RADIUS legacy 1645/1646 on modern kit** without checking — IANA moved auth/acct to **1812/1813**. 🔵

## 13) 🧪 Practical Tasks (brief here — expanded later in context)

1. **Read the map live (Wireshark):** capture a few minutes of normal traffic; use the **port column** to identify DNS(53), NTP(123), HTTPS(443), and anything on 137/138/5353 — narrate each flow from its port. 🟢
2. **See it on the device:** `show ip sockets` / `show control-plane host open-ports` (IOS) or `ss -tulpn` (Linux) — list which well-known ports the box is actually listening on, then justify or disable each. 🟢
3. **Prove separate namespaces:** `dig example.com` (53/UDP) then `dig +tcp` (53/TCP) — two transports, one number. 🟢
4. **Protocol-number vs port ACL (Packet Tracer 8):** write `permit ospf any any` and confirm OSPF adjacencies form; then *try* `permit tcp any any eq 89` and watch it **not** match OSPF — driving §6.3 home. 🕵️🔵
5. **Hardening pass:** on a lab router, disable Telnet (`transport input ssh`), HTTP (`no ip http server`), and SNMPv2c; verify SSH(22)/HTTPS(443)/SNMPv3 still work. 🟢
6. **Spot HTTP/3:** load a QUIC site and filter `udp.port == 443` — the "443 is always TCP" assumption dies on screen. 🔵
7. **Build your own one-page cheat card** from the §2 table, grouped by function, and quiz yourself transport-first ("SNMP? → UDP 161/162"). 🟢
