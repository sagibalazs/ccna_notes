## 2. 🗺️ Visualization — four purposes on one specificity spectrum

All four are just `ip route` / `ipv6 route` with a different **prefix length** or **AD**. Line them up by **specificity** (which is exactly how LPM from 4.3 ranks them):

```
  MOST SPECIFIC ◀─────────────── longest-prefix match order ──────────────▶ LEAST SPECIFIC
  (always wins)                                                            (last resort)

  ┌───────────────┬───────────────────────┬──────────────────────┬──────────────────────┐
  │ 🎯 HOST ROUTE │ 🌐 NETWORK ROUTE       │ 🕳️ (any specific)     │ 🚪 DEFAULT ROUTE      │
  │   /32  · /128 │   e.g. /24 · /64       │   ...                 │   0.0.0.0/0 · ::/0    │
  │ one exact host│ one remote subnet      │                       │ everything else      │
  └───────────────┴───────────────────────┴──────────────────────┴──────────────────────┘

  📉 FLOATING STATIC = ANY of the above, but with a deliberately HIGH AD → a dormant BACKUP
     (orthogonal dimension: not "which prefix," but "how trusted" — hides until the primary dies)
```

| Type | Prefix (v4 / v6) | Purpose | Code | Key knob |
|---|---|---|---|---|
| **Default** (3.3.a) | `0.0.0.0/0` · `::/0` | Catch-all → gateway of last resort | `S*` | shortest prefix |
| **Network** (3.3.b) | specific subnet, e.g. `/24` · `/64` | Reach one remote network | `S` | the mask |
| **Host** (3.3.c) | `/32` · `/128` | Reach one exact host / policy override | `S` | longest prefix (wins LPM) |
| **Floating** (3.3.d) | *any of the above* | Backup that activates on failure | `S` (appears only when active) | **inflated AD** |

🔑 **Two independent dimensions:** *prefix length* decides **which packets** a route matches (default/network/host); *AD* decides **whether it's primary or backup** (normal vs floating). Floating static is a modifier you can bolt onto any of the other three.

---

## 3. ⚡ TL;DR

- **Default route** (3.3.a): `0.0.0.0/0` (v4) / `::/0` (v6) — matches *anything* with no better route; becomes the **gateway of last resort**. The `/0` = shortest prefix, so LPM makes it truly *last* resort. 🟢
- **Network route** (3.3.b): a static to a **specific subnet** (`/24`, `/64`, etc.) — the everyday "reach that remote network" route. 🟢
- **Host route** (3.3.c): `/32` (v4) / `/128` (v6) — a route to **one exact address**. Most specific → **always wins LPM**. Used for policy overrides, loopbacks, and precise steering. 🟢
- **Floating static** (3.3.d): a static with a **deliberately raised AD** (higher than the primary route's AD) so it stays **dormant** in the config and only **installs when the primary disappears**. A hand-built backup. 🟢🔵
- **Choosing the floating AD:** it must be **greater than the AD of the route it backs up** (back up OSPF/110 → use ~130; back up EIGRP/90 → >90; back up a static/1 → >1). Range 1–254 (255 = never install). 🟢
- **The floating-static gotcha:** it reacts to the **primary route leaving the table**, *not* to the path actually dying. If the primary's next hop fails but the interface stays up, the backup **never activates** → pair it with **IP SLA + object tracking**. 🔵

---

## 4. ❓ Importance (problem → solution)

### The problem 🚧
A static route (4.4/4.5) can point anywhere — but real networks need routes for **different jobs**, and each job has a different prefix length and a different failure story:

- You can't type a static for **every network on the Internet** — you need **one catch-all**. (default)
- You need to reach **this branch's LAN** specifically. (network)
- You need to force traffic for **one server** down a special path, overriding everything else. (host)
- Your primary WAN link **will** fail someday, and you need traffic to **automatically fail over** to a backup — without running a full routing protocol. (floating)

If you don't understand which prefix length serves which purpose, you'll write routes that **shadow each other** (a `/24` unexpectedly beaten by a `/32`), a default that **never gets used** (or worse, **always** gets used), or a "backup" that **silently never activates** in a real outage. On the exam, 3.3.a–d is tested directly: *"which command creates a valid default route?" "what makes this a floating static?"* 🟢

### The solution 🎯
Classify every static by **purpose** and reason about it on the **specificity spectrum** from 4.3. Once you see that host beats network beats default *by longest-prefix match*, and that floating-vs-primary is decided *by AD*, all four types snap into a single coherent model — and floating-static failover (the trickiest) becomes obvious: it's just AD from 4.1 used deliberately. 🧠

---

## 5. 📖 Description

- 🟢 **Default route (3.3.a):** `ip route 0.0.0.0 0.0.0.0 <next-hop>` / `ipv6 route ::/0 <next-hop>`. Matches **every** destination; used only when no more-specific route exists. Sets the **gateway of last resort** (`S*`). Typically points at the ISP/upstream.
- 🟢 **Network route (3.3.b):** a static to a **specific prefix** (`10.2.2.0/24`, `2001:db8:2::/64`). The standard "reach a remote subnet" route.
- 🟢 **Host route (3.3.c):** a `/32` (v4) or `/128` (v6) static to **one exact address**. Most specific possible → **wins LPM over any broader route**. Uses: precise policy steering, reaching a loopback, pinning a single server's path, blackholing one host (via Null0).
- 🟢 **Floating static (3.3.d):** a static (of any prefix) with its **AD raised above** the primary route's AD, so it's installed **only** when the primary is withdrawn. A configuration-resident **backup path**.
- 🔵 **AD selection rule:** floating AD > primary AD, and < 255. Choose the *smallest value that beats the primary* (or a convention like 200/254 for defaults).
- 🔵 **Activation trigger:** the *primary route leaving the RIB* — which is not the same as the path failing. Object tracking (IP SLA) closes that gap.

## 6. ⚙️ How It Works (under the hood)

### 6.1 🚪 Default route (3.3.a) — the catch-all 🟢

```
IPv4:  R1(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1
IPv6:  R1(config)# ipv6 route ::/0 2001:db8:12::1
```
- `0.0.0.0/0` / `::/0` is a **/0** — **zero** network bits — so it "contains" every address. By **longest-prefix match** (4.3), it can only win when **nothing more specific** matches. That's *why* it's the **last** resort. 🔑
- Installs the **gateway of last resort** — visible atop `show ip route` / `show ipv6 route`, and coded `S*` (the `*` = candidate default).
- **Where it lives:** stub routers, branch offices, and any device whose "everything else → send upstream" is a single obvious exit (home router → ISP; branch → HQ). One default replaces thousands of specific routes. 🟢

> 🕵️ **Dirty secret #1 — the default that eats everything.** If you *accidentally* make a default route more attractive than it should be, or you have a default but a needed **specific** route is missing, traffic for a real internal destination silently exits toward the ISP and dies. Conversely, a **`0.0.0.0/0` with a wrong or dead next hop** blackholes *all* off-net traffic at once — the single most impactful one-line mistake in routing. Treat the default route with respect. 🔧

### 6.2 🌐 Network route (3.3.b) — the everyday route 🟢

```
IPv4:  R1(config)# ip route 10.2.2.0 255.255.255.0 192.168.12.2
IPv6:  R1(config)# ipv6 route 2001:db8:2::/64 2001:db8:12::2
```
The bread-and-butter static: "to reach *this specific subnet*, go *this way*." Nothing exotic — but note the **mask defines specificity**. A `/24` and a `/25` of the same base are different routes (from 4.3), and a stray mask typo silently changes which packets this rule catches. 🟢

### 6.3 🎯 Host route (3.3.c) — one exact address 🟢🔵

```
IPv4:  R1(config)# ip route 10.2.2.9 255.255.255.255 192.168.12.2     ← /32
IPv6:  R1(config)# ipv6 route 2001:db8:2::9/128 2001:db8:12::2         ← /128
```
A `/32` (v4) or `/128` (v6) matches **exactly one** address — the **longest possible prefix**, so it **beats every broader route** by LPM. Engineer uses:
- **Policy override / traffic steering:** force *one* server's traffic down a special path while everything else in its subnet follows the general route.
- **Loopback reachability:** advertise/reach a router's `/32` loopback (heavily used by BGP, MPLS, management).
- **Precise blackhole:** `ip route 10.2.2.9 255.255.255.255 Null0` silently drops traffic to one abusive host.
- **Efficiency:** the router itself uses `/32` **local (`L`)** routes for its own IPs (from 4.2) — a built-in host route so it recognises traffic destined to itself.

🔑 Because a host route is maximally specific, it's the **surgical tool** of static routing: it changes the fate of *one* address without touching anything else. 🔵

### 6.4 📉 Floating static (3.3.d) — the dormant backup ⭐ 🟢🔵

This is the important one. A **floating static** is any static with an **AD raised above** the route it backs up. Because the router always installs the **lowest-AD** route (4.1/4.3), the floating one stays **invisible** — it "floats" in the config, unused — until the primary route **vanishes** from the table. Then it drops in and takes over. When the primary returns, the floating **withdraws** again.

**Example — backing up a primary static default with a second ISP:**
```
! Primary default via ISP-A  (AD 1, the static default)
R1(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1

! Floating backup default via ISP-B  (AD 200 → dormant)
R1(config)# ip route 0.0.0.0 0.0.0.0 198.51.100.1 200
```

**The failover walkthrough:**
```
 STATE          ROUTING TABLE (0.0.0.0/0)                     Traffic path
 ─────────────────────────────────────────────────────────────────────────
 ① Normal       S*  0.0.0.0/0 [1/0]   via 203.0.113.1         ▶ ISP-A
                (the AD-200 route is NOT in the table — it floats, unseen)

 ② ISP-A dies   primary withdrawn (next hop unreachable / interface down)
                └─▶ router installs the floater:
                S*  0.0.0.0/0 [200/0] via 198.51.100.1         ▶ ISP-B  ✅ auto-failover

 ③ ISP-A back   primary (AD 1) returns → beats AD 200 → reinstalled
                S*  0.0.0.0/0 [1/0]   via 203.0.113.1          ▶ ISP-A  (floater hides again)
```

**Choosing the floating AD — the "why that number?" reasoning:** 🟢
The floating AD must be **strictly greater than the AD of whatever it's backing up**, and **less than 255** (255 = "never install"). Pick the smallest value that guarantees it loses to the primary:

| Primary route being backed up | Its AD | Floating static AD must be |
|---|---|---|
| Another **static** | 1 | **> 1** (e.g. 2–254; often 200) |
| **EIGRP** internal | 90 | **> 90** (e.g. 100+) |
| **OSPF** | 110 | **> 110** (e.g. **130** common) |
| **RIP** | 120 | **> 120** (e.g. 130+) |
| Dual-ISP defaults | — | **200** or **254** by convention |

> ⚠️ **The classic error:** forgetting the AD entirely. `ip route 0.0.0.0 0.0.0.0 198.51.100.1` (no AD) defaults to **AD 1** — now it **ties the primary** and the router **load-balances across both ISPs** instead of using B only as backup. The whole design collapses. **The trailing AD is the entire point of a floating static.** 🔧

> 🕵️ **Dirty secret #2 — the backup that never wakes up.** A floating static activates when the **primary route leaves the RIB** — typically because the primary's **interface goes down**. But if the primary's *interface stays up while the path beyond it is broken* (a dead next hop across a switch, a failed PVC on a multipoint interface, an ISP outage two hops away), the primary route **stays installed**, so the floating static **never activates** — and you black-hole traffic *while your backup sits idle*. Cisco explicitly warns floating statics are "**independent of line-protocol status**." **Fix:** attach an **IP SLA probe + object tracking** so the primary route is withdrawn when the *actual path* fails, not just when the local interface drops. That's the difference between a lab floating static and a production one. 🔵

### 6.5 🧩 How they interact — all four on one router 🔵

```
R1# show ip route  (excerpt)
S*   0.0.0.0/0      [1/0]   via 203.0.113.1              ← default (3.3.a)
S    10.2.2.0/24    [1/0]   via 192.168.12.2             ← network (3.3.b)
S    10.2.2.9/32    [1/0]   via 192.168.99.1             ← host (3.3.c) — overrides the /24 for .9!
     (a floating S 0.0.0.0/0 [200/0] via 198.51.100.1 exists in config but isn't shown — it floats)
```
Packet to **`10.2.2.9`** → the **/32 host route wins** (longest prefix), sending it via `192.168.99.1`.
Packet to **`10.2.2.50`** → matches the **/24 network route** → via `192.168.12.2`.
Packet to **`8.8.8.8`** → matches only the **default** → via ISP-A.
This *is* the 4.3 decision engine, now built entirely from your own static routes. 🧠

## 7. ⚖️ Pros & Cons

| Type | 👍 Pros | 👎 Cons |
|---|---|---|
| **Default** | One route replaces thousands; essential for stubs/Internet edge | Wrong/dead next hop black-holes *all* off-net traffic; can mask missing specifics |
| **Network** | Precise, predictable reach to a subnet; simple | Doesn't scale (one per network); mask errors change matching silently |
| **Host** | Surgical — override/steer one address; loopbacks, blackholes | Easy to forget it's shadowing a broader route; clutter if overused |
| **Floating** | Cheap, protocol-free failover; clean primary/backup design | Reacts to route-withdrawal, **not** path death (needs tracking); forgetting the AD breaks it entirely |

## 8. 🌿 Variants (common → specific)

```
By PURPOSE (this doc — 3.3.a–d)
├── 🟢 Default   0.0.0.0/0 · ::/0        gateway of last resort
├── 🟢 Network   /24 · /64 (any subnet)  reach a remote network
├── 🟢 Host      /32 · /128              reach/override one address
│                └── 🔵 Blackhole host   ip route <host> 255.255.255.255 Null0
└── 🟢 Floating  any prefix + high AD    dormant backup
      ├── 🟢 Backup static default (dual-ISP)
      ├── 🟢 Backup for a dynamic route (AD > protocol)
      └── 🔵 Tracked floating (IP SLA + object tracking) ← production-grade failover

Cross-cutting
├── 🔵 Null0 route      drop traffic (host blackhole, or summary loop-prevention)
├── 🔵 Permanent        keep a static installed even if the interface goes down (rarely wise)
└── 🔵 name / tag       label & mark routes for docs / redistribution filtering
```

## 10. ✅ Best Practices

- 🟢 **Every stub/edge router needs exactly one clear default** — verify the gateway of last resort is set *and* points at a live next hop.
- 🟢 **Use host routes sparingly and intentionally** — they override everything; document *why* each `/32`/`/128` exists.
- 🟢 **Floating static AD = smallest value that beats the primary.** Back up OSPF (110) → 130; back up a static (1) → e.g. 200; dual-ISP → 200/254. **Never omit the AD.**
- 🔵 **Make floating statics path-aware** with IP SLA + `track` — otherwise they only survive *interface* failures, not real outages.
- 🟢 **Keep primary and backup pointing at the same destination prefix** — a floating static only "backs up" a route to the *same* network.
- 🔵 **Use `Null0` for intentional drops** (blackhole a host, or a summary route for loop prevention) — and remember LPM means a specific `Null0` route wins.

## 11. 🚫 No-Goes (mistakes & troubleshooting traps)

- ❌ **Floating static with no AD** → defaults to AD 1, ties the primary, causes load-balancing instead of backup. Breaks the whole design. 🔧
- ❌ **Floating AD not high enough** (e.g. AD 100 to back up RIP's 120) → the "backup" is actually **preferred**, hijacking the primary. Must **exceed** the primary's AD. 🟢
- ❌ **Expecting floating failover on a dead-next-hop-but-up-interface** → it won't activate (dirty secret #2). Use tracking. 🔵
- ❌ **Default route with a bad next hop** → blackholes *all* off-net traffic at once. Verify reachability. 🔧
- ❌ **Unintended host-route shadowing** → a `/32` you forgot about steals traffic from its subnet's `/24`. Check `show ip route <ip>` for the *actual* winner. 🔵
- ❌ **Confusing `::/0` with `::/128`** (or `0.0.0.0/0` with a `/32`) → default vs single-host; opposite ends of the specificity spectrum. 🟢
- 🔧 **Trap: "backup activated but traffic still fails."** The backup path itself may lack a **return route**, or the far end may not know how to reach you via ISP-B. Failover must be **symmetric**. 🔧
- ❌ **Making a floating static `permanent`** to "keep it up" → defeats failover; the stale route stays installed and black-holes. 🔵

## 13. 🧪 Practical Tasks

> Goal: build all four types, watch host-route shadowing and floating failover happen live.

1. **🟢 Default-route lab (Packet Tracer 8).** On a stub R1, add `ip route 0.0.0.0 0.0.0.0 <ISP>`. Confirm the **gateway of last resort** appears and off-net pings succeed. Point it at a **dead** next hop → watch *all* off-net traffic black-hole. Fix it. 🔧

2. **🎯 Host-route override.** With a working `10.2.2.0/24` network route via path A, add `ip route 10.2.2.9 255.255.255.255 <path-B>`. `show ip route 10.2.2.9` → the **/32 wins**; `show ip route 10.2.2.50` → the **/24 wins**. Prove specificity beats generality (4.3 in action).

3. **📉 Floating failover (the headline lab).** Dual-path R1: primary `ip route 0.0.0.0 0.0.0.0 <A>` (AD 1) + floating `ip route 0.0.0.0 0.0.0.0 <B> 200`. Confirm only A shows. `shutdown` A's interface → watch **B install as `[200/0]`** and traffic reroute. `no shutdown` A → B **withdraws**. Then **omit the `200`** and observe the broken load-balancing behaviour. 🔧

4. **🔵 The "never wakes up" trap + tracking.** Break the primary's **path** without downing its interface (e.g. shut a switch link two hops out). Confirm the floater **doesn't activate**. Add **IP SLA + `track`** to the primary → break the path again → now it fails over correctly. *This is the lab that separates CCNA-answer from engineer.*

5. **🕳️ Blackhole a host.** `ip route 10.2.2.9 255.255.255.255 Null0` → ping .9 fails (dropped), ping .10 works. `show interface Null0` counters climb. Demonstrates surgical `/32` + Null0.

6. **🌐 IPv6 parity.** Repeat the default (`::/0`), network (`/64`), host (`/128`), and floating (`::/0 … 200`) types in IPv6 on the same topology — confirm identical behaviour with IPv6 syntax.
