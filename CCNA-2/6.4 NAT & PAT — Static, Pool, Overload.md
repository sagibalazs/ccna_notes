## 2️⃣ Visualization — The Whole Picture at a Glance

**The one job:** rewrite the address (and for PAT, the port) at the border so a private host can talk to the public internet.

```
        INSIDE (private, RFC 1918)          NAT BORDER ROUTER            OUTSIDE (public internet)
        ─────────────────────────       ──────────────────────       ──────────────────────────
         Host A 192.168.1.10  ─────▶  ip nat inside │ ip nat outside  ─────▶  Server 198.51.100.1
         src 192.168.1.10:5001         ┌─────────── rewrite ──────────┐        sees src 203.0.113.9:1024
                                       │  192.168.1.10:5001            │
                                       │        ▼  translate  ▼        │
                                       │  203.0.113.9:1024             │
                                       └───────────────────────────────┘
         ◀───── reply restored ─────    reply to 203.0.113.9:1024  ◀─────────  reply to 203.0.113.9:1024
         dst 192.168.1.10:5001          (table reverses the mapping)
```

**The four address names — the #1 CCNA confusion, settled by ONE rule:** *inside/outside = whose host it is; local/global = which side you're standing on.*

```
                        ┌──────────── INSIDE host (192.168.1.10) ────────────┐
                        │                                                     │
        INSIDE LOCAL  ──┤  192.168.1.10   how the inside host looks INSIDE    │  (private, pre-NAT)
        INSIDE GLOBAL ──┤  203.0.113.9    how the inside host looks OUTSIDE   │  (public, post-NAT)
                        └─────────────────────────────────────────────────────┘

                        ┌──────────── OUTSIDE host (198.51.100.1) ───────────┐
        OUTSIDE GLOBAL ─┤  198.51.100.1   how the outside host looks OUTSIDE  │  (its real public IP)
        OUTSIDE LOCAL  ─┤  198.51.100.1   how the outside host looks INSIDE   │  (usually identical)
                        └─────────────────────────────────────────────────────┘
```

**Three flavours — pick by how many public IPs you have:**

| Type | Mapping | Public IPs needed | Use case |
|---|---|---|---|
| 🟢 **Static NAT** | 1 : 1, **permanent** | one per inside host | a server that must be reachable inbound |
| 🟢 **Dynamic NAT** | 1 : 1, **temporary** (from a pool) | a pool | occasional outbound, fewer hosts than public IPs |
| 🟢 **PAT / Overload** | **many : 1** (via ports) | **one** (or a few) | the whole LAN behind a single ISP address (home + most offices) |

**The translation table** (`show ip nat translations`):

```
 Pro  Inside global        Inside local         Outside local        Outside global
 tcp  203.0.113.9:1024     192.168.1.10:5001    198.51.100.1:80      198.51.100.1:80    ← PAT flow
 ---  203.0.113.10         192.168.20.20        ---                  ---                ← static server
```

## 3️⃣ TL;DR

**NAT (Network Address Translation) rewrites the IP address in a packet as it crosses the border router, so hosts using private RFC 1918 addresses can reach the public internet on a routable address.** Three flavours: **static** (permanent 1:1, for servers you must reach inbound), **dynamic** (temporary 1:1 from a **pool**), and **PAT / overload** (many private hosts share **one** public IP, distinguished by unique **source port numbers** — this is what your home router does). Cisco names the four address views **inside local / inside global / outside local / outside global** (whose host × which side). You mark interfaces `ip nat inside` / `ip nat outside`, then `ip nat inside source …`. The router keeps a **translation table** to reverse the mapping on replies. NAT bought IPv4 decades of extra life — but it **breaks end-to-end connectivity**, complicates IPsec/FTP/SIP (needs NAT-T / ALGs), and **is not a firewall**.

---

## 4️⃣ Importance — The Problem First 🎯

**The problem — IPv4 ran out.** IPv4 has ~**4.3 billion** addresses (2³²). The internet blew past that years ago; the free pools are **exhausted**. Yet:

- 🏠 **Every organisation has far more devices than public addresses.** A company with 10,000 hosts can't get 10,000 public IPv4 addresses — they don't exist to hand out.
- 🔒 **Private addresses (RFC 1918: `10/8`, `172.16/12`, `192.168/16`) solve the *internal* problem but are non-routable.** Every network on earth reuses them, so the public internet **drops** them — precisely *because* they're not unique.
- ↔️ **So there's a gap:** hosts *have* addresses that work internally but are useless on the internet. Something at the border must bridge private ↔ public.

**The solution — NAT (RFC 1631 → 3022):** at the boundary router, **translate** the private source address into a public one on the way out, and **reverse it** on the replies using a **translation table**. One organisation runs thousands of hosts on `10.0.0.0/8` behind a handful of public addresses — or, with **PAT**, behind a *single* one.

**Why PAT specifically was the game-changer:** plain NAT still needs one public IP per *concurrent* inside host — you'd exhaust a small pool fast. **PAT** adds the **transport-layer port** to the mapping: many inside hosts share one public IP because each flow gets a **unique source port** on that shared address. A single public IP can theoretically carry tens of thousands of simultaneous flows. *That's* why one ISP address can serve an entire household or office. Without PAT, IPv4 would have collapsed much sooner.

**Why an engineer cares (beyond the exam):**
- The **inside-local/global** terminology trips up *everyone* first — and you can't read `show ip nat translations` or debug a NAT ticket without it cold.
- "Outbound works, inbound doesn't" is a daily reality: NAT hides inside hosts, so **inbound** needs **static NAT / port forwarding**. Knowing which flavour to reach for is the job.
- NAT **breaks assumptions** other protocols make (IPsec, FTP, SIP, VoIP). Half of "the VPN won't come up" and "voice is one-way" tickets trace back to NAT. You must know *why*.
- **NAT ≠ security.** Believing it is a firewall is a real, dangerous misconception you'll have to correct in the field.

## 5️⃣ Description 📋

- **NAT = Network Address Translation** — rewrites source and/or destination IP (and for PAT, the port) at a boundary router; maintains a **translation table** to reverse it.
- **Inside vs outside** is about **whose host** it is; **local vs global** is about **which side you're viewing from**:
  - **Inside local** — the inside host's real (private) address, as seen inside.
  - **Inside global** — the inside host's translated (public) address, as seen outside.
  - **Outside global** — the outside host's real (public) address.
  - **Outside local** — how the outside host appears to the inside (usually identical to outside global).
- **Static NAT** — a fixed, permanent 1:1 mapping. Works **both directions** → the way to make an inside server reachable from outside.
- **Dynamic NAT** — inside hosts borrow a public address from a **pool** on demand; released after idle timeout. Still 1:1 while active → pool can **exhaust**.
- **PAT / NAT overload** — many inside hosts → **one** (or few) public IPs, disambiguated by **unique source ports**. The everyday case.
- **Static PAT (port forwarding)** — a permanent mapping of a *public IP:port* to an *inside IP:port* → lets specific inbound services through PAT.
- **Interfaces are tagged** `ip nat inside` / `ip nat outside`; without both, NAT does nothing.
- **Direction keyword** `inside source` translates the *source* of inside-originated traffic (the common case); `outside source` translates outside hosts' addresses (rarer).
- NAT operates on the **routed path** — it's a boundary function, invisible to the inside hosts.

## 6️⃣ How It Works — Under the Hood ⚙️

### 6.1 A PAT packet, out and back 🟢🔬

Home LAN `192.168.1.0/24`, one public IP `203.0.113.9`. Host A browses `198.51.100.1:80`.

```
OUTBOUND (inside → outside)
  1. Host A sends:      src 192.168.1.10:5001   dst 198.51.100.1:80
  2. Router (nat inside→outside) rewrites the SOURCE and records a table entry:
        inside local  192.168.1.10:5001   ⇄   inside global 203.0.113.9:1024
  3. Leaves the router: src 203.0.113.9:1024    dst 198.51.100.1:80
        (recomputes IP + TCP/UDP checksums, since addresses/ports changed)

RETURN (outside → inside)
  4. Server replies to: dst 203.0.113.9:1024    src 198.51.100.1:80
  5. Router looks up 203.0.113.9:1024 in the table → maps back to 192.168.1.10:5001
  6. Delivered to Host A: dst 192.168.1.10:5001  src 198.51.100.1:80   ✅
```

🔑 **The port is the demux key.** Host B on `192.168.1.11:5001` browsing the same server also becomes `203.0.113.9:<some port>` — but the router assigns it a **different** global port (e.g. `:1025`), so the two flows never collide on the return trip. **The `<global IP:global port>` pair is what makes the many-to-one mapping reversible.**

### 6.2 Port preservation & selection 🕵️🔵

PAT tries to **preserve the original source port** if it's free on the global address; if it's already in use, it picks the next available. Historically Cisco allocated from ranges (0–511, 512–1023, 1024–65535) to mirror the original. Two consequences engineers hit:

- Two inside hosts using the **same** source port to the **same** destination force PAT to **remap** one of them — occasionally breaking naïve apps that assume their source port survives.
- A single public IP has a finite pool of ports → under huge scale (CGN), **port exhaustion** is real, which is why carriers assign *port blocks* per subscriber.

### 6.3 Static NAT — the two-way door 🟢

```
Router(config)# ip nat inside source static 192.168.20.20 203.0.113.10
```
- Creates a **permanent** `192.168.20.20 ⇄ 203.0.113.10` entry, present in the table before any traffic (note the `---` for port/outside columns — 1:1 needs no port).
- **Bidirectional:** outside hosts can initiate to `203.0.113.10` and reach the inside server. This is *the* mechanism for publishing an inside server.

**Static PAT (port forward)** — publish just one service on a shared IP:
```
Router(config)# ip nat inside source static tcp 192.168.20.20 80 203.0.113.9 80
```
→ inbound `203.0.113.9:80` is forwarded to the inside web server, while the same public IP still does outbound overload for everyone else.

### 6.4 Dynamic NAT — a pool, 1:1 while active 🟢

```
Router(config)# ip nat pool PUB 203.0.113.20 203.0.113.30 netmask 255.255.255.224
Router(config)# access-list 1 permit 192.168.1.0 0.0.0.255
Router(config)# ip nat inside source list 1 pool PUB
```
- ACL 1 **selects which inside hosts** may translate; the pool supplies the public addresses.
- Each active inside host consumes **one** pool address until idle timeout → **pool exhaustion** if more hosts than addresses. Fix by adding **`overload`** (→ PAT) or enlarging the pool.

### 6.5 PAT / overload — the everyday config 🟢

**Overload a pool:**
```
Router(config)# ip nat inside source list 1 pool PUB overload
```
**Overload the WAN interface IP directly** (most common — home/small office):
```
Router(config)# interface g0/0
Router(config-if)#  ip address 192.168.1.1 255.255.255.0
Router(config-if)#  ip nat inside
Router(config)# interface g0/1
Router(config-if)#  ip address dhcp
Router(config-if)#  ip nat outside
Router(config)# access-list 1 permit 192.168.1.0 0.0.0.255
Router(config)# ip nat inside source list 1 interface g0/1 overload
```
The `overload` keyword is the whole difference between "1:1 pool" and "many:1 port-multiplexed."

### 6.6 Verify & troubleshoot 🟢

```
show ip nat translations [verbose]   ! the live table — read the 4 columns
show ip nat statistics               ! hits, misses, interfaces, pool utilisation
debug ip nat                         ! per-packet translation trace (careful in prod)
clear ip nat translation *           ! flush entries (e.g. after a config fix)
```
- **`show ip nat statistics`** columns: total translations, **miss** count (packets that needed a translation but none could be built), inside/outside interface list, pool allocation %. A **climbing miss counter** or a **100 %-allocated pool** is the first sign of exhaustion or a config error.

### 6.7 Why NAT breaks things 🕵️🔵

NAT violates the internet's original **end-to-end** principle (every host uniquely addressable). That has real fallout:

- **IPsec AH** signs the IP header → NAT's rewrite **invalidates the signature** → AH is unusable through NAT. **ESP** survives only via **NAT-T** (RFC 3948), which wraps ESP in **UDP/4500**.
- **FTP (active mode), SIP, H.323** embed **IP addresses/ports inside the payload**. NAT rewrites the header but not the payload → the embedded address is wrong. Fix: an **ALG** (Application-Layer Gateway) that peeks into the payload and fixes it — brittle and a frequent VoIP-one-way-audio culprit.
- **Inbound-initiated** connections have no table entry → dropped, unless a **static/port-forward** exists.
- **Logging/attribution** gets muddy: many users behind one IP complicate abuse tracing (a real operational and legal issue with CGN).

## 7️⃣ Pros & Cons ⚖️

| ✅ Pros | ❌ Cons / Costs |
|---|---|
| **Conserves IPv4** — the reason the internet didn't stall | **Breaks end-to-end** connectivity / addressability |
| **PAT:** a whole LAN behind **one** public IP | **Inbound needs static/port-forward** — extra config |
| **Hides internal addressing** (topology opacity) | **Not a firewall** — a dangerous myth (see No-Goes) |
| **Flexible** — renumber inside without touching public | **Breaks IPsec (AH), FTP, SIP** → needs NAT-T / ALGs |
| **Cheap** — runs on the border router you already have | **Stateful** — table memory + CPU; entries can exhaust |
| Eases **ISP changes** (change the outside mapping only) | **Complicates logging / attribution**, harder troubleshooting |

## 8️⃣ Variants — Common → Specific 🧬

- 🟢 **Static NAT** — permanent 1:1, bidirectional; publish inside servers.
- 🟢 **Dynamic NAT** — temporary 1:1 from a **pool**; no overload → can exhaust.
- 🟢 **PAT / NAT overload** — many:1 via ports; the ubiquitous case (`overload`).
- 🟢 **Static PAT / port forwarding** — permanent `public IP:port → inside IP:port`; inbound service on a shared IP.
- 🔵 **Inside source vs outside source NAT** — translate inside-originated source (normal) vs translate outside hosts' addresses (rare, e.g. overlapping-subnet mergers).
- 🔵 **Twice NAT / overlapping-address NAT** — translate **both** source and destination (used when two networks share the same private range).
- 🔵 **Policy NAT** — translation driven by extended ACLs (match source *and* destination).
- 🔵 **NAT Virtual Interface (NVI)** — `ip nat enable` model, no strict inside/outside tagging.
- 🔵 **CGN / CGNAT (Carrier-Grade NAT, RFC 6598)** — ISP-scale PAT using **`100.64.0.0/10`** shared space; per-subscriber port blocks.
- 🔵 **NAT64 (RFC 6146)** — translates IPv6-only clients to IPv4 servers (an IPv6-transition tool, not IPv4 conservation).

## 9️⃣ Devices / Media / Protocols 🛠️

| Element | Role in NAT |
|---|---|
| **Border router / L3 switch / firewall** | Performs the translation; holds the table; tags `ip nat inside/outside` |
| **Inside hosts** | Use RFC 1918 addresses; unaware translation happens |
| **Outside hosts / servers** | See only the **inside global** address |
| **Firewall / NGFW** | Often does NAT *plus* real security (the two are separate functions) |
| **ISP CGN** | A second, carrier layer of PAT above your own (double NAT) |
| **Protocols affected** | **TCP/UDP** (port rewrite for PAT), **ICMP** (uses query ID as the demux key), **IPsec** (NAT-T/UDP 4500), **FTP/SIP/H.323** (need ALGs) |
| **Address spaces** | **RFC 1918** inside · public inside-global · **100.64.0.0/10** for CGN |

## 🔟 Best Practices ✅

- 🎯 **Use PAT (overload)** for general internet access — one public IP, thousands of flows. Reserve scarce public IPs for servers.
- 🖇️ **Static NAT / port-forward** only for services that genuinely need inbound reachability; keep the exposed surface minimal.
- 🧾 **Write a tight ACL** for `ip nat inside source list` — permit exactly the inside subnets that should translate. Avoid `permit any`.
- 🧭 **Mark interfaces correctly** (`ip nat inside` on the LAN side, `ip nat outside` on the WAN side) — the single most common cause of "NAT does nothing."
- 🔐 **Pair NAT with an actual firewall/ACL.** NAT is not security; make the security explicit.
- 📊 **Monitor `show ip nat statistics`** — watch the **miss** counter and pool allocation; rising misses = ACL/pool problem.
- 🧊 **Right-size timeouts** — long UDP/ICMP NAT timeouts waste table entries; too short break long-lived flows.
- 🔀 **Plan for NAT-T** on any IPsec that crosses NAT (allow UDP 4500), and know which **ALGs** your voice/FTP need.
- ➡️ **Prefer IPv6** where possible — it removes the *need* for NAT entirely (global addressing), sidestepping every NAT-breakage above.

## 1️⃣1️⃣ No-Goes — Mistakes & Troubleshooting Traps 🚫

**Config mistakes**
- ❌ **Missing `ip nat inside` / `ip nat outside`** on the interfaces → NAT silently does nothing. #1 error. `show ip nat statistics` shows the interface list — check it first.
- ❌ **Interfaces tagged backwards** (inside ↔ outside) → translations never match; traffic isn't translated the way you expect.
- ❌ **ACL too broad (`permit any`) or too narrow** → translating the wrong traffic, or none. Match the exact inside subnets.
- ❌ **Dynamic NAT without `overload`** on a network with more hosts than pool addresses → **pool exhaustion**, new hosts get no translation (rising **miss** counter).
- ❌ **Forgetting a route back to the inside global / pool subnet** (on upstream devices) → replies never return.
- ❌ **Overlapping the pool with real interface/host addresses** → conflicts.
- ❌ **Expecting inbound to "just work"** through PAT → it won't; you need **static NAT / port-forward**.

**Diagnostic signatures**
- 🔍 **`show ip nat translations` empty while hosts "can't reach internet"** → interfaces not tagged, or ACL matches nothing.
- 🔍 **`show ip nat statistics` miss counter climbing** → traffic hits NAT but no entry can be built (pool full, ACL/route issue).
- 🔍 **Outbound works, inbound to a server fails** → no static mapping/port-forward for that service.
- 🔍 **VPN won't establish across NAT** → IPsec AH through NAT (impossible) or ESP without **NAT-T** (open UDP 4500).
- 🔍 **VoIP one-way audio / FTP hangs** → embedded-address problem; missing/broken **ALG**.
- 🔍 **Two hosts, same app, one breaks** → source-port collision forcing a PAT remap the app didn't expect.

**Conceptual traps**
- ❌ **"NAT is a firewall."** It is **not**. It offers *incidental* inbound opacity (no inbound state = drop), but it enforces no policy, inspects nothing, and static/port-forward punches straight through. Always deploy real filtering.
- ❌ **Mixing up the four terms.** Re-anchor: *inside/outside = whose host; local/global = which viewpoint.* Inside **local** = private; inside **global** = public.
- ❌ **Thinking PAT changes only the address** — it changes **address *and* port**; the port is what makes it reversible.
- ❌ **Believing NAT preserves end-to-end** — it deliberately doesn't; that's the root of its side effects.

## 1️⃣3️⃣ Practical Tasks 🧪

*(listed briefly here — expanded with full walkthroughs later in context)*

1. **🧩 Packet Tracer 8 — PAT (the home-router build):**
   - Inside LAN `192.168.1.0/24`, router WAN via DHCP, one "internet" server.
   - Tag `ip nat inside` / `ip nat outside`, ACL for the LAN, `ip nat inside source list 1 interface g0/1 overload`.
   - Ping/browse out from two PCs; run `show ip nat translations` and confirm **both** appear as the same inside-global IP with **different ports**.
2. **🧩 Static NAT + port-forward:**
   - Publish an inside web server with `ip nat inside source static tcp … 80 … 80`.
   - From "outside," reach the server via the public IP; confirm the permanent `---` entry in the table.
3. **🧩 Dynamic pool → exhaustion:**
   - Build a 2-address pool **without** `overload`, drive 3+ hosts, watch the **miss** counter rise in `show ip nat statistics`. Add `overload`; watch it recover.
4. **🦈 Wireshark (two-point capture):**
   - Capture **inside** and **outside** of the router for one flow. Diff the packets: source IP:port rewritten out, restored back. Note the **checksum** recalculation.
5. **🔎 Read the table like an engineer:**
   - Correlate `show ip nat translations` columns to the live flows; use `debug ip nat` on a single ping to watch entries created/reversed; `clear ip nat translation *` and observe rebuild.
6. **🔬 Stretch (engineer):** stand up an **IPsec** tunnel across a NAT device and observe it **fail with AH / succeed with ESP + NAT-T (UDP 4500)**. Then break an **FTP/SIP** flow through NAT and fix it with the relevant **ALG**.
