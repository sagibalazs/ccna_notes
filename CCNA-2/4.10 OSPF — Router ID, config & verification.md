## 3. ⚡ TL;DR

- **Router ID (3.4.d)** is a 32-bit dotted value that **uniquely identifies** a router in OSPF — used in DR/BDR tie-breaks, master/slave negotiation, and to stamp every LSA. 🟢
- **Selection order:** ① manual `router-id` → ② highest **loopback** IP → ③ highest active **interface** IP (even non-OSPF ones). 🟢
- **RID is sticky:** picked **once** at process start; to change it you must `clear ip ospf process` (or reload) — a brief outage. 🟢🔵
- **Best practice: set the RID manually** (or via a loopback) so it's **stable and predictable** — never let it float on a physical interface that might change or go down. 🟢
- **Config:** `router ospf <pid>` → `router-id` → `network <addr> <wildcard> area <id>` (traditional) **or** `ip ospf <pid> area <id>` per interface (modern). Process ID is **local only** (need not match neighbours). 🟢
- **Wildcard mask** = inverse subnet mask (0 = must-match, 255 = ignore); `0.0.0.0` matches one exact interface. 🟢
- **`passive-interface`** stops Hellos on a port (no neighbours form) **but still advertises that subnet** — perfect for LAN/user-facing links. 🟢
- **Verify** with `show ip ospf neighbor` (adjacencies), `show ip route ospf` (routes), `show ip ospf interface`, `show ip protocols`. 🟢

## 4. ❓ Importance (problem → solution)

### The problem 🚧
You now understand OSPF's machinery (4.8) and adjacencies (4.9) — but two practical things stand between you and a working network:

1. **OSPF needs a stable identity.** Every router must have a **unique Router ID**. If you let OSPF *auto-pick* it from a physical interface, that RID can **change** when interfaces come and go — silently altering DR elections, breaking the "which router is which" mapping in your LSDB, and (if two routers collide on a RID) **preventing adjacencies entirely**. And because the RID is **sticky**, a RID you "fixed" in config may *not* take effect until you reset the process — a classic "why didn't my change work?" trap. 🔧
2. **You have to actually enable OSPF on the right interfaces** — and the syntax (`network` + **wildcard mask** + area) is unlike anything else in IOS. Get the wildcard wrong and you either enable OSPF on interfaces you didn't mean to (forming unwanted adjacencies) or fail to enable it where you needed to (missing routes). And you must know how to **verify** it came up, or you're flying blind.

The exam's "configure and verify single-area OSPFv2" *is* these two skills. 🟢

### The solution 🎯
- **Pin the Router ID** — manually or via a loopback — so OSPF's identity is stable, predictable, and collision-free, and know the `clear ip ospf process` ritual to apply changes.
- **Learn the config skeleton and the wildcard mask** cold — two methods (network vs interface), one wildcard rule (inverse mask), plus `passive-interface` for edges.
- **Own the verification set** — six commands that answer "is OSPF up, adjacent, and installing the right routes?"

Do this and you can stand up, confirm, and troubleshoot single-area OSPFv2 on demand — the capstone of the whole OSPF arc. 🧠

## 5. 📖 Description

- 🟢 **Router ID (RID):** a 32-bit value (dotted like an IP) uniquely naming a router in the OSPF domain. Chosen once at process start.
- 🟢 **Selection order:** manual `router-id` → highest loopback IP → highest active interface IP.
- 🟢 **Stickiness:** the RID doesn't update on config change until `clear ip ospf process` or reload.
- 🟢 **Loopback interface:** a virtual, always-up interface — ideal, stable RID source.
- 🟢 **`router ospf <process-id>`:** starts an OSPF instance. Process ID is **locally significant** (need not match neighbours — unlike EIGRP's AS).
- 🟢 **`network <addr> <wildcard> area <id>`:** enables OSPF on all interfaces whose IP matches, and places them in the area.
- 🟢 **Wildcard mask:** inverse subnet mask; `0` bits must match, `1` (255) bits are ignored.
- 🟢 **Interface method (`ip ospf <pid> area <id>`):** enables OSPF directly per interface — no network statement.
- 🟢 **`passive-interface`:** suppresses Hellos on an interface (no adjacency) but still **advertises its subnet**.
- 🟢 **`default-information originate`:** injects a default route (`0.0.0.0/0`) into OSPF.

## 6. ⚙️ How It Works (under the hood)

### 6.1 🆔 Router ID — what it is and why it matters 🟢

The RID is OSPF's **name badge**. It looks like an IPv4 address but is just a **32-bit identifier** — it need not be routable or even a real interface. It's used to:
- **uniquely identify** each router in the LSDB (every Type 1 Router LSA is stamped with its originator's RID),
- **break ties** in DR/BDR election (highest RID wins when priorities tie — from 4.9),
- **negotiate master/slave** in the ExStart DBD exchange (higher RID = master).

🔑 **Duplicate RIDs on directly-connected routers prevent adjacency** and cause instability. Uniqueness is non-negotiable.

### 6.2 🎯 The selection order (3.4.d) 🟢

```
 ① router-id A.B.C.D configured under 'router ospf'?  ── YES ──▶ that is the RID (wins all)
                    │ NO
 ② any UP loopback interface?  ── YES ──▶ HIGHEST loopback IP becomes the RID  ★ preferred ★
                    │ NO
 ③ ── HIGHEST IP among active (non-loopback) interfaces becomes the RID
        (the interface does NOT need to run OSPF)
```

**Why loopbacks are the classic choice:** a loopback is a **virtual interface that never goes down** (no cable, no link partner). A physical interface's IP can disappear if the port fails or is reconfigured — and if that IP was the RID, OSPF's identity is now unstable. A loopback (e.g. `Loopback0 1.1.1.1/32`) gives a **permanent, predictable** RID and doubles as an easy-to-remember router label. 🔵

### 6.3 ⚠️ Stickiness — the #1 RID trap 🟢🔵

The RID is selected **exactly once**, when the OSPF process first starts. **Changing the config afterward does NOT change the running RID:**

```
R1(config)# router ospf 1
R1(config-router)# router-id 1.1.1.1     ← you set it...
R1# show ip ospf | include Router ID
 Routing Process "ospf 1" ... Router ID 192.168.11.1    ← ...but it STILL shows the old one!

R1# clear ip ospf process               ← must reset the process
 Reset ALL OSPF processes? [no]: yes
R1# show ip ospf | include Router ID
 ... Router ID 1.1.1.1                    ← now it takes effect ✅
```

> 🕵️ **Dirty secret #1 — the RID that "won't change."** Countless engineers set `router-id`, see no effect, and assume the command is broken. It isn't — the RID is **sticky**. You **must** `clear ip ospf process` (or reload) to apply it, and that **flaps all adjacencies briefly** (a short outage). So: set the RID **before** OSPF is doing real work, or schedule the reset. On the exam, remember: *config change alone doesn't move the RID.* 🔵

### 6.4 🔧 The traditional `network` command + wildcard mask 🟢

```
R1(config)# router ospf 1
R1(config-router)# network 10.0.12.0 0.0.0.3 area 0
                            │           │       │
                            │           │       └─ put matched interfaces in AREA 0
                            │           └─ WILDCARD MASK (inverse of subnet mask)
                            └─ address to match interface IPs against
```
The `network` statement doesn't advertise a network directly — it **selects which interfaces run OSPF** (any interface whose IP falls in the matched range) and assigns them to an area. That interface's connected subnet is then advertised.

**Wildcard mask — the inverse-mask rule:** a **`0`** bit means *"this bit must match,"* a **`1`** bit (255 in an octet) means *"ignore this bit."* It's the **bitwise inverse** of the subnet mask:

```
   wildcard = 255.255.255.255  −  subnet mask
```

| Prefix | Subnet mask | Wildcard | Matches |
|---|---|---|---|
| /32 | 255.255.255.255 | **0.0.0.0** | one exact IP (a single interface) |
| /30 | 255.255.255.252 | **0.0.0.3** | a P2P link's 4 addresses |
| /27 | 255.255.255.224 | **0.0.0.31** | a /27 block |
| /24 | 255.255.255.0 | **0.0.0.255** | a whole /24 |
| /16 | 255.255.0.0 | **0.0.255.255** | a /16 |

**Binary sanity check (/27 → 0.0.0.31):**
```
 subnet /27 last octet = 1110 0000  (224)
 wildcard last octet   = 0001 1111  (31)   ← inverse: 0=match (top 3 bits), 1=ignore (low 5)
```
🔑 **The precise trick:** `network 10.0.12.1 0.0.0.0 area 0` enables OSPF on **exactly one interface** (the one with IP `10.0.12.1`) — the surgical way to control which interfaces peer.

### 6.5 🆕 The interface method (modern, cleaner) 🟢

```
R1(config)# router ospf 1
R1(config-router)# router-id 1.1.1.1
R1(config)# interface GigabitEthernet0/0
R1(config-if)# ip ospf 1 area 0            ← enable OSPF directly on THIS interface
R1(config)# interface GigabitEthernet0/1
R1(config-if)# ip ospf 1 area 0
```
No wildcard math, no ambiguity — you name the interface and the area directly. Both methods are exam-valid; the interface method is favoured in modern configs for clarity. (You still set the RID under `router ospf`.)

### 6.6 🤫 `passive-interface` — advertise but don't peer 🟢

```
R1(config-router)# passive-interface GigabitEthernet0/1
   · Stops sending/processing Hellos on Gi0/1 → NO neighbour can form there
   · BUT the Gi0/1 subnet is STILL advertised into OSPF
```
Use it on **user/LAN-facing** interfaces where there are no other OSPF routers: you want the subnet in OSPF, but you don't want to waste Hellos (or invite a rogue OSPF speaker) on a client segment. `passive-interface default` makes *all* interfaces passive, then `no passive-interface <x>` re-activates only the ones facing real neighbours — a security-minded default. 🔵

### 6.7 🌐 Injecting a default route 🟢

```
R1(config-router)# default-information originate          ← advertise 0.0.0.0/0 IF one exists locally
R1(config-router)# default-information originate always   ← advertise it even without a local default
```
This lets an edge router tell the whole OSPF domain "send Internet-bound traffic to me" — the dynamic-routing equivalent of the static default from 4.6. Other routers install it as `O*E2 0.0.0.0/0`. 🟢

### 6.8 🧩 Putting it together — a full worked config 🟢

```
! ── R1 (edge, has the Internet default) ──
interface Loopback0
 ip address 1.1.1.1 255.255.255.255           ! stable RID source
interface GigabitEthernet0/0
 ip address 10.0.12.1 255.255.255.252         ! link to R2
interface GigabitEthernet0/1
 ip address 192.168.1.1 255.255.255.0         ! user LAN
!
router ospf 1
 router-id 1.1.1.1
 network 10.0.12.0 0.0.0.3 area 0             ! the R1–R2 link
 network 192.168.1.0 0.0.0.255 area 0         ! the LAN
 passive-interface GigabitEthernet0/1         ! no OSPF neighbours on the user LAN
 default-information originate                 ! advertise the default
```

### 6.9 🔍 Verification — the six-command tour 🟢

```
R1# show ip ospf | include Router ID
 → confirm the RID is what you intended (after clear if you changed it)

R1# show ip ospf neighbor              ← THE primary health check
 Neighbor ID  Pri  State      Dead Time  Address     Interface
 2.2.2.2       1   FULL/BDR   00:00:37   10.0.12.2   Gi0/0     ← want FULL (4.9)

R1# show ip ospf interface brief
 → which interfaces run OSPF, their area, cost, network type, DR/BDR, neighbour count

R1# show ip route ospf
 O    172.16.5.0/24 [110/11] via 10.0.12.2, 00:03:20, Gi0/0    ← learned routes

R1# show ip protocols
 → "Routing Protocol is ospf 1", the RID, advertised networks, passive interfaces

R1# show ip ospf database
 → the LSDB (Type 1 Router LSAs from each router, Type 2 on shared segments)
```

🔑 **Troubleshooting flow:** neighbour missing? → `show ip ospf neighbor` (state → cause, per 4.9's matrix) → check `show ip ospf interface` for matching timers/area/network-type → confirm interfaces are actually in OSPF via `show ip protocols`. Route missing but neighbour FULL? → check the far router is advertising it (`network`/interface enabled there). 🔧

## 7. ⚖️ Pros & Cons

| Choice | 👍 Pros | 👎 Cons |
|---|---|---|
| **Manual RID** | Stable, predictable, collision-free; clear labelling | Must remember to set it (and reset process to apply) |
| **Loopback RID** | Always-up, stable; doubles as a management/label address | One more interface to configure |
| **Auto (interface) RID** | Zero config | Can change/collide; unstable — avoid in production |
| **`network` method** | One line can cover many interfaces; classic/expected | Wildcard math errors enable/miss interfaces silently |
| **Interface method** | Explicit, no wildcard math, clear intent | One statement per interface |
| **`passive-interface`** | Advertises subnet without peering; security | Forgetting it on a real link breaks that adjacency |

## 10. ✅ Best Practices

- 🟢 **Always set the Router ID explicitly** (`router-id` or a loopback) — never leave OSPF's identity to float on a physical interface.
- 🟢 **Set the RID before OSPF carries real traffic**, or schedule the `clear ip ospf process` (it briefly flaps adjacencies).
- 🟢 **Prefer the interface method** (`ip ospf 1 area 0`) for clarity, or use tight wildcards (`0.0.0.0`) to enable exactly the interfaces you intend.
- 🟢 **Make user/LAN-facing interfaces passive** (or `passive-interface default` + selective `no passive-interface`) — advertise the subnet without inviting rogue adjacencies.
- 🔵 **Set `auto-cost reference-bandwidth` identically on every router** (from 4.8) as part of your standard OSPF template.
- 🟢 **Verify in order:** `show ip ospf neighbor` (FULL?) → `show ip route ospf` (routes?) → `show ip protocols` (advertising the right nets?).

## 11. 🚫 No-Goes (mistakes & troubleshooting traps)

- 🔧 **"I set `router-id` but it didn't change."** The RID is **sticky** — run `clear ip ospf process` (or reload). Config alone won't move it. 🟢
- ❌ **Letting the RID auto-select from a physical interface.** It can change or collide; **duplicate RIDs on adjacent routers block adjacency**. Pin it. 🔧
- ❌ **Wrong wildcard mask.** Using a *subnet* mask instead of the *inverse* (e.g. `255.255.255.0` instead of `0.0.0.255`) enables OSPF on the wrong interfaces — or none. Remember: **inverse**. 🟢
- ❌ **Forgetting an interface in a `network` statement.** That interface's subnet won't be advertised and no neighbour forms there. Check `show ip protocols` / `show ip ospf interface`. 🔧
- ❌ **`passive-interface` on a real OSPF link.** Kills that adjacency (Hellos suppressed) while the subnet still advertises — a confusing "neighbour down but route present" state. 🔧
- ❌ **Assuming the process ID must match neighbours.** It's **locally significant** — `router ospf 1` and `router ospf 5` peer fine. (EIGRP's AS number *must* match; OSPF's process ID need not.) 🟢
- ❌ **Expecting `default-information originate` to work without a default** — you need a local default route, or add **`always`**. 🟢
- ❌ **Forgetting OSPFv3 needs a manually-set RID** — there's no IPv4 address to auto-borrow if the router is IPv6-only. 🔵

## 13. 🧪 Practical Tasks

> Goal: bring single-area OSPFv2 up end-to-end, and *feel* the RID stickiness trap.

1. **🟢 Full bring-up (Packet Tracer 8).** Three routers, one area 0. Configure each with a **loopback**, a manual `router-id`, `network … area 0` for all links, and `passive-interface` on LAN edges. Verify `show ip ospf neighbor` reaches **FULL** and `show ip route ospf` shows `O [110/cost]` routes. Ping end-to-end.

2. **🔧 The sticky-RID trap.** Bring OSPF up letting the RID auto-select (note it in `show ip ospf`). Then add `router-id 1.1.1.1` → observe the RID **hasn't changed**. Run `clear ip ospf process` → confirm it updates. Feel the brief adjacency flap. *Unforgettable once you've done it.* 🔧

3. **🟢 Both enable-methods.** Configure R1 with the **`network` method** and R2 with the **interface method** (`ip ospf 1 area 0`). Confirm they still peer to FULL — proving the methods interoperate and the **process ID need not match** (use `router ospf 1` on one, `router ospf 5` on the other).

4. **🟢 Wildcard drill (no device).** Convert to wildcards: `/24`, `/27`, `/30`, `/32`, `/16`. Then write a `network` statement that enables OSPF on **exactly one** interface (`… 0.0.0.0 area 0`). Verify on the device with `show ip ospf interface brief`.

5. **🟢 Passive-interface proof.** Make a LAN interface `passive`. Confirm via `show ip ospf interface` that it's passive (no Hellos), yet its subnet **still appears** in a neighbour's `show ip route ospf`. Then accidentally make a real link passive → watch that adjacency drop → revert. 🔧

6. **🌐 Default injection.** On the edge router add a static default + `default-information originate`. Confirm other routers install `O*E2 0.0.0.0/0` and can reach an "Internet" loopback. Remove the static → watch the default (without `always`) disappear domain-wide.

7. **🔬 IPv6 parity (OSPFv3).** Enable `ipv6 router ospf 1`, set a **manual** RID (required), and `ipv6 ospf 1 area 0` on interfaces. Verify with `show ipv6 ospf neighbor` / `show ipv6 route ospf`. Note the identical RID rules, now mandatory.
