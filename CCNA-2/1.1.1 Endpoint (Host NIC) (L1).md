## 3 · TL;DR ⚡

- An **endpoint** is any host that **produces or consumes** traffic — PC, laptop, phone, printer, IP camera, IoT sensor, and (role‑wise) servers. It is a **leaf**: it does *not* forward other devices' traffic. That single line separates "endpoint" from "network device."
- Its door onto the network is the **NIC (Network Interface Card)**, which is itself a small computer with three core blocks: **Controller/ASIC** (brain + DMA + offloads), **MAC** (builds Ethernet frames, adds the FCS), and **PHY** (turns bits into signals on copper/fibre).
- Every NIC has a **burned‑in MAC address (BIA)** in its EEPROM — the L2 identity the whole LAN uses to reach it.
- 🔵 **Offloads** (checksum, TSO, LRO, RSS) move per‑packet grunt work from the CPU into NIC silicon — the difference between a CPU melting at 10 Gbps and cruising at 100 Gbps.
- 🔑 **The relationship that defines NIC performance is the PCIe bus, not the port speed.** A 100 GbE NIC needs ~12.5 GB/s; a **PCIe Gen3 x8** slot only delivers ~7.88 GB/s → the NIC is **capped below its rated speed by the bus behind it.** Plug a second card and the x16 slot may **bifurcate to x8/x8**, halving each. *The limit is set by the shared resource upstream, not the headline number.*
- **Tier descent:** server SmartNIC/VIC (200G, SR‑IOV, RDMA) → enterprise desktop NIC (1–10G, offloads) → onboard LOM (1–2.5G) → USB dongle (shared bus, no offloads) → IoT MAC (10/100M, integrated into an SoC).

## 4 · Importance — the problem first 🎯

**The problem:** a CPU thinks in bytes sitting in RAM. A network is voltage and light on a shared physical medium, governed by strict timing and framing rules (Ethernet, 802.11). These two worlds don't speak the same language, don't run at the same clock, and can't be wired directly.

**Something must sit between them and do four hard jobs:**

1. **Translate memory ↔ wire.** Move bytes out of host RAM without pestering the CPU for every byte → **DMA engine**.
2. **Frame & address.** Wrap the bytes in an Ethernet frame with source/destination MAC and an error‑check trailer → **MAC block**.
3. **Signal on the medium.** Encode the frame as electrical pulses (copper) or light (fibre), at gigabit clock rates, and recover them on the way in → **PHY**.
4. **Have a stable identity.** Own a globally‑unique **MAC address** so the LAN can find it → **BIA in EEPROM**.

That translator is the **NIC**. Remove it and the endpoint is deaf and mute — it can compute, but it cannot participate in a network. Everything else in Block 1 (switches, routers, firewalls) exists to *move* what endpoints emit; the NIC is where that traffic is *born*.

🔵 **Why go deeper than "it sends packets"?** Because at 25/100/200 Gbps, the bottleneck is almost never the port. It's the **PCIe lanes**, the **CPU‑to‑queue mapping (RSS)**, the **NUMA locality**, and whether **offloads** are on. An engineer who only knows "the NIC sends frames" cannot explain why a 100G link runs at 60 Gbps — but someone who understands the silicon can point straight at the Gen3 x8 slot.

## 5 · Description 📋

- **Endpoint** 🟢 — a host at the network **edge** that is the **origin or destination** of traffic, never a transit device. PCs, laptops, phones, printers, cameras, sensors, POS terminals, medical devices.
- **Server** — architecturally an endpoint too; distinguished only by **role** (it *answers* rather than *asks*). Covered in `1.1.2`.
- **NIC (Network Interface Card / adapter)** — the hardware that connects the host to the medium. Forms:
  - **Discrete PCIe card** — plugs into a PCIe slot.
  - **LOM (LAN‑on‑Motherboard)** — soldered onto the mainboard (typical of consumer/onboard).
  - **mLOM / OCP** 🔵 — a modular card in a dedicated slot that **doesn't consume a general PCIe slot** (Cisco mLOM, Open Compute OCP) — how servers add NICs without spending expansion slots.
  - **SmartNIC / DPU** 🔵 — a NIC with its own general‑purpose CPU cores, running offloaded networking/security/storage functions independent of the host.
- **MAC address (BIA)** 🟢 — the 48‑bit L2 identity, burned into the card. First 24 bits = **OUI** (vendor); last 24 = per‑card serial.
- **MTU / jumbo frames** 🟢🔵 — standard Ethernet payload MTU is **1500 bytes**; **jumbo frames** raise it to ~**9000** (host) / **9216** (switch) to cut per‑packet overhead on big transfers.

## 6 · How It Works — a packet through the silicon ⚙️

### 6.1 Transmit (host → wire)

```
1. App writes data to a socket           (user space)
2. OS TCP/IP stack segments it, builds headers   (kernel, driver)
3. Driver places a descriptor in a TX ring; data stays in host RAM
4. NIC's DMA engine reads the buffer straight from RAM  ── no CPU copy ──▶ on-NIC FIFO
5. OFFLOADS fire in hardware:
      • checksum offload → NIC computes IP/TCP checksums
      • TSO/LSO → host hands ONE big buffer; NIC chops it into MTU-sized segments
6. MAC block frames it: adds src/dst MAC, EtherType, computes FCS (CRC-32)
7. PHY encodes the frame (SerDes, line coding) → electrical/optical signal
8. Signal leaves via the connector/transceiver onto the medium
```

### 6.2 Receive (wire → host)

```
1. PHY recovers bits from the signal, hands frame to MAC
2. MAC checks the FCS → drops if corrupt; checks dst MAC (accept if it's mine / broadcast / joined multicast / promiscuous)
3. RSS hashes the flow → picks an RX queue → steers to a specific CPU core   ◄── §9.4
4. LRO/RSC (if on) coalesces many small segments into one big one → fewer interrupts
5. DMA engine writes the frame into host RAM (a pre-posted RX buffer)
6. NIC raises an interrupt (moderated/coalesced) → driver → stack → app
```

### 6.3 Control plane vs data plane on the NIC 🔵
- **Data plane** = steps above, per‑packet, in silicon, at line rate. Never touches the host CPU more than it must.
- **Control plane** = the *rare* stuff: driver programming the rings, link up/down & autonegotiation, firmware, **PTP** time sync, and the **NC‑SI sideband** that lets the server's **BMC** reach the network even when the host OS is off (home: `1.1.2`). Same split you'll see scaled up in switches and routers — the idea is identical, only the silicon gets bigger.

## 7 · Pros & Cons ⚖️

| Choice | ✅ Strengths | ⚠️ Trade‑offs |
|---|---|---|
| **Offloads ON** (checksum/TSO/LRO) | CPU freed, high throughput, low host load | Harder to read in a packet capture (segmentation happens in HW); occasional driver bugs |
| **Offloads OFF** | Captures/troubleshooting show true wire behaviour | CPU spikes; can't sustain high line rates |
| **SmartNIC / DPU** 🔵 | Offloads whole security/storage/network stacks; isolates from host | Cost, complexity, its own firmware to manage |
| **SR‑IOV** 🔵 | VMs get near‑native NIC speed (bypass hypervisor) | Ties VM to hardware; live‑migration constraints; limited VF count |
| **Onboard LOM** | Free, simple, always present | Fixed speed; no offload depth; consumes no upgrade path |
| **USB NIC dongle** | Instant connectivity anywhere | Shares the USB bus, high CPU, no serious offloads |

## 8 · Variants — the tier descent 🪜

> The enterprise VIC above is described in full. Each rung below is **delta‑only: what shrinks, and what it consequently can't do.**

| Tier | Example | vs the enterprise VIC — what changes | What it therefore can't do |
|---|---|---|---|
| **Server SmartNIC / VIC** 🔵 | Cisco UCS VIC 15235 (200G), NVIDIA BlueField DPU | *baseline* — 200G, PCIe Gen4/5 x16, SR‑IOV (100s of VFs), RDMA/RoCE, on‑card CPU | — |
| **Server standard NIC** | Intel E810 (100G), Broadcom | Drops the on‑card CPU/DPU; keeps SR‑IOV, RDMA, rich offloads | No independent compute; can't run offloaded firewalls/storage stacks |
| **Enterprise desktop NIC** | Intel X550 (10G), i350 (1G) | 1–10G, PCIe Gen3 x4/x8, checksum/TSO/RSS offloads, VLAN, WoL, PXE | No SR‑IOV/RDMA; modest queue count |
| **Onboard LOM** | Realtek/Intel on mainboard | 1–2.5G, soldered, shares chipset lanes, basic offloads | Fixed speed; no upgrade; contends on the chipset uplink |
| **USB dongle** | USB‑C 2.5G adapter | Rides the **USB bus**, not PCIe; minimal/no offloads | Can't hit sustained high rates; heavy CPU per packet |
| **IoT / embedded MAC** | ESP32, STM32 Ethernet MAC | MAC integrated into an **SoC**; 10/100M; external tiny PHY | 10/100 Mbps ceiling; no offloads; single flow |

**The through‑line:** as you descend, the NIC loses *offload silicon, PCIe width, and identity/virtualization features* long before it loses the basic ability to send a frame. Speed is the last thing to go; *intelligence* goes first.

## 9 · Hardware Chapter — every part, one place 🔩

### 9.1 · Class‑common components (the NIC atom — the deep home)

| Block | What it is | Role · Effect · Why it matters |
|---|---|---|
| **Controller / NIC ASIC** | The NIC's processor | Runs DMA, queues, offloads, SR‑IOV. **This is what makes a "smart" NIC smart.** A weak controller can't offload → CPU pays. |
| **PHY** (physical layer transceiver) | SerDes + line coder | Turns frame bits ↔ electrical/optical signals; handles **autonegotiation** (speed/duplex) and clock recovery. **Sets the physical link speed & medium.** Wrong/failing PHY = no link or wrong duplex. |
| **MAC** (media access control) | L2 framing engine | Adds src/dst MAC + EtherType, computes/checks **FCS (CRC‑32)**, handles **802.3x flow‑control pause**. **The boundary where "data" becomes an "Ethernet frame."** |
| **DMA engine** | Bus‑master data mover | Reads/writes host RAM **without the CPU copying bytes** (scatter‑gather). **The single biggest reason NICs scale** — remove it and every byte costs CPU cycles. |
| **On‑NIC SRAM / FIFO buffers** | Small fast memory | Absorbs bursts between wire speed and bus speed. **Too little buffer → drops under microbursts.** |
| **PCIe endpoint** | Host bus interface | Negotiates **generation × lane‑width** with the slot. **Caps total throughput** — see §9.4 (the archetype). |
| **EEPROM / Flash** | Non‑volatile store | Holds **firmware**, the **MAC BIA**, and the **PXE/UEFI option‑ROM** for network boot. **Its identity + boot brain.** |
| **Clock / PTP unit** 🔵 | Hardware timestamper | Stamps packets in silicon for **IEEE 1588 PTP**. **Enables sub‑µs time sync** (finance, telco, industrial). |
| **NC‑SI sideband** 🔵 | Link to the BMC | Lets the server's **BMC/IPMI** (home: `1.1.2`) use the NIC for out‑of‑band mgmt **even with the host powered off**. |

### 9.2 · Class‑specific expansions (the endpoint "add‑module" family)

The endpoint's version of the Packet‑Tracer "add a module" idea — the real‑world options that change what a NIC *is*:

- **Form factor as an expansion choice:** discrete **PCIe card** (uses a slot) vs **mLOM/OCP** (dedicated slot, saves PCIe slots) vs **LOM** (soldered).
- **Port count & media:** single/dual/quad‑port; **RJ‑45 copper** vs **SFP/SFP+/SFP28/QSFP** cages that take **pluggable transceivers** (the same optics family detailed at its home, `1.1.5` L2 switch).
- **Converged adapters (CNA)** 🔵 — carry **LAN + SAN (FCoE)** on one card (the VIC does this), collapsing two cards into one.
- **NIC teaming / bonding** 🔵 — combine 2+ ports into one logical link for **redundancy or bandwidth** (LACP or active‑standby). The endpoint‑side cousin of switch EtherChannel/LAG.
- **Breakout** 🔵 — one QSFP (100G) split into 4× SFP28 (25G) via a breakout cable.

### 9.3 · Signature parameters (the spec sheet that defines *this* device)

| Parameter | Typical values | What it governs |
|---|---|---|
| **Link speed / duplex** | 10M → 200G · full‑duplex | Raw port bandwidth; **duplex mismatch** = collisions/errors (see `1.4`) |
| **Port count** | 1 / 2 / 4 | Redundancy & aggregate bandwidth |
| **MTU / jumbo** | 1500 · up to 9000/9216 | Efficiency of large transfers; **must match end‑to‑end** (§9.4) |
| **Offloads** | checksum, TSO/LSO, LRO/RSC, RSS | How much per‑packet work leaves the CPU |
| **RSS queues** | 4 – 256+ | How many CPU cores can share the load (§9.4) |
| **SR‑IOV VFs** 🔵 | up to **512** on the VIC 15000 | How many VMs get near‑native NIC access |
| **RDMA / RoCE** 🔵 | yes/no | Kernel‑bypass, ultra‑low‑latency (HPC, storage) |
| **PTP** 🔵 | HW timestamp yes/no | Sub‑µs time sync accuracy |
| **Latency** 🔵 | ~1.0 µs (VIC 15000) | Matters for trading/HPC/storage |
| **WoL / PXE** 🟢 | yes/no | Remote wake; network boot |
| **MAC addresses** | ≥1 per port (+ per‑VF) | Identities the card presents |

### 9.4 · ⚡ Relationship callouts — which spec limits which, and what breaks

> **The core lesson of this whole curriculum's hardware track:** a headline number is a *ceiling the device could reach* — the real limit is the **weakest shared resource upstream of it.**

**① PCIe lanes ↔ link rate — THE archetype.** 🔑
PCIe throughput is fixed per generation and *bifurcates* when you add cards:

| Link | Gen3 | Gen4 | Gen5 |
|---|---|---|---|
| **per lane** | 0.985 GB/s | 1.969 GB/s | 3.94 GB/s |
| **x8** | ~7.88 GB/s (~63 Gbps) | ~15.75 GB/s (~126 Gbps) | ~31.5 GB/s (~252 Gbps) |
| **x16** | ~15.75 GB/s (~126 Gbps) | ~31.5 GB/s (~252 Gbps) | ~63 GB/s (~504 Gbps) |

- A **100 GbE** NIC needs ~**12.5 GB/s**. On **Gen3 x8 (7.88 GB/s)** it is **physically capped to ~63 Gbps** — the port says 100G, the *bus* says no. It needs **Gen3 x16** or **Gen4 x8**.
- **Bifurcation:** a CPU x16 slot populated with a second card can split to **x8/x8** — each device now has *half*. Exactly your desktop‑GPU example: one card gets x16; add a second and both drop to x8, and a bandwidth‑hungry card loses performance.
- **CPU‑direct vs chipset lanes:** lanes straight from the CPU (the primary x16 + first NVMe) are **dedicated**; everything on the **chipset** shares **one uplink** (e.g. Gen4 x4 ≈ 7.9 GB/s). Two hungry devices behind the chipset **contend**. *A 100G NIC in a chipset‑fed x4 slot is doomed before the port even trains.*

**② RSS queues ↔ CPU cores.** A single RX queue funnels one flow to **one core**; at high packet rates that core saturates while others idle → throughput stalls **even with bus headroom**. RSS spreads flows across queues/cores — but each queue needs a core + interrupt to service it. *More ports without more cores just moves the bottleneck.*

**③ NUMA locality ↔ latency/bandwidth.** 🔵 A NIC hangs off **one CPU socket**. If the process runs on the *other* socket, every packet crosses the inter‑socket link (UPI/Infinity Fabric) → added latency and lower bandwidth. *Same NIC, same slot, wrong core = measurably worse.*

**④ Offloads ↔ CPU load.** Checksum/TSO/LRO in silicon free the CPU; **turning them off** (often done to debug a capture) makes the **CPU** the bottleneck and can halve throughput. The port didn't change — the *work location* did.

**⑤ Jumbo frames ↔ the whole path.** 🔑 A 9000‑byte MTU only helps if **every hop agrees**. One switch/interface still at 1500 → oversized frames are dropped or fragmented → mysterious "big transfers hang, pings work" failures. *An endpoint spec (jumbo) is only real end‑to‑end.*

**⑥ SR‑IOV VFs ↔ host resources.** 🔵 Each virtual function consumes PCIe/BAR/interrupt resources; the "512 VFs" ceiling is shared against everything else the platform needs. *Splitting one card many ways divides its finite plumbing, not multiplies it.*

**⑦ Interrupt moderation ↔ latency vs CPU.** 🔵 Coalescing interrupts (fewer, batched) **lowers CPU** but **raises latency**; disabling it does the reverse. You can't max both — it's a dial, not a free win.

## 10 · Best Practices ✅

- **Match the slot to the NIC, generation *and* width.** Before trusting a 25/100/200G NIC, confirm it's in a **CPU‑direct** slot with **enough lanes at the right gen** (§9.4 ①). This single check prevents most "why is it slow" tickets.
- **Pin the workload to the NIC's NUMA node** for latency‑sensitive apps. 🔵
- **Leave offloads ON in production**, and remember they're the reason a `tcpdump` shows super‑sized "packets" (TSO/LRO) — turn them off only to diagnose, then back on.
- **Configure jumbo frames end‑to‑end or not at all** — set it on the host, every switch, and the router SVI, or leave it at 1500.
- **Team/bond two ports** across two upstream switches for endpoint‑side redundancy where uptime matters.
- **Set MAC/OUI awareness:** know that the BIA's first 24 bits identify the vendor — useful when hunting a rogue device in a MAC table.

## 11 · No‑Goes 🚫

- ❌ **Believing the port speed is the throughput.** A 100G port on a Gen3 x8 bus delivers ~63 Gbps. *Read the bus, not the label.*
- ❌ **Filling every PCIe slot and expecting full speed on all.** Adding cards **bifurcates** lanes and starves chipset‑fed slots. Plan the lane budget first.
- ❌ **Jumbo frames on the host only.** Guarantees intermittent large‑transfer failures while ping still works — a classic, maddening MTU‑mismatch symptom.
- ❌ **Reading a packet capture with offloads on and thinking the wire really carried 64 KB "packets."** That's TSO/LRO; the wire still carried MTU‑sized frames.
- ❌ **Duplex/speed hard‑set on one side, autoneg on the other.** Produces a duplex mismatch → late collisions, errors, terrible throughput (full treatment in `1.4`).
- ❌ **Treating a USB NIC like a server NIC.** It shares the USB bus and lacks offloads; it will never sustain high rates no matter the "2.5G" on the box.
- ❌ **Assuming the MAC can't change.** The BIA is burned in, but the OS/driver can override it (spoofing) — relevant for both troubleshooting and security.

## 13 · Practical Tasks 🧪

1. **Find your NIC's identity** 🟢 — `ip link` / `ipconfig /all` / `ifconfig`; read the **MAC**, decode the **OUI** (first 3 bytes) against the IEEE registry to name the vendor.
2. **Prove the endpoint is a leaf** 🟢 — in Packet Tracer, connect two PCs directly with a cable; show they talk, then show a PC will *not* forward a third device's traffic — it has no forwarding table.
3. **See offloads** 🔵 — Linux `ethtool -k eth0` lists TSO/LRO/checksum/RSS state; toggle one and watch **CPU %** change under `iperf3`.
4. **Watch the queues** 🔵 — `ethtool -l eth0` (RSS queue count); `ethtool -S eth0` for per‑queue packet counts; correlate with `mpstat -P ALL` to see the RSS↔core mapping (§9.4 ②).
5. **PCIe reality check** 🔵 — `lspci -vv | grep -i "LnkSta"` shows the **negotiated** gen×width vs the card's max (`LnkCap`). Catch a NIC that trained at x8 instead of x16.
6. **MTU / jumbo lab** 🟢🔵 — set MTU 9000 on two hosts through a switch; `ping -M do -s 8972` (Linux) / `ping -f -l 8972` (Windows) to prove the path carries it un‑fragmented; then break it on one hop and watch it fail.
7. **Capture framing** 🟢 — Wireshark a simple transfer; identify the Ethernet header (dst/src MAC, EtherType) the MAC block built, and note where the FCS lives.
