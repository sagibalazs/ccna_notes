## 3. ⚡ TL;DR

- **Prereq:** create a **dynamic interface** (→ VLAN) first (8.5) — the WLAN needs somewhere to send client traffic.
- **Create the WLAN:** WLANs → Create New. **Profile Name** = internal admin label; **SSID** = the broadcast name users see (8.2); pick a **WLAN ID**.
- **General tab:** ☑ **Status** (enable), set **Radio Policy**, map to the **Interface** (VLAN), ☑ **Broadcast SSID**.
- **Security → Layer 2:** choose **WPA+WPA2** → ☑ **WPA2 Policy** + ☑ **AES** → **Auth Key Mgmt = PSK** → enter the **pre-shared key** (ASCII 8–63 or 64 hex). *(802.1X here + a RADIUS server on the AAA Servers tab = Enterprise.)*
- **QoS tab:** pick a profile — **Platinum (voice) / Gold (video) / Silver (best effort, default) / Bronze (background)**. The profile is a **ceiling**, not a reservation.
- **Advanced tab:** session timeout (default **1800 s**), P2P blocking, client exclusion, etc.
- **Verify:** WLAN shows enabled; **Monitor → Clients** shows the client associated; the client pulls a **DHCP** address and can **ping its gateway**.
- 🚨 Common traps: forgot the dynamic interface (no IP), left **WPA/TKIP** enabled, hidden SSID by accident, wrong VLAN mapping.

## 4. 🎯 Importance — The Problem First

**The problem:** You've mastered the physics (8.1), the join handshake (8.2), the controller architecture (8.3), AP roles (8.4), the wiring (8.5), and the security models (8.6) — but a pile of understood concepts serves *zero* users. At some point you have to **make the network exist**, and on a Cisco controller that means one thing: **defining a WLAN in the GUI**.

A WLAN is the object that **ties every prior document together into something a client can actually join**:
- It carries an **SSID** to advertise (8.2) — the name in the phone's Wi-Fi list.
- It maps to a **dynamic interface / VLAN** (8.5) — deciding which wired network clients land on.
- It sets a **security policy** (8.6) — WPA2-PSK/AES, or Enterprise 802.1X.
- It assigns a **QoS profile** — deciding whether this SSID's traffic is treated as voice, video, or best-effort.
- It applies **advanced policies** — timeouts, client isolation, band steering.

Get this screen right and users connect. Get one field wrong — a missing dynamic interface, TKIP left enabled, the wrong VLAN, an accidentally-hidden SSID — and you get the exact real-world tickets you'll spend your career on: *"can't see the Wi-Fi," "connects but no internet," "gets kicked off," "slow."*

Why this is the make-or-break skill:
- **It's literally on the exam as a configure-and-verify objective (5.10)** — one of the few wireless topics CCNA asks you to *do*, not just *describe*.
- **It's the daily job.** Standing up a new SSID, changing a passphrase, mapping Guest to a DMZ VLAN, tuning QoS for voice — this screen is where a wireless engineer lives.
- **It's the ultimate integration test of Block 8.** If you can build and verify this WLAN and explain every field, you understand wireless. If you can't, you've memorized facts without the picture.

> 🕵️ **Dirty secret:** The **#1 reason a freshly-built WLAN "doesn't work"** isn't security — it's that the admin **never created the dynamic interface** (8.5) or mapped the WLAN to the wrong one. The client associates fine, the WPA2 handshake succeeds, and then… **no DHCP address**, because the WLAN has nowhere to put the traffic. "Connected, no internet" on a brand-new SSID is almost always a VLAN/interface mapping problem, not a Wi-Fi problem.

## 5. 📖 Description

**A WLAN** on the WLC = a logical profile binding an **SSID** to an **interface (VLAN)**, plus **security**, **QoS**, and **advanced** policies. One WLC hosts many WLANs (classically up to **16** configurable; more on modern platforms).

**Accessing the GUI** 🟢:
- Browse (HTTP/HTTPS) to the WLC's **management interface** IP (8.5), log in, and click **Advanced** to reach the full configuration GUI. The left-side menu changes with the top tab selected.
- 🕵️ **Management-via-wireless is disabled by default** — you can't reach the WLC GUI/CLI *from* a client on its own WLANs (a security feature). Manage it from the **wired** side.

**The two identifiers** 🟢:
- **Profile Name** — an **internal** admin label for the WLAN entry (you choose it; not broadcast).
- **SSID** — the **broadcast** network name clients see (8.2). Multiple WLANs can even share an SSID for special cases, but normally one SSID per WLAN.

**The four configuration tabs** 🟢:
- **General** — Status (enable/disable), Radio Policy (which bands: All / 802.11a-only / b/g-only…), **Interface/Interface Group** (the dynamic interface → VLAN), Broadcast SSID.
- **Security** — Layer 2 (WPA/WPA2/WPA3, cipher, Auth Key Mgmt, PSK), Layer 3 (web auth for guest), AAA Servers (RADIUS, for Enterprise).
- **QoS** — the **Platinum/Gold/Silver/Bronze** profile + WMM/CAC/bandwidth.
- **Advanced** — session timeout, P2P blocking, client exclusion, load limits, band select, FlexConnect local switching, DTIM, Aironet IE, etc.

**QoS profiles (AireOS)** 🟢:
- **Platinum = Voice** (highest priority)
- **Gold = Video**
- **Silver = Best Effort** (**default**)
- **Bronze = Background** (lowest; typical for guest)
- A profile sets the **ceiling** (max QoS clients on that WLAN may use) and maps the 802.11e user priority to wired DSCP/CoS on the CAPWAP header. It **limits/prioritizes**, it doesn't reserve bandwidth.

## 6. 🔧 How It Works — Under the Hood (step-by-step)

### 6.0 Prerequisite: the dynamic interface 🟢
```
   Controller → Interfaces → New
     Interface Name: vlan20     VLAN Id: 20
     IP: 10.20.0.5 / mask / gateway     Physical port / DHCP server
```
Without this, the WLAN has no VLAN to bridge onto (8.5). **Do this first.**

### 6.1 Create the WLAN 🟢
```
   WLANs → Create New → Go
     Type:         WLAN
     Profile Name: Corp-Profile     (internal)
     SSID:         Corp             (broadcast — 8.2)
     WLAN ID:      1
   → Apply  → opens the WLAN > Edit page (General/Security/QoS/Advanced)
```

### 6.2 General tab 🟢
```
   ☑ Status ................ enable the WLAN (off = SSID not served)
   Radio Policy ............ All (or restrict to a band)
   Interface/Interface Grp . vlan20   ◄── client traffic egresses here (8.5)
   ☑ Broadcast SSID ........ advertise in beacons (uncheck = "hidden", 8.2)
```

### 6.3 Security → Layer 2 (the WPA2-PSK core) 🟢
```
   Layer 2 Security: WPA+WPA2
   ── WPA+WPA2 Parameters ──
     ☐ WPA Policy (TKIP)   ◄── leave OFF (TKIP deprecated — 8.6)
     ☑ WPA2 Policy
        ☑ AES              ◄── the cipher: CCMP/AES (8.6)
        ☐ TKIP
   ── Authentication Key Management ──
     ● PSK                 ◄── WPA2-Personal
       PSK Format: ASCII   Key: [8–63 char passphrase]   (or 64 hex digits)
     ○ 802.1X              ◄── WPA2-Enterprise (needs AAA Servers tab)
     ○ CCKM / FT (802.11r) ◄── fast-roaming options (🔵)
```
- **WPA2 Policy + AES + PSK** = **WPA2-Personal with AES** — the target of blueprint 5.10.
- **Only one PSK per WLAN** (one ASCII *or* one hex key). Need per-user keys? Use **iPSK** or **Enterprise**. 🔵
- 🕵️ The dropdown says "WPA+WPA2," but with **only WPA2 Policy + AES** checked (WPA/TKIP unchecked), you've built a **WPA2-only, AES-only** WLAN. Leaving WPA/TKIP checked silently weakens it — a real exam and real-world trap.

### 6.4 Security → AAA Servers (Enterprise only) 🟢
```
   (only if Auth Key Mgmt = 802.1X)
   AAA Servers → Authentication Servers → select RADIUS server (e.g. ISE)
```
For **Personal/PSK**, skip this entirely — no server needed (8.6).

### 6.5 QoS tab 🟢
```
   Quality of Service (QoS):
     ○ Platinum (voice)     highest
     ○ Gold (video)
     ● Silver (best effort) ◄── DEFAULT
     ○ Bronze (background)  lowest — typical for guest
   (+ WMM policy, CAC, per-client bandwidth limits)
```
Set **Platinum** for a voice SSID, **Bronze** for guest. Remember it's a **ceiling**.

### 6.6 Advanced tab 🟢🔵
```
   ☑ Enable Session Timeout .... default 1800 s (30 min) → periodic re-auth
   ☐ Peer-to-Peer (P2P) Blocking . isolate clients on the WLAN
   ☐ Client Exclusion .......... auto-block misbehaving clients
     Client user idle timeout, max clients, Band Select, DTIM,
     FlexConnect Local Switching (8.3/8.4), Aironet IE, mDNS, etc.
```
Then **Apply** to commit the whole WLAN.

### 6.7 What happens on the wire when a client joins 🟢
Tying the whole block together:
```
   1. AP beacons the SSID on its RRM-assigned channel   (8.1, 8.2)
   2. Client scans, associates                          (8.2)
   3. WPA2 4-way handshake (PSK→PMK→PTK/GTK, AES)        (8.6)
   4. AP (local mode) tunnels client traffic in CAPWAP  (8.3, 8.4)
      → WLC unwraps → places it on VLAN 20 via vlan20    (8.5)
   5. Client gets DHCP from VLAN 20, pings its gateway   ✅
   6. QoS profile caps/prioritizes the traffic          (this doc)
```

## 7. ⚖️ Pros & Cons (config choices)

**WPA2-PSK (Personal) on the WLAN**
✅ Fast to set up, no server, universal client support · ✅ Fine for small/SOHO/guest
❌ One shared key (8.6 offline-crack risk) · ❌ No per-user revocation

**WPA2-Enterprise (802.1X) on the WLAN**
✅ Per-user auth, revocable, auditable · ✅ No shared secret
❌ Requires RADIUS/AAA tab + PKI · ❌ More moving parts to break

**Broadcast SSID on**
✅ Users find it; smoother roaming · ❌ Visible to everyone (fine — hiding it isn't security, 8.2)

**QoS profile (e.g. Platinum for voice)**
✅ Prioritizes latency-sensitive traffic · ❌ It's a ceiling, not a guarantee; misassigning starves or over-privileges a WLAN

## 8. 🔀 Variants (Common → Specific)

- **Security on the WLAN:** Open → **WPA2-PSK/AES** (this doc) → WPA2-Enterprise (802.1X) → WPA3-SAE → Web-auth guest (Layer 3). 🟢
- **Auth Key Mgmt:** PSK → 802.1X → CCKM / FT (802.11r) fast roaming. 🟢🔵
- **PSK format:** ASCII (8–63) vs HEX (64 digits). 🟢
- **QoS profiles:** Platinum → Gold → Silver (default) → Bronze. 🟢
- **Forwarding (Advanced):** central (CAPWAP to WLC) vs **FlexConnect local switching** (8.3/8.4). 🔵
- **GUI generation:** **AireOS** (this doc / Packet Tracer / CCNA) vs **Catalyst 9800** (WLAN Profile + Policy Profile + Policy Tag model). 🔵

> 🕵️ **9800 note:** On the Catalyst 9800 (IOS-XE), the flow splits into a **WLAN Profile** (SSID + security), a **Policy Profile** (VLAN + QoS + settings), joined by a **Policy Tag** applied to APs. Same *concepts*, different *screens*. CCNA and Packet Tracer use the AireOS layout above.

## 9. 🧩 Devices / Media / Protocols

- **WLC** — hosts the WLAN config; management interface serves the GUI; dynamic interfaces bridge WLANs to VLANs.
- **Lightweight AP** — broadcasts the SSID, runs the association + 4-way handshake, tunnels traffic (CAPWAP) to the WLC.
- **Switch** — trunk to the WLC (8.5), carries the client VLANs; provides DHCP relay / PoE.
- **DHCP server** — hands the joining client an address on its VLAN (the "does it actually work" test).
- **RADIUS/ISE** — only for the Enterprise (802.1X) variant.
- **Protocols/features referenced:** SSID/beacons (8.2), WPA2/CCMP/AES + 4-way handshake (8.6), CAPWAP (8.3), 802.1Q (8.5), 802.11e/WMM (QoS), 802.11r/CCKM (fast roam).
- **Tools:** the WLC **GUI**, **Packet Tracer 8** WLC (WLC-3504), Wireshark, a Windows/phone client to verify.

## 10. ✅ Best Practices

- **Create the dynamic interface (VLAN) first**, then build the WLAN and map to it — avoids the "connected, no IP" trap.
- **WPA2 Policy + AES + PSK**, with **WPA/TKIP unchecked** — never ship TKIP (8.6).
- **Use a strong PSK** (long, random); the whole WLAN's security rests on it (8.6). Prefer **Enterprise** for corporate.
- **One SSID per role, one VLAN each** — Corp/Guest/IoT on separate WLANs + interfaces (8.5), with QoS to match (Platinum voice, Bronze guest).
- **Keep SSIDs per radio to ≤ 3–4** (8.2) — each WLAN adds beacon overhead.
- **Leave session timeout / client exclusion at sane defaults**; enable **P2P blocking** on guest WLANs.
- **Verify end-to-end** every time: WLAN enabled → client associated (Monitor → Clients) → DHCP IP → ping gateway. Don't assume "configured" = "working."

## 11. 🚫 No-Goes & Troubleshooting Traps

- ❌ **No dynamic interface / wrong VLAN mapping** — client associates but gets **no DHCP/IP**. The classic new-WLAN failure.
- ❌ **Leaving WPA/TKIP enabled** — weakens WPA2; use AES only (8.6).
- ❌ **Accidentally unchecking Broadcast SSID** — users "can't find the Wi-Fi" (it's hidden, not broken — 8.2).
- ❌ **Forgetting to enable Status** — the WLAN exists but isn't served.
- ❌ **PSK typo / wrong format** — client fails the 4-way handshake (MIC mismatch, msg 2 — 8.6). "Wrong password."
- ❌ **802.1X selected but no RADIUS on AAA tab** — Enterprise clients can't authenticate.
- ❌ **Wrong QoS profile** — voice SSID on Bronze = choppy calls; guest on Platinum = over-privileged.
- ❌ **Expecting to manage the WLC from a wireless client** — disabled by default; use the wired side.
- ❌ **Untagged/native-interface + 802.1p tagging** — client traffic can be blocked (interface/QoS mismatch).

**Troubleshooting map — "new WLAN, client won't work":**
```
   Can't see the SSID?           → Status enabled? Broadcast SSID on? AP joined & radio up? (8.1–8.4)
   Sees it, won't connect?       → PSK correct/format? WPA2+AES matches client? PMF mismatch? (8.6)
   Connects, no IP?              → dynamic interface exists? mapped to right VLAN? DHCP/relay? (8.5)  ← most common
   Has IP, no internet?          → VLAN routing/ACL/gateway upstream (wired side)
   Works but slow/choppy?        → QoS profile, channel/interference (8.1), co-channel (8.1)
```

## 13. 🛠️ Practical Tasks (the Block 8 capstone lab)

1. **Full Packet Tracer 8 build:** L3 switch (DHCP + gateway) ── trunk ── **WLC-3504** ── **lightweight AP** (access port) ── wireless laptop. On the WLC GUI:
   a. Create a **dynamic interface** `vlan20` (VLAN 20).
   b. **WLANs → Create New**: Profile `Corp-Profile`, SSID `Corp`.
   c. **General:** enable Status, map Interface `vlan20`, Broadcast SSID on.
   d. **Security → Layer 2:** WPA+WPA2 → WPA2 Policy + **AES** → **PSK** → set an ASCII key.
   e. **QoS:** Silver. **Advanced:** leave defaults. **Apply.**
   f. Join the laptop, confirm **DHCP IP on VLAN 20**, **ping the gateway**.
2. **Break-and-fix (the #1 trap):** delete/mis-map the dynamic interface; observe the client associate but get **no IP**; fix the mapping and confirm recovery. Internalize "connected, no IP = VLAN/interface."
3. **PSK failure drill:** enter the wrong passphrase on the client; confirm the **4-way handshake** fails (8.6). Fix and reconnect.
4. **Two-SSID segmentation:** add a second WLAN `Guest` → new dynamic interface `vlan30` → **Bronze** QoS → enable **P2P blocking**. Verify Guest clients land on VLAN 30 and can't reach Corp.
5. **Enterprise variant (real gear/CML):** flip Auth Key Mgmt to **802.1X**, bind a **RADIUS/ISE** server on the AAA tab, and authenticate a user with per-user credentials (8.6).
6. **Verify like an engineer:** from the WLC, check WLAN summary and **Monitor → Clients**; on the client, confirm IP/gateway/DNS and run a ping + a speed sanity check. Then read every field back and explain it — the mastery test for all of Block 8.
