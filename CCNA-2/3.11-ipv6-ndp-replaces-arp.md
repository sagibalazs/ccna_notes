> 🧵 **The capstone of the IPv6 sub-block.** Everything from 3.7–3.10 — link-local, solicited-node multicast, SLAAC, DAD — is actually **one protocol: NDP**. This doc assembles the pieces and contrasts them with IPv4's ARP, showing *why* IPv6 neighbour handling is more capable **and** quieter.

## 2. 🗺️ Visualization — The Whole Picture at a Glance

**NDP = 5 ICMPv6 messages doing 6 jobs (ARP + ICMP router discovery + DAD, unified):**

```
   ICMPv6 type   Message                     Job
   ───────────   ─────────────────────────   ─────────────────────────────────
     133  RS     Router Solicitation         "any routers here?"      → to ff02::2
     134  RA     Router Advertisement        prefix + flags + gateway → to ff02::1
     135  NS     Neighbor Solicitation       "who has this addr?" / alive? / DAD
     136  NA     Neighbor Advertisement      "that's me, here's my MAC"
     137  Rdct   Redirect                    "use a better first-hop router"
   Functions: router disc · prefix disc · parameter disc · ADDRESS RESOLUTION
              · Duplicate Address Detection · Neighbor Unreachability Detection
```

**ARP → NDP, the head-to-head:**

```
                    ARP (IPv4)                 NDP (IPv6)
   layer            L2 standalone (0x0806)     L3 ICMPv6 (types 133–137)
   "who has X?"     BROADCAST ff:ff:..:ff      solicited-node MULTICAST (3.9)
   noise            every NIC interrupts       ~only the target NIC 🤫
   table            ARP cache                  Neighbor Cache (with states)
   router discovery none (DHCP/static GW)      built-in (RS/RA)
   duplicate check  gratuitous ARP (weak)      DAD (built-in)
   spoof defense    none → DAI (3.x)           none native → RA Guard/SEND + Hop-Limit 255
```

**Neighbor Cache lifecycle (the IPv6 "ARP table" is a state machine):**

```
   INCOMPLETE ──NA──▶ REACHABLE ──(timer)──▶ STALE ──(traffic)──▶ DELAY ──▶ PROBE
        ▲  NS sent, no reply yet                                    │NS probes│
        └──────────────────────── unreachable ◀─────────────────────┘ no reply
```

> 🧭 **One idea:** ARP could only ask "who has this IP?" — by shouting. NDP does that **and** router discovery, DAD, and liveness — over **targeted multicast**, with a **state machine** and a built-in **anti-spoof** trick (Hop Limit 255).

## 3. ⚡ TL;DR

- 🟢 **NDP (RFC 4861)** is the ICMPv6 protocol that **replaces ARP** — and does much more: router/prefix/parameter discovery, address resolution, **DAD**, **NUD**, and redirect.
- 🟢 **Five messages:** **RS (133)**, **RA (134)**, **NS (135)**, **NA (136)**, **Redirect (137)**.
- 🟢 **Address resolution** uses **NS→solicited-node multicast** (3.9) and **NA** in reply — a targeted whisper, not ARP's broadcast shout.
- 🟢 The **Neighbor Cache** (IPv6's ARP table) is a **state machine**: INCOMPLETE → REACHABLE → STALE → DELAY → PROBE; **NUD** actively confirms neighbours are still alive.
- 🟢 **DAD** (Duplicate Address Detection) sends an NS from `::` to a tentative address's solicited-node group before using it.
- 🟢 NDP runs at **L3 over ICMPv6** (not a separate L2 protocol) and lives on **link-local** addresses (3.8).
- 🔵 🕵️ **Every NDP message must have IPv6 Hop Limit = 255, and receivers discard it otherwise** — because a router *decrements* hop limit, a 255 proves the packet was **never routed** = on-link. A free, crypto-less anti-spoofing proof (§6.6).

---

## 4. 🎯 Importance — The Problem First

**The problem — ARP was minimal, noisy, and blind.** In IPv4 (Block 2), a host that knows a neighbour's IP but not its MAC **broadcasts** "who has 192.168.1.50?" to `ff:ff:ff:ff:ff:ff`. This works, but it's a patchwork with real limits:

- 📣 **Broadcast is expensive.** *Every* NIC on the segment receives and inspects each ARP — pure overhead for all but one host (the noise you met in Block 2 and 3.6/3.9).
- 🧩 **ARP only does one thing.** Finding a router, learning the subnet prefix, detecting duplicate addresses, and checking whether a neighbour is still alive were **separate, bolted-on mechanisms** (DHCP, ICMP router discovery, gratuitous ARP) — or didn't exist at all.
- 🕳️ **ARP is utterly trusting.** Any host can answer for any IP → **ARP spoofing / MITM**, patched later with Dynamic ARP Inspection.
- 🚫 **No liveness.** ARP entries just age out; there's no active "are you still there?"

**The solution — one protocol, over multicast, at L3: NDP.** IPv6 folds neighbour discovery, router discovery, prefix/parameter discovery, duplicate detection, and reachability tracking into **a single ICMPv6 protocol**:
- 🎯 **Targeted, not broadcast** — resolution uses **solicited-node multicast**, so essentially only the target is disturbed (3.9).
- 🧠 **Stateful** — a **Neighbor Cache** tracks each neighbour through a lifecycle, with **NUD** actively confirming reachability.
- 🛡️ **Self-protecting on-link** — the **Hop Limit 255** rule makes off-link spoofing structurally hard (§6.6).
- 🏗️ **Complete** — DAD and router/prefix discovery are **built in**, powering SLAAC (3.10) with no extra protocols.

> **Why this is the keystone:** NDP is where link-local (3.8), solicited-node multicast (3.9), and SLAAC (3.10) stop being separate facts and become **one coherent system**. Reading an NDP exchange in Wireshark — RS/RA/NS/NA and their multicast destinations — is the single most useful IPv6 troubleshooting skill, and it directly feeds first-hop security topics (RA Guard, ND inspection) later.

## 5. 📖 Description

- 🟢 **NDP.** The ICMPv6 (RFC 4861) protocol handling all IPv6 neighbour/router interactions; replaces ARP + ICMP router discovery + adds DAD/NUD.
- 🟢 **RS (133) / RA (134).** Router discovery: host asks (`ff02::2`), routers announce prefix + flags + gateway (`ff02::1`) — the SLAAC engine (3.10).
- 🟢 **NS (135) / NA (136).** Address resolution (IPv6→MAC), reachability checks, and DAD. NS→solicited-node group; NA carries the target's link-layer address.
- 🟢 **Redirect (137).** A router tells a host a **better first-hop** for a destination on the same link.
- 🟢 **Neighbor Cache.** IPv6's ARP table; entries move through **INCOMPLETE / REACHABLE / STALE / DELAY / PROBE**.
- 🟢 **NUD (Neighbor Unreachability Detection).** Active confirmation a neighbour is still reachable (via unicast NS/NA).
- 🟢 **DAD.** Duplicate Address Detection: NS from `::` to a tentative address's solicited-node group before use (3.10).
- 🟢 **Runs on link-local, at L3, over ICMPv6** — not a separate EtherType like ARP.
- 🔵 **NDP options:** Source/Target Link-Layer Address, Prefix Information (PIO), MTU, RDNSS.
- 🔵 **Security:** Hop-Limit-255 rule; **RA Guard** (RFC 6105); **SEND/CGA** (RFC 3971).

## 6. 🔧 How It Works — Under the Hood

### 6.1 🟢 The five messages & six functions

```
   Router discovery ── RS(133) →ff02::2 ── RA(134) →ff02::1
   Prefix / parameter discovery ── carried in RA options (PIO, MTU, Cur Hop Limit)
   Address resolution ── NS(135) →solicited-node ── NA(136) →unicast back  (ARP's job)
   DAD ── NS(135) from :: →solicited-node of the tentative address
   NUD ── unicast NS(135)/NA(136) to confirm a cached neighbour is alive
   Redirect ── Redirect(137) from a router → host: "use next-hop Y instead"
```

### 6.2 🟢 Address resolution (the direct ARP replacement)

```
   A wants B's MAC for 2001:db8:acad:1::b (last 24 bits 00:00:0b):
   ① A → NS to ff02::1:ff00:000b   (solicited-node of B)   L2 33:33:ff:00:00:0b
        NS carries A's own link-layer address (SLLA option)
   ② B → NA (unicast to A): "target = 2001:db8:acad:1::b, my MAC = ..."  (TLLA option)
   ③ A caches B in its Neighbor Cache (state REACHABLE) and sends the real traffic
```

Only NICs whose address ends in `…00:00:0b` even receive the NS (3.9) — the surgical delivery that makes NDP quiet.

### 6.3 🟢 The Neighbor Cache — a state machine (not just a table)

Unlike ARP's flat cache, each neighbour has a **state** (RFC 4861 §7.3.2):

| State | Meaning |
| ----- | ------- |
| **INCOMPLETE** | NS sent, no NA yet — resolution in progress |
| **REACHABLE** | Confirmed reachable recently (positive proof) |
| **STALE** | Was known, but reachability now unconfirmed; entry kept |
| **DELAY** | Traffic was sent to a STALE entry; brief wait before probing |
| **PROBE** | Actively sending unicast NS probes to reconfirm |

**NUD** drives these transitions: when you send to a STALE neighbour, the stack quietly verifies it's still there (DELAY→PROBE→REACHABLE) or declares it unreachable — something **ARP never did**, giving IPv6 faster, cleaner failover.

### 6.4 🟢 DAD — proving an address is free before using it

Before *any* address (link-local or global) goes live, the host runs DAD:

```
   tentative addr = 2001:db8:acad:1::1234:5678
   NS: source = ::            (unspecified — the addr isn't confirmed yet)
       destination = ff02::1:ff34:5678   (solicited-node of the tentative addr)
       target = the tentative address
   • someone replies NA / sends their own NS for it → DUPLICATE → address not used ✗
   • silence → address is unique → mark REACHABLE/valid ✓
```

This is why a cloned VM MAC or a hand-typed collision makes an address **fail to come up** with a duplicate-address log — a trap to recognise (§11).

### 6.5 🟢 Router discovery & Redirect

- **RS/RA** (3.10) is NDP's router-discovery half: hosts learn the **default gateway (a `fe80::`)**, the **on-link prefix(es)**, and the **M/O/A flags**. Routers also send RAs unsolicited on a timer.
- **Redirect (137):** if a host sends to a router that knows a **better first-hop on the same link**, that router replies with a Redirect so future packets go directly — the IPv6 cousin of the IPv4 ICMP redirect.

### 6.6 🕵️ Dirty Secret — Hop Limit 255: proof-of-on-link without cryptography

Every NDP message is **sent with IPv6 Hop Limit = 255**, and every receiver **MUST silently discard any NDP message whose Hop Limit isn't 255** (RFC 4861). At first glance that looks pointless — why mandate the maximum value? The genius is in what routers do:

```
   A router DECREMENTS Hop Limit by 1 every time it forwards a packet.
   ⇒ a packet that arrives with Hop Limit = 255 CANNOT have crossed any router.
   ⇒ it is PROVABLY on-link (came from this very segment).
   An off-link attacker can't forge it: their packet would be decremented en route,
   arriving with Hop Limit < 255 → dropped. 🛡️
```

So a **single fixed field** gives NDP a **cryptography-free guarantee** that neighbour/router messages are genuinely local — blocking a whole class of remote spoofing attacks for free. It's one of the most elegant "why is it like that?" details in IPv6.

> ⚠️ **But NDP still trusts *on-link* peers.** Hop-Limit-255 stops *off-link* forgery; it does **nothing** against a malicious host **on the same segment**. That host can still send **rogue RAs** (becoming everyone's gateway → MITM) or spoof **NA** (like ARP poisoning). The defences:
> - **RA Guard (RFC 6105)** — switch drops RAs on ports that shouldn't source them (`ipv6 nd raguard`); the everyday fix.
> - **ND inspection / IPv6 snooping + binding table** — validate NS/NA against learned bindings (first-hop security, ENARSI).
> - **SEND + CGA (RFC 3971)** — cryptographic NDP; powerful but **rarely deployed**.
>
> **Engineer takeaway:** IPv6 fixed ARP's *noise* and *off-link* spoofing elegantly, but **inherited ARP's on-link gullibility**. In production, **RA Guard on access ports is mandatory hygiene** — a rogue RA (even accidental, from a mis-set Windows ICS or a hypervisor) can black-hole a whole VLAN.

### 6.7 🟢 ARP vs NDP — the summary

NDP is a **superset** of ARP: it does address resolution (NS/NA) *and* router discovery, prefix/parameter discovery, DAD, NUD, and redirect — over multicast, at L3, with state and a built-in on-link proof. ARP did one job, by broadcast, with no state and no security.

## 7. ⚖️ Pros & Cons

| Aspect | ✅ NDP strengths | ❌ Watch-outs |
| ------ | --------------- | ------------ |
| **Efficiency** | Solicited-node multicast → minimal disturbance 🤫 | Depends on multicast/MLD snooping working (3.9) |
| **Capability** | One protocol: resolution + router/prefix disc + DAD + NUD | More moving parts to understand than ARP |
| **Reliability** | Neighbor Cache states + NUD → real reachability tracking | Cache tuning matters on large/latency links |
| **Security** | Hop-Limit-255 blocks off-link forgery for free 🛡️ | **On-link** rogue RA/NA still possible → needs RA Guard |
| **Integration** | Powers SLAAC natively (3.10) | Runs on ICMPv6 → filtering ICMPv6 too hard breaks it |

## 8. 🌿 Variants — Common → Specific

- 🟢 **Router discovery** — RS(133)/RA(134).
- 🟢 **Address resolution** — NS(135)/NA(136) via solicited-node.
- 🟢 **DAD** — NS from `::` (a special use of NS).
- 🟢 **NUD** — unicast NS/NA reachability probing.
- 🟢 **Redirect** — Redirect(137), better first-hop.
- 🔵 **Secure NDP (SEND/CGA, RFC 3971)** — cryptographic variant, niche.
- 🔵 **First-hop security suite** — RA Guard, DHCPv6 Guard, ND inspection, IPv6 source guard (ENARSI 3.4).

## 10. ✅ Best Practices

- 🟢 **Don't over-filter ICMPv6.** NDP *is* ICMPv6 — blanket-blocking ICMPv6 breaks IPv6 entirely. Permit NDP types (133–137) on links.
- 🟢 **Deploy RA Guard on all access ports**, allowing RAs only on real router uplinks — the single most important IPv6 L2 hygiene step.
- 🟢 **Watch for duplicate-address (DAD) failures** as a duplicate-MAC/IID signal (cloned VMs, hand-typed clashes).
- 🟢 **Use `show ipv6 neighbors`** (Cisco) / `ip -6 neighbor` (Linux) to read the Neighbor Cache and its states during troubleshooting.
- 🔵 **Add ND inspection + IPv6 binding table** on switches for stronger anti-spoofing (first-hop security).
- 🔵 **Keep host subnets `/64`** so NDP/SLAAC/DAD all function (3.7 §6.6).

## 11. 🚫 No-Goes — Common Mistakes & Troubleshooting Traps

- ❌ **Blocking ICMPv6 like you'd block ICMPv4.** That kills NDP → no address resolution, no SLAAC, no connectivity.
- ❌ **Assuming NDP is broadcast/ARP-like.** It's **multicast** at **L3** — captures and ACLs must target ICMPv6 types, not `0x0806`.
- ❌ **Ignoring rogue RAs.** Without RA Guard, one bad host/hypervisor RA can hijack the gateway for a whole VLAN.
- ❌ **Expecting Hop-Limit-255 to stop on-link attacks.** It only blocks **off-link** forgery; on-link spoofing needs RA Guard/ND inspection (§6.6).
- 🕵️ **Trap — address won't come up / "DUPLICATE" log.** **DAD** found a clash (duplicate MAC/IID, cloned VM) → fix the duplicate (§6.4).
- 🕵️ **Trap — intermittent neighbour loss.** Watch the **Neighbor Cache states**: stuck **INCOMPLETE** = NS unanswered (L2 issue, MLD snooping, wrong solicited-node); flapping to **PROBE**/unreachable = NUD failing (one-way path, MTU).
- 🕵️ **Trap — NDP "works locally, fails across switch."** Suspect **MLD snooping** dropping solicited-node multicast, or a filter blocking `33:33:*` frames (3.9).
- ❌ **Forgetting the gateway is `fe80::`.** NDP-learned default routes point at link-local (3.8 §6.6) — debug there, not at a global address.

## 13. 🧪 Practical Tasks

1. 🔬 **Wireshark — the full NDP set.** Capture an IPv6 host booting and browsing; identify all five types: **RS(133)→ff02::2**, **RA(134)→ff02::1**, **NS(135)→solicited-node**, **NA(136)** unicast reply, and (if present) **Redirect(137)**. Note every one has **Hop Limit 255** and a `fe80::` source.
2. 🧠 **Read the Neighbor Cache.** Cisco `show ipv6 neighbors`; Linux `ip -6 neighbor show`; Windows `netsh interface ipv6 show neighbors`. Identify entries in REACHABLE vs STALE; ping a neighbour and watch a state change.
3. 🧰 **Packet Tracer 8 — resolution vs ARP.** On a dual-stack LAN, ping an IPv4 neighbour (watch **ARP broadcast**) then an IPv6 neighbour (watch **NS to solicited-node**). Compare the L2 destinations (`ff:ff:ff:ff:ff:ff` vs `33:33:ff:xx:xx:xx`).
4. 🚩 **DAD in action.** Configure the **same** static IPv6 address on two hosts; observe the second one fail DAD with a duplicate-address message; read the DAD NS in capture (source `::`).
5. 🛡️ **Rogue RA + RA Guard (🔵).** In GNS3/PT, have a non-router host emit a rogue RA and watch victims take it as gateway; then enable `ipv6 nd raguard` on access ports and confirm the rogue RA is dropped.
6. 🧭 **NUD experiment (🔵).** Establish a REACHABLE neighbour, disconnect it, keep sending traffic, and watch the cache go STALE→DELAY→PROBE→unreachable — the liveness ARP never had.
7. 📊 **ARP vs NDP write-up.** From your own captures, fill the §2 comparison table with real observed values (types, L2 destinations, hop limits).
