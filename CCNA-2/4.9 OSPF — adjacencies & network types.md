> 🎯 4.8 said routers "discover neighbours and synchronise databases." **This is the deep dive on exactly how** — the **neighbour state machine** (Down → … → Full), the parameters that must match, and how the **network type** decides whether a **DR/BDR** gets elected. Adjacency is where OSPF *lives or dies* — and 80% of OSPF troubleshooting is **reading which state a neighbour is stuck in.**

## 2. 🗺️ Visualization — the state ladder + the DR/BDR election

```
  ══════════════ OSPF NEIGHBOUR STATE MACHINE (RFC 2328 §10.1) ══════════════

   DOWN        no Hellos heard yet
     │  ▲       ─────────────────────────────────────────────────────────
     │  │ (Attempt — NBMA only 🔵)
     ▼  │
   INIT        I hear THEIR Hello, but it doesn't list MY Router ID yet
     │          → one-way. (Stuck here = they can't hear me.)
     ▼
   2-WAY       Their Hello lists MY Router ID → BI-DIRECTIONAL ✅
     │          ★ DR/BDR ELECTION happens here (broadcast nets) ★
     │          DROTHER ↔ DROTHER pairs STAY here — normal, not a bug!
     ▼          ───────────────── (below: only DR/BDR-bound adjacencies) ────
   EXSTART     negotiate master/slave (higher Router ID = master)
     │          ⚠ Stuck here/next = MTU mismatch (or duplicate RID)
     ▼
   EXCHANGE    trade DBD summaries of the LSDB
     ▼
   LOADING     LSR/LSU — fetch the LSAs I'm missing
     ▼
   FULL        databases IDENTICAL — adjacency complete ✅ "where you want to live"


  ═══════════════ DR / BDR ELECTION (broadcast multi-access only) ═══════════════

        Is this a POINT-TO-POINT link?  ──YES──▶ NO election. Adjacency is automatic.
                    │ NO (broadcast / multi-access)
                    ▼
        ① Highest OSPF INTERFACE PRIORITY wins   (default = 1;  priority 0 = never DR/BDR)
                    │  (tie?)
                    ▼
        ② Highest ROUTER ID wins the tie
                    │
                    ▼
        DR = winner · BDR = runner-up · everyone else = DROTHER
        ⚠ NON-PREEMPTIVE: a better router arriving later does NOT take over a sitting DR.
```

**Network-type behaviour at a glance:**

| Network type | Example | DR/BDR? | Neighbours found | Hello/Dead | Stable state |
|---|---|---|---|---|---|
| **Point-to-point** 🟢 | serial, P2P Ethernet | **No** | automatic (multicast) | 10 / 40 s | **FULL** |
| **Broadcast** 🟢 | Ethernet LAN | **Yes** | automatic (multicast) | 10 / 40 s | **FULL** w/ DR+BDR; **2-WAY** between DROTHERs |
| **NBMA** 🔵 | Frame Relay | Yes | **manual** | 30 / 120 s | FULL |
| **Point-to-multipoint** 🔵 | hub-spoke | No | automatic | 30 / 120 s | FULL |

## 3. ⚡ TL;DR

- Two routers become **adjacent** by climbing a state machine: **Down → Init → 2-Way → ExStart → Exchange → Loading → Full.** **FULL** = databases synced = healthy. 🟢
- **INIT** = I hear you but you don't list my Router ID (one-way). **2-WAY** = we hear each other (bidirectional); **DR/BDR election happens here**. **ExStart/Exchange** = database sync (master/slave, DBD). **Full** = done. 🟢
- **Adjacency requires matching:** **Area ID, Hello & Dead timers, authentication, subnet mask (broadcast), area-type flags** — and compatible **MTU** for the database exchange. Any mismatch → **no adjacency**. 🟢
- **Point-to-point** links (3.4.b): **no DR/BDR**, adjacency is automatic, both sides go straight to FULL. 🟢
- **Broadcast** links (3.4.c): elect a **DR** + **BDR** to avoid a full mesh of adjacencies. Election = **highest interface priority** (default 1), tie broken by **highest Router ID**; **priority 0 = ineligible**; **non-preemptive**. 🟢
- **DROTHERs** form **FULL only with the DR and BDR**, and stay at **2-WAY with each other** — that's **normal, not a fault**. 🟢🔵
- Hellos go to **224.0.0.5**; DROTHERs send updates to **224.0.0.6** (DR/BDR listen), DR re-floods to 224.0.0.5. 🔵

---

## 4. ❓ Importance (problem → solution)

### The problem 🚧
OSPF only works if neighbours reach **FULL** — an identical LSDB. But there are two hard problems buried in getting there:

1. **Adjacency is fragile.** A dozen parameters must agree, and IP connectivity working does **not** mean OSPF will peer. When a neighbour is *missing* or *stuck*, the router doesn't shout "MTU mismatch!" — it just sits silently in a **state**. If you can't read that state, you're blind, and OSPF problems become guesswork. 🔧
2. **Full-mesh adjacencies don't scale.** On a shared Ethernet with *n* OSPF routers, if every router formed a full adjacency with every other, you'd have **n(n−1)/2** adjacencies and every LSA flooded *n* times over — an explosion of traffic and CPU. A 10-router LAN = 45 adjacencies. Unworkable. 🚧

### The solution 🎯
- The **neighbour state machine** turns adjacency formation into a **diagnostic ladder**: each stuck state points at a *specific* cause (Init → one-way Hellos; ExStart → MTU; 2-Way among DROTHERs → normal). Learn the ladder and troubleshooting becomes *reading a status*, not guessing.
- The **DR/BDR** mechanism collapses that n(n−1)/2 mesh into a **hub**: everyone forms a full adjacency **only with the DR (and BDR)**, and floods **once** to the DR, which re-distributes. `n` routers → `~n` adjacencies instead of `n²`. The **network type** decides whether this machinery even runs (point-to-point skips it entirely).

Master these two and you can bring up, verify, and *fix* single-area OSPF on sight — which is exactly what 3.4.a–c tests. 🧠

## 5. 📖 Description

- 🟢 **Neighbour:** a router you exchange Hellos with (reached **2-Way**). **Adjacency:** a neighbour you fully synchronise databases with (reached **Full**). *Not all neighbours become adjacent* (DROTHER pairs don't).
- 🟢 **State machine:** Down → (Attempt 🔵) → Init → 2-Way → ExStart → Exchange → Loading → Full.
- 🟢 **Must-match Hello parameters:** Area ID, Hello interval, Dead interval, authentication, subnet mask (broadcast), stub/area flags. **MTU** must be compatible for the DBD exchange.
- 🟢 **Network type:** an interface property telling OSPF how to behave — **point-to-point** (no DR/BDR, auto) vs **broadcast** (DR/BDR, auto); plus NBMA/P2MP 🔵.
- 🟢 **DR (Designated Router):** the elected "hub" on a multi-access segment; originates the **Type 2 Network LSA**; central point for flooding.
- 🟢 **BDR (Backup DR):** hot standby; promoted if the DR fails.
- 🟢 **DROTHER:** any non-DR/BDR router; full only with DR/BDR, 2-Way with other DROTHERs.
- 🟢 **Priority:** per-interface value (0–255, default 1) driving election; **0 = never DR/BDR**.
- 🟢 **Router ID:** the tie-breaker in election and master/slave negotiation (detail in 4.10).

## 6. ⚙️ How It Works (under the hood)

### 6.1 🔐 Prerequisites — what must match before *any* adjacency 🟢

Before the state machine can even start climbing, both ends must agree on the Hello-carried parameters. IP reachability is **necessary but not sufficient**:

```
 MUST MATCH for neighbours to form:          MUST BE COMPATIBLE for FULL:
 ├── Area ID            (same area)           └── MTU  (else stuck ExStart/Exchange)
 ├── Hello interval                           
 ├── Dead interval                            MUST BE UNIQUE:
 ├── Authentication (type + key)              └── Router ID (duplicates break OSPF)
 ├── Subnet mask       (broadcast nets)
 └── Stub / area-type flags
```

🔑 **Golden rule:** *"Ping works but OSPF won't peer" = a parameter mismatch, not a connectivity problem.* Check these first, always.

### 6.2 🪜 The state machine, step by step 🟢

Walk two routers R1/R2 on an Ethernet from cold:

```
 DOWN      R1 boots OSPF on Gi0/0. No Hellos heard yet.
   │       R1 multicasts a Hello to 224.0.0.5:
   │         { RID=1.1.1.1, Area 0, Hello 10, Dead 40, mask /24, neighbours: [] }
   ▼
 INIT      R2 hears R1's Hello, checks params (all match ✓), adds R1.
   │       R2's Hello now lists R1: { RID=2.2.2.2, neighbours: [1.1.1.1] }
   │       ── If R1 hears Hellos but its OWN RID never appears → STUCK IN INIT
   │          = one-way (R2 can't hear R1). Suspect ACL / unicast issue. 🔧
   ▼
 2-WAY     R1 hears R2's Hello and sees its OWN RID (1.1.1.1) listed → BIDIRECTIONAL ✅
   │       ★ On broadcast: DR/BDR ELECTION runs NOW (§6.4). ★
   │       ── DROTHER↔DROTHER pairs STOP here permanently — by design (§6.5). ──
   ▼       (below: only for links that will fully sync — P2P, or DROTHER↔DR/BDR)
 EXSTART   Negotiate master/slave. HIGHER Router ID becomes MASTER (controls DBD seq #).
   │       ── STUCK here = MTU mismatch (or duplicate RID). 🔧
   ▼
 EXCHANGE  Trade DBD packets = summaries (headers) of each LSDB. Find what's missing.
   │       ── MTU-too-big drops also bite here. 🔧
   ▼
 LOADING   Send LSR ("give me these"), receive LSU (the LSAs), LSAck to confirm.
   ▼
 FULL      LSDBs identical. Adjacency complete. ✅ This is the healthy resting state.
```

The beauty: **the stuck state names the fault.** (Full matrix in No-Goes.)

### 6.3 🔗 Point-to-point (3.4.b) — the simple case 🟢

On a **point-to-point** link (a serial line, or Ethernet set to `ip ospf network point-to-point`), there are exactly **two** routers. A hub election would be pointless, so OSPF **skips DR/BDR entirely**: the two routers discover each other via multicast Hellos and go **straight to FULL**. No election, no DROTHER, less to break.

```
 R1 ●━━━━━━━━━━━━● R2      (point-to-point)
    both reach FULL directly · no DR/BDR · Hello 10 / Dead 40
```

🔑 Engineers often **force** broadcast Ethernet links between just two routers into `point-to-point` type precisely to **avoid the DR/BDR overhead** — faster, simpler, fewer failure modes. 🔵

### 6.4 🗳️ Broadcast (3.4.c) — DR/BDR election 🟢🔵

On a **broadcast multi-access** segment (Ethernet with ≥2 OSPF routers), OSPF elects a **DR** and **BDR** to be the flooding hub. **Why:** without it, *k* routers on one wire would need **k(k−1)/2** full adjacencies and flood every LSA *k* times. With a DR, each router is full **only with DR+BDR**, and floods **once** to the DR, which re-distributes. Mesh → hub.

**The election, in order:**
```
 ① Highest OSPF INTERFACE PRIORITY (0–255, default 1) → wins DR
      · priority 0  = INELIGIBLE (never DR or BDR)
 ② TIE → highest ROUTER ID wins
      · DR = winner, BDR = second place, rest = DROTHER
 ⚠ NON-PREEMPTIVE: once elected, a DR keeps the role even if a higher-priority
    router joins later. Re-election needs the DR to FAIL (or OSPF reset on the segment).
```

**Multicast roles on the segment:**
```
 · ALL routers send Hellos to 224.0.0.5 (AllSPFRouters)
 · DROTHERs send their LSAs/updates to 224.0.0.6 (AllDRouters) ── only DR & BDR listen
 · The DR re-floods to ALL via 224.0.0.5
   → this is the "flood once to the hub, hub redistributes" mechanic
```

> 🕵️ **Dirty secret #1 — non-preemption bites you after a reboot.** You carefully make your beefy core router the DR (high priority). A power blip reboots it; while it's down, a **lowly access switch** wins the election and becomes DR. When your core router returns — **it does NOT take back the DR role** (non-preemptive). Now your intended-standby is the flooding hub indefinitely, until you *manually* bounce OSPF. Engineers who don't know this are baffled why "the wrong router is DR." **Design tip:** if the DR role truly matters, plan for it — or better, on point-to-point-style links, avoid DR/BDR altogether. 🔵

### 6.5 🤝 DROTHER behaviour — why 2-WAY is *healthy* 🟢

This is the single most misread OSPF output. On a broadcast segment:

```
 R1(DR) ─── R2(BDR) ─── R3(DROTHER) ─── R4(DROTHER)   [all on one Ethernet]

 R3's neighbour table:
   R1  FULL/DR      ✅   R3 fully syncs with the DR
   R2  FULL/BDR     ✅   ...and the BDR
   R4  2WAY/DROTHER ✅   ...but only 2-WAY with the other DROTHER — INTENTIONAL
```

DROTHERs don't need to fully sync with each other — they exchange all LSAs **through the DR**. So **2-WAY between two DROTHERs is correct and expected.** If you see it and panic-troubleshoot, you're chasing a non-problem. (The real check: every router should be **FULL with the DR and BDR**.) 🔑

> 🕵️ **Dirty secret #2 — the all-priority-0 deadlock.** Set **every** router on a broadcast segment to priority **0** and *none* can become DR — so the segment has **no DR at all**, and every router gets **stuck in 2-WAY** with everyone, never reaching FULL, never exchanging databases. It looks like a mysterious adjacency failure; it's actually "nobody's allowed to be the hub." At least one router must have non-zero priority. The exam loves this one. 🔵

### 6.6 🔍 Reading `show ip ospf neighbor` 🟢

```
R3# show ip ospf neighbor
Neighbor ID   Pri   State           Dead Time   Address     Interface
2.2.2.2        1    FULL/DR         00:00:35    10.0.0.2    Gi0/0
1.1.1.1        1    FULL/BDR        00:00:38    10.0.0.1    Gi0/0
4.4.4.4        1    2WAY/DROTHER    00:00:32    10.0.0.4    Gi0/0
                    ▲     ▲
                    │     └─ ROLE on this segment (DR/BDR/DROTHER)
                    └─ FSM STATE (want FULL — except 2WAY between DROTHERs)
```
- **Neighbor ID** = the neighbour's **Router ID** (not its interface IP).
- **Pri** = its OSPF interface **priority**.
- **State = FSM/role.** `FULL/DR` = fully synced, that neighbour is the DR. `2WAY/DROTHER` on a DROTHER pair = normal.
- **Dead Time** counts down from 40 s, resetting each Hello — a *decreasing* dead time toward 0 means Hellos have stopped. 🔧

### 6.7 ⏱️ Timers & re-election recap 🟢

- Hello **10 s** / Dead **40 s** on broadcast & point-to-point (30/120 on NBMA/P2MP 🔵). Timers **must match** to peer.
- If a DR fails, the **BDR is promoted instantly** (that's its whole purpose — no election delay for the primary role), and a new BDR is elected. 🔵

## 7. ⚖️ Pros & Cons

| Mechanism | 👍 Pros | 👎 Cons |
|---|---|---|
| **State machine** | Turns adjacency into a self-diagnosing ladder; each stuck state = a specific cause | Many prerequisites; IP-up ≠ OSPF-up confuses beginners |
| **Point-to-point** | Simple, fast to FULL, no election, fewer failure modes | Only two routers per link |
| **DR/BDR (broadcast)** | Collapses n² adjacencies to ~n; floods once via the hub; BDR gives fast failover | Non-preemptive quirks; all-priority-0 deadlock; DR is a flooding bottleneck/target |
| **DROTHER 2-Way** | Saves needless adjacencies & flooding | Constantly misread as a fault |

## 10. ✅ Best Practices

- 🟢 **When a neighbour is missing/stuck, read the state first**, then match it to a cause (matrix in No-Goes). Don't randomly reconfigure.
- 🟢 **Verify the must-match set** (area, timers, auth, mask, MTU) on *both* ends before suspecting anything exotic. IP-up ≠ OSPF-up.
- 🟢 **Between just two routers, prefer `ip ospf network point-to-point`** on the Ethernet link to skip DR/BDR entirely — simpler and faster.
- 🟢 **Don't panic at `2WAY/DROTHER`** — confirm both routers are **FULL with the DR and BDR** and move on.
- 🔵 **If DR placement matters, set priorities deliberately** (and remember non-preemption — you may need to bounce OSPF to re-home the DR after a failure).
- 🔵 **Never set all routers on a segment to priority 0** — at least one must be DR-eligible.

## 11. 🚫 No-Goes (mistakes & troubleshooting traps)

**The stuck-state troubleshooting matrix — memorise this:** 🔧
| Stuck in… | Meaning | Likely cause |
|---|---|---|
| **DOWN** (neighbour absent) | No Hellos at all | Interface down (L1/L2), OSPF not enabled on the interface, ACL blocking **IP proto 89**, wrong network statement |
| **INIT** | I hear them; my RID isn't in their Hello (one-way) | They can't hear me: ACL/filter one direction, unicast-vs-multicast issue, one-side misconfig |
| **2-WAY (unexpected)** | Bidirectional but no full sync | **All routers priority 0** (no DR) → deadlock. *(2-WAY between DROTHERs is NORMAL — not a fault.)* |
| **EXSTART / EXCHANGE** | DBD negotiation fails | **MTU mismatch** (classic!), or **duplicate Router ID** |
| **LOADING (rare)** | LSA request/transfer stalls | Corrupt/oversized LSA, resource issue |

- ❌ **Treating `2WAY/DROTHER` as broken.** It's healthy DROTHER↔DROTHER behaviour. Check for FULL with DR/BDR instead. 🟢
- ❌ **Assuming IP connectivity means OSPF will peer.** A parameter mismatch stops adjacency even with perfect ping. 🟢
- ❌ **Expecting a higher-priority router to seize DR.** Election is **non-preemptive**; it won't. 🟢
- ❌ **Setting every router to priority 0.** No DR → everyone stuck 2-WAY, no databases exchanged. 🔵
- ❌ **Forgetting DR/BDR don't exist on point-to-point.** Looking for a DR on a serial link wastes time. 🟢
- 🔧 **Mismatched Hello/Dead timers** → neighbours never form. Both ends must match. (`show ip ospf interface` shows them.)
- ❌ **Duplicate Router IDs** → adjacency instability / ExStart problems (RID detail in 4.10). 🔵

## 13. 🧪 Practical Tasks

> Goal: *watch* the ladder climb, *cause* each stuck state, and *see* a DR election.

1. **🟢 Point-to-point → FULL (Packet Tracer 8).** Two routers over a serial (or `ip ospf network point-to-point` Ethernet). Watch `show ip ospf neighbor` go straight to **FULL** with **no DR/BDR**. Confirm no DR appears (`show ip ospf interface` → "No designated router on this network").

2. **🟢 Broadcast DR/BDR election.** Four routers on one Ethernet (all default priority 1). Read `show ip ospf neighbor`: identify **DR**, **BDR**, and **two DROTHERs**. Confirm the **highest Router ID** won DR (since priorities tie). Then set one router's `ip ospf priority 200`, bounce OSPF on the segment, and watch it become DR — proving priority beats RID.

3. **🔧 Force each stuck state (the diagnostic gold).**
   - **INIT:** apply an ACL on one router blocking inbound OSPF (proto 89) → the *other* side sits in INIT. Remove it → climbs to FULL.
   - **EXSTART/EXCHANGE:** set mismatched MTUs on the two ends → adjacency **hangs in EXSTART/EXCHANGE**. Fix MTU (or `ip ospf mtu-ignore`) → FULL.
   - **2-WAY deadlock:** set **all** routers on a segment to `ip ospf priority 0` → everyone stuck **2-WAY**, no FULL. Restore a non-zero priority → election runs, FULL returns.

4. **🟢 Prove 2-WAY is normal.** On the four-router LAN, confirm each **DROTHER** shows `FULL/DR`, `FULL/BDR`, and `2WAY/DROTHER` for the other DROTHER — and that connectivity works fine. Internalise: 2-WAY between DROTHERs = healthy.

5. **🔵 Non-preemption demo.** Make R1 DR (high priority). Reboot R1; watch a lower router become DR. Bring R1 back → confirm it does **not** reclaim DR (stays DROTHER/BDR) until you reset OSPF. The "wrong DR" mystery, solved.

6. **🔬 Wireshark the election.** Capture on the LAN during bring-up: watch Hellos to **224.0.0.5** carry priority + neighbour lists, then updates to **224.0.0.6** (DROTHER → DR/BDR). See the hub-flooding model live. 📸
