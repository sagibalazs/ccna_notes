**The 48-bit MAC address (EUI-48) — one address, two halves, two magic bits:**

```
   AC : DE : 48 : 23 : 45 : 67      ← 6 octets = 48 bits = 12 hex digits

   ┌───────────────── first octet (8 bits) ─────────────────┐

                              │      │
                              │      └─ 0 = unicast (individual)
                              │         1 = multicast (group)
                              └──────── 0 = universal (IEEE-burned, globally unique)
                                        1 = locally administered (software-set)
```

**Quick address-type decoder (look at the 2nd hex digit only):**

| 2nd hex digit | Binary low nibble | I/G | U/L | Meaning |
|:---:|:---:|:---:|:---:|---|
| `0 4 8 C` | `x0 x0` | 0 | 0 | 🟢 Unicast, universal (a real burned-in NIC) |
| `2 6 A E` | `x0 x1` | 0 | 1 | 🔵 Unicast, **locally administered** (VMs, randomized Wi-Fi) |
| `1 3 5 7 9 B D F` | `xxx1` | 1 | — | 🟢 Multicast / group (odd first octet) |
| `FF:FF:...:FF` | all ones | 1 | 1 | 🟢 Broadcast (special all-1s case) |

## 3️⃣ TL;DR

- 🟢 **Ethernet = the dominant Layer-2 LAN technology**, standardized as the **IEEE 802.3** family. It defines how devices **frame** data and **address** each other on a shared/switched link.
- 🟢 Layer 2 is split into two sublayers: **LLC (802.2)** talks up to the network layer; **MAC (802.3)** owns **addressing, framing, and media access**.
- 🟢 A **MAC address is 48 bits** (EUI-48): first **24 bits = OUI** (IEEE gives this to the vendor), last **24 bits = the vendor's per-unit ID**. Written as 12 hex digits.
- 🟢 Two control bits hide in the **first octet**: the **I/G bit** (unicast vs multicast) and the **U/L bit** (burned-in vs software-set). `FF:FF:FF:FF:FF:FF` is broadcast.
- 🔵 The 2-byte field after the addresses is **Length/Type**: **≤ 1500** → it's a *length* (old 802.3 style); **≥ 1536 (0x0600)** → it's an *EtherType* (modern **Ethernet II**, what virtually all IP traffic uses today).
- 🧠 **Why it matters for switching:** switches forward on **MAC**, not IP. Everything in Block 2 (VLANs, trunking, STP) rides on top of this one addressing scheme.

## 4️⃣ Importance — The Problem First 🎯

**The underlying problem:** You have a shared physical medium (a wire, or a switched fabric) and *many* devices hanging off it. When electrons/photons carry a stream of bits, three questions must be answered before any two machines can talk:

1. **"Where does one message stop and the next begin?"** → you need **framing** (delimiters, length, error check).
2. **"Who is this for, and who sent it?"** → you need **addressing** that is *unique on the link* and, ideally, *unique worldwide* so no two NICs ever collide.
3. **"Who gets to transmit right now?"** → you need **media access control** (handled historically by CSMA/CD → covered in **[2.3](./2.3-csma-cd-collisions-full-duplex.md)**).

Ethernet is the answer the industry converged on. **MAC addressing** is the part that solves problem #2 — and it's the hinge the *entire* switching world turns on:

- 🔧 A **switch** builds its whole forwarding brain (the MAC address table) purely from **source MAC addresses** it sees. No MAC = no switching.
- 🔧 **ARP**, **DHCP**, **STP**, **VLAN tagging**, **port security**, **DHCP snooping** — every one of them reads or reacts to MAC addresses.
- 🔧 When you troubleshoot "host A can't reach host B," half your evidence is MAC-level: `show mac address-table`, ARP caches, duplicate-MAC alarms.

If you don't *own* how a MAC address is built — bit by bit — you'll memorize switching rules without understanding *why* they behave the way they do. Learn it once, correctly, here.

## 5️⃣ Description 📋

- 🟢 **Ethernet** is a family of LAN technologies covering the **physical layer** and the **MAC sublayer** of the data link layer, standardized under **IEEE 802.3**. The word "Ethernet" today means "the 802.3 family."
- 🟢 The data link layer (OSI L2) is divided by the IEEE 802 project into:
  - **LLC — Logical Link Control (IEEE 802.2):** a thin, media-independent shim that identifies the upper-layer protocol and (optionally) does flow/error control. Largely vestigial in modern IP LANs.
  - **MAC — Media Access Control (IEEE 802.3):** does the real L2 work — **framing**, **MAC addressing**, and **arbitration of the medium**.
- 🟢 A **MAC address** (a.k.a. hardware address, physical address, **burned-in address / BIA**) is a **48-bit** identifier assigned to a **NIC**. Standardized as **EUI-48** by the **IEEE Registration Authority**. (The older name *MAC-48* is now obsolete terminology.)
- 🟢 **Structure — two 24-bit halves:**
  - **OUI (Organizationally Unique Identifier):** first 24 bits, assigned by IEEE to the manufacturer/organization. Guarantees different vendors start with different prefixes.
  - **Extension / NIC-specific identifier:** last 24 bits, assigned by the vendor to keep each interface unique within its own OUI space.
- 🟢 **Two control bits in the first octet:**
  - **I/G — Individual/Group bit** (least-significant bit of octet 1): `0` = **unicast** (one interface), `1` = **multicast/group** (a set of interfaces).
  - **U/L — Universal/Local bit** (second-least-significant bit of octet 1): `0` = **universally administered** (IEEE-assigned, globally unique), `1` = **locally administered** (set by software/OS).
- 🟢 **Special addresses:**
  - **Broadcast** = `FF:FF:FF:FF:FF:FF` (all 48 bits set → every station receives).
  - **Multicast** examples: `01:80:C2:00:00:00` (STP BPDUs), `01:00:5E:xx:xx:xx` (IPv4 multicast), `33:33:xx:xx:xx:xx` (IPv6 multicast), `01:00:0C:CC:CC:CC` (Cisco CDP/VTP).
- 🔵 **Notation forms:** `AC-DE-48-23-45-67` (IEEE hyphenated, preferred), `ac:de:48:23:45:67` (colon), `acde.4823.4567` (Cisco dotted-triplet, groups of 4 hex).
- 🔵 **Block sizes** the IEEE now sells (because 24-bit OUIs are a scarce resource): **MA-L** (large, full 24-bit OUI → 2²⁴ addresses), **MA-M** (medium → 2²⁰ addresses), **MA-S** (small, an OUI-36 base → 2¹² addresses). A small vendor no longer needs a whole OUI.

## 6️⃣ How It Works — Under the Hood 🔬

### A) Building a MAC address (the vendor's side)

```
Step 1  IEEE Registration Authority sells vendor an OUI.
        e.g. Cisco owns  CC:46:D6   (among many)
                          └── 24 bits, U/L=0, I/G=0 baked in ──┘

Step 2  Vendor appends a 24-bit serial-like value per interface.
        CC:46:D6  +  1A:2B:3C   →   CC:46:D6:1A:2B:3C
        └─ who made it ─┘   └─ which unit ─┘

Step 3  That value is burned into the NIC's ROM  →  the BIA.
        (OS can still override it with a Locally Administered Address.)
```

### B) Reading the two magic bits (the engineer's side) 🔍

The trick: **only the first octet carries control bits**, and you decode them from its **low two bits** (= the 2nd hex digit).

```
Take first octet = 0x33  (from the IPv6-multicast MAC 33:33:...)
  0x33 = 0011 0011  (binary)
                  └┴── low two bits = 1 1
                   │    └ b0 = I/G = 1  → GROUP (multicast) ✔ (matches 33:33 = IPv6 mcast)
                   └───── b1 = U/L = 1  → locally administered range

Take first octet = 0x02  (a classic VM / hypervisor MAC 02:...)
  0x02 = 0000 0010
                  └┴── b0 = I/G = 0 → unicast
                   │    b1 = U/L = 1 → LOCALLY administered (software-set, not IEEE) ✔
```

**Fast mental rule:** *odd first octet ⇒ multicast/group.* *(2,6,A,E) as 2nd digit ⇒ locally administered unicast.*

### C) Where the address sits in the frame (basics — full dissection in 2.2)

```
 ┌──────────┬─────┬──────────┬──────────┬────────────┬───────────┬─────┐
 │ Preamble │ SFD │ Dest MAC │ Src MAC  │ Length/Type│  Payload  │ FCS │
 │  7 bytes │  1  │ 6 bytes  │ 6 bytes  │  2 bytes   │ 46–1500 B │  4  │
 └──────────┴─────┴──────────┴──────────┴────────────┴───────────┴─────┘
                   ▲          ▲
                   │          └─ SOURCE  = who sent it (always a unicast BIA/LAA;
                   │                        a source MAC is NEVER multicast/broadcast)
                   └──────────── DEST    = who it's for (unicast / multicast / broadcast)

 • Switch reads DEST MAC → decides the exit port.
 • Switch reads SRC  MAC → learns "this MAC lives on this port" (fills the MAC table).
 • Min frame = 64 bytes, Max = 1518 bytes (untagged). Details → 2.2.
```

### D) 🔵 Length vs Type — the 2-byte field that means two things

Historically two rival frame formats collided:

- **DIX / Ethernet II** (DEC-Intel-Xerox, RFC 894): that 2-byte field is a **Type (EtherType)** — it names the upper protocol directly (`0x0800` = IPv4, `0x86DD` = IPv6, `0x0806` = ARP).
- **IEEE 802.3 (raw / with LLC):** that 2-byte field is a **Length** — the byte count of the payload; the protocol is identified by a following LLC/SNAP header.

IEEE resolved the ambiguity by **numeric range** (unified in 802.3x-1997):

```
 value ≤ 1500 (0x05DC)  →  it's a LENGTH   →  802.3-style frame
 value 1501–1535        →  undefined (reserved, never used)
 value ≥ 1536 (0x0600)  →  it's an ETHERTYPE →  Ethernet II frame
```

1536 was chosen because 1500 is the max payload, so no real length can ever be mistaken for a type. **Reality today:** essentially all IPv4/IPv6 traffic is **Ethernet II**; pure 802.3+LLC/SNAP survives only in a few control protocols (STP, CDP) and legacy stacks.

## 7️⃣ Pros & Cons ⚖️

| ✅ Pros | ❌ Cons / Limits |
|---|---|
| 🟢 **Globally unique addressing** out of the box (OUI system) — no central assignment per device needed. | 🔵 **Flat address space** — MAC has no hierarchy/subnetting, so it can't scale across networks (that's IP's job). Switching is LAN-local. |
| 🟢 **Simple, fast lookup** — switches key on a fixed 48-bit field. | 🔵 **Spoofable** — a MAC is just bytes; any host can set an LAA. Security (port security, DAI) exists *because* of this. |
| 🟢 **Vendor-identifiable** — the OUI tells you who made the NIC (great for troubleshooting/inventory). | 🔵 **OUI exhaustion** — 24-bit space is finite; IEEE now fragments blocks (MA-M/MA-S), so "OUI = vendor" lookups get fuzzier. |
| 🟢 **Ubiquity** — one addressing model spans Ethernet, Wi-Fi, and more (all use EUI-48). | 🔵 **Privacy leak** — a stable BIA tracks a device across networks; hence **MAC randomization** on modern phones. |
| 🟢 **Backward compatible** — Ethernet II and 802.3 coexist on one wire via the Length/Type range trick. | ⚠️ **No built-in confidentiality/integrity** at MAC alone (MACsec is a separate add-on). |

## 8️⃣ Variants — Common → Specific 🌿

**Frame-format lineage (common → niche):**
1. 🟢 **Ethernet II (DIX)** — *the* modern default; Type field; carries virtually all IP traffic.
2. 🔵 **IEEE 802.3 with LLC (802.2)** — Length field + LLC header; used by some legacy/control protocols.
3. 🔵 **IEEE 802.3 with LLC + SNAP** — adds a 5-byte SNAP header so old length-style frames can still name an EtherType (e.g., Cisco CDP rides SNAP).
4. 🔵 **802.3 raw (Novell "raw 802.3")** — historical IPX; no LLC. Mostly extinct.
5. 🔵 **Tagged variants** — 802.1Q inserts a VLAN tag (→ **[2.8 Trunking & 802.1Q](./2.8-trunking-802.1q.md)**); QinQ stacks tags.

**MAC address types (by the two control bits):**
- 🟢 **Unicast, universal** (BIA) — I/G=0, U/L=0 — the factory address.
- 🔵 **Unicast, locally administered** (LAA) — I/G=0, U/L=1 — VMs, containers, Wi-Fi randomization, some HA setups.
- 🟢 **Multicast** — I/G=1 — group delivery (STP, IPv4/IPv6 multicast mappings).
- 🟢 **Broadcast** — all 1s — everyone on the segment.

**Address family (why "EUI"):**
- 🟢 **EUI-48** — the 48-bit LAN address (this doc).
- 🔵 **EUI-64** — 64-bit form; relevant later for **IPv6 interface identifiers** (OUI + `FF-FE` + extension, with the U/L bit *flipped*). Cross-link → Block 3 IPv6.

## 9️⃣ Devices / Media / Protocols 🧰

**Devices that own or read MAC addresses:**
- 🟢 **[NIC / Endpoint](./devices/endpoint-nic.md)** — holds the burned-in address; source of every frame.
- 🟢 **[Layer-2 Switch](./devices/switch.md)** — learns source MACs, forwards on destination MACs. The whole reason MAC addressing exists in practice.
- 🟢 **[Router / L3 Switch](./devices/router.md)** — rewrites source & destination MAC on every hop (each L3 hop = new L2 frame). MAC is *link-local*, IP is end-to-end.
- 🔵 **[Access Point](./devices/access-point.md)** — Wi-Fi also uses EUI-48; the BSSID is a MAC.

**Media:** Any 802.3 medium — copper (Cat5e/6) and fiber (SMF/MMF), covered in Block 1. MAC addressing is **media-independent** (same scheme on Wi-Fi).

**Protocols that live at / lean on this layer:**
- 🟢 **[ARP](./protocols/arp.md)** — resolves IP → MAC. The bridge between L3 and L2 addressing.
- 🟢 **[STP / RSTP](./protocols/stp.md)** — uses multicast dest `01:80:C2:00:00:00` (→ 2.16–2.18).
- 🔵 **[CDP](./protocols/cdp.md) / [LLDP](./protocols/lldp.md)** — L2 discovery via multicast MACs (→ 2.13–2.14).
- 🔵 **[802.1Q](./protocols/dot1q.md)** — VLAN tagging inserts a tag right after the source MAC (→ 2.8).

## 🔟 Best Practices ✅

- 🟢 **Read the 2nd hex digit first** when you see an unfamiliar MAC — it instantly tells you unicast vs multicast and universal vs local. This is a real triage habit.
- 🔵 **Treat a source MAC as untrusted** on access ports facing users — enable **port security** to bound how many/which MACs may appear (→ Block 9 security). A source MAC that is multicast/broadcast is *always* malformed → drop/alarm.
- 🔵 **Plan LAAs deliberately.** If you assign locally administered MACs (VMs, VRRP virtual MACs, clusters), keep a registry and ensure U/L=1, I/G=0 to avoid clashes with real BIAs.
- 🔵 **Use OUI lookups for inventory/forensics**, but don't *trust* them for security — OUIs are public and MACs are spoofable.
- 🟢 **Match the frame format to the traffic:** modern IP = Ethernet II; only expect LLC/SNAP for specific control protocols.
- 🔵 **Standardize notation** in your docs/scripts (pick colon or Cisco dotted form) so grep/diff/regex stay consistent across tooling.

## 1️⃣1️⃣ No-Goes — Common Mistakes & Troubleshooting Traps 🚫

- ❌ **"MAC and IP do the same job."** No. MAC is **link-local** and flat; it's rewritten every router hop. IP is **end-to-end** and hierarchical. Confusing the two breaks your mental model of routing vs switching.
- ❌ **Reading control bits from the wrong end.** The I/G and U/L bits are in the **first octet's low bits** (2nd hex digit) — *not* the last octet. In canonical hex, that first octet is transmitted first, LSB-first on the wire (802.3 §3.3).
- ❌ **Expecting a source MAC to be multicast/broadcast.** A **source** address is *always* unicast. A multicast/broadcast source = corrupted/spoofed frame — a real red flag when reading captures.
- ⚠️ **Assuming OUI = one vendor cleanly.** With MA-M/MA-S fragmentation, a single 24-bit prefix can be shared; lookups may be ambiguous.
- ⚠️ **Trusting a MAC as identity.** MACs are trivially changed (LAA). Never anchor security decisions on MAC alone; that's why DHCP snooping, DAI, and 802.1X exist.
- ⚠️ **Duplicate MACs on a segment.** Two identical MACs (bad LAA planning, cloned VM, spoof) make the switch table flap between ports → intermittent connectivity. Symptom: `%SW_MATM` MAC-flap logs. Check `show mac address-table address <mac>`.
- ❌ **Calling every 2-byte "Type" field a Type.** If value ≤ 1500 it's a **Length** (802.3), not an EtherType. Misreading this mangles your manual frame decoding.

## 1️⃣3️⃣ Practical Tasks 🛠️

> Listed briefly here; expanded step-by-step later in context.

1. 🟢 **Find your own BIA.** Windows `ipconfig /all` · Linux `ip link` · macOS `ifconfig en0`. Identify the OUI half vs the extension half.
2. 🟢 **OUI lookup.** Take your first 3 octets → look them up in the IEEE OUI database (`standards-oui.ieee.org`) → confirm your NIC vendor.
3. 🟢 **Decode the control bits by hand.** For 3 MACs (your NIC, `01:80:C2:00:00:00`, `02:...` from a VM), convert the first octet to binary and state I/G and U/L. Predict unicast/multicast + universal/local *before* checking.
4. 🔵 **Wireshark capture.** Capture a few frames; for each, note Dest MAC (unicast/multicast/broadcast?), Src MAC, and whether the frame is **Ethernet II** (Type ≥ 0x0600) or **802.3+LLC** (Length ≤ 0x05DC). Find the STP frame going to `01:80:C2:00:00:00`.
5. 🔵 **Cisco CLI on a switch (Packet Tracer 8 / GNS3).** `show interfaces <id>` → read the "address is `aaaa.bbbb.cccc` (bia `aaaa.bbbb.cccc`)" line. Then `show mac address-table` and correlate learned MACs to ports.
6. 🔵 **Set a Locally Administered Address** on a test host/VM (U/L=1), re-check with Wireshark that the 2nd hex digit flipped to 2/6/A/E, and observe the switch relearn it on `show mac address-table`.
