## 2. 🗺️ Visualization — The Whole Picture at a Glance

**One IPv6 address = 128 bits = 8 "hextets" of 4 hex digits, colon-separated:**

```
   2001 : 0db8 : 0000 : 0000 : 0000 : ff00 : 0042 : 8329
   └──┘   └──┘   └──┘   └──┘   └──┘   └──┘   └──┘   └──┘
    16     16     16     16     16     16     16     16   bits each
   └──────────────────── 128 bits total ────────────────────┘
   each hextet = 4 hex digits × 4 bits = 16 bits
```

**Hex ⇄ binary (4 bits per hex digit — the whole conversion table):**

```
  0=0000  1=0001  2=0010  3=0011   4=0100  5=0101  6=0110  7=0111
  8=1000  9=1001  a=1010  b=1011   c=1100  d=1101  e=1110  f=1111
```

**Compression (RFC 5952) — shrink it the ONE correct way:**

```
  full     2001:0db8:0000:0000:0000:ff00:0042:8329
  ① drop leading zeros →  2001:db8:0:0:0:ff00:42:8329
  ② longest 0-run → :: →  2001:db8::ff00:42:8329      ✅ canonical
                           (:: may appear ONCE only)
```

**Prefix — same `/n` idea as CIDR, but the split is (almost) always 64/64:**

```
  | 48-bit global routing prefix | 16-bit subnet | 64-bit interface ID |
  |◄──────────  /64 network  ──────────►|◄──── host part (SLAAC) ────►|

  /32 ISP    ⊃   /48 site   ⊃   /56 home   ⊃   /64 ONE LAN   ⊃   /128 one host
```

> 🧭 **The two ideas to hold:** (1) it's just **hex in 16-bit chunks**; (2) the **/64 line is sacred** — network on the left, interface on the right, and you almost never move it (§6.6).

## 3. ⚡ TL;DR

- 🟢 **IPv6 = 128 bits** (vs IPv4's 32), written as **8 hextets** of **4 hex digits** separated by colons. Space = **2¹²⁸ ≈ 3.4 × 10³⁸** addresses. Core spec **RFC 8200 (2017)**.
- 🟢 **Hex** packs 4 bits per digit → each hextet is 16 bits. Learn the 16-value hex↔binary table and IPv6 math becomes trivial.
- 🟢 **Compression (RFC 5952):** drop **leading zeros** in each hextet; replace the **single longest run of all-zero hextets** with `::` — **once**. Lowercase, leftmost run wins ties.
- 🟢 **Prefix** works like CIDR (`/n`), but IPv6 host subnets are **almost always `/64`** — the address splits into a **64-bit network** + **64-bit interface ID**.
- 🟢 **No broadcast in IPv6** — its job is done by **multicast** (e.g. all-nodes `ff02::1`). Details in 3.9.
- 🔵 🕵️ **You do NOT size IPv6 subnets to host count.** Every LAN is a `/64` regardless of whether it holds 2 hosts or 2000 — and going **longer than /64 breaks SLAAC** (§6.6, 3.10).

## 4. 🎯 Importance — The Problem First

**The problem — IPv4 ran out, and the workaround has real costs.** 3.4 (CIDR) and 3.5 (private + NAT) *delayed* IPv4 exhaustion but didn't cure it — the public pool is effectively depleted (the RIRs exhausted their free IPv4 in the 2010s). And the survival hacks came with damage:

- 🕳️ **NAT broke end-to-end connectivity.** Hosts behind NAT aren't directly reachable → peer-to-peer, inbound services, and many protocols need workarounds (STUN/TURN, port-forwarding, ALGs). The internet's original "any host can reach any host" model was lost.
- 🧱 **Double/carrier-grade NAT (3.5) made it worse** — whole populations with no public address at all.
- 🐌 **Address scarcity distorted design** — every subnet plan was a fight over a few addresses (all of 3.2/3.3).

The deeper problem: **32 bits was simply too small** for a planet of phones, sensors, cars, and data-centre workloads.

**The solution — a fundamentally bigger, cleaner address.** IPv6 doesn't patch IPv4; it replaces the address with **128 bits**, enough to give **every device a globally-unique address forever** with room to spare (the entire IPv4 internet fits in a single IPv6 **/96**). That abundance lets IPv6 **restore end-to-end reachability** (no NAT needed), build in **stateless autoconfiguration** (SLAAC, 3.10) so hosts self-address, and **simplify the header and neighbour logic** (NDP replaces ARP, 3.11). The trade you pay is a **new notation (hex + colons + compression)** and a **parallel world** to learn — which is exactly what this doc starts.

> **Why learn it at engineer depth now:** IPv6 is no longer optional — mobile carriers, cloud, and large enterprises run it in production, usually **dual-stack** with IPv4. The exam tests it (`1.8`, `1.9`), and the job requires reading, subnetting, and troubleshooting it fluently. The good news: once you accept the **/64 convention**, IPv6 subnetting is *easier* than IPv4.

## 5. 📖 Description

- 🟢 **128-bit address.** Four times the *bits* of IPv4 — but the address *space* is squared twice over (2¹²⁸, not 4×2³²).
- 🟢 **Hextet (a.k.a. quartet / group / "hexadectet").** One 16-bit group = 4 hex digits. Eight of them per address.
- 🟢 **Hexadecimal.** Base-16 (`0–9`, `a–f`); each digit = exactly 4 bits (a "nibble").
- 🟢 **Text compression (RFC 5952).** The canonical short form: leading-zero suppression + one `::` for the longest zero run, lowercase.
- 🟢 **Prefix `/n`.** Same meaning as CIDR — the leftmost `n` bits are the network. IPv6 states it **always**; there is no "classful" default.
- 🟢 **The /64 split.** Global-unicast host subnets use a **64-bit network** + **64-bit interface ID** (RFC 4291). `/64` is the *de facto* subnet size.
- 🟢 **No broadcast.** IPv6 has **unicast, multicast, anycast** only (types in 3.8–3.9); "broadcast to all" = the multicast group `ff02::1`.
- 🔵 **Dual-stack.** Running IPv4 and IPv6 simultaneously on the same interfaces — the normal migration state.

## 6. 🔧 How It Works — Under the Hood

### 6.1 🟢 Hexadecimal refresher (the only new "math")

Each hex digit is one **nibble** (4 bits). That's the entire conversion:

```
   0xA = 1010 = 10      0xF = 1111 = 15
   0x2001 = 0010 0000 0000 0001   (one hextet = 16 bits)
```

Because 4 bits map cleanly to 1 hex digit, **hex ⇄ binary needs no arithmetic** — just substitute per digit. (This is *why* IPv6 uses hex: it's the most compact base that stays bit-aligned.)

### 6.2 🟢 The 128-bit structure

```
   8 hextets × 16 bits = 128 bits
   2001:0db8:85a3:0000:0000:8a2e:0370:7334
   ▲ each colon separates a 16-bit boundary
```

Leading `0x` is implied; hex letters are **case-insensitive to parse** but **written lowercase** by convention (RFC 5952).

### 6.3 🟢 Text representation & compression (RFC 5952) — the rules

Two reductions, applied in order:

```
  RULE ① — suppress LEADING zeros in each hextet (never trailing):
           0db8 → db8      0000 → 0      00ff → ff      ff00 → ff00 (unchanged)

  RULE ② — replace the ONE longest run of consecutive all-zero hextets with "::"
           :: may be used ONCE per address (else the length is ambiguous)
           tie in length → compress the LEFTMOST run
```

**Worked examples:**

```
  2001:0db8:0000:0000:0000:ff00:0042:8329
   ① → 2001:db8:0:0:0:ff00:42:8329
   ② → 2001:db8::ff00:42:8329                    ✅

  fe80:0000:0000:0000:0000:0000:0000:0001  → fe80::1
  0000:0000:0000:0000:0000:0000:0000:0001  → ::1        (loopback)
  0000:...:0000                             → ::         (unspecified)

  ⚠️ tie-break: 2001:0:0:1:0:0:0:1
     longest run = the THREE zeros on the right → 2001:0:0:1::1   ✅
     NOT 2001::1:0:0:0:1  (that compresses the shorter, left run) ❌
```

- 🔵 **Why canonical form matters:** the *same* address can be typed many ways, but RFC 5952 defines **exactly one** correct output. Mismatched forms in ACLs, logs, and configs cause "the address is there but the match fails" bugs. Always emit canonical form.

### 6.4 🟢 Prefix notation & the network/interface split

Prefix length works exactly like CIDR (3.4): `address/n` = leftmost `n` bits are network.

```
  2001:db8:acad:1::/64   → the first 64 bits are the network (the "subnet")
  interface ID = the last 64 bits (the host part)
```

**Typical allocation hierarchy (RFC 4291 / RFC 6177):**

| Prefix | Who / what | Note |
| ------ | ---------- | ---- |
| `2000::/3` | **Global unicast** currently delegated | the routable internet range |
| `/32` | An **ISP** allocation | |
| `/48` | An **organisation / site** | 65,536 subnets |
| `/56` | A **residential** customer (RFC 6177) | 256 subnets |
| `/64` | **ONE LAN / subnet** | the standard host-subnet size |
| `/127` | Router-to-router link (RFC 6164) | the IPv6 "/31-style" P2P |
| `/128` | A **single host** (loopback `::1`) | |

**Subnetting in IPv6 is easy:** you carve the **subnet ID** bits between the site prefix and the `/64`. A `/48` site has `64 − 48 = 16` subnet bits → **65,536** `/64` LANs, chosen just by counting up in hex (`...:0::/64`, `...:1::/64`, `...:2::/64`, …). **No host-count math** (3.3) needed.

### 6.5 🟢 What's gone, what's new (structural deltas from IPv4)

- 🚫 **No broadcast** → replaced by scoped **multicast** (`ff00::/8`); "all nodes on this link" = **`ff02::1`** (3.9).
- 🔗 **Every interface gets a link-local address** (`fe80::/10`) automatically — there's always an on-link identity (3.8).
- 🧩 **ARP is gone** → **NDP** (Neighbor Discovery, ICMPv6) does address resolution and more (3.11).
- 🏷️ **Hosts can self-configure** (SLAAC, EUI-64) with no DHCP (3.10).
- 🧾 **Simpler fixed 40-byte header** with extension headers (RFC 8200) — packet-level detail lands in routing/Block 4.

### 6.6 🕵️ Dirty Secret — the /64 boundary is (almost) untouchable

Coming from IPv4, the instinct is: "few hosts → use a smaller subnet." **In IPv6 that instinct is wrong and can break your network.**

RFC 4291 fixes the **interface ID at 64 bits** for ordinary global-unicast subnets. That 64-bit host space is what makes **SLAAC** and **EUI-64** (3.10) work — the host builds its own address by dropping a 64-bit interface ID into the lower half. Consequences:

```
  A /64 holds 2⁶⁴ ≈ 1.8 × 10¹⁹ addresses — for a link with maybe 5 devices.
  That "waste" is DELIBERATE: the giant host part is the price of stateless autoconfig.

  Make the subnet /70, /80, /120 "to save space"  →  SLAAC STOPS WORKING on that link.
  Hosts won't autoconfigure; you're forced into manual/DHCPv6 addressing and odd bugs.
```

**The rules of thumb the pros follow:**
- ✅ **Every host LAN = `/64`. Always.** Don't size to host count; you have 2¹⁶ subnets in a /48 to spend freely.
- ✅ **The only common exceptions are infrastructure:** **`/127`** on point-to-point router links (RFC 6164, avoids a neighbour-discovery DoS quirk) and **`/128`** loopbacks. These carry no SLAAC hosts, so the /64 rule doesn't apply.
- ❌ **Never subnet "into" the interface ID** for a normal LAN.

> **Engineer takeaway:** in IPv4 the boundary was a resource you fought over; in IPv6 the `/64` boundary is a **fixed architectural line** you respect. Accepting this makes IPv6 addressing *simpler* than IPv4 — the "hard part" (host-count subnetting) simply disappears.

## 7. ⚖️ Pros & Cons

| ✅ Pros of IPv6 | ❌ Cons / friction |
| -------------- | ----------------- |
| **Vast space** — end-to-end addressing, no NAT needed 🌍 | New notation (hex/colons/compression) to learn |
| **Stateless autoconfig (SLAAC)** — hosts self-address 🏷️ | Dual-stack means running/securing **two** stacks |
| **Simpler subnetting** — every LAN is `/64`, no host math 🧮 | "Huge subnets" feel wasteful to IPv4-trained eyes |
| **Cleaner header + NDP** replacing ARP/broadcast 🧩 | NDP has its own attack surface (RA spoofing, 3.11) |
| **Restores the original internet model** (any-to-any) | Slower/uneven adoption → long IPv4 coexistence |

## 8. 🌿 Variants — Common → Specific

- 🟢 **Representation forms:** full (uncompressed) · leading-zero-suppressed · fully compressed (`::`) — same address, RFC 5952 canonical = the last.
- 🟢 **Prefix sizes:** `/32` ISP · `/48` site · `/56` home · **`/64` LAN** · `/127` P2P · `/128` host.
- 🟢 **Address types (preview → 3.8/3.9):** global unicast (`2000::/3`) · link-local (`fe80::/10`) · unique-local (`fd00::/8`) · multicast (`ff00::/8`) · anycast (syntactically unicast).
- 🔵 **Embedded IPv4 / transition forms:** IPv4-mapped `::ffff:0:0/96`, and translation/tunnel mechanisms (dual-stack, NAT64 — CCNP/design).
- ⚪ **Documentation prefix:** `2001:db8::/32` (RFC 3849) — the IPv6 TEST-NET (used throughout these docs).

## 10. ✅ Best Practices

- 🟢 **Always write canonical RFC 5952 form** — lowercase, leading-zeros dropped, one `::` on the longest run. Consistency prevents match/log bugs.
- 🟢 **Use `/64` for every host subnet.** Don't size to host count; spend subnet IDs freely from your `/48`.
- 🟢 **Use the documentation prefix `2001:db8::/32`** in all examples and labs.
- 🔵 **Reserve `/127` for router-to-router links** (RFC 6164) and `/128` for loopbacks; keep them out of SLAAC LANs.
- 🔵 **Plan a readable subnet scheme** — encode site/floor/VLAN into the hex subnet-ID nibbles (e.g. `2001:db8:acad:<vlan>::/64`); IPv6's space rewards human-friendly numbering.
- 🔵 **Deploy dual-stack** during migration; treat IPv6 security (RA guard, 3.11) as first-class, not an afterthought.

## 11. 🚫 No-Goes — Common Mistakes & Troubleshooting Traps

- ❌ **Using `::` more than once.** Ambiguous → invalid. Only the single longest run gets compressed.
- ❌ **Dropping *trailing* zeros in a hextet.** Only **leading** zeros go (`ff00` stays `ff00`, not `ff`).
- ❌ **Compressing a shorter run when a longer one exists**, or the wrong run on a tie (leftmost wins) — non-canonical, may fail exact-match ACLs.
- ❌ **Subnetting a host LAN longer than `/64`.** Breaks SLAAC/EUI-64 (§6.6, 3.10) → hosts don't autoconfigure.
- ❌ **Expecting broadcast.** There is none; use multicast (`ff02::1` for all-nodes) (3.9).
- 🕵️ **Trap — "the address is right but it won't match."** Almost always a **non-canonical vs canonical** mismatch (uppercase, extra zeros, `::` placement). Normalise both sides.
- 🕵️ **Trap — single-hextet zero and `::`.** `2001:db8:0:1::1` is fine, but don't `::` a **single** zero hextet if it doesn't shorten/help clarity; RFC 5952 says `::` must represent **at least one** 16-bit group and shouldn't be used for a single group when it doesn't reduce length ambiguously — write `0` there instead.
- ❌ **Treating IPv6 like "IPv4 with more digits."** No NAT-by-default, no ARP, no broadcast, mandatory link-local — it's a different model.

## 13. 🧪 Practical Tasks

1. 🖐️ **Compression drill (both directions) ×10.** Compress: `2001:0db8:0000:0000:1111:0000:0000:0020` · `fe80:0000:0000:0000:0204:61ff:fe9d:f156` · `0000:0000:0000:0000:0000:0000:0000:0000`. Then **expand** three compressed addresses back to full form. Watch the tie-break rule.
2. 🔢 **Hex ⇄ binary ×8.** Convert `0xB` , `0xE`, `0x2001`, `0xfe80` to binary and back. Then binary `1101 1010` → hex.
3. 🧩 **Subnet a `/48`.** Given `2001:db8:acad::/48`, list the first five `/64` subnets in canonical form and state how many `/64`s the `/48` yields (2¹⁶).
4. 🖥️ **Read your machine.** `ipconfig` (Windows) / `ip -6 addr` (Linux/macOS): identify your **link-local** (`fe80::…`) and any **global** (`2000::/3`) address; note the `/64` prefix. (Cross-OS verification is 3.12.)
5. 🧰 **Packet Tracer 8.** Put `ipv6 address 2001:db8:acad:1::1/64` on a router LAN interface and `ipv6 address autoconfig` (or a `/64` static) on two PCs; ping across. Observe every interface *also* has an `fe80::` link-local (preview 3.8).
6. 🔬 **Wireshark.** Capture IPv6 traffic; find the 128-bit **Source/Destination** fields; note there's **no broadcast** — neighbour traffic goes to multicast (`ff02::1`, `ff02::1:ff..` solicited-node) (preview 3.9/3.11).
7. 🚧 **Break-it lab (🔵).** Configure a LAN as `/80` and set PCs to `autoconfig`; confirm SLAAC **fails**, then fix to `/64` and watch it work — proving §6.6.
