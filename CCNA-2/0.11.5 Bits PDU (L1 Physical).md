                        │  L1 line-coding (per speed)
                        ▼

## 3. ⚡ TL;DR

- 🟢 **The L1 "PDU" = bits** (really **symbols/signals**). It has **no header or trailer** — L1 just **encodes** the frame's bytes onto the medium and decodes them back.
- 🟢 **Why encoding (not raw high/low):** the signal must **carry a clock** (self-clocking), stay **DC-balanced**, and let the receiver **align** — a long run of identical bits would desync the receiver.
- 🔵 **Encoding ladder by speed:** 10BASE-T **Manchester** → 100BASE-TX **4B/5B + MLT-3** → 1000BASE-T **4D-PAM5** → 10G **64B/66B**/PAM-16 → modern **PAM-4**.
- 🔵 **"Special values" at L1 = control symbols:** 4B/5B **Idle / J-K (start) / T-R (end)**; 8B/10B **K-symbols**, the **K28.5 "comma"** for alignment; 64B/66B **2-bit sync header** (`01`=data, `10`=control).
- 🟢 **In-band framing:** **Preamble/SFD** start a frame; **idle** symbols fill the **IFG** between frames.
- 🟢 **Devices:** the **PHY** (transceiver) does encode/decode; a **hub/repeater** just **regenerates** bits (pure L1).

---

## 4. 🎯 Importance — the problem *first*

**❗ The underlying problem:** every layer above has been shuffling **abstract bits**. But a wire carries **voltage**, a fiber carries **light**, the air carries **radio** — none of them carry "a 1." And you can't naively send "high = 1, low = 0," because:
1. a long run of the same bit gives **no transitions**, so the receiver's clock **drifts** and it loses count; ⏱️
2. a DC imbalance (too many 1s) **saturates** transformers/optics; ⚡
3. the receiver needs to know **where a symbol/byte boundary is** (alignment); 🎯
4. and — with **no header** to carry control — it needs an **in-band** way to say "idle," "frame starts," "frame ends," "error." 🚩

**✅ What L1 does:** **line coding** maps bits to symbols that **guarantee transitions** (clock recovery), keep **DC balance**, and reserve **special control symbols** for idle/delimiters/alignment/error — solving all four with the *encoding itself* rather than a header. Then it drives those symbols onto the medium as real signals and recovers them at the far end. 🧠

**Engineer's "why it matters":** this is where "the network is down" becomes physics — a PHY that won't **link up**, **CRC** errors from marginal signal, a **speed/duplex** autoneg failure, a fiber with too much loss to recover the clock. It's also *why* faster Ethernet needed cleverer codes (Manchester's 100% overhead couldn't scale). 🔧

## 5. 📋 Description (the essentials)

- 🟢 **PDU:** **bits** (symbols/signals). **No header, no trailer** — the frame's bytes *are* the content; L1 encodes them.
- 🟢 **Job:** bit ↔ signal conversion, clocking, alignment, idle/framing — over copper, fiber, or radio.
- 🔵 **The PHY is itself sublayered** (IEEE 802.3): **PCS** (Physical Coding Sublayer — does the line coding), **PMA** (attachment/serialization), **PMD** (medium-dependent driver). Encoding lives in the **PCS**.
- 🟢 **Structure substitute:** in-band **control symbols** (idle, delimiters, comma, sync headers) plus **Preamble/SFD** and the **IFG** provide framing without a header.

## 6. 🔬 How It Works — the header-less PDU, structured by encoding

### 6.1 🧠 Why "bits" has no header (the principle)

Every other PDU adds a header of control fields. L1 can't — its "payload" is *already* the fully-built frame, and there's nothing below it to address. So L1 puts its control **in-band**, as **reserved symbols** the line code defines. The **encoding scheme is the structure.** 🎯

### 6.2 🪜 The encoding ladder — bit → symbol → signal 🔵

(Condensed from 0.8; here we focus on the *symbol structure*.)
```
   10BASE-T   Manchester   — 1 transition per bit (self-clocking); 100% overhead
   100BASE-TX 4B/5B+MLT-3  — 4 data bits→5-bit group, then 3-level MLT-3
   1000BASE-T 4D-PAM5      — 5 voltage levels, 2 bits/symbol, all 4 pairs
   10GBASE-R  64B/66B      — 64 data bits + 2-bit sync header (3% overhead)
   modern     PAM-4        — 4 levels, 2 bits/symbol (100G+ lanes)
```
- **Baud ≠ bit rate:** multilevel codes (PAM) carry **several bits per symbol**, so bit rate > baud. 🔵
- **Manchester** self-clocks by putting a transition in **every** bit (great sync, wasteful). Higher speeds moved to **block codes** (fewer transitions, more efficiency) + scrambling. 🎯

### 6.3 🏷️ Block-code **structure & special values** — the "fields" of the bits PDU 🔵

**4B/5B (100BASE-TX, FDDI):** map every **4 data bits → a 5-bit code group**, chosen so there are **≥2 transitions and ≤3 consecutive zeros** (self-clocking). 16 groups are **data**; the spare groups are **control**:
```
   Data (examples):  0000→11110   0001→01001   0010→10100 …
   Control (non-data code-groups):
     I  (Idle)                = 11111   ← link idle / IFG fill
     J,K (Start delimiter)    = 11000, 10001   (the "JK" pair begins a stream)
     T,R (End delimiter)      = 01101, 00111
     H  (Halt / error)        = 00100
```
- On fiber the 5-bit stream is **NRZI**-encoded; on copper (100BASE-TX) it's **MLT-3**. 
- **These control code-groups do the framing a header would** — idle vs data, start, end. 🎯

**8B/10B (1000BASE-X, Fibre Channel):** map **8 bits → 10 bits** (20% overhead) for DC balance + clocking. Symbols come in two kinds:
- **D.x.y** = data symbols. 
- **K.x.y** = **control** symbols (12 valid). The famous **K28.5 = "comma"**: a unique bit pattern that **can't occur across data boundaries**, so the receiver uses it to **find symbol alignment**. Comma + data form **"ordered sets"** (idle, start-of-packet, etc.). 🔵
```
   … K28.5(comma) D.. D.. …   ← receiver locks alignment on the comma
```

**64B/66B (10GBASE-R and up):** the modern low-overhead code — **64 scrambled data bits + a 2-bit sync header**:
```
   ┌────┬───────────────────────────────────────────┐
   │ SH │            64-bit (scrambled) payload      │
   └────┴───────────────────────────────────────────┘
    2 b
   Sync Header:  01 = all-DATA block
                 10 = has CONTROL (start/stop/idle info)
                 00 or 11 = CODE ERROR 🚫
```
- Only **3% overhead** (vs 20% for 8B/10B). A **scrambler** provides DC balance; the **2-bit header** provides block sync and marks data vs control. 🎯

### 6.4 🚦 In-band framing around the frame 🟢

- **Preamble (7 B) + SFD (1 B):** the run-up (from 0.11.4) — alternating `1010…` lets the receiver's **CDR** lock the clock; the **SFD** says "frame starts now." 🏁
- **Idle** symbols/ordered sets fill the **IFG** (12 bytes / 96 bit-times) so the link never goes ambiguous between frames. ⏸️
- 🔵 **Link pulses (10/100BASE-T):** **NLP** (Normal Link Pulse) keeps a quiet link alive; **FLP** (Fast Link Pulse) bursts carry **auto-negotiation** (speed/duplex). — [internal](./terms/link-pulse.md) · [external](https://standards.ieee.org/ieee/802.3/7071/)

### 6.5 🔑 The three jobs of any line code (the "why") 🔵

| Goal | Why | How |
|---|---|---|
| **Clock recovery** | receiver has no separate clock wire | guarantee frequent **transitions** (self-clocking) |
| **DC balance** | avoid saturating transformers/optics | keep 1s ≈ 0s (balanced codes / scrambling) |
| **Alignment / control** | find symbol/byte edges; signal idle/error | reserved **control symbols** (comma, sync header) |

### 6.6 👁️ Reading/writing order at L1 — who, when, why 🟢

- **On send (very last step):** the **PHY** takes the finished frame's bytes → the **PCS** line-codes them into symbols → the **PMA/PMD** drive them onto the medium as **signals**. Bits go on the wire **last** of everything. ✍️
- **On receive (very first step):** the PHY's **CDR** recovers the clock from the signal → decodes symbols → reassembles **bytes** → hands the **frame** up to L2 (which then checks the FCS). Bits are read **first**. 📖
- **Devices at L1:**
  - **Hub / repeater** — pure L1: **regenerate and repeat** the bit stream to all ports (no decode of addresses). 🔁
  - **PHY / transceiver / SFP** — encode/decode + drive the medium. 🔧
  - **Media converter** — re-encodes between media (copper↔fiber). 
  - (A **switch/router** operate above L1; they rely on the PHY to hand up clean bytes.)

### 6.7 🔌 Handoff (up only — this is the bottom)

- **Up:** decoded **bytes** become the **frame** for L2 (0.11.4), which verifies the **FCS** and reads the destination MAC. 
- **Down:** there is no "down" — the medium **is** the bottom. The bits leave as photons/electrons/waves. 🌐

## 7. ⚖️ Pros & Cons (of encoding as the L1 "structure")

| 👍 Pros | 👎 Cons |
|---|---|
| Self-clocking → no separate clock wire needed ⏱️ | Coding **overhead** (Manchester 100%, 8B/10B 20%) 📉 |
| DC balance protects transformers/optics ⚡ | More complex PHY (PCS/PMA/PMD, scramblers) 🧩 |
| Control symbols give **in-band** framing (no header) 🏷️ | Symbol errors can corrupt whole blocks 🐛 |
| Newer codes (64B/66B, PAM-4) scale to 100G+ efficiently 🚀 | Marginal signal → link-up/CRC problems (hard to see) 🔍 |

---

## 8. 🧬 Variants (common → specific)

1. 🟢 **Manchester** — 10BASE-T (simple, high overhead).
2. 🟢 **4B/5B + MLT-3 / NRZI** — 100BASE-TX / fiber.
3. 🟢 **4D-PAM5** — 1000BASE-T (copper).
4. 🔵 **8B/10B** — 1000BASE-X / Fibre Channel / older SerDes.
5. 🔵 **64B/66B** — 10G–100G (low overhead + scrambler).
6. 🔵 **PAM-4** — 100G+ per-lane (2 bits/symbol at high baud).

> 💡 **Why encoding got cleverer with speed:** Manchester's transition-per-bit is simple but doubles the required bandwidth — untenable at gigabit+. Block codes (4B/5B, 8B/10B) then **scrambled** codes (64B/66B) and **multilevel** signaling (PAM) pack more bits into less bandwidth while *still* self-clocking. Encoding evolution **is** the story of Ethernet's speed. 🏎️

**Media:** twisted pair, multimode/single-mode fiber, radio (see 0.8).

## 10. ✅ Best Practices (engineer habits)

- 🔌 **Check link/PHY first.** No link light or flapping = an L1/encoding/clock problem — verify cable, transceiver, and both-ends speed/duplex.
- 🧼 **Keep fiber endfaces clean.** A speck of dust = enough loss to break clock recovery → dead link.
- 🎛️ **Match speed/duplex** (both auto or both fixed) so autoneg (FLP) succeeds.
- 🔦 **Use the right optic/medium** for the reach; too much loss = the receiver can't recover the clock.
- 🧮 **Read PHY/interface counters** (CRC, symbol errors, link flaps) as the earliest warning of marginal signal.

## 11. 🚧 No-Goes (common mistakes + troubleshooting)

| ❌ Mistake | ✅ Reality / Fix |
|---|---|
| "Encoding is just high=1, low=0." | Real codes are **self-clocking & DC-balanced** (Manchester/MLT-3/PAM/64B66B). |
| "The bits layer has a header." | **No header** — control is **in-band** via reserved symbols. |
| "A hub is a slow switch." | A hub is **L1** (regenerates bits, one collision domain); a switch is L2. |
| "Idle time is empty." | The link sends **idle symbols** (the IFG isn't truly silent). |
| "CRC errors are a software bug." | Usually **physical** — marginal signal, bad cable/optic, duplex mismatch. |
| "Faster Ethernet just raises the voltage rate." | It uses **better encoding** (block/scrambled/multilevel), not just faster on/off. |

**🩺 Troubleshooting reflexes:**
- Link won't come **up** → speed/duplex (autoneg), dead SFP, wrong fiber, broken cable.
- Link up but **CRC/symbol errors** climbing → marginal signal (cable/optic/EMI).
- Works short, fails long → **too much loss/reach** for the optic → clock can't recover.

## 13. 🧪 Practical Tasks (hands-on)

> *Listed briefly; expanded in the lab context later.*

1. **〰️ See a waveform.** Watch a scope/logic-analyzer capture (or a good animation) of **Manchester** vs **MLT-3** — connect "bits" to an actual signal and its transitions. → *Encoding made physical.*
2. **🔌 Force an autoneg/link event.** Toggle speed/duplex on a lab link and watch it re-link (FLP); mismatch it and watch it fail. → *Link-up as an L1 handshake.*
3. **🧮 Read PHY counters.** `show interfaces` → **CRC**, **input/symbol errors**, **link flaps**; correlate with a marginal cable/optic. → *Where L1 pain surfaces.*
4. **📏 Test reach.** Bring up a fiber link near/over its rated distance; observe loss/errors as the receiver struggles to recover the clock. → *Why reach limits exist.*
5. **🔁 Prove a hub is L1.** In a capture through a hub vs a switch, note the hub **repeats to all ports** (bits only). → *Pure-L1 behaviour.*
