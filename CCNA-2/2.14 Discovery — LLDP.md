## 3️⃣ TL;DR

- 🟢 **LLDP is the vendor-neutral, open-standard (IEEE 802.1AB) equivalent of CDP** — it discovers directly-connected neighbors of **any** vendor at Layer 2.
- 🟢 On Cisco, **LLDP is disabled by default** — enable it globally with **`lldp run`**, and (if needed) per-interface with **`lldp transmit`** / **`lldp receive`** (which are **independent** — you can send without receiving or vice-versa).
- 🟢 **Timers:** transmit every **30 s** (half of CDP's 60), **TTL/holdtime 120 s** (= timer × multiplier 4), **reinit 2 s**. Multicast **`0180.C200.000E`**, EtherType **`0x88CC`**.
- 🟢 **Not forwarded** → one-hop only, just like CDP. Works at **Layer 2** (no IP needed) → same troubleshooting power.
- 🟢 Each LLDP frame carries an **LLDPDU** of **TLVs**. **Mandatory:** Chassis ID, Port ID, TTL. Optional: system name/description, capabilities, management address, etc.
- 🟢 **`show lldp neighbors`** shows five fields (**Device ID, Local Intf, Hold-time, Capability, Port ID**) — **no Platform** column. Watch the capability code: **B = Bridge = a switch** (CDP uses S).
- 🟢 **LLDP-MED** is the extension for **IP phones** — voice VLAN, PoE, QoS/network policy, E911 location. It's how **non-Cisco phones** get their voice VLAN (CDP does this for Cisco phones, → 2.7).
- ⚠️ **Same security leak as CDP** — advertises identity/capabilities/mgmt address/software version. **Disable on user-/internet-facing ports.** **CDP and LLDP can run simultaneously.**

## 4️⃣ Importance — The Problem First 🎯

**The underlying problem:** CDP (2.13) is fantastic — but it only speaks **Cisco**. Real networks are **mixed-vendor**: Cisco cores, Juniper/Arista switches, Aruba/Ubiquiti APs, Polycom/Yealink phones, Dell/HP servers. Plug a Cisco switch into a Juniper switch and `show cdp neighbors` shows **nothing** — the Juniper doesn't speak CDP. You're blind exactly where multi-vendor complexity makes discovery most valuable.

- ❓ *"How do I discover neighbors when they aren't Cisco?"* → **LLDP**, the IEEE open standard every serious vendor implements.
- ❓ *"How does a non-Cisco IP phone learn its voice VLAN and PoE budget?"* → **LLDP-MED** (the standards analog of CDP's phone signaling).
- ❓ *"Can I run both?"* → yes — **CDP and LLDP coexist**; many networks run both so every device is discoverable.

**Why an engineer must own this cold:**

- 🔧 **Mixed-vendor is the norm, so LLDP is the *universal* discovery tool.** Where CDP goes dark, LLDP maps the topology — and interviews/exams specifically test the CDP-vs-LLDP differences (timers, defaults, MACs, `B` vs `S`).
- 🔧 **LLDP-MED runs real voice deployments** with non-Cisco phones — voice VLAN, PoE, and QoS all ride it. If you only know CDP, you can't troubleshoot half the phones in the world.
- 🔧 **The "disabled by default" gotcha bites.** People expect discovery to "just work" like CDP and are baffled when `show lldp neighbors` is empty — because nobody ran `lldp run`. Knowing the default flips troubleshooting instantly.
- 🔧 **Tx/Rx independence is a real hardening lever.** You can *receive* neighbor info without *advertising* your own — useful on sensitive ports where you want visibility but not exposure.

## 5️⃣ Description 📋

- 🟢 **What LLDP is:** a **vendor-neutral Layer-2** neighbor-discovery protocol defined in **IEEE 802.1AB**. Devices advertise their **identity, capabilities, and management info** to **directly-connected** neighbors — the open-standard counterpart to CDP, usable across **any vendor**.
- 🟢 **Default state on Cisco:** **disabled**. Enable **globally** with **`lldp run`** (this activates Tx and Rx on all interfaces). Contrast with CDP, which is **on by default**.
- 🟢 **Directly connected only:** LLDP frames go to multicast **`0180.C200.000E`** and are **processed then discarded** — **never forwarded**. So, like CDP, you see **one hop** only.
- 🟢 **Layer-2, no IP needed:** LLDP frames use **EtherType `0x88CC`**. Because it runs below IP, LLDP works even when a neighbor has no IP — same troubleshooting benefit as CDP.
- 🟢 **Timers:** transmit interval **30 s** (`lldp timer`) — **half** of CDP's 60 s; **TTL/holdtime 120 s** (`lldp holdtime`) = **timer × holdtime-multiplier (default 4)**; **reinitialization delay 2 s** (`lldp reinit`).
- 🟢 **One-way per direction (Tx/Rx independent):** you can control **`lldp transmit`** and **`lldp receive`** **separately** per interface — e.g., receive neighbor info without advertising your own.
- 🟢 **LLDPDU & TLVs:** each LLDP frame carries one **LLDPDU** = a sequence of **TLVs (Type-Length-Value)**.
  - **Mandatory TLVs (in order):** **Chassis ID**, **Port ID**, **Time-to-Live (TTL)**.
  - **Optional TLVs:** system name, system description, port description, **system capabilities**, **management address**, and more.
  - Ends with the **End-of-LLDPDU** TLV (type and length both 0). Vendors can add **organizationally-specific** TLVs.
- 🟢 **`show lldp neighbors` fields (five):** **Device ID · Local Intf · Hold-time · Capability · Port ID** — **no Platform** column (a CDP-only field). `detail` adds system name/description, capabilities (and **enabled** capabilities), management address, VLAN, software version.
- 🟢 **Capability codes:** **(R)** Router, **(B)** Bridge = **switch**, **(T)** Telephone, **(C)** DOCSIS, **(W)** WLAN AP, **(P)** Repeater, **(S)** Station, **(O)** Other. ⚠️ **A switch is `B` (Bridge) in LLDP** — CDP calls it `S` (Switch). Also note **capabilities vs enabled capabilities** (what it *can* do vs what's *active*).
- 🟢 **LLDP-MED (Media Endpoint Discovery):** the LLDP extension for **endpoints/IP phones** — carries **voice VLAN**, **PoE/power** requirements, **QoS/network policy**, and **location (E911)**. It's the **standards-based** way non-Cisco phones get their voice VLAN (Cisco phones can use CDP *or* LLDP-MED) (→ 2.7).
- 🔵 **Coexistence:** **CDP and LLDP can run at the same time** — common in mixed environments so every device is discoverable.
- ⚠️ **Security:** LLDP leaks the **same** sensitive info as CDP (identity, capabilities, mgmt address, software version) to anyone on the segment → **disable on untrusted / user- / internet-facing ports** (`no lldp transmit`/`no lldp receive`, or don't `lldp run` there).

## 6️⃣ How It Works — Under the Hood ⚙️

### A) 📢 Transmit & TTL — the neighbor lifecycle (faster than CDP)

```
 Every 30s, each LLDP-enabled port MULTICASTS an LLDPDU to 0180.C200.000E (EtherType 0x88CC).
 A neighbor that hears it:
    1. Parses the TLVs (Chassis ID, Port ID, TTL, system name, capabilities, mgmt addr, …).
    2. Stores/refreshes the entry; lifetime = the advertised TTL (default 120s).
    3. DISCARDS the frame (never forwards it → one hop only).

 TTL countdown with no new LLDPDU:  120 → 60 → 0 → aged out.
 (LLDP's 30s/120s is snappier than CDP's 60s/180s — quicker to appear, quicker to age.)

 Note: TTL(120) = lldp timer(30) × holdtime multiplier(4). Change the timer and the TTL scales.
```

### B) 🧩 LLDPDU / TLV structure

```
  ┌──────────── one LLDP frame (EtherType 0x88CC) ────────────┐
  │  ┌─────────── LLDPDU ───────────┐                          │
  │  │ [Chassis ID TLV] MANDATORY   │  ← who I am (base MAC/etc.)
  │  │ [Port ID TLV]    MANDATORY   │  ← which of MY ports sent this
  │  │ [TTL TLV]        MANDATORY   │  ← how long to keep me (120s)
  │  │ [System Name]    optional    │
  │  │ [Capabilities]   optional    │  ← Bridge/Router/… + which are ENABLED
  │  │ [Mgmt Address]   optional    │  ← IP to reach me
  │  │ [ … more / org-specific … ]  │
  │  │ [End of LLDPDU]  (type=len=0)│
  │  └──────────────────────────────┘                          │
  └────────────────────────────────────────────────────────────┘
```

### C) 🛠️ Configuration — enable it first! (the #1 gotcha)

```
! GLOBAL — LLDP is OFF by default on Cisco. This is why 'show lldp neighbors' is empty.
Switch(config)# lldp run                 ! turn LLDP ON (activates Tx+Rx on all ports)

! PER-INTERFACE — Tx and Rx are INDEPENDENT
Switch(config)# interface Gi0/1
Switch(config-if)#  lldp transmit         ! advertise ourselves out this port
Switch(config-if)#  lldp receive          ! learn neighbors on this port
! Harden a sensitive port: listen but don't advertise
Switch(config-if)#  no lldp transmit      ! receive-only (visibility without exposure)

! TIMERS
Switch(config)# lldp timer 30             ! transmit interval (default 30s)
Switch(config)# lldp holdtime 120         ! TTL advertised (default 120s)
Switch(config)# lldp reinit 2             ! reinit delay (default 2s)
```

### D) 🔍 Verification

```
Switch# show lldp                          ! global: ACTIVE?, timer, holdtime, reinit
  Status: ACTIVE
  LLDP advertisements are sent every 30 seconds
  LLDP hold time advertised is 120 seconds
  LLDP interface reinitialisation delay is 2 seconds

Switch# show lldp neighbors                 ! summary (5 fields, B = switch)
Switch# show lldp neighbors detail          ! system name/desc, capabilities, mgmt IP, VLAN, version
Switch# show lldp interface Gi0/1           ! per-port Tx/Rx enabled + state
Switch# show lldp traffic                    ! LLDP packet counters
Switch# show lldp entry SW2                   ! one neighbor's detail
```

> 🕵️ **Dirty secret #1 — an empty `show lldp neighbors` usually means nobody ran `lldp run`.** People assume discovery "just works" (CDP habit) and burn time hunting a cabling/port fault when the real cause is that **LLDP is off by default**. First check `show lldp` → `Status: ACTIVE?`. Also: enabling `lldp run` on one switch isn't enough — **both ends** must have LLDP on (and Tx/Rx aligned) to see each other.

### E) ☎️ LLDP-MED — how a (non-Cisco) phone gets its voice VLAN

```
 1. Phone links up (PoE powers it). It sends LLDP with LLDP-MED TLVs ("I'm a media endpoint").
 2. Switch replies with LLDP-MED Network-Policy TLV: "Voice VLAN = 40, tag it, CoS/DSCP = X."
 3. Phone tags its voice on VLAN 40 with that priority; the daisy-chained PC stays untagged in
    the data VLAN — exactly the model from 2.7, but via the OPEN standard instead of CDP.
 4. LLDP-MED also negotiates fine-grained PoE and can carry E911 LOCATION for the phone.

  → CDP does this for Cisco phones; LLDP-MED does it for everyone. Keep LLDP(-MED) ON on phone
    ports even if you disable plain LLDP elsewhere for security.
```

### F) 🔀 Reading the comparison in practice

```
 Same link, two lenses:
   show cdp neighbors   → sees only the CISCO neighbor (Platform column shows model)
   show lldp neighbors  → sees the Cisco AND the non-Cisco neighbor (no Platform column)

 The neighbor that a Cisco device calls 'S' (Switch) in CDP is 'B' (Bridge) in LLDP.
 If you see a device in LLDP but NOT in CDP → it's almost certainly NON-Cisco. Useful clue!
```

> 🕵️ **Dirty secret #2 — CDP and LLDP timers/defaults are a favorite exam swap.** They'll give you "60 s / 180 s" and ask if it's LLDP (it's **CDP**), or claim LLDP is on by default (it's **off**). Lock in: **CDP 60/180, on, `0100.0CCC.CCCC`, S** vs **LLDP 30/120, off, `0180.C200.000E`, B**. Getting these crossed is the classic trap.

## 8️⃣ Variants — Common → Specific 🌿

**Discovery protocol family:**
- 🟢 **LLDP** — open standard, multi-vendor, off by default (this doc).
- 🟢 **CDP** — Cisco, on by default (→ 2.13).

**LLDP forms:**
- 🟢 **Base LLDP (802.1AB)** — device/topology discovery.
- 🟢 **LLDP-MED** — endpoint/phone extension (voice VLAN, PoE, QoS, location).
- 🔵 **Organizationally-specific TLVs** — vendor extensions (802.1/802.3 TLVs: VLAN, link aggregation, MAC/PHY, max frame size…).

**Direction control:**
- 🟢 **Tx + Rx** (default when `lldp run`).
- 🟢 **Rx only** (`no lldp transmit`) — listen without advertising.
- 🟢 **Tx only** (`no lldp receive`) — advertise without learning.

**TLV categories:**
- 🟢 **Mandatory** (Chassis ID, Port ID, TTL) · **Optional** (name/desc/capabilities/mgmt) · **End-of-LLDPDU**.

## 9️⃣ Devices / Media / Protocols 🧰

**Devices:**
- 🟢 **[Router](./devices/router.md) / [L2 Switch](./devices/switch.md) / [L3 Switch](./devices/switch.md)** (any vendor) — advertise/learn via LLDP.
- 🟢 **Non-Cisco switch / AP / server** — the whole point: discoverable via LLDP (invisible to CDP).
- 🟢 **IP Phone (any vendor)** — uses **LLDP-MED** for voice VLAN/PoE/QoS (→ 2.7).

**Media:** Ethernet LAN segments (LLDP runs on 802.3 links).

**Protocols / relationships:**
- 🟢 **[CDP](./protocols/cdp.md)** — the Cisco counterpart; coexists (→ 2.13).
- 🟢 **[Voice VLAN](./terms/voice-vlan.md)** — delivered to phones via LLDP-MED (→ 2.7).
- 🔵 **PoE (802.3af/at)** — LLDP-MED negotiates fine-grained power (Block 1, 1.2).
- 🔵 **QoS / network policy** — LLDP-MED carries CoS/DSCP for voice (→ IP Services 4.7).
- 🔵 **SNMP** — LLDP data is exposed via the LLDP-MIB for NMS topology tools.

## 🔟 Best Practices ✅

- 🟢 **Enable LLDP (`lldp run`) in mixed-vendor networks** so non-Cisco gear is discoverable; run **CDP and LLDP together** for full coverage.
- 🟢 **Remember it's off by default** — if `show lldp neighbors` is empty, check `show lldp` for `Status: ACTIVE` on **both** ends first.
- 🟢 **Keep LLDP/LLDP-MED on phone ports** (non-Cisco phones need it for voice VLAN/PoE), even if you disable plain LLDP on user data ports.
- 🟢 **Disable LLDP on user-/internet-facing ports** (`no lldp transmit`/`no lldp receive`) to limit info leakage — same reasoning as CDP.
- 🔵 **Use Rx-only** (`no lldp transmit`) on sensitive ports where you want visibility but not exposure.
- 🔵 **Leave default timers** (30/120/2) unless you have a reason; align them on both ends.
- 🔵 **Feed LLDP into your NMS** (LLDP-MIB via SNMP) for automatic, vendor-neutral topology maps.

## 1️⃣1️⃣ No-Goes — Common Mistakes & Troubleshooting Traps 🚫

- ❌ **Expecting LLDP to be on by default.** It's **off** on Cisco. No `lldp run` = empty neighbor table (not a cabling fault).
- ❌ **Enabling LLDP on only one side.** Both ends must have LLDP on (and Tx/Rx aligned) to see each other. Rx-only on one side + Tx-only on the other still works one-directionally — align them.
- ⚠️ **Swapping CDP/LLDP defaults.** CDP = 60/180/on/`0100.0CCC.CCCC`/S; LLDP = 30/120/off/`0180.C200.000E`/B. Crossing these is the classic exam/ops error.
- ⚠️ **Reading `B` as "bridge, not a switch."** In LLDP, **B (Bridge) = a switch**. Don't dismiss it.
- ⚠️ **Looking for a Platform column in LLDP.** `show lldp neighbors` has **five** fields — no Platform (that's CDP). Model info is in `detail`.
- ⚠️ **Disabling LLDP on non-Cisco phone ports.** They may lose their **voice VLAN/PoE** (LLDP-MED). Keep it on phone ports.
- ⚠️ **Leaving LLDP on internet-/user-facing ports.** Same reconnaissance leak as CDP (identity, software version, mgmt IP). Disable there.
- 🔵 **Assuming LLDP carries VTP info.** It doesn't — that's a **CDP-only** field.

## 1️⃣3️⃣ Practical Tasks 🛠️

> Listed briefly; expanded step-by-step later in context.

1. 🟢 **Enable & discover (Packet Tracer 8 / GNS3).** On two switches, `lldp run` on **both**; verify with `show lldp neighbors`. Note the neighbor shows `B` (Bridge) for a switch and there's **no Platform** column.
2. 🟢 **Prove off-by-default.** Before `lldp run`, confirm `show lldp` shows LLDP inactive and `show lldp neighbors` is empty; enable and re-check.
3. 🟢 **Tx/Rx independence.** On one port `no lldp transmit` (Rx-only); confirm the neighbor still sees *nothing new from you* while you still learn *it*. Restore.
4. 🟢 **Detail dive.** `show lldp neighbors detail` — read system name/description, **capabilities vs enabled capabilities**, management address, software version.
5. 🔵 **CDP + LLDP side by side.** On a link, run both; compare `show cdp neighbors` vs `show lldp neighbors` outputs and map the field/timer/MAC/`S`-vs-`B` differences to the comparison table.
6. 🔵 **LLDP-MED phone (Packet Tracer / lab).** Attach a phone that uses LLDP-MED; verify it receives the voice VLAN and PoE via `show lldp neighbors detail` / `show power inline`; contrast with the CDP path from 2.7.
7. 🔵 **Security pass.** Disable LLDP on user/internet-facing ports (`no lldp transmit`/`receive`) while keeping it on infra + phone ports; verify with `show lldp interface`.
