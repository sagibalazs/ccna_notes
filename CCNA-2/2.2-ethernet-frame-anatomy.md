┌──────────────┬─────┬───────────┬───────────┬┅┅┅┅┅┅┅┅┅┬────────────┬───────────┬─────────┬─────┐
│  Preamble    │ SFD │ Dest MAC  │ Src MAC   │ 802.1Q  │ Length/Type│  Payload  │   Pad   │ FCS │
│   7 bytes    │  1  │  6 bytes  │  6 bytes  │ (4 opt) │  2 bytes   │ 46–1500 B │ 0…46 B  │  4  │
│ 1010…1010    │ …11 │ who for   │ who from  │ VLAN    │ len OR type│ L3 packet │ zeros   │ CRC │
└──────────────┴─────┴───────────┴───────────┴┅┅┅┅┅┅┅┅┅┴────────────┴───────────┴─────────┴─────┘
                     │◀────────────── covered by the FCS (CRC-32) ──────────────▶│
                     │                                                            │
                     └─ frame length is measured from HERE (DA) to HERE (end FCS) ┘

**Field cheat-sheet (untagged):**

| # | Field | Size | In FCS? | In "frame size"? | One-line job |
|---|---|:---:|:---:|:---:|---|
| — | Preamble | 7 B | ❌ | ❌ | Clock sync (PHY) |
| — | SFD | 1 B | ❌ | ❌ | "Frame starts *now*" |
| 1 | Destination MAC | 6 B | ✅ | ✅ | Who receives |
| 2 | Source MAC | 6 B | ✅ | ✅ | Who sent (always unicast) |
| (2½) | 🔵 802.1Q tag | 4 B | ✅ | ✅ | VLAN tag (optional → 2.8) |
| 3 | Length/Type | 2 B | ✅ | ✅ | ≤1500 len / ≥1536 type |
| 4 | Payload (Data) | 46–1500 B | ✅ | ✅ | The L3 packet |
| 5 | Pad | 0–46 B | ✅ | ✅ | Zeros to reach 46 B min |
| 6 | FCS | 4 B | (is itself) | ✅ | CRC-32 error check |

**Sizes to memorize:** 🟢 **min frame = 64 B**, **max (untagged) = 1518 B**, **max (1× 802.1Q) = 1522 B**, **preamble+SFD = 8 B**, **IFG = 12 B**.

## 3️⃣ TL;DR

- 🟢 A frame is **preamble(7) + SFD(1)** on the PHY, then the frame proper: **DA(6) + SA(6) + [VLAN(4)] + Len/Type(2) + Data(46–1500) + Pad + FCS(4)**.
- 🟢 **Preamble** is 7 bytes of `10101010` for clock sync; **SFD** is `10101011` — the trailing `…11` says "destination MAC begins on the next bit."
- 🟢 **Min frame = 64 bytes, max = 1518** (untagged). If the payload is < 46 bytes, **Pad** (zeros) fills it up so the frame reaches 64.
- 🟢 **FCS** is a **32-bit CRC** over DA→Pad (**not** preamble/SFD, **not** itself). Bad CRC ⇒ frame silently **dropped** — this is where "CRC / input errors" counters come from.
- 🔵 **Why 64 bytes?** = **slot time** (512 bit times). On old shared media a sender must still be transmitting when the farthest collision echo returns, or it can't detect the collision. Fully explained in **[2.3](./2.3-csma-cd-collisions-full-duplex.md)**.
- 🔵 **Interframe gap = 96 bit times (12 bytes)** of silence between frames. Preamble(8) + IFG(12) = 20 bytes of pure overhead per frame → why tiny packets kill efficiency.
- 🔵 **Bit order:** each octet goes on the wire **LSB-first** (§3.3); the **FCS** is the exception, sent **MSB-first**.

## 4️⃣ Importance — The Problem First 🎯

**The underlying problem:** the PHY hands the MAC a raw stream of electrical/optical transitions. That stream must be turned into *discrete, trustworthy, correctly-bounded* units. Every field in the frame exists to answer a specific failure question:

- ❓ *"When exactly does a frame begin, and is my clock aligned to the sender's?"* → **Preamble + SFD**.
- ❓ *"Where are the address boundaries?"* → fixed **6+6** byte addresses (no delimiters needed — position is implicit).
- ❓ *"How do I know the payload wasn't corrupted by noise, a bad cable, or a dying transceiver?"* → **FCS/CRC-32**.
- ❓ *"How does the receiver know where the data stops?"* → **Length** (802.3) or an implicit end via the PHY + FCS position.
- ❓ *"How do I keep a frame long enough that collisions are detectable, and short enough that no one hogs the wire?"* → **min 64 / max 1518** + **Pad**.
- ❓ *"How do receivers get a breath between frames?"* → the **interframe gap**.

**Why an engineer must own this (not just memorize field names):**

- 🔧 **Every error counter you'll ever read maps to a field here.** `CRC`/`input errors` = FCS failed. `runts` = frame < 64 B. `giants` = frame > max. `late collision` = collision after slot time. You cannot diagnose an interface without this map.
- 🔧 **Throughput math is frame math.** A 64-byte frame drags 20 bytes of preamble+IFG overhead; a 1518-byte frame drags the same 20. That's why "small packets" tank a link's usable bandwidth — and why jumbo frames exist.
- 🔧 **Security & tagging bolt onto this layout.** 802.1Q, QinQ, MACsec all insert bytes at precise offsets; if you don't know the base layout you can't reason about MTU, tag stacking, or why an oversized-but-valid "baby giant" appears.

## 5️⃣ Description 📋

- 🟢 **Preamble — 7 bytes (56 bits).** A repeating `10101010` pattern. It's a **physical-layer** construct (not addressed, not checksummed) that lets the receiver's clock **lock onto the incoming bit rate** (clock recovery) before real data arrives.
- 🟢 **SFD — Start Frame Delimiter — 1 byte.** The pattern `10101011`. Identical to the preamble *except the final bit is `1`* (`…10 11`). That broken cadence is the unambiguous marker: **"the next bit is bit 0 of the Destination MAC."**
- 🟢 **Destination MAC — 6 bytes.** Unicast, multicast, or broadcast (see 2.1). Placed **first** on purpose so a switch can decide the exit port with minimal latency (**cut-through** switching keys off this early field).
- 🟢 **Source MAC — 6 bytes.** **Always unicast** (a multicast/broadcast source = malformed). This is the field a switch *learns* from.
- 🔵 **802.1Q VLAN tag — 4 bytes (optional).** Inserted **between Source MAC and Length/Type** (starts at the 13th frame byte / 21st wire byte). = **TPID (2 B, `0x8100`)** + **TCI (2 B)**. Details → **[2.8](./2.8-trunking-802.1q.md)**. It bumps max frame **1518 → 1522** and min **64 → 68**.
- 🟢 **Length/Type — 2 bytes.** Dual meaning (see 2.1): **≤ 1500 (0x05DC)** = payload **length** (802.3); **≥ 1536 (0x0600)** = **EtherType** (Ethernet II, e.g. `0x0800` IPv4, `0x86DD` IPv6, `0x0806` ARP). `1501–1535` undefined.
- 🟢 **Payload / Data — 46 to 1500 bytes.** The encapsulated upper-layer PDU (typically an IP packet). **1500 = the classic Ethernet MTU.**
- 🟢 **Pad — 0 to 46 bytes.** If the real data is shorter than 46 bytes, the MAC appends **zero-padding** so the payload region hits 46 → total frame ≥ 64. The receiver relies on the L3 length field (e.g. IP Total Length) to know how much of the payload is real vs pad.
- 🟢 **FCS — Frame Check Sequence — 4 bytes.** A **CRC-32** computed over **DA + SA + [VLAN] + Length/Type + Data + Pad**. The receiver recomputes it; mismatch ⇒ **drop** (Ethernet does *no* retransmission — that's L4's job).
- 🔵 **Interframe Gap (IFG) — 96 bit times = 12 bytes** of idle line between frames. Gives receivers time to process and hardware to re-arm.

## 6️⃣ How It Works — Under the Hood ⚙️

### A) 🔍 Preamble + SFD, bit by bit

```
Preamble  = 10101010 10101010 10101010 10101010 10101010 10101010 10101010   (7 bytes)
SFD       = 10101011                                                          (1 byte)
                    ▲▲
                    ││
                    │└─ this final 1 breaks the "…10" rhythm
                    └── → "sync's over — Destination MAC bit 0 is next"
```

The alternating pattern is a **square wave** the receiver PLL uses to recover the clock. By the time the `…11` of the SFD arrives, the receiver is bit-synchronized and byte-aligned. **These 8 bytes are pure overhead**: not addressed, not in the FCS, not counted in the 64–1518 range.

### B) 🧮 The FCS / CRC-32 — the frame's lie detector

**Coverage (IEEE 802.3 §3.2.9):** DA, SA, Length/Type, Data, Pad. **Not** preamble/SFD, **not** the FCS field itself.

**Generator polynomial** (degree-32):

```
G(x) = x³² + x²⁶ + x²³ + x²² + x¹⁶ + x¹² + x¹¹ + x¹⁰ + x⁸ + x⁷ + x⁵ + x⁴ + x² + x + 1
     = 0x04C11DB7   (the standard "CRC-32" used across Ethernet, PKZIP, PNG…)
```

**Mechanism (conceptual):**
```
   1. Treat the protected bytes as one huge binary number M(x).
   2. Append 32 zero bits, divide by G(x) using modulo-2 (XOR) division.
   3. The 32-bit REMAINDER (after the standard invert/complement steps) = the FCS.
   4. Transmit FCS after the Pad.

   Receiver: run the same division over DA…Pad…FCS.
      remainder == a fixed "magic" constant  → frame intact  ✔  accept
      remainder != that constant             → corrupted     ✘  DROP + increment CRC counter
```

CRC-32 reliably catches **all** single/double-bit errors, all odd numbers of bit errors, any burst ≤ 32 bits, and >99.99…% of longer bursts. It is **error *detection*, not correction** — Ethernet drops and lets TCP retransmit.

> 🕵️ **Dirty secret:** CRC errors almost never mean "bad frame from software." They mean **physical-layer rot** — a nicked cable, EMI, a duplex mismatch, a dirty fiber connector, or a dying SFP. When you see rising `input errors / CRC` on `show interfaces`, go check **layer 1**, not your config.

### C) 📏 Min / Max frame math (memorize the arithmetic)

```
MINIMUM (untagged):  DA 6 + SA 6 + Len/Type 2 + Payload(+Pad) 46 + FCS 4 = 64 bytes ✅
MAXIMUM (untagged):  DA 6 + SA 6 + Len/Type 2 + Payload    1500 + FCS 4 = 1518 bytes ✅
MAXIMUM (1× 802.1Q): 1518 + 4 (VLAN tag)                                 = 1522 bytes ✅
```

- **Runt** = frame **< 64 B** (usually a collision fragment). **Giant** = frame **> max**. **"Baby giant"** = a valid frame slightly over 1518 because of tags/MPLS (e.g. 1522/1526).
- **Padding exists to guarantee the 64-byte floor**, which in turn guarantees the **slot time** window ↓.

### D) ⏱️ Slot time — *why* 64 bytes (the CSMA/CD hook)

```
Slot time = 512 bit times = 64 bytes (at 10/100 Mbps).

Shared coax, worst case: Station A at one end, Station B at the far end.
  t0   A starts sending.
  t≈   Signal races to B; just before it arrives, B (hearing silence) also sends.
  →    They collide near B. The "collision echo" must travel all the way back to A.
  RULE: A must STILL be transmitting when that echo returns, or A never knows it collided.

  Guaranteeing frames are ≥ 512 bit times long = guaranteeing A is still on the wire
  for one full round-trip = collisions are always detectable = the 64-byte minimum.
```

Full CSMA/CD algorithm, jam signal, and backoff live in **[2.3](./2.3-csma-cd-collisions-full-duplex.md)**. The *consequence* — the 64-byte floor and the `late collision` counter (a collision **after** slot time = a real fault, e.g. duplex mismatch or an over-length segment) — lives **here** because it's frame geometry.

### E) 🚦 Interframe Gap & wire overhead

```
IFG = 96 bit times = 12 bytes of idle:  9.6 µs @10M · 960 ns @100M · 96 ns @1G · 9.6 ns @10G

Per-frame fixed overhead on the wire:  Preamble 7 + SFD 1 + IFG 12 = 20 bytes

So a max frame really occupies:  1518 + 20 = 1538 bytes of "wire time"
  → efficiency ≈ 1500 / 1538 ≈ 97.5% at full payload
  → for a 64-byte frame: 1518-min-payload logic flips — overhead dominates, efficiency plummets.
```

This is the arithmetic behind **jumbo frames** (below): fewer, bigger frames ⇒ less per-frame overhead ⇒ higher goodput.

### F) 🔵 Bit transmission order (the classic gotcha)

Per **§3.3**, each octet is placed on the wire **least-significant-bit first**. That's *why* the MAC I/G bit (LSB of octet 1, see 2.1) is literally the **first bit** a receiver sees — enabling an instant "is this multicast?" decision. **Exception:** the **FCS is transmitted MSB-first** (bit 31 down to bit 0). Don't let a hex dump fool you into byte-reversing the CRC.

## 7️⃣ Pros & Cons ⚖️

| ✅ Pros of this design | ❌ Cons / Limits |
|---|---|
| 🟢 **Fixed-position fields** → no delimiters, dead-simple/fast hardware parsing. | 🔵 **Fixed 1500 MTU** by default → fragmentation or PMTUD headaches for larger L3 payloads. |
| 🟢 **Strong, cheap error detection** (CRC-32) catches virtually all line noise. | 🔵 **Detect-only, no correction** → relies on upper layers to retransmit. |
| 🟢 **Self-clocking start** (preamble/SFD) → robust sync without a shared clock line. | 🔵 **Per-frame overhead** (preamble+SFD+IFG = 20 B) hurts small-packet efficiency badly. |
| 🟢 **Min-size rule** makes collisions detectable on shared media. | 🔵 **Padding wastes bandwidth** for small payloads (e.g. a 1-byte L3 payload still ships 64 B). |
| 🟢 **Extensible** — tags/MACsec insert cleanly at defined offsets. | ⚠️ **Tag stacking pushes past 1518** → "baby giants" that mis-configured gear may drop. |

## 8️⃣ Variants — Common → Specific 🌿

- 🟢 **Standard untagged frame** — 64–1518 B. The everyday case.
- 🔵 **802.1Q-tagged frame** — +4 B → 68–1522 B. VLAN trunks (→ 2.8).
- 🔵 **QinQ / 802.1ad (stacked tags)** — +8 B → up to 1526 B. Service-provider VLAN nesting.
- 🔵 **Jumbo frames** — payload up to **~9000 B** (frames ~9018, or 9216 "super jumbo"). **Non-standard**; must be enabled **on every device in the path** or you get black-holing/fragmentation. Common in data-center storage (iSCSI, NFS, vMotion).
- 🔵 **Envelope frames (802.3as)** — standardized headroom (up to ~2000 B) for extra headers (tags, MACsec) without "jumbo."
- 🔵 **Runt / fragment** — < 64 B; a *result* (collision/error), not a designed variant.
- 🔵 **Baby giant** — slightly-over-1518 valid frame due to encapsulation overhead.

## 9️⃣ Devices / Media / Protocols 🧰

**Devices that read/act on frame fields:**
- 🟢 **[NIC / Endpoint](./devices/endpoint-nic.md)** — builds preamble/SFD, pads, computes FCS on TX; validates FCS on RX (drops bad frames in hardware).
- 🟢 **[Layer-2 Switch](./devices/switch.md)** — reads DA to forward; reads SA to learn; **store-and-forward** switches validate the **FCS before forwarding** (so they drop errors), **cut-through** switches forward after reading DA and *don't* (they can propagate errored frames — a real trade-off).
- 🟢 **[Router / L3 Switch](./devices/router.md)** — strips the frame, routes the packet, builds a **brand-new frame** (new DA/SA, recomputed FCS) per hop.

**Media:** all 802.3 copper/fiber (Block 1). FCS/CRC counters are your **primary layer-1 health signal**.

**Protocols / fields riding here:**
- 🟢 **EtherType** values (`0x0800`, `0x86DD`, `0x0806`) select the L3 protocol → **[terms](./terms/ethertype.md)**.
- 🔵 **[802.1Q](./protocols/dot1q.md)** tag insertion point (→ 2.8).
- 🔵 **MACsec (802.1AE)** — inserts SecTAG + ICV, recomputing/extending the trailer (Block 9).

## 🔟 Best Practices ✅

- 🟢 **Treat rising CRC/FCS counters as a layer-1 alarm.** `show interfaces` → check cabling, transceivers, EMI, duplex — *before* touching config.
- 🟢 **Keep MTU consistent end-to-end.** If you enable jumbo frames, enable them on **every** switch/router/NIC in the path, or you'll get silent drops / PMTUD failures.
- 🔵 **Account for tag/encap overhead** when sizing MTU (802.1Q +4, QinQ +8, MPLS/VXLAN more). Set "system MTU" to admit baby giants on trunks/uplinks.
- 🔵 **Prefer store-and-forward** where error isolation matters (it validates FCS); use cut-through only where latency is king and you accept error propagation.
- 🔵 **In throughput planning, always add the 20-byte preamble+IFG overhead** — headline "line rate" is never the goodput.
- 🔵 **Watch `late collisions`** on any link that *should* be full-duplex: a late collision on a "full-duplex" link almost always means a **duplex mismatch** (→ 2.3 / 1.4).

## 1️⃣1️⃣ No-Goes — Common Mistakes & Troubleshooting Traps 🚫

- ❌ **Counting preamble/SFD in the frame size.** They're PHY overhead, outside the 64–1518 range and outside the FCS. Min frame (64) starts at the **Destination MAC**.
- ❌ **Thinking the FCS covers the whole thing.** It covers **DA→Pad only** — never preamble/SFD, never itself.
- ❌ **Byte-reversing the FCS in a hex dump.** The FCS is transmitted **MSB-first** (unlike other octets, which are LSB-first). Different rule.
- ⚠️ **Assuming a short payload = short frame.** Sub-46-byte payloads get **zero-padded** to hit 64 B. Reading pad bytes as data corrupts your analysis — trust the L3 length field.
- ⚠️ **CRC error → blaming software/OS.** It's ~always **physical**: cable, connector, SFP, EMI, or **duplex mismatch** (half-duplex NIC vs full-duplex switch → late collisions + FCS errors).
- ⚠️ **"Giants" on trunks are broken.** Often they're **baby giants** (valid 1522/1526 B tagged frames) hitting a device with default 1518 MTU. Fix MTU, don't chase ghosts.
- ❌ **Expecting Ethernet to retransmit a dropped bad frame.** It won't. Ethernet detects & drops; **only L4 (TCP) recovers**. UDP loss from CRC drops is just gone.
- ⚠️ **Ignoring the IFG in efficiency math.** Small-frame workloads can sit far below "line rate" purely from preamble+IFG overhead — not a fault, just physics.

## 1️⃣3️⃣ Practical Tasks 🛠️

> Listed briefly; expanded step-by-step later in context.

1. 🟢 **Dissect a real frame in Wireshark.** Capture ICMP/HTTP; expand the Ethernet II layer. Identify DA, SA, Type (`0x0800`?), and note that Wireshark shows **[preamble/SFD stripped]** and often reports FCS as "not captured" (NICs strip it) — understand *why*.
2. 🟢 **Find the min-frame padding.** `ping` a host, capture an ARP request. Confirm the frame is padded to 64 B and spot the trailing zero pad after the ARP payload.
3. 🔵 **Force & observe FCS errors (lab).** In GNS3/real gear, introduce a duplex mismatch (one side `duplex half`, other `full`); run traffic; watch `show interfaces` grow **`CRC` / `input errors` / `late collision`**. Then fix and watch them stop.
4. 🔵 **Read the counters vocabulary.** On a Cisco switch: `show interfaces <id>` → map each of `runts`, `giants`, `CRC`, `frame`, `overrun`, `late collision` back to a field/geometry in this doc.
5. 🔵 **Frame-size math drill.** Compute wire bytes and efficiency for a 64-B and a 1518-B frame (include preamble 8 + IFG 12). Then redo for a 9000-B jumbo — quantify the goodput gain.
6. 🔵 **Tagged-frame offset check.** Capture a trunk (802.1Q) frame; confirm the 4-byte `0x8100` tag sits **between Src MAC and Type**, and that the frame length is up to 1522. (Deep 802.1Q → 2.8.)
