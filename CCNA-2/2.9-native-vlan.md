## 2️⃣ Visualization — Big Picture at a Glance

**On a trunk, everything is tagged — except the one native VLAN:**

```
   SW1 ══════════════ 802.1Q TRUNK ══════════════ SW2
        VLAN 10 ─▶ [TAG VID=10] ────────────────▶ VLAN 10   ✅ tagged
        VLAN 20 ─▶ [TAG VID=20] ────────────────▶ VLAN 20   ✅ tagged
        VLAN 99 ─▶ (no tag, plain frame) ───────▶ VLAN 99   🏳️ NATIVE = untagged
                    │
                    └─ the ONE VLAN per trunk sent WITHOUT a tag.
                       Default = VLAN 1. Ingress: an untagged frame → native VLAN.
```

**Native VLAN MISMATCH — two VLANs quietly become one:**

```
   SW1 (native 10) ═══════ TRUNK ═══════ SW2 (native 20)
     VLAN 10 frame ─▶ sent UNTAGGED ─────▶ arrives untagged
                                            │ SW2: "untagged = my native = VLAN 20"
                                            ▼
                               VLAN 10 (SW1)  ⇄  VLAN 20 (SW2)  ← STITCHED TOGETHER
                        an unauthorized L2 path your firewall/ACLs never see 😨
   Detected by: CDP (warns only) · STP PVST+ (blocks → PVID inconsistent)
```

**Native VLAN facts:**

| Fact | Value |
|---|---|
| 🟢 Default native VLAN | **VLAN 1** |
| 🟢 On the trunk | sent **untagged** |
| 🟢 Untagged frame received on a trunk | placed in the **native VLAN** |
| 🟢 Config | `switchport trunk native vlan <id>` |
| 🟢 Must match | **both ends** of the trunk |
| 🟢 Security rule | never VLAN 1; a dedicated **unused** VLAN with **no access ports** |

## 3️⃣ TL;DR

- 🟢 The **native VLAN** is the **one VLAN per 802.1Q trunk whose frames are sent untagged**. Every other VLAN on the trunk is tagged.
- 🟢 **Egress:** a native-VLAN frame leaves the trunk **without a tag**. **Ingress:** an **untagged** frame arriving on a trunk is assigned to the **native VLAN**.
- 🟢 It exists for **backward compatibility** — so a device that doesn't understand tags (old hub/bridge/AP) can still exchange frames over the trunk.
- 🟢 **Default = VLAN 1.** Change it with `switchport trunk native vlan <id>`, and it **must match on both ends**.
- ⚠️ **Native VLAN mismatch** = the two ends disagree → untagged frames get **re-homed** → two VLANs are silently **bridged together** (a hidden path bypassing security). **CDP warns** (`%CDP-4-NATIVE_VLAN_MISMATCH`) but takes no action; **STP (PVST+)** actually **blocks** the port (PVID inconsistency).
- 🔓 **Double-tagging VLAN hopping** abuses the native VLAN: attacker (in the native VLAN) sends a frame with **outer tag = native**, **inner tag = target**; the first switch **strips the outer** (native) tag and forwards untagged; the second switch reads the **inner** tag and delivers into the target VLAN. **One-way**, but real.
- 🛡️ **Mitigate:** native VLAN ≠ VLAN 1, use a **dedicated unused VLAN with zero access ports**, or force **`vlan dot1q tag native`** so nothing is ever untagged.

## 4️⃣ Importance — The Problem First 🎯

**The underlying problem:** 802.1Q (2.8) tags every frame so the far switch knows its VLAN. But early Ethernet had devices that **couldn't read tags** — plain hubs, old bridges, some phones/APs. If *every* frame on a trunk were tagged, those devices would drop everything. So 802.1Q kept a deliberate escape hatch:

> *"Let exactly one VLAN travel untagged, so a tag-unaware device can still participate — and so untagged frames arriving on a trunk have a defined home."*

That escape hatch is the **native VLAN**. It sounds trivial — "the untagged VLAN" — but it's **small and load-bearing**: two ways it bites you are among the most dangerous L2 faults in real networks.

- ❓ *"Where does an untagged frame on a trunk belong?"* → the native VLAN. Without this rule, untagged trunk traffic would be undefined.
- ❓ *"What if the two trunk ends disagree on the native VLAN?"* → untagged frames get **re-homed into a different VLAN** on the far side → two broadcast domains get **stitched together** with **no obvious symptom** — an unauthorized L2 path your firewalls and router ACLs are completely blind to.
- ❓ *"Can an attacker exploit 'untagged'?"* → yes — **double-tagging** rides the native VLAN to jump into a VLAN they were isolated from.

**Why an engineer must own this cold:**

- 🔧 **The mismatch is trivially fixable yet disproportionately dangerous.** It's a severity-4 log that never drops the link and repeats forever, so people filter it out — while two VLANs quietly bridge. Recognizing it is a security skill, not just a cleanup.
- 🔧 **The native VLAN is a named CCNA security topic.** Double-tagging is *the* attack tied to it; "why must native ≠ VLAN 1?" is a guaranteed exam-and-interview question.
- 🔧 **Every trunk you build has a native VLAN whether you think about it or not.** Defaulting to VLAN 1 on both ends "works," which is exactly why the risk hides in plain sight.

## 5️⃣ Description 📋

- 🟢 **Definition:** the **native VLAN** is the VLAN whose frames traverse an 802.1Q **trunk untagged**. There is **exactly one** per trunk. All other allowed VLANs are tagged.
- 🟢 **Behavior:**
  - **Egress (switch → trunk):** if a frame belongs to the native VLAN, the switch sends it **without an 802.1Q tag**.
  - **Ingress (trunk → switch):** an **untagged** frame received on a trunk is classified into the **native VLAN**. (A tagged frame is classified by its VID.)
- 🟢 **Default:** the native VLAN is **VLAN 1** unless changed.
- 🟢 **Why it exists:** **backward compatibility** with devices that don't understand 802.1Q, and a defined home for untagged trunk traffic. (It also lets a receiver "pop a tag without padding," historically.)
- 🟢 **Configuration:** `switchport trunk native vlan <id>` on the trunk interface. It is **per-trunk and locally significant**, so the two ends *can* be set differently — which is exactly the danger.
- 🟢 **Control-plane traffic:** Cisco control protocols (**CDP, VTP, DTP**) are sent **untagged when the native VLAN is 1**; if native ≠ 1 they're tagged with VLAN 1. **PVST+/PVRST+ BPDUs** on trunks carry the originating VLAN, which is how STP detects mismatches (below).
- ⚠️ **Native VLAN mismatch:** if the two trunk ends have **different** native VLANs, untagged frames sent by one end are **absorbed into a different VLAN** on the other → the two VLANs are effectively **bridged**. Consequences: **misdirected traffic, data leakage between broadcast domains, an unauthorized L2 path** (invisible to L3 firewalls/ACLs), and potential loops.
  - **CDP** detects and **reports** it (`%CDP-4-NATIVE_VLAN_MISMATCH`, severity 4) — **warning only, no corrective action**. Disable CDP (or trunk to a non-Cisco device) and the *alarm* disappears while the *bridge remains*.
  - **STP (PVST+/PVRST+)** compares the BPDU's originating VLAN to the receiving VLAN; on mismatch it declares **PVID inconsistency** and **blocks** the port for the offending VLANs (state **`PVID_Inconsistent`**) — this is the mechanism that actually *prevents* the cross-VLAN bridge.
- 🔓 **Double-tagging VLAN hopping (the native VLAN's security hole):** because native frames are untagged and switches **strip only one tag**, an attacker on the native VLAN can craft a **double-tagged** frame (outer = native, inner = target) to reach a VLAN they were isolated from. **One-way** (no return path).
- 🛡️ **Mitigations:**
  - **Move the native VLAN off VLAN 1** to a **dedicated, unused VLAN** (e.g., 999) — and **match both ends**.
  - **Ensure the native VLAN has zero access ports** — the attack only works when the attacker's access VLAN equals the trunk's native VLAN. *Moving* the native VLAN isn't enough if a live access port sits in the new native VLAN.
  - **Force native tagging** with `vlan dot1q tag native` (global) so **nothing** crosses the trunk untagged → the attacker's outer tag can never match an untagged native → double-tagging breaks.
  - Defense in depth: disable **DTP** (`switchport nonegotiate`), set modes explicitly, and **prune** the allowed list (2.8). (Switch-spoofing, the other hopping method, → 2.11/Block 9.)

## 6️⃣ How It Works — Under the Hood ⚙️

### A) 🏳️ Native VLAN classification — untagged in, untagged out

```
 EGRESS (switch → trunk):
    frame in VLAN 99 (native) ─▶ send with NO tag  (plain Ethernet)
    frame in VLAN 10          ─▶ insert 802.1Q tag VID=10

 INGRESS (trunk → switch):
    tagged frame (VID=10)     ─▶ classified as VLAN 10
    UNtagged frame            ─▶ classified as the NATIVE VLAN (99)
                                  (this rule is the whole point — untagged has a home)
```

### B) 🧵 The mismatch — how two VLANs get stitched

```
  SW1 native = 10                         SW2 native = 20
  ────────────────                        ────────────────
  VLAN 10 frame ─▶ leaves UNTAGGED ─────▶ arrives untagged on SW2's trunk
                                          │ SW2 rule: untagged = native = VLAN 20
                                          ▼
                             SW1's VLAN 10  ≡  SW2's VLAN 20    ← now one L2 domain

  Guards:
   • CDP  → logs %CDP-4-NATIVE_VLAN_MISMATCH (interfaces + both native IDs) — WARNS only.
   • STP  → PVST+ BPDU carries originating VLAN; SW2 sees VLAN-10 BPDU arriving where it
            expects VLAN 20 → PVID INCONSISTENCY → BLOCKS the port for those VLANs.
```

> 🕵️ **Dirty secret — the alarm you're trained to ignore.** `%CDP-4-NATIVE_VLAN_MISMATCH` is severity 4, never drops the trunk, and repeats forever — so it gets filtered out of syslog and forgotten. Meanwhile two broadcast domains are bridged through an accidental L2 path that **no firewall or router ACL can see**. Treat this log as a **security event**, not noise. And note: kill CDP and the *warning* vanishes but the *bridge stays* — silence is not verification. **Only STP's PVID-inconsistency block actually stops the bridge.**

### C) 🔓 Double-tagging VLAN hopping — step by step

```
 Setup: attacker's access port is in the NATIVE VLAN (say VLAN 1). Victim is in VLAN 20.
         SW1 ═══ trunk (native 1, allows 20) ═══ SW2 ── VLAN 20 ── Victim

 1. Attacker crafts a frame with TWO 802.1Q tags:
        [ outer VID = 1 (native) ][ inner VID = 20 (target) ][ payload ]

 2. SW1 processes it and forwards toward the trunk. Because the frame's OUTER tag = native (1),
    SW1 sends it onto the trunk UNTAGGED → it STRIPS ONE tag (the outer/native one).
        result on the wire:  [ inner VID = 20 ][ payload ]   ← inner tag SURVIVES

 3. SW2 receives it on the trunk, reads the (now only) tag VID=20 → delivers into VLAN 20.

 4. Victim in VLAN 20 receives the attacker's frame. The attacker "hopped" VLAN 1 → VLAN 20.

  ⚠ ONE-WAY: the reply can't be double-tagged back, so no return session — but it's enough
     for DoS, spoofing, or one-way payload injection. Works ONLY when attacker's VLAN = native.
```

### D) 🛡️ Why the mitigations work

```
 • Native ≠ VLAN 1, dedicated UNUSED VLAN (999), ZERO access ports:
     the attack needs the attacker's access VLAN to equal the trunk native VLAN.
     If no user/access port is in the native VLAN, no attacker can BE in it.  ✔

 • vlan dot1q tag native  (global):
     forces EVEN the native VLAN to be TAGGED on trunks → nothing untagged →
     the attacker's outer "native" tag never matches an untagged native → step 2 fails.  ✔

 • Also: switchport nonegotiate (kill DTP), explicit access/trunk modes, prune allowed VLANs.
     (These also blunt the OTHER hopping method — switch-spoofing → 2.11/Block 9.)
```

### E) 🔍 Configuration & verification

```
! Set a safe native VLAN — MATCH ON BOTH ENDS
Switch(config)# vlan 999
Switch(config-vlan)#  name NATIVE_UNUSED
Switch(config)# interface Gi0/1
Switch(config-if)#  switchport mode trunk
Switch(config-if)#  switchport trunk native vlan 999      ← both trunk ends identical
Switch(config-if)#  switchport nonegotiate                ← no DTP

! Or the strongest option — tag everything, no untagged native at all:
Switch(config)# vlan dot1q tag native                     ← global; tags native on all trunks

! Verify
Switch# show interfaces trunk                 ← "Native vlan" column — compare BOTH switches
Switch# show interfaces Gi0/1 switchport      ← "Trunking Native Mode VLAN: 999"
Switch# show spanning-tree                      ← watch for *PVID_Inconsistent (broken_)* states
! And watch the log for %CDP-4-NATIVE_VLAN_MISMATCH
```

## 7️⃣ Pros & Cons ⚖️

**The native VLAN concept:**

| ✅ Pros | ❌ Cons / Risks |
|---|---|
| 🟢 **Backward compatibility** — tag-unaware devices can share a trunk. | ⚠️ **Mismatch bridges VLANs silently** — hidden L2 path past your security. |
| 🟢 **Defined home** for untagged trunk frames. | 🔓 **Enables double-tagging** VLAN hopping if native = a live user VLAN. |
| 🟢 **Saves 4 bytes** on native-VLAN frames (no tag). | ⚠️ **Locally significant** → easy to misconfigure differently per end. |
| 🟢 Carries Cisco control-plane cleanly when native = 1. | ⚠️ **Default VLAN 1** is the insecure default everyone forgets to change. |

**Native-VLAN handling choices:**

| Approach | ✅ | ❌ |
|---|---|---|
| 🟢 **Dedicated unused native (999), no access ports** | closes hopping, clean | must configure on every trunk, both ends |
| 🟢 **`vlan dot1q tag native`** | strongest (nothing untagged) | slight overhead; must be consistent |
| ❌ **Leave default VLAN 1** | zero effort | insecure, mismatch-prone |

## 8️⃣ Variants — Common → Specific 🌿

**Native VLAN states:**
- ❌ **Default (VLAN 1)** — out-of-box; discouraged.
- 🟢 **Dedicated unused VLAN** (e.g., 999) — best practice, matched both ends.
- 🟢 **Tagged native** (`vlan dot1q tag native`) — no untagged frames at all.

**Mismatch detection/response:**
- 🟢 **CDP** — reports only (Cisco-to-Cisco).
- 🟢 **STP PVST+/PVRST+** — **blocks** via PVID inconsistency (the real guard).
- 🔵 **Silent** — CDP off + non-Cisco peer → no alarm, bridge persists.

**VLAN-hopping methods (context):**
- 🟢 **Double-tagging** — abuses the **native VLAN** (this doc).
- 🔵 **Switch-spoofing** — abuses **DTP** to negotiate a trunk (→ 2.11/Block 9).

## 🔟 Best Practices ✅

- 🟢 **Never use VLAN 1 as the native VLAN.** Set a **dedicated, unused** native VLAN (e.g., 999).
- 🟢 **Match the native VLAN on both ends of every trunk.** Verify with `show interfaces trunk` on *both* switches.
- 🟢 **Keep the native VLAN free of access ports** — no host should ever live in the native VLAN (kills double-tagging at the source).
- 🔵 **Prefer `vlan dot1q tag native`** in security-sensitive designs so nothing crosses untagged.
- 🟢 **Treat `%CDP-4-NATIVE_VLAN_MISMATCH` as a security event** — investigate immediately; don't filter it into oblivion.
- 🔵 **Don't rely on CDP for detection** — it only warns and vanishes if CDP is off/non-Cisco. Rely on STP's PVID-inconsistency block and consistent config.
- 🟢 **Harden trunks holistically:** `nonegotiate` (kill DTP) + explicit modes + pruned allowed list (2.8) alongside a safe native VLAN.

## 1️⃣1️⃣ No-Goes — Common Mistakes & Troubleshooting Traps 🚫

- ❌ **Confusing native VLAN with default VLAN.** Both default to VLAN 1, but **default VLAN** = where unconfigured *access* ports live; **native VLAN** = the untagged VLAN on a *trunk*. Different roles (from 2.7).
- ⚠️ **Ignoring the CDP mismatch log.** Severity 4 + never drops the link ≠ harmless. Underneath, two VLANs may be bridged — a real security hole.
- ⚠️ **Assuming CDP off = problem solved.** Disabling CDP only silences the *alarm*; the mismatch bridge (or its risk) persists. Fix the config, not the logging.
- 🔓 **Leaving native VLAN = VLAN 1 with user access ports in VLAN 1.** Textbook double-tagging exposure. Move native off 1 **and** keep it access-port-free.
- ⚠️ **Moving the native VLAN but leaving an access port in the new native VLAN.** The hop still works — the native VLAN must have **zero** access ports (or use `vlan dot1q tag native`).
- ⚠️ **Setting native VLAN on only one trunk end.** Instant mismatch. Always configure **both** ends identically.
- 🔵 **Expecting double-tagging to be bidirectional.** It's **one-way** — no return path. Still dangerous (DoS/injection), just not a two-way session.
- 🔵 **Trunking to a tag-unaware device without thinking about the native VLAN** — that device only "hears" the untagged native VLAN; everything else is invisible to it.

## 1️⃣3️⃣ Practical Tasks 🛠️

> Listed briefly; expanded step-by-step later in context.

1. 🟢 **Identify the native VLAN.** On a working trunk, run `show interfaces trunk` on both switches; read and compare the **Native vlan** column. Confirm they match.
2. 🟢 **Change it safely.** Create VLAN 999, set `switchport trunk native vlan 999` on **both** ends; re-verify. Confirm traffic still flows.
3. 🔵 **Provoke a mismatch (lab).** Set native 10 on one end, 20 on the other. Observe: the `%CDP-4-NATIVE_VLAN_MISMATCH` log **and** the STP port going **PVID-inconsistent/blocking** (`show spanning-tree`). Then fix and confirm both clear.
4. 🔵 **CDP-off experiment.** Disable CDP on the mismatched link; watch the *warning* disappear while the misconfig remains; note why STP is the real guard. Re-enable and fix properly.
5. 🔵 **Double-tagging demo (isolated lab only).** With attacker in VLAN 1 (= native) and a victim in VLAN 20, use Scapy (`Ether()/Dot1Q(vlan=1)/Dot1Q(vlan=20)/IP()...`) to send a double-tagged frame; capture on the victim side to see it arrive in VLAN 20. Then apply `vlan dot1q tag native` and confirm the hop fails.
6. 🟢 **Hardening pass.** On every trunk: dedicated unused native VLAN (no access ports) + `switchport nonegotiate` + pruned allowed list; verify with `show interfaces trunk`.
