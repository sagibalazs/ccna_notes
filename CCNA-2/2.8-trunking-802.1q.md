## 2️⃣ Visualization — Big Picture at a Glance

**Access vs trunk — one VLAN untagged vs many VLANs tagged:**

```
   ACCESS LINK (to a host)                 TRUNK LINK (switch ↔ switch)
   ───────────────────────                 ────────────────────────────
   PC ── untagged ── SW                     SW1 ══════════════════════ SW2
        (one VLAN,                              carries VLAN 10, 20, 30…
         no tag)                                each frame TAGGED with its VID
                                                 (except the NATIVE VLAN → untagged, → 2.9)
```

**The 802.1Q tag — 4 bytes slipped in after the Source MAC:**

```
  UNTAGGED frame:
  ┌──────────┬──────────┬────────────┬───────────┬─────┐
  │ Dest MAC │ Src MAC  │ EtherType  │  Payload  │ FCS │
  │   6 B    │   6 B    │    2 B     │ 46–1500 B │  4  │
  └──────────┴──────────┴────────────┴───────────┴─────┘

  802.1Q-TAGGED frame  (+4 bytes → max 1522):
  ┌──────────┬──────────┬═══════════════════┬────────────┬───────────┬─────┐
  │ Dest MAC │ Src MAC  ║   802.1Q TAG 4B   ║ EtherType  │  Payload  │ FCS │  ← FCS RECOMPUTED
  │   6 B    │   6 B    ║ TPID  │   TCI     ║    2 B     │ 46–1500 B │  4  │
  └──────────┴──────────╬═══════╪═══════════╬════════════┴───────────┴─────┘
                        ║0x8100 │ PCP DEI VID║
                        ║ 16 b  │ 3b  1b 12b ║
                        ╚═══════╧═══════════╝
                         └ sits where EtherType used to be; real EtherType moves right
```

**Tag fields cheat-sheet:**

| Field | Bits | Value / meaning |
|---|:---:|---|
| 🟢 **TPID** (Tag Protocol ID) | 16 | **`0x8100`** = "this frame is 802.1Q-tagged" |
| 🔵 **PCP** (Priority Code Point) | 3 | 802.1p priority / **CoS 0–7** (voice = 5, from 2.7) |
| 🔵 **DEI** (Drop Eligible Ind., ex-**CFI**) | 1 | drop-eligibility (CFI legacy: MAC canonical format) |
| 🟢 **VID** (VLAN Identifier) | 12 | the VLAN, **1–4094** (0 = priority-only, 4095 reserved) |

**Sizes:** 🟢 tag = **4 B** · tagged frame max **1522 B** · min **68 B** · QinQ (double tag) **1526 B**.

## 3️⃣ TL;DR

- 🟢 A **trunk** is a switch-to-switch (or switch-to-router/AP) link that carries **many VLANs at once**. To keep them separated, each frame is **tagged** with its VLAN ID.
- 🟢 **802.1Q** is the standard tag: a **4-byte** field inserted **between the Source MAC and the EtherType**. Its front half, **TPID = `0x8100`**, sits where the EtherType normally is and flags "I'm tagged."
- 🟢 The back half, **TCI (16 bits)**, splits into **PCP (3-bit priority/CoS)**, **DEI/CFI (1 bit)**, and **VID (12-bit VLAN ID, 1–4094)**.
- 🟢 Adding the tag pushes max frame size **1518 → 1522** and **forces the FCS to be recomputed**.
- 🟢 **One VLAN per trunk is sent UNTAGGED — the native VLAN** (default VLAN 1). Everything else is tagged. (Deep dive → 2.9.)
- 🟢 **Configure:** `switchport mode trunk` (+ `switchport trunk encapsulation dot1q` on ISL-capable gear); **prune** with `switchport trunk allowed vlan`. **Verify:** `show interfaces trunk`.
- 🔵 **ISL** (Cisco's old proprietary trunking that *wrapped* the whole frame) is **dead** — 802.1Q won. **QinQ** (802.1ad) double-tags with an outer **`0x88A8`** for service providers.
- 🔵 A trunk **defaults to carrying all VLANs** — prune it to the VLANs you actually need (broadcast scope, STP load, security).

## 4️⃣ Importance — The Problem First 🎯

**The underlying problem:** VLANs (2.6) segment a switch — but a VLAN is only useful if it can **span multiple switches**, and real networks have dozens of VLANs and only so many physical links. You cannot run one cable per VLAN between every switch pair; that's absurd wiring.

So: *"How do I carry VLAN 10, 20, and 30 across a **single** link between two switches, and have the far end know which frame belongs to which VLAN?"*

- ❓ Without a marker, frames from different VLANs arriving on one link are indistinguishable → the receiving switch can't keep them separated → segmentation collapses.
- ✅ **802.1Q answers this by stamping each frame with its VLAN ID** (a tag). One link, many VLANs, perfectly separated. That's a **trunk**.

**Why an engineer must own this cold:**

- 🔧 **Trunks are the connective tissue of every multi-switch network.** Every uplink between access and distribution, every switch-to-switch link, is a trunk. Get it wrong and whole VLANs go dark.
- 🔧 **The tag is where QoS, security, and MTU all live.** The **PCP** bits carry voice/video priority (from 2.7); the **native VLAN** and **DTP** are attack surfaces (VLAN hopping); the **+4 bytes** cause "baby giant" MTU issues on downstream gear. All of it is *in this tag*.
- 🔧 **"VLAN works on switch A, not switch B" is a trunk problem 90% of the time** — VLAN not in the **allowed list**, native VLAN mismatch, or the link isn't actually trunking. `show interfaces trunk` is your scalpel.
- 🔧 **Router-on-a-stick, inter-VLAN routing, and multi-SSID APs all ride 802.1Q trunks** — this tag is the foundation those later topics build on.

## 5️⃣ Description 📋

- 🟢 **Trunk port:** a switch port that carries traffic for **multiple VLANs** over a single physical link, using **VLAN tags** to keep them separate. Typically switch↔switch, switch↔router (router-on-a-stick → 2.10), or switch↔AP (multi-SSID).
- 🟢 **Access vs trunk (recap + contrast):** an **access** port = **one VLAN, untagged** (to a host, 2.7); a **trunk** port = **many VLANs, tagged** (to another network device). A trunk does **not** appear under any VLAN in `show vlan brief` (from 2.6).
- 🟢 **IEEE 802.1Q tagging:** the industry-standard method. It **inserts a 4-byte tag** into the Ethernet frame **between the Source MAC and the EtherType/Length field** — it does *not* wrap the frame. The original frame is otherwise intact; only the **FCS is recomputed**.
  - **TPID — Tag Protocol Identifier (16 bits) = `0x8100`.** It occupies the position where the EtherType normally sits; a device reading `0x8100` there knows a tag follows.
  - **TCI — Tag Control Information (16 bits):**
    - **PCP — Priority Code Point (3 bits):** the **802.1p** priority, **CoS 0–7**, for QoS (voice = 5, from 2.7).
    - **DEI — Drop Eligible Indicator (1 bit):** marks a frame as drop-eligible under congestion. Historically **CFI (Canonical Format Indicator)** for Ethernet↔Token-Ring MAC-format compatibility (CFI=0 canonical).
    - **VID — VLAN Identifier (12 bits):** the VLAN, range **1–4094** (VID **0** = "priority tag only, no VLAN"; VID **4095/0xFFF** reserved).
  - After the tag comes the **original EtherType** (e.g., `0x0800` IPv4).
- 🟢 **Frame size impact:** tag adds 4 bytes → **max 1518 → 1522**, **min 64 → 68**. (802.3ac formalized this frame extension.)
- 🟢 **Native VLAN (intro only, → 2.9):** exactly **one VLAN per trunk is sent UNTAGGED** — the **native VLAN** (default **VLAN 1**). It exists for backward compatibility with devices that don't understand tags. Everything else on the trunk is tagged.
- 🟢 **Allowed VLAN list:** by default a trunk carries **all VLANs (1–4094)**. You **prune** it with `switchport trunk allowed vlan` to only the VLANs that need to cross that link.
- 🔵 **ISL (Inter-Switch Link):** Cisco's **legacy, proprietary** trunking. Unlike 802.1Q's *insertion*, ISL **encapsulated the entire frame** in a 26-byte header + 4-byte CRC (**30 bytes** overhead). It's **deprecated/unsupported** on modern switches — **802.1Q is universal**. Historical relevance only.
- 🔵 **QinQ (IEEE 802.1ad):** stacks **two** tags — an outer **S-TAG (TPID `0x88A8`)** for the provider + inner **C-TAG (`0x8100`)** for the customer — to carry customer VLANs transparently across a provider core (frame up to **1526 B**). Beyond CCNA.
- 🔵 **DTP (intro only, → 2.11):** Cisco's **Dynamic Trunking Protocol** auto-negotiates whether a link becomes a trunk. Modes: `access`, `trunk`, `dynamic auto`, `dynamic desirable`, plus `nonegotiate`. Auto-trunking is a **security risk** (VLAN hopping) — hardcode and `nonegotiate` in production.

## 6️⃣ How It Works — Under the Hood 🔬

### A) 🏷️ Tag insertion & stripping — the trunk's job at each hop

```
PC-A (VLAN 10) → SW1 access port → SW1 trunk → SW2 trunk → SW2 access port → PC-C (VLAN 10)

 1. PC-A sends an UNTAGGED frame into SW1's access port (access vlan 10).
 2. SW1 associates it with VLAN 10 internally.
 3. Frame EXITS SW1's TRUNK → SW1 INSERTS an 802.1Q tag: VID=10 (+ PCP if QoS).
       → recomputes FCS → sends the 1522-max tagged frame across the trunk.
 4. SW2 receives on its TRUNK, reads TPID 0x8100 → sees VID=10 → keeps it in VLAN 10.
 5. Frame EXITS SW2 toward PC-C on an ACCESS port → SW2 STRIPS the tag → PC-C sees plain Ethernet.

 Rule of thumb:
   • enters/leaves an ACCESS port → UNTAGGED (host side)
   • crosses a TRUNK            → TAGGED (except the native VLAN → untagged, → 2.9)
```

### B) 🔬 The 4-byte tag, bit by bit

```
        ┌──────────────── 32 bits ────────────────┐
        │  TPID (16)  │        TCI (16)            │
        │  0x8100     │ PCP(3) │ DEI(1) │ VID(12)  │
        └─────────────┴────────┴────────┴──────────┘
                         │        │        │
   priority/CoS 0–7 ◀────┘        │        └────▶ VLAN ID 1–4094
   (voice=5, from 2.7)            │              (0 = priority-only tag,
                                  │               4095 = reserved)
        drop-eligible / ex-CFI ◀──┘

 Placement trick: TPID sits in the EtherType slot. A switch reads 0x8100 there and
 thinks "not a payload type — a tag!" → parses the next 2 bytes as TCI, THEN finds the
 real EtherType (0x0800 IPv4, 0x86DD IPv6, …) after the tag.
```

### C) 🧮 Why the FCS must change, and the MTU cost

```
The FCS (from 2.2) is a CRC over DA…payload. Inserting 4 tag bytes CHANGES the covered
data → the old FCS is now wrong → the switch MUST recompute the CRC when it tags/untags.

Size math:
   untagged max = 1518   →  tagged max = 1518 + 4 = 1522   ("baby giant")
   untagged min =   64   →  tagged min =   64 + 4 =   68
   QinQ (2 tags)         =  1518 + 8   = 1526

 ⚠ A device with a hard 1518 MTU may DROP 1522-byte tagged frames as "giants."
   On trunks/uplinks carrying full-size tagged frames, allow for the extra bytes
   (system/jumbo MTU) — a real cause of mysterious large-frame loss. (Ties to 2.2.)
```

### D) 🛠️ Trunk configuration (Cisco)

```
! On ISL-capable switches you must pick the encapsulation first; on dot1q-only gear it's implicit
Switch(config)# interface Gi0/1
Switch(config-if)#  switchport trunk encapsulation dot1q   ← (only where ISL exists, e.g. 3560/3750)
Switch(config-if)#  switchport mode trunk                  ← force this port to be a trunk
Switch(config-if)#  switchport trunk allowed vlan 10,20,30 ← PRUNE to needed VLANs (best practice)
Switch(config-if)#  switchport trunk native vlan 99        ← native VLAN (→ 2.9; match both ends)
Switch(config-if)#  switchport nonegotiate                 ← disable DTP (harden; → 2.11)

! Managing the allowed list later:
Switch(config-if)# switchport trunk allowed vlan add 40
Switch(config-if)# switchport trunk allowed vlan remove 20
Switch(config-if)# switchport trunk allowed vlan all        ← back to default (1–4094)
```

### E) 🔍 Verification — reading a trunk like an engineer

```
Switch# show interfaces trunk
Port      Mode        Encapsulation  Status    Native vlan
Gi0/1     on          802.1q         trunking  99            ← is it actually trunking? which native?

Port      Vlans allowed on trunk
Gi0/1     10,20,30                                           ← your pruned list

Port      Vlans allowed and active in management domain
Gi0/1     10,20,30                                           ← allowed AND exist in the DB

Port      Vlans in spanning tree forwarding state and not pruned
Gi0/1     10,20                                              ← actually forwarding (STP may block some)

Switch# show interfaces Gi0/1 switchport
  Administrative Mode: trunk
  Operational Mode: trunk           ← admin vs operational (a DTP/mismatch can differ! → 2.11)
  Trunking Native Mode VLAN: 99
  Trunking VLANs Enabled: 10,20,30
```

> 🕵️ **Dirty secret — "administrative vs operational" is where trunks lie to you.** You can *configure* `switchport mode trunk` (admin), but if the other side won't agree (DTP mismatch, encapsulation mismatch, or an access port on the far end), the **operational** mode may not be `trunk` — and the link silently fails to carry tagged VLANs. **Always read the *operational* line**, and check `show interfaces trunk` shows `trunking`. Admin intent ≠ operational reality.

### F) ✂️ Why prune the allowed list

```
Default trunk = carries ALL VLANs (1–4094). Consequences of NOT pruning:
  • Every broadcast in every VLAN crosses every trunk → wasted bandwidth.
  • STP runs an instance per VLAN (Rapid PVST+, → 2.18) → more CPU, bigger failure domain.
  • Bigger attack surface (a VLAN reachable where it needn't be).
Prune to only the VLANs a link must carry → less broadcast, less STP, tighter security.
(VTP pruning automates some of this → 2.12.)
```

## 7️⃣ Pros & Cons ⚖️

**Trunking / 802.1Q as a design:**

| ✅ Pros | ❌ Cons / Costs |
|---|---|
| 🟢 **Many VLANs on one link** — no per-VLAN cabling. | 🔵 **+4 bytes** per frame → MTU/"baby giant" issues on strict gear. |
| 🟢 **Open standard** (802.1Q) — multi-vendor interoperable. | 🔵 **FCS recompute** at every tag/untag (tiny cost, but real). |
| 🟢 **Carries QoS (PCP) & VLAN in one tiny header.** | ⚠️ **Native VLAN + DTP = attack surface** (VLAN hopping → 2.9/Block 9). |
| 🟢 **Prunable** — control which VLANs cross each link. | ⚠️ **Admin ≠ operational** — silent trunk-formation failures. |
| 🟢 **Foundation** for inter-VLAN routing, multi-SSID APs, QinQ. | 🔵 **Per-VLAN STP** over trunks scales cost with VLAN count. |

**802.1Q vs ISL (why 802.1Q won):**

| | 802.1Q ✅ | ISL ❌ |
|---|---|---|
| Standard | 🟢 IEEE, universal | Cisco-proprietary |
| Method | inserts 4-byte tag | wraps whole frame (30 B) |
| Native VLAN | 🟢 untagged support | none (tags all) |
| Status | current | **deprecated/unsupported** |

## 8️⃣ Variants — Common → Specific 🌿

**Trunk encapsulations:**
- 🟢 **802.1Q (dot1q)** — the standard; **the only one you'll use**.
- 🔵 **ISL** — Cisco legacy, dead.
- 🔵 **QinQ / 802.1ad** — provider double-tagging (outer `0x88A8`).

**Tag types (by VID):**
- 🟢 **VLAN tag** — normal (VID 1–4094).
- 🔵 **Priority tag** — VID 0, PCP only (QoS without changing VLAN).

**Trunk formation (→ 2.11):**
- 🟢 **Static `mode trunk`** (+ `nonegotiate`) — the secure/best-practice way.
- 🔵 **DTP-negotiated** (`dynamic auto`/`desirable`) — convenient, riskier.

**Trunk endpoints:**
- 🟢 **Switch ↔ switch** — the classic uplink.
- 🟢 **Switch ↔ router** — router-on-a-stick subinterfaces (→ 2.10).
- 🟢 **Switch ↔ AP** — multi-SSID/VLAN wireless.
- 🟢 **Switch ↔ server** (tagged NIC) — VM hosts trunking multiple VLANs.

## 🔟 Best Practices ✅

- 🟢 **Hardcode trunks** with `switchport mode trunk` + **`switchport nonegotiate`** — don't rely on DTP auto-negotiation (security + determinism).
- 🟢 **Prune the allowed VLAN list** to only what each trunk must carry (`switchport trunk allowed vlan`) — less broadcast, less STP, smaller attack surface.
- 🟢 **Change the native VLAN off VLAN 1 and match both ends** (`switchport trunk native vlan 99`) — full rationale in 2.9.
- 🟢 **Verify operational, not just admin.** Confirm `show interfaces trunk` shows `trunking` and the right native/allowed VLANs; read the **Operational Mode** line.
- 🔵 **Account for the +4-byte MTU** on trunks carrying full-size tagged frames (avoid baby-giant drops).
- 🔵 **Use dot1q everywhere** (ISL is dead); keep encapsulation consistent end-to-end.
- 🔵 **Keep both ends' allowed lists and native VLANs consistent** — asymmetric trunks cause silent, one-directional VLAN loss.

## 1️⃣1️⃣ No-Goes — Common Mistakes & Troubleshooting Traps 🚫

- ❌ **Assuming `switchport mode trunk` guarantees a trunk.** The **operational** mode may differ (DTP/encapsulation/access-port mismatch on the far end). Verify with `show interfaces trunk`.
- ❌ **Forgetting the VLAN must be in the allowed list.** A VLAN exists on both switches but isn't allowed on the trunk → it silently can't cross. Classic "works locally, not across" bug.
- ⚠️ **Native VLAN mismatch** between trunk ends → the untagged VLANs differ → traffic leaks between VLANs + STP/CDP errors. (Deep → 2.9.)
- ⚠️ **Leaving DTP on** (`dynamic auto/desirable`) → an attacker can negotiate a trunk and VLAN-hop; also unpredictable trunk formation. `nonegotiate` it.
- ⚠️ **Ignoring the +4-byte MTU** → 1522-byte tagged frames dropped as "giants" on strict-MTU gear. Allow for tag overhead.
- 🔵 **Connecting an 802.1Q trunk to a non-tag-aware device** → it sees `0x8100` as an unknown EtherType and drops/mishandles frames. Trunks go between tag-aware devices only.
- ❌ **Expecting a trunk in `show vlan brief`.** Trunks aren't members of one VLAN — they never appear there (from 2.6). Use `show interfaces trunk`.
- 🔵 **Mixing encapsulations** (ISL one side, dot1q other) → no trunk. Modern answer: dot1q both ends.

## 1️⃣3️⃣ Practical Tasks 🛠️

> Listed briefly; expanded step-by-step later in context.

1. 🟢 **Build a trunk (Packet Tracer 8 / GNS3).** Two switches, VLANs 10 & 20 on each, two PCs per VLAN. Trunk the uplink; verify PC-A(SW1,VLAN10) ↔ PC-C(SW2,VLAN10) works and cross-VLAN doesn't.
2. 🟢 **Read `show interfaces trunk`.** Identify Mode, Encapsulation, Status (`trunking`), Native VLAN, and the three VLAN lists (allowed / allowed+active / forwarding).
3. 🟢 **Prune & observe.** `switchport trunk allowed vlan 10` (remove 20); confirm VLAN 20 can no longer cross while VLAN 10 still works.
4. 🔵 **Dissect the tag in Wireshark.** Capture a trunk frame; expand the 802.1Q layer; read TPID `0x8100`, PCP, DEI, VID; confirm the real EtherType sits *after* the tag and the frame length reaches ~1522.
5. 🔵 **Admin vs operational.** Set one side `mode trunk` and the other `mode access` (or leave DTP mismatched); observe the **operational** mode fail to become trunk in `show interfaces switchport`. Fix and recheck.
6. 🔵 **MTU/baby-giant test.** Push full-size tagged frames across a trunk to a device with default MTU; observe/reason about giant drops; correct MTU.
7. 🔵 **Native VLAN preview.** Set mismatched native VLANs on the two trunk ends; note the CDP native-VLAN-mismatch warning (full treatment → 2.9). Then match them.
